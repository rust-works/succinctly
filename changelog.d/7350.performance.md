- **jq: a wide object that repeats a key finds its repeats from its text** (#7350).
  When the only reason the canonical scan declines an object is a repeated key, the printer used to walk every
  field through the index to find the few that repeat before printing the object from its text (#7346). It now
  cuts the members out of the certified text and hashes each key the way the scan did, and leaves only objects
  of long members (over 256 bytes each on average) to the walk, which costs the same per member whatever its
  length. On a 100 MB object of 7.1 M keys with one repeated key, `.` takes 0.47 s instead of 0.64 s and `-c .`
  0.38 s instead of 0.54 s on an AMD Ryzen 9 7950X (0.40 s instead of 0.49 s, and 0.31 s instead of 0.40 s, on an
  Apple M4 Pro, which retires 9,579 M instructions instead of 11,195 M for `.`). The saving grows with the
  object: `-c .` is 17%, 24% and 30% faster at 1, 10 and 100 MB on the 7950X. A repeat-declined object inside a
  larger value gains as much, and peak memory is unchanged.
