- **jq: pretty-printed output of a compact document streams, in about half the memory and up to 2.7x faster** (#7271).
  `succinctly jq .` rendered the whole result into memory before writing any of it, so that a document that turns
  out malformed late prints nothing, as in jq; it held the input plus the full output. When the canonical scan the
  compact path already uses certifies the document, the indented render cannot fail, so it is now written out
  64 KiB at a time, and written by re-indenting the certified bytes instead of walking the tree. At 100 MB,
  `jq .` over `users` peaks at 89 MiB instead of 197 MiB and takes 199 ms instead of 532 ms on an Apple M4 Pro
  (92 MiB instead of 200 MiB, 253 ms instead of 666 ms on an AMD Ryzen 9 7950X); over `numbers` 119 MiB instead
  of 245 MiB and 315 ms instead of 446 ms (121 instead of 249 MiB, 339 instead of 520 ms), and over `strings`
  111 MiB instead of 203 MiB, below jq 1.7.1's 130-159 MB (113 instead of 206 MiB), with `--tab`, `--indent n`,
  `-C` and piped input the same. Pretty-printed input, `-S` and any document the scan declines (a number spelling
  jq rewrites, a repeated key, a fault anywhere) keep the buffer and print exactly what they printed before, and
  a document with a late fault still prints nothing.
