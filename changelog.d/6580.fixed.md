- **yq: a line left after a comment-ended scalar inside an explicit key's block is refused, and a lone dash in a key's sequence takes the value below it, as yq does** (#6580). `? - b` / `   # c` / `   x` is `did not find expected '-' indicator` in yq v4.53.3; here it was accepted, with `x` read as a second item of the key (and dropped altogether from a later item, `? - a` / `  - b` / `    # c` / `    x`; the same under `? - - b` and `? - k: b`). The stray-line refusal was skipped for everything while an explicit key was pending, which was meant for the key's own plain scalar (judged separately since #6371); it is now skipped only for that scalar, so a scalar inside a container the key opened is refused like any other. The second difference was in the same arm: a dash alone on its line (`? -` / `   &x` / `   x`, or without the properties) closed the first item as null and read the value as a second item, so the key held `[null, x]` where yq's holds `[x]` and the YAML output spelled it `? -` / `  - &x x` where yq writes `? - &x x`. The item now stays open for the main loop, and its comments are placed by the routine an ordinary item uses (extracted as `defer_item_value_to_later_lines`, one copy instead of two). A differential of 784 documents (seven key-sequence heads, four lines between the dash and the value, seven values, four followers) as YAML and JSON against yq v4.53.3: 1,456 of 1,568 outputs agreed before and 1,536 after, none the other way; the 32 left differ before and after (a comment line left of a nested container under a lone dash, and a plain scalar folded over a blank line, spelled `"a\nx"` where yq writes a `|-` block, which ordinary items share).
