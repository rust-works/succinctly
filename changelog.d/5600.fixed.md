- **jq: a `::`-qualified name is accepted as an unquoted object key and as a parameter name** (#5600). jq reads `a::b` as one identifier wherever an identifier is allowed, so `{a::b: 1}` is `{"a::b":1}`, `{a::b}` is `{"a::b":null}`, `. as {a::b: $x} | $x` binds, and `def f(a::b): a::b; f(1)` and `def f($a::b): $a::b; f(1)` are `1`; `succinctly jq` failed each with exit 3. #5590 had taught only the `def` name and a call. A reserved word before the `::` (`{if::x: 1}`) is part of the name, and a `::` with a gap or no name after it (`{a:: 1}`, `{a::1: 1}`) stays a compile error, as in jq. `succinctly yq` is unchanged. Pinned against the jq 1.7.1 source build in `tests/jq_cli/i5600.rs`; fifteen syntax-form probes of `dev compare jq` (#5552) cover them.
