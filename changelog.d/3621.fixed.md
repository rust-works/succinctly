- **jq: a `?//` retry past `first`/`nth`'s stop keeps the retried element's position for `key`/`path`** (#3621). `[.a | first([1] as [$q] ?// $b | (.b[], 5)) | key]` answered `[0,null]` (and `path` `[["a","b",0],[]]`): the second output the retry delivers was decoded into a value that stands at no node, so a `key`/`path` after it read the root placeholder, where `limit(1; ...)` already answered `[0,0]`. The decode is still checked first, so an undecodable retried element still raises; only the node is no longer thrown away. `nth(1; ...)` follows (`[1,0]`, the element jq's value mode delivers second, `[2,1]`). `skip` is unchanged: it has no stop to retry past, and the `5` it delivers is a literal with no node.
