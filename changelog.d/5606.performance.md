- **jq: an array constructor, an object construction and an `as` binding after a computed number no longer write the number out and index it again** (#5606, #5602 follow-up).
  `[.numbers[]|.+1|[.]]` wrote each `.+1` result out as JSON and indexed it to build `[.]`. For a computed `Int` or `Float` (not a NaN, not a document's literal)
  `[e]` is now the one-element array of `e`'s answer, `{k: e}` the object of its entries' answers, and `. as $x | body` binds `$x` to the number as the evaluator's own bind does and
  answers the body from the number, for the element, entry values and body the owned routes answer (the operators, `$x`, `.`, literals, constructors, nested `as`). Anything else
  (a generator element, a computed key, a destructuring bind, a body that calls a function) bridges as before. Over a generated `numbers` document (Apple M5 Max, interleaved
  min, 10 MB, jq 1.7.1, against a build with #5602): `.+1|[.]` 0.67x -> 1.18x of jq, `.+1|. as $x|$x` 0.50x -> 1.03x, `floor|. as $x|$x*2` 0.61x -> 1.40x,
  `.+1|{a:.}` 0.60x -> 1.13x and `.+1|[.+1]` 0.61x -> 1.17x; instructions retired fall to 0.43-0.56 of the base build, and the same rows on an Apple M4 Pro read 0.66x -> 1.20x, 0.53x -> 1.11x, 0.73x -> 1.46x, 0.65x -> 1.19x and 0.64x -> 1.29x.
