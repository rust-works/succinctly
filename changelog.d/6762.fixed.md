- **yq: the routes that gather a source before indexing it read a BOM-prefixed file with no header too** (#6762). #5357 did it for the streaming routes (stdin and files with `.`, `-N`, `-I=0`, `-o=json`); `-P`, a write (`.a = 5`, `del(.a)`), `-i`, `--eval-all` and `--slurp` still echoed the first document's leading `---`. `printf '\xef\xbb\xbf---\na: 1\n' | yq '.a = 5'` printed `---` / `a: 5` where yq prints `a: 5`. Now such a source has no preamble to print back, `line` and `column` count every line of the text (`---` / `a: 1` is line 2, as in yq, where it was 1), the blank lines or the marker between a first document's head comment and its content are no part of the comment (`# c` / blank / `a: 1` with `.a = 5` prints `# c` / `a: 5`), and a run of leading `---` is a null document and then the next one for `--eval-all`/`--slurp` too. Measured against yq v4.53.3 over three seeds of 1,800 random BOM rows on the DOM routes, 0 rows got worse and 145, 176 and 163 got right.
