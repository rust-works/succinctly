- **yq: `-C` colors YAML the way yq does** (#5416). yq colors by tokenizing the text it encoded with go-yaml's scanner and printing each line of a token in the color of its type, so keys are cyan, strings green, numbers and booleans bright magenta, anchors and aliases bright yellow and comments grey; and the empty span at the start of a line, the span that opens on the space before a value and a scalar result printed bare all follow from the same scanner. `succinctly yq -C` colored with a fixed three-color re-lexer instead: numbers and booleans were not colored, an apostrophe in a plain scalar (`a: it's ok`) opened a green span that ran to the end of the output, a bare scalar result such as `.a` was colored as a key, anchors, aliases and comments were plain, and a quoted key was colored as a string. It now runs a port of that scanner and printer, line by line so that a streamed `-C` keeps its bounded working set (#808), and matches yq v4.53.3 byte for byte over several thousand generated documents, about twenty filters and the `-P`, `-I`, `-N`, `--no-doc`, `-e` and `-0` flags, wherever the uncolored output already agrees. One difference is deliberate: go-yaml drops the digits of a `\x`, `\u` or `\U` escape in a double-quoted scalar from the text it prints, which changes the string, so the escape is kept (`docs/compliance/yq/limitations.md`).
