- **jq: a negated class of bytes alone whose range holds the lead bytes matches no multibyte character** (#6246). `"aé€" | [match("[^\\x80-\\xFF]";"g").string]` is `["a"]` in jq 1.7.1 and was `["a","é","€"]`; `[^\x41-\xFF]` matches nothing, and `[^\x80-\xBF]` still matches all three. Oniguruma keeps single bytes in a bitset and tests a negated class with no code point against the first byte of a multibyte character, so a range that holds `C2`..`F4` excludes every one of them. The class is now written with the non-ASCII range added; a member that is a code point or a Unicode class (`é`, `\x{E9}`, `\w`, `\p{L}`, `[:alpha:]`) keeps the negation of characters, as in jq. Under `i` (the modifier, or any inline option that sets it) a class holding `k`, `s`, `[:ascii:]` or a range over them is left as it was, since their folds to the Kelvin sign and the long s are code points, which is a gap where `i` is not really in force at that class; the others are written with the character checked after the class (a look-behind, so they run on the backtracking engine). The grid of `[^\xLO-\xHI]` over seven starts and four ends, and 60 further shapes, agree with jq.
