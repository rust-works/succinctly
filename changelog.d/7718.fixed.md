- **jq: `--seq` reads a record after the last newline** (#7718). `printf '\x1e1\n\x1etrue' | jq --seq -c .` printed `1` alone and exited 0, as jq 1.7.1 does: an empty record that was the first thing jq's last read held ended the stream silently, so `\x1e"a"\n\x1e"b"` lost `"b"`, `\x1e\x1etrue` printed nothing, `[inputs]` over `\x1e[1]\n\x1e[2]` was `[[1]]`, and a last record cut short after a newline went without its warning (#2998). Now every record is read, as jq 1.8.2 does (jqlang/jq#3279), on every `--seq` route (a file, several files, standard input, a pipe or a file read in windows, and `--seq --stream`). The same upstream change makes a byte-order mark that breaks off wipe the end-of-text warning, makes `--seq -s` print that warning before the program runs, and puts every event of `--seq --stream -s` in the array; all three follow 1.8.2. Where the run stands after the last input (`<unknown>` positions) stays jq 1.7.1's (#7607). The difference from the pinned 1.7.1 is recorded in `docs/compliance/jq/limitations.md`.
