- **jq: `tojson`/`tostring` write their text in one pass, and a `del` of a static path no longer round-trips through JSON** (#5549).
  `tojson`, `tostring`, string interpolation and `@json` built a `String` per node and joined them, so every level of nesting copied everything below it again;
  they now append to one buffer, and `.users | map(tostring)` over a 7 MB document is 21% faster on a 7950X and 31% on an M4 Pro.
  A `del(.users[0])` (a path of field names and literal indices) used to write the whole document out as JSON and index it again to hand the builtin a cursor;
  it now deletes from the document it already holds (a program that binds a variable to a node of the document, `. as $x | ...`, keeps the old route).
  `del(.users[0]) | .users | length` over 7 / 73 MB went from 93 / 922 ms to 75 / 738 ms on an Apple M4 Pro (jq 1.7.1: 70 / 746 ms) and from 153 / 1555 ms to 123 / 1253 ms on a 7950X;
  `tojson | fromjson | .users | length` from 259 / 2608 ms to 208 / 2085 ms (M4 Pro; jq 1.7.1: 195 / 1986 ms) and from 352 / 3807 ms to 308 / 3159 ms (7950X).
  Release builds, interleaved, min of 11, output identical on all 27 configurations; the rows this change cannot reach read within the control run's noise (`.users | length` and a `select` over the records).
  What is left of the gap to jq on `.users[0].name = "x" | .users | length` (about 1.10x on an M4 Pro) is the cost of building the owned document, the same for every query that has to.
