- **yq: `-p csv` / `-p tsv` read a cell as its first YAML document and its first complete flow collection, as yq does** (#7136). yq decodes one document from a cell and never reads what follows it, so `[1-4];[5-8];9` (a real cell of a phone-prefix table) is `["1-4"]`, `a: 1` / `---` / `b: 2` is `{"a": 1}`, `5` / `---` / `1` is `5`, and a document marker with nothing in it is `null`. `succinctly yq` kept the cell's own text whenever anything followed the first node, and wrote a `...` line into the table (`a: 1` / `...` was a parse error). A cell whose text after the node fails go-yaml's scanner (`[1] - x`, `[1] 'q`) is still its text, as in yq. Pinned against 51 cells from yq v4.53.3 in `tests/yq_cli/i7136.rs`; on 109 real `.tsv` files the differences fell from 7 to 3 (the others are integers past `i64`).
