A `--seq` record left open (`\x1e[1,`) that runs on into a file meets its fault at the read of the last file, and the fault is an event of the stream, so jq has it in the array: `jq --seq -s --stream-errors . trunc pa missing missing2` printed the array without `["Unfinished JSON term at EOF at line 1, column 7",[1]]`, which `trunc pa missing empty` and `trunc pa missing dir` also lost. A failed file in the middle of the list is now a source of that read, as it is for `-s --stream-errors` without `--seq` (#6730), and a last file that did not open is given its tail once. One failed file after the last file with bytes (`trunc pa missing`, `trunc pa dir`) and `--seq -s --stream`, whose fault is a warning, are unchanged. 58 of 72,180 rows of a sweep over five programs, six flag sets and every list of up to three files (and of four over six of them) moved to jq's answer and none moved away.
