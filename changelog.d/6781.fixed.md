- **jq: `--seq --stream` and `--seq --stream-errors` stop at a failed file after a program that reads `input`** (#6781). A program that reads `input` without `-n` and stops before the end of the stream (`first(inputs)`, `[limit(2;inputs)]`, `try input` twice) ended jq's main loop at the file that did not open or the directory it reached, so the fault at the end of the text was never popped. succinctly read on: it said `Unfinished JSON term at EOF` under `--stream` and ran the program once more for the fault event under `--stream-errors` (`jq -c --seq --stream 'first(inputs)' rend gone obj` now says only `Could not open file gone`, as jq 1.7.1 does). The loop now stops as soon as a read has counted a failure, as jq's `while (jq_util_input_errors(...) == 0 ...)` does, instead of when the last value read names a source past it, which the held-back closing event the program's `input` read does not.
