- **jq: `-R -n` reports a file that did not open only when a read reaches it** (#6602). With a file before it whose last line had no newline, `-R` reported every missing file up front where jq reads on and stops first: `jq -R -n input pnum.json gone empty.json gone2` printed `"1"` and exited 0 in jq 1.7.1 and printed two `Could not open file` lines and exited 2 here. The report is now left to the read that crosses into the file, as it already was for a file ending in a newline; a read of the unterminated line itself (`[input,input]`, `[inputs]`) still reports it. Across 5,312 shapes (`-R`, `-R -n`, `--seq -R`, `-s`, `-e`, `-r` x eight programs x 41 file lists with missing and empty files) the mismatches with jq 1.7.1 went from 207 to 0.
