- **ci: changelog entries are per-PR fragments under `changelog.d/` instead of edits to `CHANGELOG.md`** (#3920).
  Every PR used to add its entry at the same place, the top of `[Unreleased]`, so any two PRs in flight conflicted on the same hunk, and follow-up edits to an
  existing entry conflicted wherever new entries landed. A PR now adds `changelog.d/<issue>.<type>.md` (`+<slug>` when there is no issue; `.<n>` for a second
  entry), whose body is the entry exactly as it was written in `CHANGELOG.md`. `scripts/changelog.py collect --version X.Y.Z [--dry-run]` renders them into the
  release section (Keep a Changelog order, ascending issue number), carries the legacy `[Unreleased]` text into that first release verbatim, updates the
  compare links and deletes the consumed fragments. The `Changelog fragments` workflow validates every fragment's name, type and body and fails a PR that
  neither adds a fragment nor is waived (`no-changelog` label or a `[no changelog]` line in the PR body). Pinned by `scripts/test_changelog.py`.
