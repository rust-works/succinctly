- **yq: a timestamp used as a flow-mapping key is single-quoted by a write** (#5469). After a DOM write (`.zz = 1`, `-P`), `a: {2001-12-14T21:59:43Z: 1, 12:30:45: 2}` printed its keys bare where yq prints `{'2001-12-14T21:59:43Z': 1, '12:30:45': 2}`: a key was echoed as written whatever the context, so the flow-indicator quoting that #5778 gave a value did not reach it. A key that reads as another type (a timestamp, `12:30:45`) now takes the same rule by its characters (a `:` or `?` in flow context); a key that is a plain string already went through the string rule. Captured from yq v4.53.3 over 19 key spellings in four contexts (flow mapping, flow mapping in a sequence, nested, block), two of them controls for the string rule (`a?b`, `a:b`): a date with no time, `200`, `~`, `true`, `0x10`, `1_000` and the other keys with no flow indicator stay bare, and block context quotes nothing. Still different: an alias as a mapping key, and a literal `<<` key in a flow mapping.
