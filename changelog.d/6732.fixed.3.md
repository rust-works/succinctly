- **`succinctly jq --stream-errors` no longer reads the fault a token left open across files ends the text in after a last directory that takes the read of a held-back closing event** (#6732). With `open.json` = `[`, `obj.json` = `{"a":1}` and a directory last, `jq -c --stream-errors . open.json obj.json dir` printed `["Unfinished JSON term at EOF at line 1, column 8",[0]]` as a third output where jq prints the two events and exits 2: `obj.json` ends in a container with a scalar before its closer, so the closing event comes out with the read of the directory, which fails, and the main loop reads no further, so the fault the text ends in is never made. It is the same for `first` and `halt_error`, and for the first file `[1,`. A program that reads `input` still reads the fault, as jq does (`[inputs]` prints it inside the array and says `Is a directory`, `.,input` over `open2.json obj.json dir` prints it as the fourth output). An empty file between the two, or a closing event that is not held back (`arr.json` = `[1,[2]]`), leaves the read to the fault, as before. Checked against jq 1.7.1 over 32,000 random file lists with open tokens, closers and directories: 7 rows fixed, none changed for the worse.
