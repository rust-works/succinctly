- **jq: a NUL byte in a module path is refused, and an index error stops its key at a NUL** (#7450). `include "a\u0000b"`, `import "a\u0000b" as x`, a data import and `"a\u0000b" | modulemeta` read `module not found: a\0b` with the NUL on stderr; they now fail with `Module path contains a NUL byte` (exit 3, or exit 5 / the caught string for `modulemeta`), as jq 1.8.2 does (CVE-2026-43895: jq 1.7.1 looked the path up as a C string cut at the NUL, which could open a different file from the one the program names), ahead of the other path checks. `[] | try .["a\u0000b"] catch .` was `Cannot index array with string "a\u0000b"`; it is `Cannot index array with string "a"` as in jq 1.7.1 (the key is written with a C `%s`), for the caught string and on stderr, through `.[k]`, `getpath`, `setpath`, assignment and `del`. jq 1.8.2 rewords every `Cannot index` message, so 1.7.1 stays the reference there. An uncaught `error("a\u0000b")` is #7442.
