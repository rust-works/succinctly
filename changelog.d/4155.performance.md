- **jq: `path(f)` for a lone `//`, `first` or `try` leaf allocates 2-4.5x less per scalar member** (#4155). A path expression the cursor walkers decline runs through the path resolver in `eval.rs`, which cloned the whole expression to flatten it (only to ask whether it ends in a bare iterate), evaluated a `.` over a scalar to clone the value back out, cloned a field's name before knowing the lookup found anything, and walked the empty path a `.` resolution names. Each is now skipped (a lone leaf is not flattened, a scalar `.` is borrowed, the clone waits for the one arm that reads it, an empty path is emitted directly). Allocator calls over 2,000 integer members (`examples/alloc_probe_3022`): `[.[] | path(. // .)]` 24,024 to 10,024, `path(.a? // .)` 34,024 to 12,024, `path(first(.a?))` and `path(try .a catch empty)` 18,014 to 4,014, `path(.[]? // .)` 26,024 to 10,024; `path(.)` is unchanged at 6,024. Interleaved A/B over a 250,000-integer array and a 150,000-member array of integers and `{"a":n}` objects, output identical on every row: -20% to -39% on an M4 Pro (medians) and -11% to -25% on a Ryzen 9 7950X, with the unchanged `path(.)` rows inside the noise (M4 Pro -0.9%/+0.7%, 7950X +0.4%/+0.7%; a same-binary control on the M4 Pro read +0.2%). The `Cannot index number with "a"` message a `?` drops over a scalar is still built per member.
