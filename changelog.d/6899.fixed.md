- **yq: a zero-padded decimal with an 8 or a 9 (`08`, `0018`, `-09`) prints as a float in JSON on every route** (#6899). #6866 made `a: 08` a `!!float` that is `8.0` in `-o=json`, but only where the document node itself is printed. A value that is bound, copied, merged, written through or rebuilt (`. as $x | $x`, `. * .`, `.zz = 1`, `with_entries(.)`, `to_entries | from_entries`, `{"k": .b}`) and `tojson`/`@json` of it still printed `8`, where yq prints `8.0`. The JSON writers asked for a literal's text from the text alone, which a decimal parse reads as the integer `8`; they now ask with the number the literal is of, so the `08` of a float is `8.0` and the `08` an explicit `!!int` tag forces stays `8`. Known residual (#6927): an explicit `!!int 08` loses its integer across the reindex bridge, so on the routes that write through it (`.zz = 1`, `with_entries(.)`) and in `tojson` it prints `8.0` (see `docs/compliance/yq/limitations.md`).
