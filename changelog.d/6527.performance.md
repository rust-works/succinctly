- **jq: `add`, `min` and `max` of an array that an earlier stage built out of numbers no longer go through the reindex bridge** (#6527). `.numbers | map(. * 2) | add`, `| max` and `| min` (and `[.numbers[] | . * 2] | add`) wrote the array out as JSON text (a shortest-round-trip float each), indexed it, and parsed every number back, 150 to 160 ms over 800,000 floats that jq 1.7.1 does not spend (0.64x to 0.75x of it on an Apple M5). The array is now folded where it stands, with the bridged builtins' own `arith_add`, `jq_min_by` and `jq_max_by`, so the answers are the same, including which of `1` and `1.0` a `max` keeps. An array holding anything but integers and finite floats (a NaN, an infinity, a number copied from the document, a string) still takes the bridge, as do an empty array, an object, yq mode and a run with a bound node in scope. A differential of 696 program-by-array rows against `/usr/bin/jq` is clean before and after.
