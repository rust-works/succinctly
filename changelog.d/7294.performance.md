- **jq: one big document piped on standard input is no longer validated whole before it runs** (#7294).
  A pipe of 4 MiB or more is read a window at a time and each window is certified by the strict validator,
  so that a fault in it can still be worded once its text is dropped (#7024). The last window is never
  dropped, so it is now certified only when the run asks for a fault, over its own buffer, which it shares
  with the certifier instead of copying. One big document is that one window, and a run over it that
  meets no fault reads as the same file read by name does: `.users[0]` over a 70 MB document piped on
  stdin takes 107 ms instead of 170 ms on an Apple M4 Pro (the file: 101 ms) and 189 ms instead of 249 ms
  on an AMD Ryzen 9 7950X, `-c .` over a 100 MB one-line object 770 ms instead of 861 ms (M4 Pro), and the
  same programs over a 7 MB document hold 10.2 MB of private memory instead of 17.0 MB (M4 Pro; 9.0 MB
  instead of 15.0 MB on the 7950X). NDJSON on a pipe, whose windows are dropped and keep being certified
  on their thread, is unchanged. Output, fault wording and exit status are unchanged.
