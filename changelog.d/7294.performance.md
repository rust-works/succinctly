- **jq: one big document piped on standard input is no longer validated whole before it runs** (#7294).
  A pipe of 4 MiB or more is read a window at a time and each window is certified by the strict validator,
  so that a fault in it can still be worded once its text is dropped (#7024). The last window is never
  dropped, so it is now certified only when the run asks for a fault, over its own buffer, which it shares
  with the certifier instead of copying. One big document is that one window: a run over it that meets no
  fault reads as the same file read by name does. `.users[0]` over a 70 MB document piped on stdin runs
  2851M instructions instead of 4621M on an AMD Ryzen 9 7950X (the file: 2831M), and `-c .` over a 100 MB
  one-line object 20001M instead of 22753M. NDJSON on a pipe, whose windows are dropped and keep being
  certified on their thread, is unchanged. Output, fault wording and exit status are unchanged.
