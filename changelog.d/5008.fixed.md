- **yq: a write and `-P` keep the blank lines a file starts with, and the blank lines between its head comments** (#5008). yq prints the header it slurps off the front of a file verbatim, so `\n\na: 1` under `.b = 2` or `-P .` keeps both blank lines, and `# h` / two blanks / `# g` keeps both; `succinctly yq` printed them with `.` but dropped them on every route that rebuilds the document (a write, `-i`, `-P`), because the comment index records no blank line before the first comment and at most one between two. A GitHub workflow file that begins with a blank line lost it on any `-i` edit. The head is now built from the header's text on those routes, as it was for a header with a CRLF break or a line of only blanks (#6401): it travels as the root node's head comment lines, so `.a` and `.[0]` carry none. The made-up document of an empty input does not count as a blank line. Pinned against yq v4.53.3 in `tests/yq_cli/i5008.rs`; over 928 header/body/filter cases `main` differed from yq in 446 and this differs in 144, and over 7,398 real YAML files 32 file/filter pairs that differed now agree and none newly differs. Still different, as it is for a header of comments: a result built from the root (`map(. + 1)` over a sequence) carries the header here, and `to_entries` drops it where yq keeps it.
