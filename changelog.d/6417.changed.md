- **`bench run yq_bench` and `dev bench yq` interleave the two tools and fail a row on a non-zero exit** (#6417). Each repetition, warmups included, now runs both yq and `succinctly yq`, alternating which goes first, instead of all of yq's runs followed by all of succinctly's (rule 1 of `docs/guides/benchmarking.md`; the old order always ran succinctly second). A tool that exits non-zero fails its row where it used to be timed on its near-instant error. `dev bench yq --yq <path>` picks the yq to compare against (default: `yq` on `PATH`, and succinctly alone when there is none; a `--yq` that will not run is an error), `--runs 0` is a usage error, and the generated markdown names the yq's version, its path and the method. The committed tables in `docs/benchmarks/yq.md` predate the change and say so. `jq_bench` shares the helpers (`bench_runner::utils::interleaved_reps`, `ensure_success`).
