- **jq: a `foreach` whose EXTRACT is a constructor holding the state is 1.6-1.9x faster, and 4-5x where the state grows** (#6581).
  `[foreach range(n) as $i (0; . + $i; [$i, .])]` and `{i: $i, s: .}` now build the EXTRACT's array or
  object on the owned tree, as an UPDATE of that shape already did. It is taken for a constructor with exactly
  one `.` member whose other members are closed or read off the state. Before, every step ran it on the
  evaluator's general route and re-indexed the state for each `.` it read. On an AMD Ryzen 9 7950X, 400,000
  steps of `[$i, .]` take 157 ms instead of 289 ms and of `{i: $i, s: .}` 262 ms instead of 425 ms; a state
  that grows by `. + [$i]` while only the last output is kept takes 1,590 ms instead of 7,558 ms at 20,000
  steps (still quadratic: the output shares the state, so the next append copies it). A constructor the arm
  does not take runs as before, within 0-5% of the old time. Output is identical to jq 1.7.1's. Apple silicon
  was not measured.
