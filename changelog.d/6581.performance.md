- **jq: a `foreach` whose EXTRACT is an array holding the state is 1.9x faster, and 4-12x where the state grows** (#6581).
  `[foreach range(n) as $i (0; . + $i; [$i, .])]` now builds the EXTRACT's array on the owned tree, as an UPDATE
  of that shape already did. It is taken for a constructor with exactly one `.` member whose other members are
  closed or read off the state. Before, every step ran it on the evaluator's general route and re-indexed the
  state for each `.` it read. 400,000 steps take 109 ms instead of 208 ms on an Apple M4 Pro and 157 ms instead
  of 289 ms on an AMD Ryzen 9 7950X (measured before #6608 landed); a state that grows by `. + [$i]` while only the last output is kept takes
  561 ms instead of 6,656 ms at 20,000 steps on the M4 Pro (1,590 ms instead of 7,558 ms on the 7950X; still
  quadratic: the output shares the state, so the next append copies it). An object EXTRACT (`{i: $i, s: .}`)
  was already answered off the tree by #6608, so it does not change here (0.99x on the M4 Pro). A constructor the
  arm does not take runs as before, within 0-5% of the old time. Output is identical to jq 1.7.1's.
