- **`succinctly jq --seq -s --stream` and `--seq -s --stream-errors` meet the fault of a record left open across files at the read jq does, when one file after it did not open** (#6730, family 1, the `--seq` form). `jq -c --seq -s --stream . trunc pa missing` (`trunc` = `\x1e[1,`, `pa` = `[1]`) printed nothing and said `ignoring parse error: Unfinished JSON term`; it now prints the array and says only `Could not open file missing`, as jq does, because the read of the failed file brings out the closing event `pa` held back and the fault waits for a read the main loop never makes. A directory last is the same single read, for both flags: `--seq -s --stream . trunc pa dir` prints the array, and `--seq -s --stream-errors . trunc pa dir` no longer prints the fault as a second output. A second read behind `pa` (another file that did not open, an empty file or a directory) is where the fault is met, as before: `--seq -s --stream . trunc pa missing empty` still loses the array and says the warning.
