- **jq: a materialized document builds and prints with fewer allocations** (#5594).
  In jq mode, an object in an array now makes room up front for the member count the two objects before it agreed on, instead of growing its map from empty.
  `tojson` and the other JSON writers append each number to the output instead of building a `String` for it.
  A JSON string is scanned once for its end and its escapes.
  On the `users` pattern at 7.1 MB (Apple M5 Max, instructions retired, output identical), `del(.users[0]) | .users | length` is -8.7% instructions and -5.8% peak RSS, `.users[0].name = "x" | .users | length` -8.9% and -5.6%, and `tojson | length` -10.9% (-15.6% on a float-heavy 8 MB document).
  An array that alternates wide and narrow records is unchanged.
  The object map keeps its per-process-seeded SipHash: an unseeded Fx hash would have saved at most 2.6%.
