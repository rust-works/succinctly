- **jq: `--seq` reports a file that did not open when its reader reaches it, and keeps the last record before a missing last file** (#6555). With `seq.json` holding `\x1e1\n\x1e2\n`, `succinctly jq --seq -n input seq.json gone` reported `Could not open file gone` and exited 2 where jq 1.7.1 prints `1` and exits 0, since `input` never reads as far as `gone`; and `--seq -c input gone seq.json gone2` reported `gone2` too, which jq's main loop never reaches. A file before the missing one that ends mid-record (`\x1e1\n\x1e2`) no longer sends every failure to the up-front report either. A last file that did not open is now one more (empty) source to the `--seq` readers, as it is to jq's: `--seq -c . seq.json arr.json gone` (`arr.json` holding `\x1e[1]`) no longer drops `[1]`, `--seq -c . seq.json norsend.json gone` (`norsend.json` holding `\x1e7`) no longer drops jq's `Potentially truncated top-level numeric value` warning, and what is read at the end of the text names `gone`, line 0, under `--seq --stream` and `--seq --stream-errors` as well. A differential sweep of 22,308 runs (`--seq`, `--seq --stream`, `--seq --stream-errors`, `--seq -R`, `--stream`, `--stream-errors`, `-R` and plain JSON, each plain, `-n` and `-s`, over 9 programs and lists of two or three files with missing ones) moved 2,341 runs to match jq 1.7.1 and changed none that already matched.
