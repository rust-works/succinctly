- **jq: `--seq` with a program that reads `input` reports a file that did not open when a read reaches it** (#6555). `jq --seq -c input missing records.json m2` printed the open error for `m2` as well as for `missing`; jq 1.7.1 reports only `missing`, because the main loop stops one value past the first failure and the `input` that read the second record never asked past `records.json`. A `--seq` stream that jq's reader reads without a fault now hands its failures to the input queue's reads, as a JSON stream's run has since #6475 and #6525. That holds under `-n` and without it, with `--stream` or `--stream-errors` over the records, and under `-R`, which reads the lines of a `--seq` stream as it reads any text. A stream the reader faults on keeps the up-front report (#6584), including one whose final buffer starts on a record separator (#2998), and so does `--input-dsv` (#6585). Swept against jq 1.7.1 over 14 programs and 300 file lists of clean, faulty, empty and missing files, 4200 runs per mode, comparing stdout, stderr and the exit status: `--seq` 782 runs differ where 1478 did, `--stream` 1029 where 1902 did, `--stream-errors` 817 where 1543 did, `-R` 395 where 1043 did, and none the other way.
