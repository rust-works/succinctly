- **jq: `--seq` with a program that reads `input` reports a file that did not open when a read reaches it** (#6555). `jq --seq -c input missing records.json m2` printed the open error for `m2` as well as for `missing`; jq 1.7.1 reports only `missing`, because the main loop stops one value past the first failure and the `input` that read the second record never asked past `records.json`. A `--seq` stream that jq's reader reads without a fault now hands its failures to the input queue's reads, as a JSON stream's run has since #6475 and #6525, under `-n` and without it, with `--stream` or `--stream-errors` over the records too, and under `-R`, which reads the lines of a `--seq` stream as it reads any text. A stream the reader faults on keeps the up-front report, and so does `--input-dsv`. Swept over 14 programs and 192 file lists against jq 1.7.1, with and without `--stream`/`--stream-errors`: 277 of 2688 runs differ where 1193 did, `--stream` 438 where 1145 did, `--stream-errors` 276 where 846 did, `-R` 71 where 615 did, and none the other way; every run left over holds a stream with a fault.
