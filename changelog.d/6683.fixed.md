- **`succinctly jq --stream-errors` no longer reports files behind the value a halting program stops at** (#6683). With a program that does not read `input` (`jq --stream-errors halt_error a.json dir`), a directory given last was counted, and a file that would not open reported, before the first value ran, so `halt` exited 2 where jq keeps its own status (0, 5, `halt_error(3)`'s 3) and `Could not open file` printed where jq says nothing. They are now placed by the loop's reads, as `-R` and `--input-dsv` do (#6531, #6585): a first value that completes inside its file never reads past it, and one that needs the next file to end (a bare number with no newline) still reaches the failure on that read. A file with bytes behind the first failure no longer sends a halting program up front either: the loop reads one value, which is whole in its own file, and halts before it reaches anything (`jq -c --stream-errors halt_error pn.json dir p.json gone.json` prints `[[],1]` and exits 5). A program that goes on reading (`.`, `[inputs]`) reaches the rest, as before. A 35,090-row differential against jq 1.7.1 (11 flag sets, 10 programs, lists of up to four files with a directory and missing files) left 1,284 rows fixed and none changed for the worse; 180 rows are still apart (`--stream-errors` with a program that reads `input`, and `1 2` as a first file, #6732).
