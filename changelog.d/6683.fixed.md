- **`succinctly jq --stream-errors` no longer reports files behind the value a halting program stops at** (#6683). With a program that does not read `input` (`jq --stream-errors halt_error a.json dir`), a directory given last was counted, and a file that would not open reported, before the first value ran, so `halt` exited 2 where jq keeps its own status (0, 5, `halt_error(3)`'s 3) and `Could not open file` printed where jq says nothing. They are now placed by the loop's reads, as `-R` and `--input-dsv` do (#6531, #6585): a first value that completes inside its file never reads past it, and one that needs the next file to end (a bare number with no newline) still reaches the failure on that read. A good file behind a failure keeps the up-front report.
