- **jq: a file appended to while the run reads it is read to its new end** (#7446). A lone input file (named, redirected on standard input, read by `-R` or by `input`/`inputs`) and each file of a list under the plain filter were read only to the length `stat` gave when the run opened them, so lines a writer appended while the run went were dropped and a last document completed after the run opened the file was reported as cut short (`jq -c . app.log` on a log still being written), where jq reads on to the read that returns nothing and prints them. Each file is now read on past that length, a window at a time and in the memory of a window, so a file that keeps growing (`jq -c . f | tee -a f`) is read for as long as it grows, as in jq, and one cut short ends where its reads find the end. A file under 1 MiB under the plain filter or `-R` is still read whole before the run, and a `--seq` file stops at the length its records were vouched for up to; both are recorded in `docs/compliance/jq/limitations.md`.
