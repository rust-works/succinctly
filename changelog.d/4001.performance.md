- **jq: `path(f)` repeated over one document reuses a single owned copy of it** (#4001). A `path(f)` whose `f` the cursor
  walk does not take (a computed key, `.big[$k]`) copied the whole input and re-walked the copy for the reindex-bridge test on
  every call, so each lookup cost the size of the document (about 1.6 ms per lookup into a 4,000-key object). The second
  `path(f)` over the same node now keeps the copy and the test's verdict for the rest of the evaluation, one copy at a time,
  so a single call holds nothing past itself. The kept copy lives to the end of the evaluation, not of the call, so a query
  that allocates heavily after a looped `path(f)` holds one document copy on top of it (peak RSS on a 10,000-key
  object, 300 lookups: 12.8 MB vs 13.2 MB); it is not kept while an `as` binding is in scope unless `f` only reads variables as index keys (`.big[$k]`). `[.ks[:3000][] as $k | path(.big[$k])] | length` over a 10,000-key object, Apple M4 Pro, release:
  4.85 s -> 0.01 s; 600 lookups into 1,000 keys 217 -> 4.7 ms, into 4,000 keys 824 -> 7.4 ms. Output unchanged.
