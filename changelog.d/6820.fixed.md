- **yq: a block scalar's header line ends at U+0085, U+2028 and U+2029, as in go-yaml** (#6820). `a: |<U+0085>  x` is `"x\n"` in yq and was `""` here: the header was read to the next `\n`, so the first content line was taken for its comment. The parser now walks the header line to the first break of any of the five spellings and lists the scalar like one that holds a Unicode break in its body (#6369), so the decoders end the header at the same byte. A header that ends at `\n` or `\r`, which is all of the usual ones, costs what it did. Checked against yq v4.53.3 on 57 pinned documents and on 6,000 random ones (ten headers, six owners, five breaks, four spacings and comments, twelve bodies): the new build agrees with yq on 2,453 documents it did not before, and on every document the old build already read as yq does. Still different, recorded in `docs/compliance/yq/limitations.md`: a plain scalar or key that spans a break, a comment line that ends at one, a document-root `--- |` whose first blank line is spaces and a NEL, a document-root `--- |<break>  x` whose text ends in one `\n` (yq loses that break), and a sequence item `- |<break>key: v` with the key on the header's physical line.
