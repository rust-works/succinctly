- **jq: `--stream` takes each document apart into its events instead of copying it** (#5611).
  When the program reads the events with `inputs`, `-n` or `--slurp`, each input document is turned into its `[path, leaf]` events and then dropped, but the events were built by a borrowed walk that cloned every leaf and cloned every key of a leaf's path again for each event beneath it.
  The walk now moves a leaf and its own key into its event and shares a container's key once, so the events under it clone a reference count; the events and their order are unchanged.
  `--stream -n '[inputs] | length'` over 0.7 / 7 / 74 MB of records went from 20.5 / 171.5 / 1748 ms to 17.5 / 145.0 / 1442 ms on an Apple M4 Pro and from 36.9 / 402 / 3842 ms to 30.0 / 352 / 2818 ms on a 7950X, `--stream -s 'length'` by 11% to 14% (M4 Pro) and 20% to 23% (7950X), and the `reduce (inputs | select(length == 2)) as $e (0; . + 1)` form by 10% to 12% (M4 Pro) and 8% to 20% (7950X); retired instructions over 7 MB fell 20% (4.03G to 3.22G, Apple M5 Max).
  Release builds, interleaved, min of 11, output identical on every configuration. A plain `--stream .`, which prints each event and does not hold them, is unchanged (printing dominates it), and so are the rows this cannot reach (`.users | length` retires the same 281.7M instructions on a 7950X; its wall-clock read 5% slower at 7 and 74 MB there with the instruction count flat, which is code placement).
