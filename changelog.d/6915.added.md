- **`succinctly dev compare jq --full --huge` adds a 1 GB tier** (#6915, #5409's dimension E). Every `perf.tsv` row stopped at 100 MB, where both tools fit in RAM and memory reads as a ratio; above that a difference can be pass/fail, which is what the NDJSON peak-memory growth of #6913 is. Six rows (`identity`, `identity_compact`, `users_first_early_exit`, `ndjson_field`, `ndjson_inputs_reduce`, `ndjson_inputs_first`) now run on two sha256-pinned generated inputs of about 1 GB, `users-1gb` and `ndjson-1gb`, in their own `perf_huge` array and report section, so no headline geomean or tier column moves, and `--quick` and a plain `--full` are unchanged. A 1 GB row records how each tool ended (`exit`, the `signal` that killed it, a `timed_out` deadline) and its peak memory as a multiple of the input, so an out-of-memory kill or a refusal is a result: a tool that is killed makes the row `incomplete` instead of aborting the run, and the 100 MB row of the same query is shown beside it for the scaling curve.
