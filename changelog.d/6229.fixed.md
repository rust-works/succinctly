- **jq: a malformed character class is refused with jq's message** (#6229). `"a" | test("[]")` and `test("[a")` reported the `regex` crate's multi-line `regex parse error`. They now say `empty char-class` (a class that opens with `]` and has no other `]` to close it: `[]`, `[^]`, `a[]`, `[]a`), `premature end of char-class` (any other class the pattern ends inside) and `end pattern at escape` (a trailing backslash), as jq 1.7.1 does. Both tools exit 5; only the wording changed. A `]` first in a class stays a member when a later `]` follows, escaped or not, as in jq. A pattern with two errors reports the class error when the earlier one is found only by the crate (see `docs/compliance/jq/limitations.md`).
