- **jq: `del(.[]?)` and `del(.)` over scalars copy no expression tree per member** (#4218).
  A scalar crossing the owned-evaluator bridge paid ten allocator calls for `del(.[]?)` and
  eight for `del(.)`, four of them `Expr` boxes cloned only to be read: `eval_builtin`
  rebuilt the `Expr::Builtin` node its dispatcher already held, and `builtin_del` copied
  its path into a one-element `Vec`. Both now borrow (the path is copied only while a yq
  alias table is installed): `[.[] | del(.[]?)]` over 2,000 integers 20,024 -> 12,022
  allocator calls, `[.[] | del(.)]` 16,024 -> 12,022; output unchanged. Interleaved A/B on an
  M4 Pro (min of 15, output identical): `[.[] | del(.[]?)]` over 300k integers -19.1%, over
  300k strings -13.9%; `[.[] | del(.)]` -11.3% / -7.0%; container members
  (`[.[] | del(.a)]` over 100k objects) -6.4%. The remaining six calls per member are the
  scalar reindex bridge (#4154) and the scalar's two decodes.
