- **jq: `--stream` input is validated without building a discarded tree and without walking each document twice** (#5608).
  The strict pass deserialized every value of the input into a `serde_json::Value` it then threw away, and each accepted span was then converted through a check that walked its delimiters again, though `serde_json` had just accepted that very span.
  The pass now deserializes into `IgnoredAny` (the same parser, recursion limit and error text) and skips the second walk for a span `serde_json` accepted; the splitter's fallback spans, which it has not seen, keep the walk.
  `--stream -n '[inputs] | length'` over 0.7 / 7 / 74 MB of records went from 24.0 / 209 / 2111 ms to 19.4 / 166 / 1648 ms on an Apple M4 Pro and from 43.1 / 443 / 4488 ms to 36.7 / 389 / 3734 ms on a 7950X, `--stream -c .` by 6.7% to 8.6% (M4 Pro) and 10.3% to 14.8% (7950X), and peak memory of `--stream -n '[inputs] | length'` over 7 MB fell 19% (332 to 271 MB, Apple M5 Max).
  Release builds, interleaved, min of 11, output identical on every configuration; `--slurp` and the rows this cannot reach read within the control run's noise.
  On the M4 Pro `--stream` is now at about 0.8x of jq 1.7.1's speed (`reduce (inputs | select(length == 2)) as $e (0; . + 1)`: 27.9 / 250 / 2481 ms against jq's 22.3 / 197 / 1909 ms), up from 0.7x; what remains is converting each document to an owned value and one owned array per event.
