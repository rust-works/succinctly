- **jq: `recurse(f; cond)` answers a bounded walk past 10,000 nodes for any tree-descending `f` and any `cond` that does not fork** (#3867).
  #3737 lifted the node cap only for `.[]?` with a `cond` whose shape `yields_at_most_one_value` admitted, so `[recurse(.[]?; tonumber? // true)] | length`,
  `try true`, `first(.[]?, true)`, `limit(1; true)`, a user function, a destructured `$a` and a `def g($c)` argument raised `recurse: maximum nodes exceeded` over a
  12,001-node document where jq answers 12001, and so did `[recurse(.[]; type == "array")]`, `recurse(.children[]?)` and `path(recurse(.a.b[]?))`, in value and path
  position. The walk now starts uncapped for an `f` whose every output is a child of a real container (`.[]?`, `.[]`, or a chain of `.field`/`.[n]`/`.[]` steps ending
  in an iterate) and gets the 10,000-node cap back the moment a `cond` gives one child a second truthy verdict, the only way such a walk can visit a node twice, so a
  forking `cond` (`(true, true)`) is still refused (it raises at the first node after the fork once 10,000 were delivered, so a fork late in a walk is seen only after the nodes before it).
