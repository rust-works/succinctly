- **jq: `--seq` over more than 32 regular files is read a window at a time too** (#7221, the remainder of #7218). `jq --seq -c . part-*.seq` over a list of more than 32 files read every file whole, since such a list is opened by path as the run reaches each file and no prepass could vouch for what the run would then read. Each file is now judged (plain `RS value LF` records ending in an LF) on the handle the run opened when it reached it; at the first that is not, the windows end and that file and the ones after it go to the route that reads them whole, which reads them as jq's reader does after the files before (a parse warning names the line counted over every file, a runtime error the line in its own file, a byte-order mark there is not the stream's front). Over 100 MiB of RFC 7464 records in 100 files, peak RSS falls from 248.8 MiB to 11.3 on a Ryzen 9 7950X and from 255.9 to 8.9 on an M4 Pro, flat from 10 MiB; with file 50 of the 100 not plain it is 132.6 and 135.6 MiB (the files from there are held), and with every file plain the run took about half the time on the idle 7950X (714 against 1,435 ms, three interleaved runs, no control). Output and exit status are main's in every row, and `scripts/jq-windowed-file-fuzz.py --seq --files K`, which now takes K up to 512, found no difference against the same files read as descriptors over 610 streams cut into 33 to 300 files.
