- **CLI: a standard error that cannot be written no longer turns a diagnostic into a panic** (#7476).
  With standard error on `/dev/full`, a full disk or a file past `ulimit -f`, every error report of
  `succinctly jq` (a runtime error, a parse error, a missing file, a compile error) exited 101, and so did
  `json validate` and `yaml validate` on a standard error pipe with no reader. The message is now dropped,
  as jq drops its failed `fprintf(stderr, ...)`, and the run keeps the status it would have had: 5, 2 or 3
  in `succinctly jq` (as jq 1.7.1 and 1.8.2 do), 1 in `succinctly yq` (as yq does).
