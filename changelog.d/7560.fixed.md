- **jq: `split(re; flags)` and `splits(re; flags)` whose FLAGS argument yields nothing slice a non-string input whole, as jq 1.7.1 does** (#7560). With no FLAGS value jq's definition runs no `match`, so nothing checks the input's type and the one piece is `$s[0:($s | length)]`: `null | split("b"; empty)` is `[null]`, `[1] | [splits("b"; empty)]` is `[[1]]`, a boolean raises `boolean (true) has no length`, and a number or an object raises `Cannot index number with object` (`object`). `succinctly jq` raised `null (null) cannot be matched, as it is not a string` for all of them. A string input was already answered as 1.7.1 answers it (`["abc"]`). jq 1.8.2 yields nothing for every input here, strings included, as a side effect of a refactor of `splits` (jqlang/jq#3260) that upstream does not describe as a fix, so the pinned 1.7.1 stays the reference.
