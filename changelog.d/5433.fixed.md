- **yq: destructuring patterns in `as` need `--jq-extensions`, as yq's lexer rejects them** (#5433). Real yq's `as`
  takes a variable name and nothing else: `. as {a: $v}` is a lexer error (`invalid input text`) and `. as [$a]`
  fails with `RHS of 'as' operator must be a variable name` (v4.53.3), yet `succinctly yq` accepted both without the
  flag. Every `{...}` and `[...]` pattern now fails with the same `is not part of yq's syntax; pass --jq-extensions`
  error as `limit` or `paths`; `. as $name` is unchanged. A yq script that destructured adds the flag. `succinctly
  jq` is unchanged.
