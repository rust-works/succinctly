- **jq: a malformed value under a key that a later member repeats is refused, not dropped** (#7427). `{"a":tru,"b":2,"a":1}` printed `{"a":1,"b":2}` at exit 0 under `.`, `-s .`, `.[]`, `[.[]]`, `to_entries` and `with_entries(f)`, where jq 1.7.1 rejects the document with `jq: parse error: Invalid literal at line 1, column 9` (exit 5) and `tojson` on the same text already did. Every route that reads the values an object keeps now reads the value a repeated key shadows too, and raises jq's own message and exit status; `length`, `keys` and `.a` still read no value they do not answer with, as for any member (`docs/compliance/jq/limitations.md`). The check runs only on an object whose key repeats.
