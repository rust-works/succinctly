- **yq: `\w`, `\d`, `\s` and `\b` are Go's ASCII classes** (#5374). yq compiles a pattern with Go's `regexp`, where `\w` is `[0-9A-Za-z_]`, `\d` is `[0-9]`, `\s` is `[\t\n\f\r ]` (no `\v`) and `\b` is an ASCII word boundary; the `regex` crate's are Unicode, so `"é" | test("\\w")` was `true` here and is `false` in yq (`"٣"` for `\d`, U+00A0 for `\s`, and `"aé b" | [match("\\b";"g")|.offset]` is `[0,1,4,5]` in yq). Each is now rewritten to the ASCII class, inside a character class too (`[\w-.]`, `[^\W]`), so a following `-` stays a literal. A `[` inside a class is a literal (`"x[y" | test("[[]")` is `true` in yq and was a parse error here). Checked over every scalar value against yq v4.53.3 for the shorthand and class patterns the issue names, with and without `(?i)`; jq mode is unchanged.
