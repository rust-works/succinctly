- **jq: `--seq` reads past the text before a stream's first RS a run at a time** (#7263).
  jq's reader discards every byte before the first RS, so a `--seq` stream with no RS at all (the
  `users_seq_output` comparison row, whose input is one plain JSON document) prints only
  `Unfinished abandoned text at EOF`; `succinctly jq` used to walk those bytes twice, one at a time, at
  about 80 instructions a byte against jq's 17-28. The walk now takes the run up to the next RS at once,
  the end-of-stream position is counted a file at a time, and the newline that ends each `fgets` chunk
  is found a block at a time. `--seq -c '.users[]|.id'` over a 10 MB `users` document takes 4.4 ms
  instead of 23.6 ms on an Apple M4 Pro (67.7M instructions instead of 551.7M) and 6.2 ms instead of
  21.7 ms on an AMD Ryzen 9 7950X, and 22.7 ms instead of 226 ms (M4 Pro) and 55 ms instead of 206 ms
  (7950X) at 100 MB. A stream with a malformed record, whose walk counts the same chunks, is 4-8% faster
  (`--seq -r .name` over a 100 MB stream whose last record is cut short: 917 ms instead of 995 ms on the
  M4 Pro, 977 ms instead of 1056 ms on the 7950X). The output is unchanged.
