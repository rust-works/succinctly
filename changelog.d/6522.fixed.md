- **jq: `-R`, `--seq` and `--stream-errors` do not report a file past the first failure that jq's main loop never reaches** (#6522). `jq -R -c . missing lines.txt m2` printed the open error for `m2` as well as for `missing`; jq 1.7.1 reports only `missing`, because its main loop ends the run one line past the first failure and so never opens the file after the one that line comes from. The same holds for `--seq` records and `--stream-errors` events, and for a directory in place of the missing file. A first value that is not complete inside its file (a last line with no newline, a record that runs to the end of the file) still sends the reader on, and keeps the old report; so does a program that reads `input`, and `--input-dsv`, which has no jq to follow. Swept over 100 file lists with failures before, between and after the opened files against jq 1.7.1: `-R` 18 of 800 runs differ before and 0 now, `--seq` 8 to 5, `--stream-errors` 52 to 40, none the other way; what is left needs a fault at the end of a file (#6531) or a program that reads `input`.
