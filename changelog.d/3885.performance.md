- **jq: a long arithmetic chain no longer re-walks itself once per operator** (#3885). Each binary operator asked `settles_before_consumer` of its left operand first, and refusing an operand that calls no `def` means walking all of it, so in `1 + 1 + ... + 1` every one of N operators re-walked everything below it (N² node visits). The literal on the right is refused in one step, so the operator now asks the cheap side first (`settles_both`); which operands settle is unchanged. `map(<N terms>)` over 20,000 numbers on an Apple M-series, `succinctly jq` user time against the commit before: 50 terms 0.23 s → 0.12 s, 100 terms 0.83 s → 0.23 s, 200 terms 3.24 s → 0.49 s (now ~2x per doubling, was ~4x); `succinctly yq` 100 terms 0.76 s → 0.23 s. Output identical. Pinned by `settles_both_asks_the_cheap_side_first_3885` (both orderings mutation-checked).
