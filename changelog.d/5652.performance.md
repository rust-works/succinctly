- **jq: the stage after an object or array the filter built, or `fromjson` parsed, no longer writes it out and indexes it again** (#5652, #5606 follow-up).
  `[.users[]|{a:.age,b:.name}|.a]` wrote each object out as JSON and indexed it to read one key. A computed array or object (not with the embed table active) now meets
  `.a`, `.[0]`, `select(cond)`, `if`, `tojson`, `has("k")` and `keys` from the owned tree, the way a computed number has since #5601. A stage outside that grammar
  (arithmetic on a read, a comma, a nested `.b.c`, a generator condition) bridges as before. Over a generated `users` document (Apple M5 Max, interleaved min, 10 MB,
  jq 1.7.1, against a build with #5606): `{a:.age,b:.name}|.a` 1.39x faster, `|select(.a>30)` 1.64x, `|keys` 1.56x, `|has("a")` 1.40x, `[.age,.name]|.[0]` 1.33x,
  `tojson|fromjson|.age` 1.49x (0.63x -> 0.94x of jq) and `tojson|fromjson|select(.age>30)` 1.47x; instructions retired fall to 0.58-0.69 of the base build, and an Apple M4 Pro reads the same rows 1.37x, 1.51x, 1.47x, 1.40x, 1.30x, 1.42x and 1.42x faster.
