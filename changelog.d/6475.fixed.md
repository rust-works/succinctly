- **jq: under `-n`, `input` no longer reports a file it never reaches** (#6475). `jq -n input nums.json missing` printed the first value of `nums.json`, then `jq: error: Could not open file missing: No such file or directory`, and exited 2; jq 1.7.1 prints the value and exits 0, because its reader opens a file only when it has read the one before and asks for more. Each file that will not open (or is a directory, #6472) is now said when a read of the `input` queue reaches it, or finds the stream at its end, before that read returns, and fails the run then: `jq -n '[input,input,input,input]' nums.json missing b.json` reports it on the fourth read, and `jq -n '[inputs]' nums.json missing` at the end. The queue has a read hook for it. The 19 rows pinned in `tests/jq_cli/i6475.rs` were captured from jq 1.7.1. A file whose last value is a bare number with no newline after it (`printf 1`) completes only at its end, which sends jq's reader on to the next file, so a failure after it is still reported up front, as is the chunked `--stream` walk's.
