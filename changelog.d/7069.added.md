- **yq: `...` is accepted as a value, the walk that yields each mapping key before its value** (#7069). `[...] | length` is 7 over `a:` / `  b: thing` / `  c: something` (where `[..] | length` is 4), and `... | select(tag == "!!str")` names the keys too; it was a parse error anywhere but a metadata assignment (`... comments = ""` is read as before). Checked on 32 rows against yq v4.53.3. A key is a string here, so `key`, `path` and `line` over a key node, an alias walked into (yq stops at it) and a write through the walk (`(... | select(...)) |= f`) differ; they are listed in the yq limitations page.
