- **yaml: a flow collection, alias or tagged value in a flow-sequence pair entry is no longer wrapped or emptied** (#4091). `a: [k: [c]]` answered `{"a":[{"k":[["c"]]}]}` (one sequence level too deep), `a: [k: {x: 1}]` answered `{"k":{}}`, `a: [&x 1, k: *x]` answered `{"k": null}`, and `[? k : [c]]` shared the first, silently and with exit 0, where yq answers `{"k":["c"]}`, `{"k":{"x":1}}` and `{"k":1}`. The single-pair forms of a flow sequence (`[k: v]` and `[? k : v]`) opened a BP node for the value and then called `parse_flow_sequence`/`parse_flow_mapping`, which open a node of their own, so a sequence value was a one-element sequence holding it and a mapping value's members landed outside it; and they read an alias value as a plain scalar. They now share one value parser with the flow mapping (properties, then an alias, a collection with its own node, or a wrapped scalar). A one-off sweep of 7 key forms x 17 value forms x 5 contexts x 4 routes against yq v4.53.3 found no row that matched before and differs now; plain, quoted, explicit and anchored keys now match yq on every route. Still different from yq, unchanged by this fix: a complex key (`[{a: 1}: v]`) renders as `{"": v}` / `{"": v}` in YAML where yq writes `? {a: 1} : v`, an empty value (`[k:]`) is a pair where yq reads the plain scalar `k:`, and a tag on a pair's key is dropped on YAML output (#4088).
