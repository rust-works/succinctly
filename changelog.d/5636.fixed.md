- **jq: `-n --seq` with `input`/`inputs` raises `Unfinished abandoned text at EOF` on a stream with no RS byte** (#5636). jq never syncs onto text that has no leading RS, so the first read of it is an error: `printf '1\n' | jq -cen --seq '[inputs] == []'` exits 5 with `jq: error (at <stdin>:1): Unfinished abandoned text at EOF at line 2, column 0`. `succinctly jq` read it as no inputs and answered `true`, exit 0. `input` raises the error (catchable), `inputs` re-raises it, and the marker names the last source and its newline count as jq's does (`a.json b.json` reads `b.json:0`). The same stream without `-n` still only warns. `-n -s` and the reader's other parse errors under `-n` are unchanged.
