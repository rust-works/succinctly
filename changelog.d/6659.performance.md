- **jq: a slice of a built array is a view, not a copy, so a loop that peels one element per step is linear** (#6659).
  `.[a:b]` of an array the program built (or a loop carries) copied the range; it is now a refcount bump on the
  same storage, as jq's slice is (ADR-0029), an append to such a view writes in place, and `def`'s tail loop
  settles a `length > 10`-style condition without writing the array out as JSON. On `[range(50000)]`,
  `def f: if length>10 then .[1:]|f else length end; f` went from 62.9 s to the 68 ms floor of a bare `length` on an
  AMD Ryzen 9 7950X (54.3 s to 89 ms on an Apple M4 Pro), and stays there at 100,000; `[while(length>10; .[1:])]`
  at 25,000 elements peaked at 9.78 GB on the 7950X and now peaks at 13 MB (22.7 MB at 100,000). A queue loop
  (`.[1:] | . + [$i]` per round) went from 685 ms to the floor at 50,000. Array reads that never slice are
  unchanged on both machines (median -1.0% and -0.5% on the 7950X, -0.1% and -0.1% on the M4 Pro, all inside an
  A/A control's band). Output is unchanged, and a slice now has jq's identity: `[1,nan,2] as $a | $a[1:] ==
  $a[1:]` is `true`, as in jq, where it was `false`.
