- **jq: a `select` or `if` condition that does arithmetic on a computed value no longer takes the reindex bridge** (#6536). `select(. % 3 == 0)`, `if . % 2 == 0 then . else empty end` and `select(.a % 2 == 0)` over a number a stage produced (or a field of an object one built) wrote the value out as JSON text, indexed it and read it back for every element, because the owned-value condition grammar had no arithmetic; `select(. > 10)` never did. Both operands are now settled in place and combined with the evaluator's own `arith_combine`; an operator that raises (`. % 0`, `{} - 1`) still takes the bridge so jq's message and order are kept. `[range(3000000) | select(. % 3 == 0)] | length`, against jq 1.7.1 interleaved on a Ryzen 9 7950X: 1490 to 322 ms (jq 992 ms, so 0.67x became 3.1x); the `if ... else empty end` form 1464 to 375 ms (jq 872 ms, 0.60x became 2.3x); the same at 300000 elements: 149 to 35 ms and 151 to 41 ms.
