- **`succinctly jq` reads an input-reading argument of `split`, `splits`, `combinations`, `in`, `map_values`, `walk` and `repeat` one value at a time, as jq does** (#7859). Such an argument ran to its end before its first value was used: the flags of `split(re; flags)` and `splits(re; flags)` and the count of `combinations(n)` were all read before the first was checked, so `[split("a"; inputs)]` raised its error on `<unknown>` after reading every input and the run ended with exit 5; and the closures of `in(xs)`, `map_values(f)`, `walk(f)` and `repeat(f)` produced every output before the first was handed on, so `first(in(inputs))`, `map_values(inputs)` and `first(walk((1, input)))` read inputs jq leaves for the main loop. The same held for the condition and update of `while` and `until`, the operand of a unary minus, the condition of an `if` and the keys and values of an object construction (`[if inputs then input_line_number else -1 end]` read `5` four times where jq reads `2, 3, 4, 5`). A `debug` in such an argument ran where jq never runs it, or before an earlier one (`{"a":1} | map_values((., ("y" | debug)))` printed a `DEBUG` line jq does not). An argument with an effect (an input read, `input_line_number`, `debug`, `stderr`, `halt`) now runs depth-first, as `as` sources have since #7845; any other argument is evaluated as before. This retires the residual `limitations.md` recorded for #5791 and #5794: `[1] | map_values(2, halt_error(6))` no longer writes `1` to stderr, which jq never writes.
