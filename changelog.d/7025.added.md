- **`succinctly yq` accepts yq's `--expression`, `--split-exp-file`, `-f`, `-v`/`--verbose`, `--security-disable-env-ops` and `--security-disable-file-ops`** (#7025). `--expression EXPR` takes the filter from the flag so every positional is an input file; `--split-exp-file FILE` reads the `--split-exp` expression from a file (an empty file means no split); `-f` is the short `--front-matter`; the two security flags refuse `env()`, `strenv()` and `envsubst`, or `load()`, `load_str()` and `load_base64()`, with yq's `env operations have been disabled` and `file operations have been disabled`. They were `error: unexpected argument`. Pinned against 36 rows from yq v4.53.3; `docs/compliance/yq/limitations.md` records the three that differ (an operator no value reaches is not refused, `-v` writes no debug log, a missing split file is worded differently).
