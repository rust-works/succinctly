- **jq: `--stream-errors`, and `-b`** (#5474). `succinctly jq --stream-errors` exited 2 with `unexpected argument '--stream-errors'`; it now implies `--stream` and reports a parse error as an input of the form `[message, path]` (`printf '[1,' | jq --stream-errors -c .` prints `[[0],1]` then `["Unfinished JSON term at EOF at line 1, column 3",[1]]` and exits 0), and keeps reading with the next line, as jq does. The reader is a port of the streaming half of jq 1.7.1's parser, so the events before a fault, the path at it (`null` for an object key not yet read), a value lost to the byte that fails, the `--slurp` array closing at the call that empties jq's buffer and the `(at <file>:<line>)` marker all match. Checked against `/usr/bin/jq` on random malformed inputs. `-b` is now accepted and ignored, as in jq outside Windows (`--binary` is rejected there too). Recorded divergence: `--seq` wins over `--stream-errors`.
