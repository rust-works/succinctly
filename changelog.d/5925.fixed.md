- **`succinctly jq` resumes after a parse error that ends in an unterminated string, as jq does** (#5925). After a fault `input` raises, jq drops the rest of the read the fault was in and reads on. When the fault is a number a quote ends (`1e"str`, `-"x`, `1."x`), `succinctly jq` took the string the quote opens for a token to complete, and a string that never closes put the fault at the end of the input, so the stream ended there: `printf '{"a"}\n\n1e"str\n\ntrue\n\n]\n[}12 34\t' | jq -nc '[limit(14; repeat(try input catch .))]'` read the first two errors and then `break`, where jq goes on to `true`, `]` and `}`. The fault is now met at the quote.
