- **jq: `fromjson` reads plain JSON in one pass** (#5675). `fromjson` ran a validation pass, built a semi-index and walked it into a value, three passes and half a dozen allocations for a 90-byte record. Text that is plain RFC 8259 (no `nan`, leading zero, repeated key, surrogate escape or nesting past 64 levels) is now read straight into the value, and every other text, with every error and its message, still takes the old route. Over a generated NDJSON file (`-R 'fromjson|.id'`, Apple M-series, interleaved min, output identical to jq's): 1 MB 32.4 -> 23.6 ms (-27%), 10 MB 300 -> 224 ms (-25%), 50 MB 1.47 -> 1.09 s (-26%), which moves jq's lead from 1.8x to 1.3x; a 400,000-call `fromjson` loop over one record is -40%. The rest of the gap is the per-line cost of `-R` itself. `tonumber` and every other filter are within noise. Measured on one machine; x86_64 was not.
