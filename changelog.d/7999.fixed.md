- **yq: a hex or leading-zero bracket key on a mapping names the key it spells** (#7999). `.m[0x1]` and `.m[01]` were folded to the integer index `1`, so a read took the key `1`, and `.m[0x1] = 9`, `|=`, `+=` and `del(.m[0x1])` wrote or deleted the key `1`, one the filter never named. yq indexes a mapping by the key's text, so they now reach the keys `0x1` and `01` (and `.m[-0]` the key `-0`) (`.m[0x1] = 9` on `m: {"1": 6}` is `m: {"1": 6, "0x1": 9}`), as `.m[1]` still reaches `1` and a sequence is still indexed by the value (`.s[0x1]` is its second element), as in yq v4.53.3. Such a key is static navigation as `.s[1]` and `.m["0x1"]` are, so a write or `del` through it keeps the document's comments, quoting, flow style and anchors under `eval` and `eval-all` alike. A decimal literal with leading zeros (`01`, `007`, `-01`) now keeps its spelling, as a hex one does since #7615: `01 | tostring` is `"01"`, `1 == 01` is `false`, `{01: 2}` has the key `01` and `.a = 01` writes `a: 01`. `succinctly jq` reads `01` as the number 1, as jq does.
