- **jq / yq: a body rebuilt for each value that reads its variable late (in its last stage, or after a long run of stages) is linear in the pipe's length, not quadratic** (#5441).
  #5436 keeps the tails that start after a rebuilt body's last reading stage, so a body that reads its variable in its last stage
  (`. as $x | (. + 1 | ... | . + $x)`, a `def f($a)` that reads `$a` last, a `reduce`/`foreach` update that reads `$i` last) had no tail to keep
  and copied its rest for each value at each stage. A tail that holds a reading stage is now split around it: the runs of stages
  between the reading stages are the ones the source pipe keeps, and only the reading stages are cloned for the value. A tail of
  fewer than eight stages is copied as before, and so is a pipe that reads its variable in every stage (it has no run to share).
  The doors of the owned evaluator now see a kept run at the head of a tail as a pipe, and a container a bridged evaluation hands
  back keeps the storage it went in as, so a container compared by identity (`[nan] as $a | ... | . == $a`) is still the same one
  after a run of stages: that last part also fixes `[nan] as $a | [range(0;3) | . as $x | ($a | . | . | ... | .)] | map(. == $a)`,
  which is `[true,true,true]` in jq and was `[false,false,false]`.
  20,000 values, interleaved min of 9 CPU seconds, output identical, on an Apple M4 Pro, `[range(0;20000) | . as $x | (. + 1 | ... x n | . + $x)] | length`:
  n=14 0.222 s -> 0.095 s, n=40 1.382 s -> 0.322 s (the same pipe reading no variable: 0.258 s); the variable read in the middle
  (n=40) 1.084 s -> 0.306 s, in the second-last stage 1.383 s -> 0.329 s; a `reduce` update 0.318 s -> 0.082 s, a `foreach`
  extract 0.318 s -> 0.083 s, an update `.[] |= (. as $x | ...)` 0.337 s -> 0.086 s, a destructuring bind 1.256 s -> 0.330 s,
  `def f($a)` read last 1.391 s -> 0.320 s; over a document input 1.484 s -> 0.369 s. `walk` over 200,000 records is 22% faster.
  A body of six stages reading its variable last is +3% (+1.6% retired instructions), one reading it in every one of 40 stages
  +4% (+3.4%), and a body reading it first or not at all, a plain pipe and the other bridge-heavy queries measured (`sort_by`,
  `group_by`, `to_entries`, `reduce`, `tostring | fromjson`, ...) are within 3%. The AMD Ryzen 9 7950X was not measured.
