- **the CLI runs under a capped address space** (#5634). The evaluation thread reserves 256 MiB of stack (2 GiB in a debug build), and `ulimit -v` counts a reservation, so under a cap below that every run died with `failed to spawn the evaluation thread`, whatever its input, where jq reads the same document. The stack now starts at a quarter of the cap (never below 16 MiB, never above its full size) and halves if it still cannot be mapped; its native-stack floor follows the size it got, so deep recursion is refused rather than overflowing. A 1M-integer array and a 300,000-key object now answer under `ulimit -v` 64 MiB (jq aborts there), and a 1M-integer array under 256 MiB, where each used to fail at start. A cap of 32 MiB or less still fails to start, and a document that does not fit still aborts on the failed allocation, as jq does.
