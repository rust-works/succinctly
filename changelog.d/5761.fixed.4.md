- **jq: a container read off a fold's loop variable keeps its storage when stored** (#5761).
  `[{"items":[nan]}] as $in | reduce $in[] as $r ({}; .a = $r.items) | .a == $in[0].items` is `true` in jq, where the stored member is the element's own array, and was `false` here: only a whole-variable read (`.a = $r`) carried the fold's marker, so a field read (`.a = $r.items`, `.a += $r.items`, `. + $r.items`, `.[$r.n] = $r.items`) rebuilt the container.
  The gate that decides whether a fold step marks its loop variable now counts any read of it on the right-hand side of an assignment or in arithmetic; the in-place step is unchanged and still takes the marker as one `Rc` clone.
  `succinctly yq` is unchanged.
  Measured interleaved A/B on an AMD Ryzen 9 7950X over 300,000 records, min of 7, output identical: `.[$r.name] = $r.tags` -6.2% time, `.[$r.name] = $r.meta` -2.8%, `. + $r.tags` -5.1%, `.x[$r.name] += $r.score` +1.6%, `.[$r.name] += ($r.score|floor)` -0.7%.
  Peak RSS is unchanged (within 1%) except `.[$r.name] = $r.meta`, which keeps each record's `meta` object alive: 206 MB to 225 MB (+9.2%).
  Not measured on ARM.
