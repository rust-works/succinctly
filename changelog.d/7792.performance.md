- **One JSON value spread over many input files is read once, not again at every file boundary** (#7792). The stitch that carries a token a file ends inside onto the next file scanned, validated and copied the whole value so far at each boundary, so the cost grew with the number of files times the size: `length` over a 10 MB array cut into 40 files took 4.83 G instructions where one file takes 0.26 G (cachegrind on the x86_64 box), and on the AMD Ryzen 9 7950X box a 100 MB array in 40 files took 2.8 s where jq 1.7.1 takes 1.4 s. jq's parser state now goes on with the carry and each file is read from where it stopped; the same 10 MB array takes 0.42-0.53 G instructions in 2, 8, 40 or 200 files.
