- **jq: a malformed member found when the filter reads it is worded as jq's parser words it** (#5576).
  `succinctly jq -c . a.json b.json c.json` with `{"a":1,}` in `b.json` printed `jq: error (at b.json:2): Invalid JSON text:
  expected string key, found '}'` and went on to read `c.json`, where jq 1.7.1 prints `jq: parse error: Expected another
  key-value pair at line 4, column 8` after the values before the fault and reads nothing more. The semi-index accepts
  such a member and the evaluator finds it only when the filter reads it, so the stream is now read again from its start
  for jq's first fault when that error is reported, on the error path alone: a filter that reads no malformed member
  pays nothing. The fault is jq's text and position, which count lines across the files as one stream, and the run
  stops there with exit 5, as jq's does. `-s` over files words it the same way; `-s` from stdin keeps the evaluator's
  line, since the original bytes are gone once the values are joined. A differential against jq 1.7.1 over 120 filter,
  flag and input combinations had 105 differing runs before this and 26 after, the 26 being filters that never read
  the malformed member and `-s` from stdin.
