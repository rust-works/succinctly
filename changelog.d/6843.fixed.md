- **yq: a comment at or left of the parent's indent, straight after a block scalar's header, ends the scalar empty, and the deeper text after it is refused** (#6843). `a: |` / `#x` / `  y` is an error in yq (the scalar is empty, the comment is a comment, `y` is a stray line) and was `a: ""` here with the `y` dropped without a word: the parser skipped the comment to find the content line, found `  y`, and the block-end kernel (which never looks at a scalar's first line) then took the comment line as the scalar's first line, so the scalar ran over `y` and the decoder, which reads `#x` as the first content line, answered empty. The same held for `>`, `|-`, `|+`, a sequence item (`- |`) and a nested key. A document's root block scalar is as it was: yq's first document reads past the comment on its own `--- |` line (`"y\n"`, as here), and refuses the other roots, which are still read as empty here (recorded in `docs/compliance/yq/limitations.md`). Checked against yq v4.53.3 on 41 pinned documents and on 4,000 random ones (eight owners, seven headers, four leading blank runs, eight comment shapes, nine bodies): 44 documents newly agree, none that agreed before differs, and none of the 4,000 differs from yq now.
