- **x86_64: the JSON index is built by a branch-free kernel, faster on every input measured and much less sensitive to code placement** (#7299).
  The AVX2 standard-cursor kernel ran a per-byte `match` with about three data-dependent branches and kept both bit writers' state in memory, and on a Ryzen 9 7950X its speed moved by up to 10% with where unrelated changes placed it in the binary.
  It now steps a compile-time table of the state machine with one load and one shift per byte, pulls each 32-byte block's bits out with `movemask`, and skips blocks that lie wholly inside a string.
  The kernel alone is 1.2x faster on its weakest input (strings that are all backslash escapes), 1.7-2x on record-shaped JSON, and up to about 50x on long strings.
  On the 7950X, 100 MB `users`: `.users[0]` 155.1 -> 119.4 ms, `-c .` 235.6 -> 197.4 ms, `[.users[]]|length` 173.4 -> 134.2 ms; `strings` `-c .` 258.7 -> 173.3 ms, `nested` `-c .` 286.3 -> 179.8 ms; NDJSON of 48-byte documents -7% to -9% at 1, 10 and 100 MB; every timed row is as fast or faster.
  Inert padding that moved the old kernel through four positions mod 64 spread `.users[0].name` over 143.5-154.5 ms (min), a 7.7% band; the new kernel's band is 1-4% across the rows swept, and its slowest position is faster than the old kernel's fastest.
  Peak RSS reads 0.5-1.0 MB higher (100 MB `users` `-c .` 94.4-94.9 -> 95.1-95.7 MB), not yet explained.
  Apple silicon builds the index with NEON and is unchanged.
