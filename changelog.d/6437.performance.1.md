- **The CLI allocates from glibc's main arena on Linux** (#6437).
  All the work runs on the evaluation thread, and glibc gave that thread a secondary arena, which grows its heap one
  4 KiB `mprotect` at a time: about 1,500 system calls for a 667 KB file. With `M_ARENA_MAX` set to 1 the heap grows
  through `brk` in 128 KiB steps. On an AMD Ryzen 9 7950X, at 10 MB, `.users[0].name="x"|.users|length` takes
  73.4 ms instead of 91.0 ms (1.24x faster; jq 1.7.1 takes 91.8 ms), `del(...)` is 1.22x faster, `tostream` 1.30x and
  `walk` 1.18x. An interleaved run of all 190 rows of the jq comparison's performance queries, plus yq, printed the
  same output before and after, with peak memory unchanged. The rows that allocate little are within noise. macOS
  and other allocators are unaffected.
