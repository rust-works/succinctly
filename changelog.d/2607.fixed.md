- **yq: `-o json` escapes U+2028 and U+2029 on the streaming path too** (#2607, #2663). A line or paragraph separator that arrived as a raw UTF-8 byte in a scalar was written raw wherever the cursor streamed (`.`, `.a`, `.[]`, the default for a read) and escaped to ` `/` ` only when a write or `--arg` forced the DOM; a ` ` or `\U00002029` YAML escape was raw on the streaming path too. Real yq v4.53.3 escapes all of them. The streaming writer kept a private copy of the escaper, which never learned the separator rule; it now calls the one shared definition (`jq::escape::write_json_body_yq`), so the two routes cannot drift again. The fork existed because `#[inline]` on the shared body seemed to cost jq's `arrays keys_unsorted` 13.9% on a 7950X (#1638); re-measured under the pinned release profile, every jq row executes the same instructions with or without the fork and with or without `#[inline]` on a 7950X and an M4 Pro, so that figure was code layout. The separator check is a real cost on the YAML-to-JSON streaming path: +1.0% to +3.4% instructions on a 7950X and +0.9% to +3.0% on an M4 Pro over 10 MB of users, strings, unicode and block-scalar YAML, about +3% to +5% wall-clock on string- and unicode-heavy documents on both chips. Numbers in `docs/parsing/yaml.md` (O3).
