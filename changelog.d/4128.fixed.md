- **jq: a `reduce`/`foreach` whose source destructures the register, or is a fold that does, no longer answers where jq raises a path error, so `del` can no longer wipe the document through it** (#4128). `del(reduce .[]? as $k (.; foreach ((.|.) | reduce . as {a:$a} (0; .)) as $x (.; .; .)))` on `{"a":false,"b":null}` printed `null` (exit 0, the document deleted) where jq 1.7.1 raises `Invalid path expression near attempt to access element "a"`. The destructure `. as {a:$a}` is a tracked `INDEX` step run against the value in hand, which raises when that value is not the register (an untracked entry such as `{a:{b:1}} | ...`, or the accumulator of an enclosing fold whose source navigated); the by-value drive of a fold source ran it unchecked. A source that destructures `.` anywhere in its spine, a nested `reduce` and a `select(true) as {...}` bind included, is now resolved when the register is not known to be at `.`. Over the 48 destructuring-fold operands of the path-register sweep (40,000 sampled rows) `ACCEPT_WRONG` went from 51 to 0 and `DIFF` from 5 to 0; 11 rows jq answers (contrived `?//`/nested-fold shapes) are now refused, in the safe direction.
