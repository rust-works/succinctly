- **jq: a `try ... catch` operand of `and`/`or` or unary minus that reads the register is refused in path position, as jq refuses it** (#4125).
  `del((.a)? or try (.a | error) catch .)` removed `.a`, `path(try (select(. // 1) | error) catch (.a)? and .[0])`
  printed nothing and `del(-(try (if true then error(. // 5) else . end) catch (.a)?))` was a silent no-op, where jq
  raises `Invalid path expression ...` (exit 5). The right operand now runs from the register the left operand left
  (a body that navigates before it always raises is no longer evaluated from the entry), and a handler whose payload
  may be the register's own node no longer has its `(.a)?` quietly pruned. Over a seeded 12,000-row sample of the
  path-register sweep's `try`/`catch` operands the build writes where jq refuses on 0 rows (18 on `main`) and
  refuses where jq answers on 13 more (219 against 206), all of them under an outer `try` that jq uses to swallow
  the path error.
