- **jq: the exit status is the last input's, as in jq; `--on-error=continue|stop` opts into failing on any error** (#5471). `printf '1 {"a":2}' | sjq .a` prints `2` and now exits 0, as jq 1.7.1 does, where it used to exit 5 because an earlier input had raised. Each document, `-R` line, DSV row and `--stream` event is a top-level input; under `-e`, an input that printed and then raised no longer counts as the last output (jq's `last_result`). A document that fails to decode, or an input stopped by a succinctly resource limit such as `range: maximum iterations exceeded`, still fails the run wherever it is: jq stops at the first and exits 5, and has no cap for the second. Scripts that relied on the old any-error status should pass `--on-error=continue`; `--on-error=stop` evaluates nothing after the first failure. Both are succinctly extensions. `succinctly yq` is unchanged (#5507 tracks the flag there). See `docs/compliance/jq/limitations.md`.
