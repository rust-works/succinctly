- **`succinctly jq` reports jq's location for an error raised after input runs out** (#4303). Once an `input`/`inputs` read reached the end, an error named the last file at its last document's line (`in.json:0` for `1 2 3`). jq 1.7.1 prints `(at <unknown>)` when the read that reached the end completed the stream's last value: a file not ending in a newline, or a bare number ending a full 4095-byte read. Otherwise it names the file at its newline count, so `3\n\n` is line 2, not 1. Both now match, for files, stdin and `-R`. `jq -c input` over `1 2 3` prints `jq: error (at <unknown>): break` as jq does. `input_line_number` follows the marker: the first read past the end takes its line (0 for `<unknown>`), and every later failed read is `<unknown>` at 0. That rule also closes the divergence recorded after #1309 (`input_line_number` keeping its line after a failed read). `--seq` keeps its own rules (#2947, #3003).
