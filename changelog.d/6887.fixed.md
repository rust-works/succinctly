- **yq: a document `.inf`/`.nan` used as a number, and `to_json`/`@json` of a non-finite float, fail as yq does** (#6887).
  yq reads each operand's text with Go's `strconv.ParseFloat`, which has no `.inf` spelling, so `printf 'a: .inf\n' | yq '.a + 1'` is
  `Error: strconv.ParseFloat: parsing ".inf": invalid syntax` in every output format, and so are `-`, `*`, `/`, `%`, the ordering
  operators `<`, `<=`, `>` and `>=` (in an assignment too) and `min`/`max` over two numbers one of which is such a scalar; `succinctly yq`
  printed `+Inf` (or `NaN`, `true`, `.inf`). It names the left operand when both fail, as yq does. `to_json`, `to_json(N)`, `tojson` and
  `@json` printed `null` for a non-finite float and now raise the JSON encoder's marshal error with yq's wrap count (`.a | to_json` over
  `a: .inf` one, `[.a] | to_json` two, `[1 / 0] | @json` two). `==`, `!=`, `//`, `length`, a string or `null` on the other side and a
  computed infinity (`1 / 0`) are unchanged. Two corners stay recorded in `limitations.md`: yq names the last node when an update fails
  on several, and it panics on a `sort` over such a scalar.
