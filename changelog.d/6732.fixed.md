- **`succinctly jq --stream-errors` stops at the first failure when a file of several values follows a directory behind a bare number** (#6732). `jq -c --stream-errors halt_error p.json dir r2.json gone.json` (`p.json` = `1` with no newline, `r2.json` = `1 2`) prints `Is a directory` and `[[],11]`: the number goes on into `r2.json`, where the first event is whole at the space, so the main loop stops there and `gone.json` is never opened. succinctly judged `r2.json` by its last token (`2`, a bare number), sent the run up front, and said `Could not open file gone.json` too. A file that is all number or letters (`2`, `ab`) still continues the token into the next read, and a number that ends inside a string is judged as before. 20 of the 180 rows of #6683's 35,090-row differential against jq 1.7.1 were of this shape; they are fixed and none changed for the worse. The other 160 (a first file that ends in a container, `{"a":1}` or `[1,2]`, with a program that reads `input` under plain `--stream-errors`) are the closing-event shape of #6646 and stay with #6732.
