- **jq: a `\xHH` at 0x80 or above inside a character class is a byte of a UTF-8 sequence, as it is outside one** (#6240).
  `[\xC3\xA9]` was read as the two characters U+00C3 and U+00A9 and matched neither `é` nor anything jq matches, and `[\x80]` as U+0080; jq decodes the bytes, so `[\xC3\xA9]` matches `é` and `[\x80]` matches nothing.
  A sequence that stops short is `too short multibyte code string`, a bad tail byte is `invalid code point value`, and a range between a decoded character and a character or another byte run (`[\xC3\xA9-\xC3\xAB]`, `[a-\xC3\xA9]`) holds what jq holds, including the one-sided reading of a stray byte (`[\x80-\x90]` matches nothing, `[\x80-\xC3\xA9]` is U+0080 to U+00E9).
