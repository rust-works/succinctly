- **`succinctly jq` reads a JSON document of 4 GiB or more instead of panicking** (#7425). One document that long (a named file or a pipe), or a `-s` slurp of a stream that long, panicked with exit 101 on the index's `u32::MAX` assertion where jq 1.7.1 answers. A document no index can hold is now read into a tree by the one-pass reader of plain JSON and the program runs on the tree: `length` over a 4,296,011,781-byte array prints `4098`, as jq does. A program stage the owned evaluator can only answer by indexing the whole document, a document that is not plain JSON (a repeated key, a lone low surrogate escape, `nan`, nesting past 128 levels), and `--preserve-input` on such a document are refused with an error at exit 5 (recorded in `docs/compliance/jq/limitations.md`); a malformed one is reported as jq's parse error. `jq-locate` and `succinctly yq -p json` refuse such an input with an error rather than a panic.
