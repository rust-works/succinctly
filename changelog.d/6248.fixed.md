- **jq: Oniguruma's `\o{...}` octal escape is read, in a character class and out of one** (#6248).
  `"aA" | [match("\\o{101}"; "g").string]` and `[\o{101}-\o{102}]` were refused with `invalid regex: regex parse error`; the escape is now the code point it names, as in jq 1.7.1.
  The edge cases follow jq: a value past U+10FFFF or a surrogate matches nothing, `\o{8}` and a twelfth digit are `too long wide-char value`, a value past 32 bits is `too big number`, and a missing brace is `invalid code point value`.
  A surrogate or a value past U+10FFFF as the end of a range in a class (`[a-\o{154000}]`, which jq clamps) stays refused.
