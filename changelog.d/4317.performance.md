- **jq: `E[a:b][$k]` with a computed index no longer builds the slice** (#4317). #4251 and #4315 fused `E[a:b]` followed by a literal `[k]`, `length`, `first` and `last`; a computed index (`.[$i:][$k]`) parses as an index expression over the slice, not a pipe, so it still built the whole tail per read. `0 as $k | [range(length-1;-1;-1) as $i | .[$i:][$k] | .a.b] | length` over 3,000 elements takes 8.6 ms (was 1,667 ms) and over 6,000 elements 11.3 ms (was 6,376 ms): the old time quadrupled per doubling, the new one is linear, and the `[0]` control row is unchanged (10.3 vs 10.4 ms). The `?` form matches (13.8 ms against 5,777 ms). Release builds, Apple M5 Max, interleaved min of 3; x86_64 not measured. Fused only for a key that is one integer-valued number; a fractional, string, `null` or fanning-out key keeps the ordinary route, which answers or raises it as before. Like the other fused reads, it converts only the element it names, recorded in `limitations.md`.
