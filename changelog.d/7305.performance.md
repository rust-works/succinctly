- **x86_64: the SSE2 JSON index builder runs the AVX2 builder's branch-free kernel, and both are faster** (#7305).
  The SSE2 standard-cursor builder, which runs on x86_64 CPUs without AVX2 and in every `no_std` x86_64 build, still had the per-byte branch tree that #7299 removed from AVX2, and was no faster than the scalar PFSM builder.
  The two builders now share one block loop; each instruction set answers only which bytes of a block are a quote or backslash, and the three bit masks of the block's stored steps.
  Both read those masks as two 16-byte halves, which on a Ryzen 9 7950X made the AVX2 kernel 15-20% faster than one 32-byte `movemask` per mask, and a run of blocks inside a string is now skipped with one write.
  Kernel alone on the 7950X: the SSE2 builder is 1.25x (strings made only of escapes) to 38x (long strings) faster, about 2x on record-shaped JSON (100 MB `users` 81.5 -> 41.2 ms); the AVX2 builder is 9-18% faster on every generated pattern and size (100 MB `users` 44.1 -> 37.6 ms).
  End to end with AVX2, 100 MB `users`: `.users[0].name` 117.3 -> 110.1 ms, `-c .` 138.7 -> 129.9 ms, `length` 100.4 -> 93.2 ms (medians); no row is slower beyond the A/A noise.
  With the SSE2 builder forced on the same machine (a stand-in for a CPU without AVX2; nothing else in the binary changes path), the same rows run 24-36% faster at 10 and 100 MB (`.users[0].name` 157.9 -> 113.0 ms), `nested` `-c .` 56-59% faster, and NDJSON of small records 3-11% faster.
  Apple silicon builds the index with NEON and is unchanged.
