- **`succinctly yq --jq-extensions` now reaches the text `eval(...)` runs** (#7012). `eval` parsed its text with the flag off, so `eval("paths")` was a parse error even under the opt-in that makes `paths` run in the program itself. The call now carries the run's flag and parses its text under it, in the read position and in the path position a write or `del` names (`eval("limit(1; .a)") = 5`), and through a nested `eval`. Without the flag the text is refused as before, as yq refuses it.
