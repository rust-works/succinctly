- **jq: a capture group that holds only a zero-width anchor, after a nullable item in the same way, is set by the copy of the way that consumes text** (#6492). `"abc" | [match("(?:(a)|(\\w*)(\\z)){2,3}?";"g") | .captures | map(.string)]` gave `["a","bc",null]` for the first match and jq 1.7.1 gives `["a","bc",""]`: the group-copies rewrite wrote the consuming copy of `(\w*)(\z)` from the anchor's own text, `(\w+)\z`, which dropped the group around it. The copy is now written from the text of the item, group included. The issue called it latent, because the fancy-regex route it was found on does not run the rewrite; the plain route does. A grid of 1,890 patterns (7 nullable items, 9 anchor spellings, 3 other ways, 10 quantifiers) over 7 strings fixed 130 and changed none the other way, and the `--assert`, `--bounded`, `--ways`, `--nest`, `--fancy`, `--newlines` and `gx`/`gi` sweeps broke none.
