- **jq: POSIX bracket classes (`[[:alpha:]]`, `[[:upper:]]`, `[[:digit:]]`, ...) are Unicode-aware, as in jq** (#5367). They were the `regex` crate's ASCII-only classes, so `"é" | test("[[:alpha:]]")` was `false` where jq says `true`, `[^[:alnum:]]` matched every accented letter, and `gsub("[^[:alnum:] ]";"")` stripped them from `"héllo wörld"`. A POSIX bracket inside a character class is now rewritten to a nested Unicode class with Oniguruma's definitions (`alpha` is `Alphabetic`, `lower`/`upper` the `Lowercase`/`Uppercase` properties, `punct` is `\p{P}\p{S}`, `space` and `blank` the Unicode spaces, and so on); `[:ascii:]` and `[:xdigit:]` are ASCII in both. Checked class by class against the pinned jq over every scalar value: nothing jq matches is missed, and the only extra matches are code points the `regex` crate's newer Unicode tables assign (Unicode 16 against Oniguruma's older tables).
