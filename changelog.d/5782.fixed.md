- **jq: dropping a value built millions of levels deep no longer aborts the process** (#5782). `succinctly jq -n 'reduce range(10000000) as $i ([]; .[0] = .) | length'` overflowed the native stack in `OwnedValue`'s drop glue (exit 134) and now prints `1`, as does the object form (`.a = .`). jq 1.7.1 segfaults on the same program from a few hundred thousand levels (between 150,000 and 200,000 on macOS with an 8 MB stack), so there is nothing to match (ADR-0018). A per-thread count of nested container drops lets a shallow value drop through the ordinary glue as before; once 256 are running, the rest of the value goes onto a heap worklist, so a drop needs at most about 43 KB of native stack. The count costs about 1% of instructions on queries that build and drop millions of small containers (`[.users[] | [[[.id]]]]`), and -0.4% to +2.2% wall-clock on a 7950X over 10 and 100 MB inputs; on an M4 Pro the median row is +1.5%, the same as a scan of each container's children costs there.
