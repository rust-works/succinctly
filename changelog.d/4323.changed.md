- **jq/yq: a literal-bound slice read no longer validates the rest of the array** (#4323). `.[2:][0]`, `.[2:][-1]`, `.[2:] | length`, `first` and `last` (jq mode) and `.[2:][$k]` convert only the element they name, as the computed-bound forms (`.[$i:][0]`) already did, so a malformed value elsewhere in the array no longer raises: `.[0:3][0]` on `[1,1.2.3,3]` is `1` (jq rejects the document at parse), and `.[1:][0]` on `[tru]` is `null`. The unfused spelling `(.[2:])[0]` and a bare `.[a:b]` still convert every element of the range (and, since #6231, only those). Recorded in `limitations.md` ("A fused slice read does not validate the rest of the range"); the speedup is the `performance` entry of the same issue.
