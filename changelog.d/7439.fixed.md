- **`succinctly jq -f` is a flag, as in jq: the first positional word is the program file wherever it sits** (#7439). `-f` used to take the word right after it as the file, so `jq -f -r prog.jq in.json`, `jq -fr prog.jq in.json`, `jq prog.jq in.json -f` and `jq -n --args -f prog.jq a` failed with a usage error or `Could not open r`, and `jq in.json -f prog.jq` ran `prog.jq` where jq runs `in.json`. Over 281 generated orderings of `-f`, `--from-file`, flags, bundles, `--arg`, `--args`, `--jsonargs` and `--`, 116 differed from jq 1.7.1 in stdout or exit status before and none do now (jq 1.8.2 agrees with 1.7.1 on all of them). `-f` with no positional word prints jq 1.8.2's usage text and exits 2, following jq's 1.8 fix where 1.7.1 tried to open `.` as the program file. A directory given to `-f`, `--slurpfile` or `--rawfile` is reported in jq's words (`It's a directory`, not `Is a directory`). `-fFILE` and `--from-file=FILE` are now refused with exit 2, as jq refuses them.
