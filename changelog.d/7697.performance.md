- **jq: a program the path-mode interpreter runs no longer takes the last document's tree apart** (#7697).
  `[path(.data[] | .name // empty)] | length` freed every member of the document but `.data` as it read
  `.data`, millions of small blocks, and on glibc a later free swept them all again
  (`malloc_consolidate`). The last value's document is now kept to the end of the run and forgotten, as
  its index already was (#7332), when it is 64 KiB or more and the program cannot walk it with `..`
  (such a walk frees the tree as it goes, and keeping it would raise the peak). At 100 MB, wall clock on
  an AMD Ryzen 9 7950X / an Apple M4 Pro: that row -26.2% / -30.1% (1773.9 -> 1308.9 ms /
  858.4 -> 600.1 ms), `(.data[] | .name // empty) |= 1 | .data | length` -27.0% / -30.1%,
  `[path(.users[] | .name // empty)] | length` on users -10.2% / -25.9%; peak memory unchanged, output
  identical.
