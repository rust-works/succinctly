- **`OwnedValue::as_object_mut` now returns `&mut ObjectMap`** (#1344). It returned `&mut IndexMap<String, OwnedValue>`. `ObjectMap` dereferences to that map (and mutably to it), so a call that uses the result as a map still compiles, as does a `let` or an argument that names `&mut IndexMap`; code that names the old type inside another type, such as `Option<&mut IndexMap<String, OwnedValue>>`, needs `.map(|m| &mut **m)`. A raw `&mut IndexMap` borrow of an object drops any repeated-key entries first; the new `ObjectMapOf::push_occurrence`, `occurrences`, `has_shadows` and `first_occurrence` methods keep and read them. Nothing records a repeated key yet, so no output changes: this is the representation `succinctly yq` needs to keep both entries of `a: 1` / `a: 2` through `-s`, `--eval-all`, `[...]` and variable bindings (ADR-0027).
