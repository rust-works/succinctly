- **`OwnedValue::as_object_mut` now returns `&mut ObjectMap`** (#1344). It returned `&mut IndexMap<String, OwnedValue>`. `ObjectMap` dereferences to that map (and mutably to it), so a call that compiled before still does. A raw `&mut IndexMap` borrow of an object drops any repeated-key entries first; the new `ObjectMapOf::push_occurrence`, `occurrences`, `has_shadows` and `first_occurrence` methods keep and read them. The shared variant of `ObjectMapIntoIter` holds the object's store instead of its `IndexMap`. Nothing records a repeated key yet, so no output changes: this is the representation `succinctly yq` needs to keep both entries of `a: 1` / `a: 2` through `-s`, `--eval-all`, `[...]` and variable bindings (ADR-0027).
