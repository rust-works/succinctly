- **`succinctly jq -n` no longer reports a file that did not open when the program stops before the last value of the file ahead of it** (#6657). `jq -c -n input str.json missing.json one.json` (`str.json` = `"a" 12`) prints `"a"` and exits 0: the bare `12` completes only when jq's reader goes on into the next file, so a program that reads `"a"` alone never makes the read that meets the failure. succinctly reported `Could not open file missing.json` up front and exited 2. The failure is now the read of `12`'s to reach: `[inputs]`, `input, input` and the like say it as before, and a program that stops earlier says nothing. A 45,612-row differential against jq 1.7.1 (flags, programs and lists of up to five files with one or two missing ones) left 412 rows fixed and none changed for the worse; the rows still apart are the `--stream` closing-event shapes of #6646 and #6680.
