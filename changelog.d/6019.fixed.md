- **jq: `-n -s` raises a fault in the stream from `input`, as jq does** (#6019). A stream with a fault was read in full before the program ran, so the fault ended the run at exit 5 even for a program that never calls `input`. jq reads on the first `input`: `printf '1 2 }' | jq -nc -s 'try input catch "E"'` prints `"E"`, `input_line_number` prints `0`, and the call after the fault returns the array of every value read (`[1,2]`, with the ones that follow the fault too). Every fault is one call, all of them before the array, the one at the end of the stream included. 17,000 stream-by-program runs over one to three files matched `/usr/bin/jq` 1.7.1 on stdout, stderr and exit status, but for the rows #6004 tracks (the file a stitched fault names, a bare token ended by a bracket at the end of the stream).
