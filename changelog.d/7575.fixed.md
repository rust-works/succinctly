- **A run that meets a parse error leaves a redirected stdin where jq does** (#7575). A run over a regular file on standard input that stopped at a parse error (the main loop, an uncaught `input` error) left it where its own reads had taken it, often its end, where jq 1.7.1 leaves it at the end of the line (or 4095-byte read) that held the error; a run that catches the error and reads on (`try input catch ...`) now also resumes counting from the next line, as jq's reader drops the rest of the error's. A standard input that shares its open file with the output (`<> f >&0`) is no longer moved at all; `--stream` parse errors, `--seq` and `--stream-errors` are unchanged.
