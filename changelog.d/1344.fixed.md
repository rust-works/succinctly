- **yq: an owned value keeps a repeated mapping key's earlier entries** (#1344, #1343, #2063, #2186, #5414). `a: 1` / `a: 2` was merged to `a: 2` by every route that materializes a document into an owned value: `-s`/`--eval-all` input, `[...]`, `as $x`, `..`, `-P`/`-C`/`-0`, `reduce`/`foreach` bindings, `group_by`, `while`/`until`, and every write. `succinctly yq` now prints what yq v4.53.3 prints on all of them (`[.]`, `[..]` and `. as $d | $d` are `{"a":1,"a":2,"b":3}`; `.a = 5` is `{"a":1,"a":5,"b":3}`; `del(.b)` is `{"a":1,"a":2}`), and `to_entries`, `with_entries`, `from_entries`, `map_values`, `omit` and `+` follow yq's rule for which entry they act on. 68 oracle rows are pinned in `tests/yq_cli/i1344.rs`. `contains`, `sort_keys` and an earlier entry's comment, anchor or style are still the collapsed answer (see `docs/compliance/yq/limitations.md`). `succinctly jq` is unchanged: jq reads the last value of a repeated key.
