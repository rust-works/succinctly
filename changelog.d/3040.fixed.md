- **yq: a YAML float with more than 17 significant digits keeps its source text instead of being rewritten to the shortest `f64` spelling** (#3040). `yq -i '.n = 1'` on `z: 2.7293109604053567083` rewrote the untouched `z` to `2.729310960405357`, and `.c == 2.7293109604053567083` was `false`. Real yq keeps a scalar's text until an operation computes a new number, so `is_preservable_float_literal` no longer caps the mantissa (#1008, #1211 added the cap); arithmetic still uses the plain `f64` parse. Streams, `-o json`, `tostring`, `==`, `sort` and writes now match yq v4.53.3 as captured in the issue; a bare digit run above `i64` is unchanged (#1129).
