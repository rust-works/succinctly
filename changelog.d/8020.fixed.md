- **yq: `del()` with a metadata reader target no longer deletes the whole document, and `-i` no longer empties the file** (#8020).
  `del(.a, document_index)`, `del(.a, filename)` and `del(.a, (.b | line))` printed nothing and exited 0, `succinctly yq -i 'del(.a, document_index)' f.yaml` left `f.yaml` at 0 bytes, and `(.a, line) = 7` replaced the document with `7`: the target was resolved on the cursor to the path of the node the reader read, which at the root is the document itself. yq's readers (`line`, `column`, `kind`, `style`, `tag`, `anchor`, `alias`, the comment readers, `path`, `document_index`, `file_index`, `filename`) answer a fresh node that keeps its input's parent and key, so `del(.b | line)` deletes `.b`, `del(.. | line)` leaves `{}`, a reader at the root stops yq's back-to-front loop (`del(.a, line)` keeps the document, `del(line, .a)` deletes `.a`), and a write through one writes nothing (a literal beside a cursor selection, `del(1, (.. | select(style == "x")))`, deleted the document the same way); `succinctly yq` now does the same, and `del(.b | key)` deletes `.b` as in yq instead of nothing. A metadata `select` before a reader (`del(.[] | select(style == "") | line)`) is resolved on the document's cursor, since the owned value answers every reader's default; `key` straight after `key` answers nothing, as in yq. about 625 rows captured from yq v4.53.3 across the document, `ea`, multi-document, `-n`, `-o=json` and `-i` routes.
