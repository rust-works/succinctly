- **`succinctly jq` reads a NUL byte glued to a number as the end of that number, as jq does** (#7437). jq's number parser reads a token as a C string, so `[1`, a NUL, `x,2]` and a newline is `[1,2]` and `1`, a NUL and a newline is `1` in jq 1.7.1 and 1.8.2, where `succinctly jq` refused them with `Invalid JSON text`; the rest of the token after the NUL is dropped with it. This holds on every reading route (whole files, windows, `-s`, `input`/`inputs`) for a NUL in one of jq's 4,095-byte reads that holds a newline (a read with none still truncates jq's input, #5654), and for `fromjson`, which reads its string whole: `"[1\u0000,2]" | fromjson` is `[1,2]`. A text with no NUL pays one search for one.
