- **jq: `try path(.[]) catch LITERAL` over a scalar no longer builds the `Cannot iterate over ...` error its handler ignores** (#4280). #4157 settled `path(.[])?` and `try path(.[]) catch empty` this way, and #3704 `try .[] catch LITERAL`; a literal handler around `path(.[])` still built the payload (a preview string and an owned copy of the scalar) and ran the handler over a re-indexed scalar document. `[.[] | try path(.[]) catch "c"] | length` over 2,000 integers makes 2,022 allocator calls, down from 18,022, the same as `try .[] catch "c"`. Output is unchanged: the literal for a scalar, the paths for a container, and an undecodable string still escapes.
