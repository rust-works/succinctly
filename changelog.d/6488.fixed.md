- **jq: a loop with capture groups in a pattern with `\z` or a `$` before its end answers as jq does** (#6488).
  Such a pattern runs on the `fancy-regex` route that reads `$` exactly, which only had the plain
  loop rewrite: that rewrite keeps a loop as written when it would copy a group, so
  `"ba b" | [match("(?:$\\z|\\B(\\w*)){2,}";"g") | .string]` was `["a",""]` where jq 1.7.1's is
  `["",""]`. The capture and group-copies rewrites now run there too, for a pattern nothing in which
  can match a newline (the rewrites read `$` as the end of the text) and with no group that holds
  only an anchor (#6492). A rewrite holding a shape `fancy-regex` merges wrongly keeps the pattern
  as it was, and a search whose copies exhaust the backtracking budget is answered by the pattern as
  written. `scripts/jq-regex-capture-loop-sweep.py` fixes 3 to 11 patterns in 4,000 per `--assert`
  seed and 11 to 22 per `--bounded` seed, under the `g`, `gi` and `gx` flags, and breaks none.
