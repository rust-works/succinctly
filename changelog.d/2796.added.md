- **yq: `head_comment = ""`, `foot_comment = ""` and `comments = ""` clear comments, and `...` is accepted as the target of a comment write, so `... comments = ""` strips every comment in a document** (#2796, part 1). `succinctly yq '... comments = ""'` on `# top\na: 1 # line\n# mid\nb: 2\n# end\n` was a parse error at position 2, and `.a comments = ""` raised `comments = ... is not yet supported`; both now print what yq v4.53.3 prints (`a: 1\nb: 2\n`). `...` is yq's recursive descent that also visits mapping keys, so it clears the comments above and below an entry (which yq keeps on the key) as well as the values'; `..` and an ordinary path address values only, so `.a head_comment = ""` leaves the `# mid` above `b:` alone. Setting a non-empty text (`head_comment = "hi"`, `foot_comment`, `comments`) and `tag =` still raise `not yet supported`: where yq prints a set head or foot comment follows go-yaml's emitter state, which the emitters here do not model. Checked by 13 pinned-yq goldens and a differential fuzz of about 5,900 clearing operations over random commented documents, none differing.
