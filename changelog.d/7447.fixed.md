- **jq: `input`/`inputs` over a source whose first document is longer than 256 KiB no longer hold the whole source** (#7447, #7502). The lazy route's start turned such a source down and read it whole, so `-n 'reduce inputs as $x (0;.+1)'` over NDJSON whose first line is a 300 KB string peaked at 105, 305 and 1029 MiB at 100 MiB, 300 MiB and 1 GiB on an M4 Pro, where jq holds 3 MiB and the same line later in the file held a window; it now reads on until the first document ends and peaks at 5.6 to 5.8 MiB at every size (a pipe: 106 to 5.9 MiB; the first of two files: 157 to 6.3 MiB). The start's buffer is also no longer sized for the whole file, so under a `ulimit -v` smaller than the file `-n input`, `-n first(inputs)`, `input_line_number` and `reduce inputs` read the file a window at a time as jq does instead of aborting with `memory allocation of <file size> bytes failed` (exit 134; checked on x86_64 Linux with a 300 MiB file under 200,000 and 400,000 KiB caps).
