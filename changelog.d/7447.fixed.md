- **jq: `input`/`inputs` over a source whose first document is longer than 256 KiB no longer hold the whole source** (#7447, #7502). The lazy route's start turned such a source down and read it whole, so `-n 'reduce inputs as $x (0;.+1)'` over NDJSON whose first line is a 300 KB string held the whole source (its peak RSS was about the size of the file at every size, on a pipe and for the first of two files), where jq holds a few MiB and the same line later in the file held a window; it now reads on until the first document ends and its peak RSS is flat in the size of the source (305 MiB to 6.1 MiB at 300 MiB on an AMD Ryzen 9 7950X). The start's buffer is also no longer sized for the whole file, so under a `ulimit -v` smaller than the file `-n input`, `-n first(inputs)`, `input_line_number` and `reduce inputs` read the file a window at a time as jq does instead of aborting with `memory allocation of <file size> bytes failed` (exit 134; checked on x86_64 Linux with a 300 MiB file under 200,000 and 400,000 KiB caps).
