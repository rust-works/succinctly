- **jq: a long string named argument is spliced as one shared string instead of a literal copied at each read** (#5713).
  A `--arg`/`--rawfile` string became a `Literal::String` in the program (one copy) and was cloned again each time the literal was evaluated (a second copy per read), so `[range(20)|$s|startswith("a")]` over an 84 MB `--rawfile` copied 84 MB twenty times. A string of 4096 bytes or more now rides one reference-counted marker that every read shares; a shorter one stays a literal, and a container named argument is unchanged (#5690: a marked container was found unsafe in a path target and quadratic in a fold). On an AMD Ryzen 9 7950X, 84 MB: `$s|length` and `$s|startswith("zzz")` 120-130 ms to 90 ms, peak 252 MB to 172 MB; the twenty-read program 720-820 ms to 90-100 ms, peak 1774 MB to 173 MB. At 10 MB the twenty-read program peaks at 31 MB instead of 217 MB, at 1 MB 14 MB instead of 33 MB. A program that never reads the variable is unchanged (50 ms, 91 MB). Output is identical to the previous build on 510 program-and-input combinations, and to jq 1.7.1 on all but `trim`, which 1.7.1 lacks.
