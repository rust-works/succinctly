- **yq: `error(...)` evaluates its message at the input's position** (#8080). A message that read the position -- `key`, `path`, `parent`, `line` -- was evaluated over a copy with no position, so `.b | error(key)` raised `aborted`, `.b | error(path | join("."))` raised an empty message and `.b | error(line)` raised `0`, in a plain pipe as in `|=`, `with()`, `select`, `map` and an `as` body. Each now raises what yq v4.53.3 raises (`b`, `b`, `2`), as the already-correct `key as $k | error($k)` did; a message that reads no position is evaluated as before.
