- **jq: `--seq` over a regular file of RFC 7464 records is read a window at a time, so its peak memory no longer grows with the file** (#7082, slice 4 of #6920). `jq --seq -c .` over a file or `< file` of 4 MiB or more whose stream is RFC 7464's own framing (every record `RS value LF`) used to hold all of it: 126 MiB (x86_64) and 123 MiB (aarch64) at 100 MiB, where jq's is 2.3 MiB. It now holds about a 1 MiB window and the record being run, 11.2 and 6.8 MiB, flat from 10 MiB. A prepass reads the file once by position to check the framing with the checker the whole-file route uses, then the plain route's windows read it with each RS as a space. Output, error wording, exit status and the `(at file:N)` lines are the whole-file route's, checked against the base binary over 1,680 random-stream runs and against jq 1.7.1. A stream that is not that framing (a fault, a truncated tail, bytes before the first RS, a BOM, invalid UTF-8), a pipe, several files, `-s`, `--validate` and `-n` are read whole as before. Time at 100 MiB: −6.0% (`-c .`, 7950X, control −0.5%) and −1.3% (M4 Pro, control +0.6%).
