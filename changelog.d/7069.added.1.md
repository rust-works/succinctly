- **`succinctly yq` accepts a metadata assignment inside the body of `with(PATH; ...)` and `PATH |= (...)`** (#7069). `with(.a.b; . = "new" | . style="double")` is `b: "new"` and `with(.a; .b line_comment="x")` is `b: thing # x`, as in yq v4.53.3; both were refused with `metadata assignment ... is only supported as a pipe stage`. Each stage of the body is written as a stage of the filter with the path in front of its target, in the order written, which is what yq answers for both spellings whether the path exists or not (2,815 probe rows over eight documents, thirteen paths and fourteen bodies; 2,000 random bodies against the build before: 1,246 fixed, 0 changed that matched). A body with a right side that reads the node (`.b line_comment = .c`), a `del` or a comma path is still refused; `... style=` and `ref`, which the issue also names, are not part of this change.
