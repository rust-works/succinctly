- **yq: a folded scalar that starts with blank lines is written with the blank lines it had** (#6446). The streaming route (`.`) widened the run of breaks a `>` scalar starts with, which wrote one empty line too many and changed the value when it was read back: `a: >` / blank / blank / `  x` came out with a third blank line (`"\n\nx\n"` became `"\n\n\nx\n"`), and a `>+` of nothing but blank lines gained one. go-yaml's folded writer widens nothing for a string that starts with a break and adds no trailing extra to a value of only breaks, and the write route (`.zzkey = 1`, `-P`, `-i`) already agreed with yq; the streaming route does now. Found by a differential sweep of real YAML files, where it was 1 of 250 differing file/filter pairs (most of the others in folded scalars are the more-indented shape below). A fuzz of random folded scalars classes every one whose yq output reads back as the same value as byte-identical to yq now (it was 62 of 700 that differed, and 51 more whose yq output changes the value were data-corrupting here and are lossless); a more-indented line keeps the lossless spelling that ADR-0018 and #836 chose, where yq adds an empty line that changes the value. Pinned against yq v4.53.3 in `tests/yq_cli/i6446.rs`.
