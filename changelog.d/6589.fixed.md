- **jq: `--seq -s` beside a file that does not open reports it where jq's reader reaches it, and keeps the array when jq does** (#6589). `--seq -s . bad.json gone`, with a record cut short in `bad.json`, printed the open failure before the warning and lost the array; it now prints the warning, then the failure, then the array, as jq 1.7.1 does. The array is lost only when a warning comes after a failure, where jq's main loop stops (and reports nothing after it). A missing last file now gets the EOF report straight after its failure instead of deferring it past the array. Once a file has failed, the deferred report is never printed, though `input` still raises it. `--seq -s` with a program that reads `input` no longer trips a debug assertion when the array is lost. Over 3,780 runs (`--seq -s` x 9 programs x lists of two or three files with missing ones), 1,701 differed from jq 1.7.1 before and none do now.
