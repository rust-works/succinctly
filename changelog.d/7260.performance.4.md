- **jq: `map_values` and `to_entries` walk a wide object's fields in place instead of listing them** (#7260).
  Both built a list of every field with its key and value decoded (144 bytes each) before doing any work;
  over one object of 82,210 fields that list was 18 MiB. When the object is well formed and no key repeats,
  the fields are now walked in place; any other object takes the old route, with its errors and
  duplicate-key rule unchanged. `to_entries` also sizes each entry object and the result exactly.
  `to_entries|length` on a 10 MB object peaks at 360 MB instead of 512 MB on an AMD Ryzen 9 7950X (jq
  1.7.1: 435 MB) and is 13% faster; `map_values(.+1)` peaks at 219 MB instead of 324 MB and is 7% faster.
  On an Apple M4 Pro they peak at 295 MB instead of 447 MB (jq: 513 MB) and 213 MB instead of 315 MB, and
  are 2-3% faster. `with_entries` is 3-5% faster on both.
