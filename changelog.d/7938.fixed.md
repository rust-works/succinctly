- **jq: the windowed document loop counts jq's reads in the bytes jq read** (#7938). A regular file of 4 MiB or more is read a window at a time, and a window kept the invalid-UTF-8 substitution's edits only when its tail was handed to a later file, so the loop counted a value's 4,095-byte read over the text with U+FFFD in it, three bytes for each byte replaced, and a value just past a read boundary after invalid UTF-8 on a long line was named a line late in a runtime error's `(at f:N)`. Over 2,097,162 lines of `0` and then a line holding `"\x80"`, `0`s to byte 4,080 and `1` to `9`, `select(. != 0) | error` named the string and `1` to `5` on line 2,097,162 and `6` to `9` on the next, where jq 1.7.1 names the string and `1` to `6` on line 2,097,162; it now does too, on a file, on standard input and through a pipe. #7934 had fixed the same count on every other route.
