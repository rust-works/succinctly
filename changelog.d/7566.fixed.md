- **jq: a UTF-8 byte-order mark cut across the first input files is skipped** (#7566). `EF BB` in one file and `BF [2]` in the next, or a byte of the mark in each of three files, was `Invalid numeric literal at line 1, column 4` (exit 5) under `.`, `-s`, `-n input`/`inputs`, `--stream` and `--stream-errors`, where jq 1.7.1 and 1.8.2 skip the mark and read `[2]`: jq reads its files as one stream and its parser matches the mark a byte at a time. A stream that ends inside a mark cut that way (`EF` then `BB BF`) is empty input, as a lone `EF` has been since #7454. The routes that read several files a window at a time leave such a list to the route that reads the files whole.
