- **yq: `path` reports an integer-spelled mapping key as an integer** (#2801). yq's `path` renders a key through `getParsedKey`: a `!!str` key stays a string and any other key is `parseInt64(text)` when that parses, so on `1: x` / `0x1f: y` / `+4: z` / `true: w` `[.[] | path]` is `[[1],[31],[4],["true"]]` in yq. `succinctly yq` answered `[["1"],["0x1f"],["+4"],["true"]]`, and `.[] | select(key == 1) | path` was `["1"]` where yq prints `[1]`. The component is now the parsed integer for `path`, `..` and `.[]` walks, and for `paths`/`leaf_paths` under `--jq-extensions`; quoted and `!!str` keys, JSON input, `true`/`~`/`1.5`/`1.0`/`0b11` and an overflowing digit string stay strings. `setpath` (and `getpath` under the flag) read an integer over a mapping by its decimal text, so a `path` result round-trips (`setpath([1]; "Q")` used to fail with `Cannot index object with number`). jq mode is unchanged.
