- **jq: `nulls`, `strings`, `objects` and the other type selectors in path position run natively** (#6359), `succinctly yq` under `--jq-extensions` too. `path(..|nulls)`, `del(..|nulls)`, `(..|numbers) |= f`, `paths`-style targets built on `booleans`, `numbers`, `strings`, `arrays`, `objects`, `iterables`, `scalars` and `values` went through the path-program interpreter (a function lookup and call per node) while the `select(type == "...")` spelling of the same filter was already resolved natively; they are now static path targets too. Over a 50 MB document on an Apple M4 Pro: `[path(..|nulls)]` 2.10x, `del(..|nulls)` 1.93x, `[path(..|objects)]` 2.32x, `(..|numbers) |= . + 1` 1.50x; on an AMD Ryzen 9 7950X 2.30x, 2.15x, 2.47x and 1.59x; flat from 1 to 50 MB, interleaved, min of 7, with the controls `select(type=="null")` and `[.. | strings]` at 0.99-1.01x. The answers are unchanged, errors included (`path(..|nulls|tostring)` still raises `Invalid path expression`).
