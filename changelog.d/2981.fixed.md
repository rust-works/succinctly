- **yq: an unbound `$variable` is no output, as in yq, instead of a runtime error** (#2981, #2776, #2767, #3976). `$nope` printed `Error: undefined variable: $nope` (exit 1); yq prints nothing and exits 0, `[.[] | $nope]` is `[]`, `[$nope, 1]` is `[1]`, `1 + $nope` is `1` and `$nope // 5` is `5`. The same rule makes `$__loc__` (no builtin in yq) print nothing, and `5 as $x | $x-1` (the variable `x-1`) print nothing. Checked against yq on 40 positions, with and without `-P`. `succinctly jq` keeps the compile error (`$nope is not defined`, exit 3). The rule lives on `EvalSemantics::UNBOUND_VARIABLE_YIELDS_NOTHING`. Not fixed, and not specific to variables: `.[empty]`, `del(.[empty])` and `empty as $y | 3` (#4139).
