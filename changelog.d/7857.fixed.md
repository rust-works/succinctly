- **jq, yq: a run started with SIGPIPE blocked answers a closed pipe as jq and yq do** (#7857). With SIGPIPE at its default but blocked in the signal mask the process inherited, a closed standard output made `succinctly jq -n '"x"'` print `succinctly: failed to flush output: Broken pipe (os error 32)` and `Error: Broken pipe (os error 32)` and exit 1, where jq 1.7.1 and 1.8.2, whose write then fails `EPIPE`, report `jq: error: writing output failed: Broken pipe` and exit 2. The inherited mask is now read before `main`, beside the inherited disposition (#7732), and a blocked SIGPIPE is treated as an ignored one: a closed standard output is jq's failed write, exit 2, on every output route (plain, `-r`, `-j`, `--stream`, `--seq`, a large result and one written at exit, `debug`, `stderr`, `halt_error`, the `jq` and `sjq` aliases), and a closed standard error is ignored, as before. `succinctly yq` printed the same two lines and exited 1, and exited 1 for a diagnostic to a closed standard error, where yq v4.53.3 dies of SIGPIPE, since Go lifts the block before it raises the signal for descriptors 1 and 2; it now lifts an inherited block too and dies of SIGPIPE as yq does.
