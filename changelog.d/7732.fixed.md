- **jq: a run started with SIGPIPE ignored keeps it ignored, as jq does** (#7732). Under a parent that ignores SIGPIPE (a systemd unit, Python's `subprocess` with `restore_signals=False`, `trap '' PIPE`), a closed standard output killed `succinctly jq` with SIGPIPE (status 141) and a closed standard error did too, because every run set SIGPIPE to its default (#5547). The disposition the process inherited is now read before `main`, ahead of Rust's runtime, and kept: a closed standard output is `jq: error: writing output failed: Broken pipe`, exit 2, on every output route (plain, `-r`, `-j`, `--stream`, `--seq`, `halt_error`, `debug`, `stderr`, the `jq` and `sjq` aliases), and a closed standard error is ignored, as in jq 1.7.1 and 1.8.2 on Linux and macOS (36 of 96 matrix rows differed, none now). With SIGPIPE inherited at its default nothing changes. `succinctly yq` still dies of SIGPIPE whatever it inherited, as yq does; the other subcommands report the closed pipe as `succinctly: error: writing output failed: Broken pipe`, exit 2, when started with SIGPIPE ignored. The route that writes a whole-file result straight from the document's index (`jq . file`) dropped the write's own error and printed `Error: write error`, exit 1, for a closed pipe and for a full disk alike; it now reports both as jq does (`writing output failed: <strerror>`, exit 2).
