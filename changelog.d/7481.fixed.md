- **`succinctly jq -f` runs a shell/jq polyglot program file, as jq 1.7.1 does** (#7481). A file that opens `#!/bin/sh`, `# \`, `exec jq -n -f "$0" "$@"` and then holds the program failed with `unexpected character 'j'` at its third line; jq 1.7.1 drops those three lines (`skip_shebang` in its `src/main.c`, which applies to `-f` files only) and runs the rest, and jq 1.8.2 runs it too, through its Tcl-style comment continuation. The rule is exact and is now matched over a 2,229-file matrix (a shebang or none, a second line with 0 to 4 trailing backslashes, CRLF, the third line, what follows): stdout and exit status agree with jq 1.7.1 on every file but one, a file with a NUL byte, which follows jq 1.8.2 (#7434). A comment that ends in a backslash anywhere else still ends at its newline, as in jq 1.7.1; jq 1.8.2's continuation of every such comment is a language change and is not adopted.
