- **yq: `strenv()` and `env()` say a non-UTF-8 environment value is not valid UTF-8, not that it is not provided** (#6566). With `BADVAR` set to the bytes `\xff\xfe`, `strenv(BADVAR)` printed those two bytes in yq v4.53.3 and stopped here with `value for env variable 'BADVAR' not provided in strenv()` (and the same for `env()`), as if the variable were unset, because `std::env::var` refuses a value that is not UTF-8 and every refusal was worded as a missing one. The refusal is now `value for env variable 'BADVAR' is not valid UTF-8 in strenv()`: a string value here cannot hold the bytes, so the run still fails (exit status 1), now naming the cause; an unset variable is still `not provided`. The divergence is recorded in the yq limitations page.
