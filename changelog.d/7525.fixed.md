- **jq: a bare `n` token is `Invalid numeric literal` on every route** (#7525). `printf '\036"iu"\n\036n\n' | jq --seq -c .` reported `Invalid literal`, and `printf '"iu" n' | jq --stream -c .` (also `--stream-errors`) reported `Invalid literal at EOF`, because the readers modelled jq 1.7.1's read of a stale byte from an earlier token (`check_literal` read `tokenbuf[1]` without checking the token's length); the plain, `-n` and `-s` routes already said `Invalid numeric literal`. They now follow jq 1.8.2, which fixed the uninitialised read (jqlang/jq#3324), so one set of bytes has one fault word on every route. A token that starts `nu` (`nul`) stays `Invalid literal`.
