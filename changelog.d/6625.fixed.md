- **`succinctly jq` reports a directory given last after another open failure, or after a text
  fault under `-n`, as jq does** (#6625). A file that would not open before the directory (or a
  directory that is not last) sent the run up front, where every failure was said at once and the
  last directory was left out: `jq -n '[inputs]' bare.json missing.json dir` and `jq -n '[inputs]'
  p.json dir dir2` each printed one `Is a directory` line fewer than jq, and `jq input p.json dir
  dir2` printed one too few. The directory is now left to the reads, as it is with nothing before
  it (#6615). A `-n` program reads on past a parse error it catches, so a failure after a text's
  fault is the later reads' to reach: `jq -ns '(try input catch .), (try input catch .), (try input
  catch .)' r.txt dir` now prints the message and exits 2 where it exited 0, and so does the same
  program over `lines dir dir2` without `-s`. The `--stream`, `--stream-errors` and `--seq`
  readers are #6624.
