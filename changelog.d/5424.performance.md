- **jq / yq: a body rebuilt for each value (`. as $x | (...)`, the update of a `reduce`, the extract of a `foreach`, a destructuring bind) is linear in its stage count, not quadratic** (#5424).
  #5404 and #5421 keep the copy of each tail a pipe hands on, but a body that a substitution rebuilds for each value
  was a new pipe each time, so the tails kept for it were made once per value and used once: `n^2/2` stage copies
  and a table for a pipe that goes down once. A pipe rebuilt by a substitution now reads the tails kept for the pipe
  it was rebuilt from (from the second value on; a substitution that happens once keeps nothing). Only a stage that
  reads a variable, or holds a `def` call, differs from one value to the next; it is cloned afresh for each value, and
  the runs of stages around it are the ones the source pipe keeps. That is linear for a body that reads its variable
  at its first, middle or last stage when the variable is bound to a computed value (`(. + 0) as $x | (...)`, n=40
  2.21 s -> 0.41 s on the 7950X, 1.33 s -> 0.27 s on the M4 Pro), and for one bound to `.` itself (`. as $x`, which marks the variable so `path($x)` can use it) when it
  reads it at its first stage or not at all; read at its last stage, the owned re-entry rewrites the marker and
  rebuilds the kept run behind it for each tail, and the body gains only 5-12% at 14 to 40
  stages. 20,000 values, interleaved min of 5 CPU seconds, output identical, `[range(0;20000) | . as $x | (. + 1 |
  ... x n)] | length`: n=6 0.070 s -> 0.042 s, n=14 0.354 s -> 0.124 s, n=40 2.199 s -> 0.387 s on an AMD Ryzen 9
  7950X; n=6 0.055 s -> 0.035 s, n=14 0.216 s -> 0.085 s, n=40 1.338 s -> 0.260 s on an Apple M4 Pro. The `reduce`
  update (n=40 2.028 s -> 0.450 s, 1.258 s -> 0.332 s), the `foreach` extract (2.022 s -> 0.454 s, 1.292 s -> 0.332
  s) and a body that reads `$x` at its first stage (2.216 s -> 0.394 s, 1.327 s -> 0.264 s) match it. The same pipe
  written without a binding is unchanged (n=40 within 4%), and a short body read last is unchanged in instructions
  (n=6, cachegrind on the 7950X, -0.15%).
