- **jq / yq: a body rebuilt for each value that reads no variable (`. as $x | (...)`, the update of a `reduce`, the extract of a `foreach`, a destructuring bind) is linear in its stage count, not quadratic** (#5424).
  #5404 and #5421 keep the copy of each tail a pipe hands on, but a body that a substitution rebuilds for each value
  was a new pipe each time, so the tails kept for it were made once per value and used once: `n^2/2` stage copies
  and a table for a pipe that goes down once. A pipe that reads no variable is rebuilt stage for stage, so the one
  rebuilt for a value now reads the tails kept for the pipe it was rebuilt from (from the second value on; a
  substitution that happens once keeps nothing). A body that reads its variable differs from one value to the next
  and still copies its rest per value, as before, and a source pipe rebuilt twice now keeps its tails for the life of
  the program like any pipe that went down twice. 20,000 values, interleaved min of 5 CPU seconds, output identical,
  `[range(0;20000) | . as $x | (. + 1 | ... x n)] | length`: n=6 0.068 s -> 0.042 s, n=14 0.357 s -> 0.123 s, n=40
  2.205 s -> 0.384 s on an AMD Ryzen 9 7950X; n=6 0.054 s -> 0.034 s, n=14 0.216 s -> 0.085 s, n=40 1.346 s ->
  0.261 s on an Apple M4 Pro. The `reduce` update (n=40 2.022 s -> 0.429 s, 1.243 s -> 0.329 s) and the `foreach`
  extract (2.019 s -> 0.434 s, 1.242 s -> 0.332 s) match it. The same pipe written without a binding (n=40 within
  1.3%), a body that reads its variable (within +2.9%), a program pipe holding a `reduce` or `as` stage, a 1,000-value
  fan-out per body and a NaN container compared by identity down a 9-stage tail are unchanged on both machines.
