- **yq: a string that parses as a timestamp is compared as a time** (#5651). On the left of `<`, `<=`, `>` or `>=`, a string that Go's `time.Parse` reads as RFC 3339 or `2006-01-02` is now an instant, and its right operand is parsed the same way: `"2001-01-01T00:00:00Z" < 1` raises `parsing time "1" as "2006-01-02": cannot parse "1" as "2006"` (it answered `false`), so does a `null`, a bool or a string in another layout, with Go's own wording (`extra text`, `month out of range`, `cannot parse "0101" as "-"`), and the same moment in two zones is equal where the strings ordered. `==`, `!=`, `sort`, `min` and `max` are unchanged. `src/jq/go_time.rs` ports the part of `time.Parse` the two layouts use, including a one-digit hour, a comma fraction and a 24-hour zone offset; `scripts/yq-time-fuzz.py` replays mutated timestamps against yq (0 differences over 2,500 strings x 4 expressions). Still different: a `!!timestamp`-tagged document value that no layout reads, and a `!!str` against a `!!timestamp`, which need a timestamp kind.
