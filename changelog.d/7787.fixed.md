- **`succinctly jq` answers a tree recursion over many more leaf and combination shapes, and retries a `?//` inside `first` again** (#7787). The test that decides whether a call is run to its value before its consumer (#7460, #7713) was a list of shapes; a recursion over any other one, such as `def t($n): if $n <= 0 then [1] | first else t($n-1) + t($n-1) end; 0 | t(13)`, a leaf written with `limit(1; ...)`, `foreach`, `until`, `env`, `input_line_number` or a local def with parameters, or a combination through `first`, `//`, `label`, an object, `getpath`, `and`, `or`, a string interpolation or an `if` condition, was refused with `exceeded maximum recursion depth` at about 8,192 leaves where jq 1.7.1 and 1.8.2 answer. The test now reads every form of the language by what it yields (at most one output, and nothing observable left to run after it), for an expression that holds a call to a def that may recurse; an operator settles such an operand when the other one answers once (`and`/`or` when both hold such a call). Which expressions hold one is a shape test plus a flag remembered on each definition, so an operator, object or interpolation over plain paths asks nothing more. #7713's list had also admitted `first(...)` without looking inside, so `def f: first([1] as [$a] ?// $a | $a); f | if . == 1 then error("e") else . end` raised `e` where jq retries the `?//` and answers `[1]`; a `?//` anywhere in the expression now keeps it streaming. A filtered generator as a leaf (`(1, 2) | select(. == 1)`) and a `?//` leaf are still refused at the same depth: limitations.md says why.
