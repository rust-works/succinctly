- **jq: `pow` and `atan2` of a number whose operands are `.` or a literal no longer write it out and index it again** (#5680, #5669 follow-up). `[.numbers[]|pow(.;2)]` took the general two-operand call for every number, including the reindex bridge. When both operands are `.` or a literal (one value each, so there is no fan-out), the call is now the builtin's own libm call on those numbers, for a document number and for one the filter computed, with the operands read as the builtins read them (a `-0` keeps its sign). A generator operand (`pow(.; (1, 2))`), a computed operand (`pow(2; ./1e6)`), a value that is not a number, a non-finite one and yq mode keep the evaluator. Over a generated `numbers` document (Apple M5 Max, interleaved min of 7, 10 MB, jq 1.7.1): `pow(.;2)` 0.55x -> 0.88x of jq, `pow(.;0.5)` 0.56x -> 0.91x, `atan2(.;1)` 0.56x -> 0.93x and `.+1|pow(.;2)` 0.48x -> 0.76x.
