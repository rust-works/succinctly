- **jq: a fault met in bytes that rode across two or more files is placed where jq places it** (#5936).
  A file that is only an open tail (`[1,\n` then `x<TAB>`) hands it on to the next, and jq reads each file
  in reads of its own, so a fault in those bytes drops the rest of the read that ends at that file's end.
  For the files `}\n[1,\n`, `x<TAB>` and `[1,\nx  }}[}  `, `[limit(8; repeat(try input catch .))]` now reports
  `Invalid numeric literal at line 3, column 2` as its third message, where `succinctly jq` said `line 2,
  column 4`. Against jq 1.7.1, a randomised run over 3 and 4 files (7,200 programs) changes 266 from
  different to identical and none the other way; the 127 and 160 left over all hold invalid UTF-8.
