- **jq: `path($k)` accepts an object key read twice, as jq does** (#7401). `keys[0] as $k | keys[0] | path($k)` on `{"a":1}` raised `Invalid path expression with result "a"` where jq 1.7.1 answers `[]`: jq's `keys`, `keys_unsorted` and `.[]` (and so `to_entries`, `paths` and `tostream`) hand out the object's own key, which `path()` takes as the same value. Each object's keys now have one identity in the path-mode interpreter: reads of one key are identical, a string of the same text and the same key of another object (sibling records included) are not, a literal key is one value per constructor site, and `+`, `*`, `setpath` and `{($k): v}` keep a key the object has and store the one they are given, as jq's `jv_object_set` does. A differential sweep of 12,191 such programs against jq 1.7.1 went from 1,799 differences to none.
