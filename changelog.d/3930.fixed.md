- **jq: a `reduce` over a string slice no longer fabricates a write** (#3930, after #3494, #3793).
  `(reduce (.[0:2]) as $k (.; $k)) = 9` on `"s"` wrote `9` and `path(reduce (.[0:2]) as $k (.; $k))` printed `[]`, where jq refuses both with
  `Invalid path expression with result "s"` (an `INIT` of `1` or `null` reproduced it, as did `""`). A string slice is a fresh `jv`, never `jv_identical`
  to the register it was sliced from, but `reduce` bound the element with a position-less marker that certifies a string by value, so the final
  accumulator was taken for the register. An element that is a slice's copy (a string, or an empty array) is now bound with no marker in `reduce`.
  A non-empty array's slice, which does share its buffer, still answers. The fold-source sweep gains `"s"` and `""` as documents.
  Pinned by `test_reduce_string_slice_accumulator_is_not_the_register_3930`.
