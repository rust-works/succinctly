- **jq: a `foreach` UPDATE comma with a register-neutral builtin sibling (`now`, `input_line_number`, `floor`, `sort`, ...) no longer refuses or skips the write** (#3960).
  `jq 'del(foreach .a as $v (.; (($v | .b?), input_line_number); try ($v | .b?)))'` on `{"a":{"b":1,"c":[1,2]},"z":0}` is `{"a":{"c":[1,2]},"z":0}` in jq; this exited 5 with
  `Invalid path expression near attempt to access element "b"`, and with the `try` in the UPDATE instead it echoed the document at exit 0.
  The fold reads the register a comma sibling leaves only for an expression `cannot_move_register` lists, and it listed few builtins. The ones that navigate nothing at all are now there:
  `now`, `input_line_number`, `input_filename`, `env`, the C-coded math (`floor`, `sqrt`, `pow`, the `Libm` family, ...), `explode`/`implode`, `startswith`/`endswith`/`split`/`contains`/`inside`,
  the date builtins, `builtins`, and the C-coded `min`/`max`/`sort`/`min_by(f)`/`max_by(f)`/`group_by(f)`/`sort_by(f)`. The predicate is shared, so the same builtins also leave a pipe stage's register
  alone: `path(. as $x | map(sort) | $x)` is `[]` (it refused), and `del(. as $x | contains({"a":{}}) | try ($x | .a))` writes as jq does.
  A 148-builtin by 5-accumulator differential in the fold-comma shape (740 rows) went from 562 rows differing from jq to 294 with no row getting worse (30 of the 294 are builtins jq 1.7.1 does not define);
  48 builtins are pinned. Left out on purpose: `abs`, `ltrimstr` and `rtrimstr` hand their input back by pointer when it does not apply, so listing them turned a loud refusal into a skipped write
  (`del(ltrimstr("x") | foreach (., 1) as $x (null; .; try $x.a))`), and `ascii_downcase`/`ascii_upcase` are `explode | map(..) | implode` in jq, so they raise a path error on an input the register
  is not on. A builtin that navigates and backtracks (`add`, `to_entries`, `reverse`), the regex family, a sibling with a `.` in a pipe (#3959) and `trim`/`ltrim`/`rtrim`/`toboolean` (not defined in jq 1.7.1) are unchanged. jq mode only.
