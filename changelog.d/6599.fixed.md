- **jq: `--seq -s -n` beside a file that does not open places the failure where the program's `input` reaches it, and each fault in the file it was met in** (#6599). `--seq -s -n input bad.json gone.json`, with a record cut short in `bad.json`, reported `gone.json` up front, named it in the fault's location (`gone.json:3`) and exited 2; it now prints only the fault at `bad.json:3` and exits 5, as jq 1.7.1 does, since the fault stops the program before the reader gets to the missing file. A missing file is said by the read that reaches it (before a fault met after it), a fault names the file it was met in instead of `<stdin>` or the missing file, and a fault at the end of the text is raised at a missing last file (`gone.json:0`). No main loop reads the stream under `-n`, so no failure loses the array: `try input catch .` over `gone.json defer.json` reads `[1]` first, with the EOF fault after it. Over 7,860 runs (`--seq -c -s -n` x 15 programs x lists of two or three files, with missing files, a directory and an empty file among them), 3,914 differed from jq 1.7.1 before and none do now.
