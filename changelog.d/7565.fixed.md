- **`succinctly jq` finishes `map(f)` before a following `map(g)` starts** (#7565). The lazy `map` chain ran `map(f) | map(g)` element by element, so `g`'s error, `debug` line or `input` came before `f` had run on a later element: `[1,"x"] | try (map(if . == "x" then error("first") else . end) | map(error("second"))) catch .` answered `"second"` where jq 1.7.1 and 1.8.2 answer `"first"`. A `map(g)` now joins the chain only when `g`, or every stage already on it, can neither raise nor have an effect; otherwise the chain is drained first, its cursors kept as cursors.
