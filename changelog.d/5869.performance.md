- **jq: `..` and `recurse` through the library `eval` entry are linear in nesting depth** (#5869).
  Listing a container's elements checks the text after its last element, and for a last element
  that is itself a container that check counted the closers from the nest's innermost leaf every
  time, so `..` over a linear nest `[[[...1...]]]` cost the sum of the depths. The closers a check
  has read are now kept on the index, so each container on the same run of closers is answered
  from the one asked before it. `last(..)` over 80,000 levels takes 0.05 s instead of 1.4 s, and
  `[..] | length` 0.04 s instead of 1.6 s (Apple M5 Max, release); 20,000 to 320,000 levels, walked in document order or from the innermost level out, now
  take 0.009 s to 0.21 s, where each doubling used to cost 4x. The CLI refuses a document past 256
  levels at parse time and so never reached this; library callers did, and the 100,000-level
  library test took 200-256 s of every `cargo test` CI leg and now takes under a second.
