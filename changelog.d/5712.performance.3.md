- **jq and yq: an `if`, an array, an object, an arithmetic or a `//` built from a string's `length` is answered from the string** (#5712).
  `if length > 5 then 1 else 2 end`, `[length]`, `{a: length}`, `length + 1`, `(length > 3) // 7` and what nests in them (a literal, or another such answer) over an owned string wrote the string out as JSON text and indexed it again, once per crossing; the string door of #5712's earlier steps answered a lone `length`, a comparison, `try` and the prefix tests but stopped at these. It now answers them, in both modes with that mode's `length` (codepoints in jq, bytes in yq), and a shape that raises (`length / 0`), fans out, computes a key or reads the input back (`if length > 3 then . else 0 end`) keeps the bridge and its error.
  On an AMD Ryzen 9 7950X (terminus, jq mode, min of 15 interleaved runs, output identical on all 18 rows), over a computed string of 1 / 8 / 32 MB of text, each of the five shapes went from 36 / 279 / 1100 ms to 28 / 209 / 821 ms (-23% / -25% / -25%): one crossing less. A lone `length` after the same stage, which this does not touch, read +3.1% / +0.8% / +1.6% at identical instruction counts (1,954,880,268 against 1,954,880,565 at 8 MB), code placement; the base binary against itself read within +-0.2%.
  Measured in jq mode on x86_64 only; yq mode takes the same door (its answers are pinned against the bridge) and ARM64 was not measured.
