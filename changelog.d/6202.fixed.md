- **yq: `pivot` of an alias row raises, as yq does, and every `pivot` refusal is in yq's words** (#6202). `.l | pivot` over `[*row, [c]]` transposed the anchor's value (`[[a, c], [b, null]]`) where yq raises `sequence contains elements of  and !!seq types` (an alias node has no tag), and over `[*row, *row]` `can only pivot elements of !!seq or !!map types, received `. The rows are now compared by tag as yq does, on the document route and on a computed array alike, so `[1, 2.5]`, `[[a], 1]` and `[!foo [a], [b]]` give yq's `sequence contains elements of ... types`, scalar rows `can only pivot elements of !!seq or !!map types, received !!str`, a non-array `cannot pivot node of type !!int`, and an empty array (which yq refuses and `pivot` used to answer `[]`) the same `received ` error. Collection rows pivot as before. An array the filter builds (`[.l[]] | pivot`) still resolves its aliases, and a row with a `<<` merge key is still merged first (both recorded in `docs/compliance/yq/limitations.md`).
