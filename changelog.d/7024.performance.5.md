- **jq: a plain filter over more than 32 regular files reads them a window at a time too** (#7024). `jq -c . logs/*.json` over a list of more than 32 files read every file whole, since the several-files route held each file open for the second read that words a fault and capped the list to keep the descriptor table under 64 slots. Such a list is now judged a file at a time and closed, and each file is opened again as the run reaches it, as jq opens it. A run over hundreds of files holds one of them open at a time, as jq does, and its peak memory stays flat: `-c .` over 100 MiB of NDJSON in 64 or 256 files peaks at 9.6 to 10.6 MiB against 109 to 110 MiB before on x86_64 and at 6.4 to 6.8 MiB against 107 on aarch64, flat from 10 MiB, and reads 7.6% to 8.5% faster on x86_64 and 5.0% on aarch64 (`select` 2.1% to 3.0%, against an A/A control within 1.4% at 100 MiB). A path removed or replaced after the run starts is read as jq reads it when it gets there: a file that will not open is reported in jq's words once the reader is past it, and the run ends after the next value with exit 2.
