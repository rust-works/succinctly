- **jq: a `foreach` UPDATE `try` comma with a sibling that navigates without a pipe no longer skips the write** (#3932).
  `jq '(foreach .x as $w (0; try (($w|.a), .b); .)) = 9'` on `{"a":[{"b":1}],"x":{"a":[{"b":1}],"b":2}}` is `{"a":[{"b":1}],"x":{"a":9,"b":2}}` in jq;
  this was the document unchanged at exit 0, and `del(...)` and `path(...)` through it dropped the write and the path the same way.
  A comma that held a plain navigation (`.b`, `.a?`, `first(.a)`, `.[]?`) made the fold withhold jq's register from the whole body, so the pipe sibling's `$w`
  could not re-establish it, the `try` swallowed that refusal and nothing was yielded. A plain navigation resolves against the accumulator and raises where jq raises, so
  the `try` catches it as jq's own does; it no longer withholds the register. The read follows `first`, `last`, `limit`, `nth`, a nested comma and a `//` down to the navigation. A sibling the register analysis cannot read (`now`, `input_line_number`, a computed key) still withholds it, so those keep refusing loudly where jq answers (#3960), and a `select(f)` sibling still skips the write silently (#3974). Two `foreach` comma rows that refused (`(try ..), 5` and `5, (try ..)` as an UPDATE) now answer as jq does. jq mode only.
