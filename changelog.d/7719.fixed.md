- **jq: a `break` caught by `try` is jq's `{"__jq":N}`, a label stops on an equal error, and a `break` stops at the label it is bound to** (#7719, #7724). `label $f | try (1, break $f) catch error` printed `1` and then failed with `(not a string): null` (exit 5); it now prints `1` and exits 0, as jq does, and `catch .`/`catch type` see `{"__jq":0}`/`"object"` instead of `null`. A hand-made `error({"__jq":0})` is the break of the first label (`[limit(3; 1, error({"__jq":0}), 2)]` is `[1]`), the number counts every label entered, including the ones jq's own `first`, `limit`, `isempty` and `|=` enter, and keeps counting across inputs; and a `break` passed through a same-named label (`def f(g): label $out | g; [label $out | f(break $out), 2]`) stops at its own label, `[]` where succinctly printed `[2]`. A program that can observe any of this runs on the path-mode interpreter; every other program keeps the shipped route unchanged. A sentinel built from data or a computed key, without `__jq` spelled in the program, is still not honoured (recorded in the jq limitations page).
