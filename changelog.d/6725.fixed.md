- **jq: `--seq --stream` and `--seq --stream-errors` reach a stream's warnings and a file's open failure as jq's main loop does** (#6725). Without `-n` and `-s`, these said every warning and every file that did not open before the program ran, so a program that halted or raised an error on an early value came after them, and exited 2 where jq 1.7.1 exits 0 or 5 because it never reaches the failure (`jq -c --seq --stream-errors halt arr missing` now exits 0 and says nothing). The stream's faults now wait for the main loop to pop them, as `--seq` already did for the record reader (#6147), and a failure is said when a read reaches the file. A file that did not open in the middle of the list is an empty read, so the closing event a file ending in `[1]` holds back is read at it (`error (at gone:0)`), and a directory whose read delivers that event fails the run with exit status 2 and no message. Over 1,260 file lists of up to three files per flag set, the 642 (`--seq --stream`) and 682 (`--seq --stream-errors`) rows of `halt`, `halt_error` and `error("x")` that differed from jq now match, as do 143 and 87 rows of the programs that read `input`, with and without `-n`; no row that matched changed.
