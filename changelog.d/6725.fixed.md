- **jq: `--seq --stream` and `--seq --stream-errors` reach a stream's warnings and a file's open failure as the main loop does** (#6725). Without `-n` and `-s`, these two said every warning and every file that did not open before the program had run, so a program that halted or raised an error on an early value (`halt`, `halt_error`, `error("x")`) came after them, and exited 2 where jq 1.7.1 exits 0 or 5 because the failure is never reached (`jq -c --seq --stream-errors halt arr miss` exits 0 and says nothing). They now take the `--seq` record reader's route (#6147): the reader's faults wait in the input queue for the main loop to pop, and a failure is said when a read reaches the file. A file that did not open in the middle of the list is an empty source of its own there (#6646), so the closing event a file ending in `[1]` holds back is read at it (`error (at gone:0)`), and a directory whose read delivers that event counts as failed, with the exit status 2, without a word. Over 1,260 file lists of up to three files for each of the two flag sets with `halt`, `halt_error` and `error("x")`, the 642 and 682 rows that differed from jq 1.7.1 now match; 143 and 87 rows of the general programs (`.`, `input`, `inputs`, `input_filename`), with and without `-n`, over the same fixtures also now match, and none that matched changed.
