- **`succinctly jq` keeps reading options after a positional word that starts with `-`** (#7494). jq reads `-1`, `-.a`, `-(1)` and `-[1]` as positional words wherever they sit and goes on reading options after them, so `jq -1 -n` prints `-1` and `jq . a.json -1 -c` prints compactly. `succinctly jq` made every later word a file (`Could not open file -n`, and `--arg` and `--` read as files too). And after `--args --`, an option-shaped word is the program in jq (`jq -n --args -- -c .` is the compile error `c/0 is not defined`), where `succinctly jq` skipped it and ran `.`. Over 5,000 random orderings of options, `--args`/`--jsonargs`, `--` and positional words, the rows where `succinctly jq` differed from both jq 1.7.1 and 1.8.2 in stdout or exit status fell from 149 to 91, and every one left gives the malformed file `bad.json` (`{"a":1,}`) to a program that does not read its input: jq still reports the parse error and exits 5, and `succinctly jq` does not, which is input validation, not the command line.
