- **yq: a scalar that starts on the `---` line runs on into the next line, as yq reads it** (#6276). yq's header slurp pushes the text after a leading `--- ` back without the marker line's own line break, so `--- x` / `y` is `"xy"` where `succinctly yq` read `"x y"`, and `--- x` / `y: 1` is `{"xy": 1}` where it was a parse error. The same lost break applies to a flow collection (`--- [a, x` / `y]` is `["a","xy"]`), a quoted scalar, a comment (`--- # c` / `x` / `y` is the comment `# cx` and the document `"y"`) and a following marker (`--- x` / `--- y` is the one scalar `x--- y`), and `a: 1` / `b: 2` after `--- ` is refused as yq refuses it. A marker on a line of its own, a marker after the first content line, a lone CR break and `load()` are unchanged, and under `--eval-all` only the first file's marker line is glued, as in yq.
