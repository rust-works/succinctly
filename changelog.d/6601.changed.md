- **jq: `--input-dsv` reads its files as one stream of records, so a quoted field that runs past the end of a file continues in the next** (#6601). With `span1.csv` holding `a,"b` and `span2.csv` holding `c",d`, `succinctly jq -c --input-dsv , . span1.csv span2.csv` printed `["a","\"b\n"]` and `["c\",d\n"]` where the two files joined (`span.csv`) give the one row `["a","b\nc","d"]`; it now prints that row, from every route (a plain run, `-s`, and a program that reads `input`), and `input_filename` names `span2.csv`, the file the record ends in, as it does for `-R`'s line that runs into the next file. A record still open at the end of the last file is read as before. jq has no DSV input, so this follows the way jq (and `-R`) read their files, as one byte stream. A run over one file, or over files that each end on a record, pays a count of each earlier file's quote bytes and no copy; only a spanning record is moved, from the end of one file to the front of the next.
