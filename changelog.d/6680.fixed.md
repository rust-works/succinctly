- **jq: `--stream` stops at the failed open that follows a held-back closing event** (#6680). When the last file before a missing file or a directory ends in a container whose closer follows a scalar and has no byte after it (`[1,2]`, `{"a":1}`), jq's parser holds the closer's event until the next read, which is the open of the failed file, and its main loop ends there: a failure after it is not reported and a file after it is not read (`jq -c -n --stream '[inputs]' arr.json missing.json dir` says nothing of `dir`; `jq -c --stream . arr.json dir other.json` never reads `other.json`). The chunked `--stream` reader, and `-n --stream-errors`, treated a failed file in the middle of the list as no read at all, put the closer in the file it came from, read on and reported the directory. A failed file in the middle is now an empty source of its own, as a directory already was, and a directory's failure is placed at its own read. Over a sweep of 22,128 file lists of up to three files and 29,520 of up to four (6 programs, with and without `-n`), the 308 and 706 rows that differed from jq 1.7.1 now match, and none that matched changed. `--stream-errors` without `-n`, which reads through the in-memory route, is not changed (#6646).
