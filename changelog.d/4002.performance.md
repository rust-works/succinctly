- **jq: `has($k)` on a wide document object is a hash probe after the second lookup** (#4002). `has` walked the object's members on
  every call (`contains_checked`), so a loop of lookups into one wide object was quadratic; a walk of 64+ members now
  registers the object and the second lookup builds, then every lookup probes, the per-object key index #3913 added for
  `.big[$k]`. An object whose walk could raise depending on the name (a key that will not decode, a missing or doubled
  `,`/`:`) keeps the walk and gets no speedup, so output and errors are unchanged. `[.ks[] as $k | .big | has($k)] | length` over 3,000 keys, interleaved A/B (Apple M4 Pro, release):
  1,000-key object 62.8 -> 5.6 ms (11x), 10,000 keys 596 -> 7.1 ms (84x), 100,000 keys 5.85 s -> 17 ms (338x); objects of
  8-100 members are unchanged.
