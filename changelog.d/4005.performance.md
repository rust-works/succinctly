- **jq: a `reduce`/`foreach` assignment whose right side compares a container loop variable with `==`/`!=` no longer copies its accumulator on every step** (#4005, a #3944 follow-up). `reduce .[] as $r ({}; .[$r.name] = ($r.a == $r.b))` was quadratic: an explicit equality on `$r` marks it as a storage-sharing marker so jq's `jv_equal` identity short-circuit holds (#3896), and a marker made the in-place assignment step decline. The step now reads a marker by value, declining only when its answer is a container, so none of the binding's identity reaches the accumulator. Apple M5 Max, release build, interleaved A/B (box under load, three reps, minimum): 2,500 / 5,000 / 10,000 / 15,000 records `($r == $r)` 308 / 1,255 / 4,849 / 8,693 ms to 12 / 20 / 31 / 33 ms, `($r.a == $r.b)` 337 / 1,435 / 4,598 / 9,754 ms to 13 / 21 / 25 / 30 ms; the unmarked control `($r.score > 50)` is unchanged (17 / 30 / 40 / 49 ms against 17 / 30 / 41 / 51 ms). Output identical to `jq` 1.7.1 on every row, NaN-bearing containers included (`reduce ([nan]) as $a ({}; .x = ($a == $a))` stays `{"x":true}`).
