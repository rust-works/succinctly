- **yq: a `{...}` with a `select` or a `.[]` in a pair no longer pays for the fold on every record** (#4240). #4193 sent every construction with an operand that might be empty through yq's fold up front, +9% (two entries) to +16% (five) on a 7 MB document. An empty operand always empties the cross product, so the cross product is now built first and the fold runs only for a record whose construction came out empty: the same shapes read -1% to +3% against the old binary on a 7-14 MB `users` document (M4 Pro, interleaved, control range -2% to +2%). A construction that is empty for every record is built twice (+69% on that shape). Side effects in such an operand are not run twice.
