- **jq: a label value that reaches the program through an argument or the environment is the one jq's labels stop on** (#7880). jq's `break` raises `{"__jq":N}` and a label stops on any error equal to its own value (#7719), wherever the value came from. `--argjson v '{"__jq":0}'` with `[limit(3; 1, error($v), 2)]` or `[isempty(error($v))]` raised the object (exit 5) where jq 1.7.1 and 1.8.2 answer `[1]` and `[]`, while `[label $f | 1, error($v), 2]` answered as jq does: the value counted only where it happened to be substituted into the program as a literal, so a `--slurpfile` value, a value read through `$ARGS` (`--args`, `--jsonargs`, `$ARGS.named`) and a `$ENV`/`env` value did not. A program that holds an `error` now treats `__jq` in any of them as it treats `__jq` written in the program. A value read from the input, or a key the program computes, is still the recorded difference.
