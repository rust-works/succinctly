- **yaml: a `-` between two open blocks and an explicit key's own-line value are rejected as yq rejects them** (#5086). `- k: a` / ` - z` read as `[{"k":"a"},"z"]`, `a:` / `  - x` / ` - y` as `{"a":["x","y"]}` and `- - a` / ` - b` as `[["a"]]` (the `b` gone), where yq stops with `did not find expected '-' indicator` (`did not find expected key` under a key); `? a` / `  b: 1` and `?` / `  a` / `  z: 1` read as `{"a b":1}` and `{"a z":1}`, where yq stops with `mapping values are not allowed in this context`. The out-dented `-` of #325/#485 and the compact-mapping gap of #900 were tolerances for yq 4.x releases that read them; v4.53.3 refuses them, so they are an `inconsistent indentation` error now, and a `-` at a key's own indent (`- k:` / `  - 1`) or a sequence at its own indent is unchanged. A sequence-valued explicit key records the `-`'s own column (`?` / ` - a` / ` - b` was held together only by the tolerance), and the `:` of an explicit value closes every frame deeper than its `?`. Checked against 11,718 YAML files on disk (none changed) and 7,400 randomized dash/key/`?` documents against yq v4.53.3: about 215 more documents match yq, none that matched stopped matching. The YAML Test Suite case `ZVH3` (invalid, must fail) leaves the known-failures list.
