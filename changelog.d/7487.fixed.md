- **jq: an environment entry with an empty name is listed in `$ENV` and `env`, as jq lists it** (#7487). jq splits each `environ` string at its first `=`, so the entry `=v` (made by a raw `execve`, or `Command::env("", "v")`) is `"": "v"` and `=X=1` is `"": "X=1"`; jq 1.7.1 and 1.8.2 agree. `succinctly jq` read the environment through `std::env::vars_os`, which skips `=v` and reads `=X=1` as `X`, so `{"":"v","Y":"1"}` printed `{"Y":"1"}`. Unix now reads the `environ` strings themselves (the read `std` makes, without its lock: a thread that calls `set_var` while another builds `$ENV` is as unsound as for C's `getenv`; the CLI sets nothing).
