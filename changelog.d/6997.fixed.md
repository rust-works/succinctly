- **`succinctly yq`'s `@base64d` answers a line break inside the text as yq does** (#6997). It now reads the text through the same port of yq's base64 decoder as `-p base64` (#6925), over Go's stream decoder: a `\n` or `\r` inside the text is dropped after the text was padded by its raw length, so `"aGVs\nbG8=" | @base64d` is `unexpected EOF`, where it was `illegal base64 data at input byte 4`. An error's offset in a text longer than 680 bytes now counts from the decoder's chunk, as yq's does. It agrees with yq v4.53.3 on 800 random texts.
