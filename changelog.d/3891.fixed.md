- **jq: a `catch` handler that navigates the node the `try` stood on is a path, not a silently skipped write** (#3891). `del(try error catch (.a)?)` and `(try error catch (.a)?) = 9` left the document unchanged at exit 0, and `path(try error catch (.a)?)` printed nothing, where jq 1.7.1 deletes, writes and answers `["a"]`. `error` and `error(.)` raise the very node the `try` entered on, so the handler is now seeded as that node whenever it shares the register's storage (jq's `jv_identical`), and `.a`, `.a?`, `(.a | .b)?`, `(.a // 1)?` and `first(.a)?` reach it. A payload that is merely equal (`error("x")`, `error({"a":1})`) is still a fresh value and the navigation still prunes. Measured over 119,907 handler rows of `scripts/jq-path-register-sweep.py` against jq 1.7.1: rows where succinctly accepted what jq refuses (or wrote differently) went from 2,394 to 0, other wrong answers from 931 to 1, and refusals of what jq answers from 2,426 to 1,247 -- but 187 rows that matched before now refuse, a compound handler (`(try .a catch 0)`, `(.a // 1)?`) next to an `and`/`or`/`-` navigation, the same failure `main` already has for a `null`/`true`/`false` input (#3967).
