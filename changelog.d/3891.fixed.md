- **jq: a `catch` handler that navigates the node the `try` stood on is a path, not a silently skipped write** (#3891). `del(try error catch (.a)?)` and `(try error catch (.a)?) = 9` left the document unchanged at exit 0, and `path(try error catch (.a)?)` printed nothing, where jq 1.7.1 deletes, writes and answers `["a"]`. `error` and `error(.)` (and `. | error`) raise the very node the `try` entered on, so for such a body the handler is now seeded as that node whenever the payload shares the register's storage (jq's `jv_identical`), and `.a`, `.a?`, `(.a | .b)?`, `(.a // 1)?`, `first(.a)?` and `.[0]` reach it, on an object or an array register, at the root or below it. A payload built by value (`error([.][0])`, `error({"a":.}|.a)`) shares that storage here but jq raises a path error inside `error`'s argument, so it still refuses, as does a payload that is merely equal (`error("x")`, `error({"a":1})`, which prunes). A string or computed-number register has no storage to compare and still refuses (`"abc" | try error catch .[1:]` is a path in jq). The final measurement over the handler operands of `scripts/jq-path-register-sweep.py` is in the PR; a compound handler (`(try .a catch 0)`, `(.a // 1)?`) next to an `and`/`or`/`-` navigation still refuses where jq answers, as `main` already did for a `null`/`true`/`false` input (#3967).
