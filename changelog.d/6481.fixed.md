- **jq: a slurped `--stream` or `--seq` input that ends in a fault prints no array when a file did not open** (#6481). `jq -c -s --stream . t1.json missing` with `t1.json` holding `[1,` printed `[[[0],1]]` and jq 1.7.1 prints nothing, with the same two stderr lines and exit 2; `-s --seq` printed `[]` (or the records it had read) and `--seq --stream -s` the events, where jq prints nothing. jq's reader moves on to the file that did not open in the call that consumes the last byte, so the fault is that call's result, and its main loop reads no further once a file has failed, so the array is never read. A clean stream, or a file that did not open ahead of a stream with no fault, still prints its array. Pinned over 21 rows against jq 1.7.1 in `tests/jq_cli/i6481.rs`.
