- **yq: a string inside `\(...)`, a number like `5.` and a space after a `.` are refused as yq's lexer refuses them** (#5452).
  Real yq (v4.53.3) ends an interpolation slot at its first `"` (`"\("x")"` is `lexer: invalid input text`), has no number
  token for `5.` (`bad expression`) and ends the identity at whitespace (`. a`, `. "a"`, `.a . b` are errors), yet
  `succinctly yq` accepted all three. A string literal in a slot and a trailing-dot number now need `--jq-extensions`,
  like the rest of the jq-only surface; a name, quote or bracket after a gap is an error either way, as in jq (#5447).
  `. style = "flow"`, `. as $x`, `. and`, `.a [0]` and `1.5` are unchanged, and so is `succinctly jq`.
