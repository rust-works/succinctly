- **yq: a regex pattern is read the way Go's `regexp` reads it** (#5388). yq's patterns are RE2's, and `succinctly yq` handed them to the Rust `regex` crate unread, so it accepted programs yq rejects (`a++`, `(?x)a`, `[a--b]`, `\p{Script=Greek}`, `[[:foo:]]`, `a{1001}`), refused ones yq runs (`\Qa.b\E`, `\0`, `\12`, `a{,3}`, `\p{^L}`), took `\<` and `\>` for word boundaries where Go reads a `<` and a `>`, and let `$` match before a final newline (`"a\n" | test("a$")` is `false` in yq). A translator (`src/jq/go_regex.rs`) now reads the pattern as Go's parser does and writes the crate's equivalent, with every literal escaped, and refuses what Go refuses with Go's own wording (`error parsing regexp: invalid nested repetition operator: `++``, `missing closing ]`, `invalid escape sequence: `\Z``). Checked against yq v4.53.3 on 115 pinned rows and 3,000 random patterns with no difference. jq mode is unchanged. Still different: a `\p{Name}` Go's tables lack but the crate accepts (`\p{IsL}`), a group name that starts with a digit or repeats an earlier one, and a surrogate escape (`\x{D800}`). A follow-up closes what that left: a flag set and cleared in one group (`(?i-i)a`, `(?s-s)a`) was refused as a duplicate flag where Go reads it, a repeated or digit-led group name was refused where Go accepts it, `\p{Cs}` was refused, and `\p{..}` names were the crate's rather than Go's table (`\p{Alphabetic}` and `\p{Old_Italic}` were accepted, `\p{CS}` was refused; yq has the reverse); the error for `\pX` is Go's. Checked against Go's `regexp` over 70,000 generated patterns (0 differences in acceptance, matches and error text, from 567, 0 and 405) and 1,552 `\p{..}` spellings against yq v4.53.3 (from 663 wrong).
