- **yq: through an unexploded alias, `length` is `0`, a slice is `[]` and `keys` is refused** (#7111). yq reads an alias node's own kind and content, which is empty, for those three, where indexing, iteration and a field read through it to the anchored value; `succinctly yq` read the anchored value for all of them (`c: *x` over `x: &x [5, 6]` had `.c | length` 2, `.c[0:1]` `[5]` and `.c | keys` `[0,1]`). The rule holds where the value is read from the document, including through `[.c] | .[0]`, a variable and `select`; a copy of the alias that the filter makes (the right side of an assignment, `to_entries`, `map_values`) and every other operator on an alias node still read the anchored value (limitations.md). Pinned against 62 rows and 7 refusals from yq v4.53.3 in `tests/yq_cli/i7111.rs`. A filter that took the `length` of an alias to read its target (`select(.name | length > 0)` with `name: *n`) now answers as yq does, `0`.
