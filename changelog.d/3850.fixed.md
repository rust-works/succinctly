- **jq: `path(..)` and `path(recurse)` answer on documents nested 256-383 levels deep** (#3850, a #3429 residual). `[path(..)] | length` on a 300-deep document raised `nesting depth exceeds limit of 256` where `[..]`, `[paths]` and `[.. | path]` answered 301, 300 and 301: `path(..)` materialized the whole document first and inherited the materializer's lower ceiling. A bare `path(..)`, `path(recurse)` or `path(recurse(.[]?))` now walks with cursors and an explicit stack, streaming one path at a time, so it takes the path walkers' 384 (a 383-level document answers; 384 and deeper refuse with `nesting depth exceeds limit of 384`), fits a default 2 MiB debug thread, and no longer builds the document it only names positions in: on a 10 MB document in a debug build `first(path(..))` fell from 0.83 s / 124 MB to 0.20 s / 26 MB and `[path(..)] | length` from 2.7 s / 391 MB to 1.9 s / 331 MB. A descent inside a larger path expression (`path(.. | .a?)`, `path(.a | ..)`), `paths(f)`, `path(recurse(f; c))`, `path(getpath(p))`, `walk`, `del(..)` and `tostream` still stop at 256. A repeated mapping key still counts once in yq mode.
