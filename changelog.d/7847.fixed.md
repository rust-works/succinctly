- **jq, yq: on macOS a write to a closed pipe always ends the run with SIGPIPE** (#7847). With SIGPIPE at its default and standard error a pipe whose reader had gone, `succinctly jq -n '"x"|debug'` now and then exited 0 and `jq -n 'error("x")'` exited 5 (`succinctly yq -n 'error("x")'` exited 1), where jq 1.7.1, jq 1.8.2 and yq v4.53.3 always die of SIGPIPE. macOS raises a write's SIGPIPE on the whole process and hands it to the first thread that does not block it, which was the main thread waiting for the evaluation thread; the evaluation thread that wrote could end the process with its own status before the main thread acted on the signal. The main thread now blocks SIGPIPE while the evaluation thread runs, so the thread that writes takes the signal and the write ends the run, on standard output and standard error alike. Linux, which raises SIGPIPE on the writing thread, was not affected. A process started with SIGPIPE ignored (#7732) or blocked keeps it so, as jq does.
