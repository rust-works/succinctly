- **jq: a junk byte, a form feed or a glued token between a sibling and its `,` is refused instead of skipped** (#5650). `[1@,2]` printed `[1,2]`, `[1null,2]` printed `[1,2]` and `[1,2]<FF>` (a form feed before the closing bracket, or around the root: `<FF>[1]`, `[1]<FF>`, `[1,2]<FF>[3]`) were read as whitespace, because the index judged a gap by the byte it stopped on and took `is_ascii_whitespace` (which counts a form feed) for JSON's whitespace. jq 1.7.1 stops with `Invalid numeric literal` on each, and so does `succinctly jq` now, with the same message and exit status. A sibling must end on a byte a value can end on, a bare token that starts like a number must be one number (`1null`, `1true`, `1e` are refused; `1e5`, `1.`, `.5`, `+1`, `nan` and `-Infinity` still read), and the splitter and the closing-bracket gap use space, tab, LF and CR only. `succinctly yq` is unchanged. A bare token glued to a number that ends in a digit (`0x1`, `1_000`) is not checked, so the pretty printer pays one byte test per element. A byte sweep of the `stdin` route (every byte x 14 templates against jq 1.7.1) leaves four differences: a NUL between documents, which jq ignores, and `[[1]},2]`. Still open, filed apart (#5654): a junk byte after a container that is a container's last child (`[[1]@]`), a NUL inside a document (the message differs), `--slurpfile` and `--argjson` (a form feed around the value), and programs that read a document lazily (`map(.)`, `first(.[])`).
