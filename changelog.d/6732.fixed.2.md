- **`succinctly jq --stream-errors` counts the directory behind a closing event the program's own `input` reads, and stops where a first event spanning two files is whole** (#6732). A container that ends its file with no newline (`{"a":1}`, `[1]`) holds its closing event back until the next read, which is the open of the directory behind it: `jq -c --stream-errors 'input,halt_error' obj.json dir gone.json` read it and exited 2 with nothing said, where succinctly exited 5 with the halt's status, and `jq -c --stream-errors input arr.json dir p.json gone.json` printed `Is a directory` and `Could not open file gone.json` where jq prints neither (the bare number in `p.json` had sent the run up front). A first event that two files make (`1` in `p.json`, then `1\n` in `pn.json`) is whole in the second, so `jq -c --stream-errors halt_error p.json pn.json gone.json` no longer says `Could not open file gone.json` and exits 5 with the halt's status. A 12,000-row differential against jq 1.7.1 (three seeds, 11 programs, lists of up to four files with a directory and missing files, `-n` rows alongside) left 107 rows fixed and none changed for the worse; 21 rows are still apart, all with a token left open across files (`[`, `[1,`).
