- **yq: bare `env`, `@text` and `@html` need `--jq-extensions`, as yq's lexer rejects them** (#5444). Real yq has
  `env(NAME)` but no bare `env`, and no `@text` or `@html` format (`lexer: invalid input text`, v4.53.3), yet
  `succinctly yq` parsed all three without the flag, so `env` printed the whole environment. They now fail with the
  same `is not part of yq's syntax; pass --jq-extensions` error as `limit` or `paths`. `env(NAME)`, `strenv(NAME)`
  and yq's own formats (`@json`, `@csv`, `@tsv`, `@uri`, `@urid`, `@sh`, `@base64`, `@base64d`, `@yaml`, `@props`)
  are unchanged, as is `succinctly jq`. A yq script that used one adds the flag.
