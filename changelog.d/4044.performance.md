- **jq: an object holding document nodes no longer decodes them** (#4044, #3856 Phase 2). `{a: .users}` decoded every member at construction, so a program that only moved or counted a subtree paid for a full decode. In jq mode an object over literal, distinct keys whose values each name one node (`.`, `.a`, `.[0]`, a pipe of those) now holds its container nodes as cursors, as `[.users]` (#3919) and an `as` bind (#4021) already did, and reads none of them: `.k`, `length`, `keys` and `keys_unsorted` answer without reading a member's contents, and printing walks each node once from the source. 7 MB `users` document, release build, instructions retired / peak RSS (min of 3) on an Apple M5 Max: `{a: .users}` 2,460 M / 81 MB -> 490 M / 25 MB (the cost of `[.users]`), `{a: .users} | .a | length` 1,701 M / 81 MB -> 277 M / 18 MB, `{meta: .users[0], data: .users}` 2,479 M -> 522 M, `.users[] | {u: .}` 2,885 M -> 1,028 M, `.users[] | {u: ., n: .name}` 3,608 M -> 1,724 M. Per-record small objects are unchanged or cheaper: `.users[] | {name, age}` -10%, `[.users[] | {name, age}]` -11%, `.users | map({id}) | length` -11%, `.users | map({u: .}) | length` -2%, `[.users[] | {u: .}]` -2%. On a 7950X (wall-clock, min of 5, interleaved): `{a: .users}` 166 -> 30 ms, `{a: .users} | .a | length` 140 -> 21 ms, `.users[] | {u: .}` 134 -> 45 ms, every per-record row within -6% / +2%. Output is identical to the previous build across 1,008 filter/tail/flag combinations. Visible consequences, both the array's: an object holding a node that fails to decode answers `length`, `keys` and a well-formed member and raises when printed or read (`{x: .b} | length` over `tru` is `1`, where it raised), and `--preserve-input` keeps a repeated key inside a node the object holds (`{a: .dup}` prints `{"a":{"k":1,"k":2}}`, as `[.dup]` does). yq mode and an object with a repeated, computed or fan-out member are unchanged (`docs/compliance/jq/limitations.md`).
