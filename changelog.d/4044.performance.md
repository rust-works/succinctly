- **jq: an object holding document nodes no longer decodes them** (#4044, #3856 Phase 2). `{a: .users}` decoded every member at construction, so a program that only moved or counted a subtree paid for a full decode. In jq mode an object over literal, distinct keys whose values each name one node (`.`, `.a`, `.[0]`, a pipe of those) now holds its container nodes (and a scalar that fails to decode) as cursors, as `[.users]` (#3919) and an `as` bind (#4021) already did, and reads none of them: `.k`, a chain starting at one (`.a.x`, `.a[0]`), `length`, `keys` and `keys_unsorted` answer without reading a member's contents, and printing walks each node once from the source; any other stage after it takes the owned object through the arm that has always handled one. Apple M5 Max, release build, instructions retired / peak RSS (min of 3), `users` documents of 0.2 / 7 / 22 MB: `{a: .users}` 121 M / 2,460 M / 7,430 M -> 54 M / 493 M / 1,425 M and 11 / 81 / 219 MB -> 0 / 25 / 58 MB (the cost of `[.users]`); on the 7 MB document `{a: .users} | .a | length` 1,701 M -> 277 M, `{a: .users} | .a[0]` 1,700 M -> 277 M, `{meta: .users[0], data: .users}` 2,479 M -> 522 M, `.users[] | {u: .}` 2,881 M -> 947 M, `.users[] | {u: .} | .u.name` 2,636 M -> 938 M, `.users[] | {u: ., n: .name}` 3,608 M -> 1,724 M. Per-record small objects and the stages after one are unchanged or cheaper (`.users[] | {name, age}` -12%, `.users | map({id}) | length` -11%, `.users[] | {u: .} | .u.age > 30` -1%, `[.users[] | {u: .}]` -3%, `.users[] | {n: 1}` +0.9%). On a 7950X (wall-clock, min of 5, interleaved): `{a: .users}` 166 -> 30 ms, `{a: .users} | .a | length` 140 -> 21 ms, `.users[] | {u: .}` 134 -> 45 ms, per-record rows within -6% / +2%. Output is identical to the previous build across 1,008 filter/tail/flag combinations, and 130 filters against `/usr/bin/jq` 1.7.1 are pinned. Visible consequences (`docs/compliance/jq/limitations.md`): an object holding a node that fails to decode answers `length`, `keys` and a well-formed member and raises when printed or read (`{x: .b} | length` over `tru` is `1`, where it raised); `--preserve-input` keeps a repeated key inside a node the object holds (`{a: .dup}` prints `{"a":{"k":1,"k":2}}`, as `[.dup]` does); `{a: .} | .a | first(map(f) | .[])` (and `limit(1; ...)`, `| map(f) | .[0]`, `| map(f) | first`, `| nth(0; ...)`) yields the first element like the document's own spelling instead of raising on a later element, because `.a` is now a node, not an owned copy (an object with a literal member keeps the owned route and the old answer); and the library entries `eval_with_cursor*`/`eval_each_with_cursor*` return `GenericResult::LazyObject` where they returned `Owned(Object)` (`into_owned`/`collect_owned` report a node's decode failure as `Err`). yq mode, a repeated or computed key, a fan-out member and a construction held inside another are unchanged.
