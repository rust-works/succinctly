- **jq: `path(f)` for a lone `.` leaf over a scalar member (`. // .`, `first(.)`, `.a? // .`) allocates what `path(.)` does** (#4226). #4155 left these at 5 allocator calls per member against `path(.)`'s 3: the resolver built a one-element `Vec` of branches that it emptied into its sink on the next line, and allocated a fresh root path-prefix node on every call. The branch now goes straight to the sink, and under `std` the root is a handle on one per-thread node (`no_std` still allocates). The third term, the member's own copy (a boxed number literal), stays: a bare `Int` is not interchangeable with a number literal under jq's `jv_identical`, so skipping it needs a cursor route, not a cheaper copy. Allocator calls over 2,000 integer members (`examples/alloc_probe_3022`): `[.[] | path(. // .)]` and `path(first(.))` 10,024 to 6,024, `path(.a? // .)` 12,024 to 8,024; `path(.)` is unchanged at 6,024. Interleaved A/B over 250,000- and 1,000,000-integer arrays and a 150,000-member array of integers and `{"a":n}` objects, output identical on all 15 configurations: -10% to -14% on the integer rows and -5% to -7% on the mixed rows on an M4 Pro (medians), -6% to -12% and -1% to -5% on a Ryzen 9 7950X, with the unchanged `path(.)` rows inside the noise (same-binary control: M4 Pro +0.1% median, 7950X +0.5%). Split by term, the `Vec`-free emit alone reads -5.1% (M4 Pro) and -1.2% (7950X) across the `//` rows, and the shared root a further -4.4% and -3.5%. The time gap to `path(.)` does not close with the allocation gap (`. // .` over the integer array is still 1.5x `path(.)` on the 7950X and 1.6x on the M4 Pro), so what remains is the resolver's per-call machinery, not allocation.
