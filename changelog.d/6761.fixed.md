- **jq: `--seq --stream` and `--seq --stream-errors` stop at a directory given last that delivers a held-back closing event** (#6761). When the file before a last directory ends in a container whose closer waits for the next read (`[1]` with no record separator and no newline) and an unfinished record runs on into it, jq's reader reads the closer at the directory and its main loop ends there, so it never reaches the `Unfinished JSON term at EOF` fault. succinctly went on and said it (`--seq --stream`) or printed it as an event (`--seq --stream-errors`): `jq -c --seq --stream . trunc nors dir` now prints the three events, says nothing and exits 2, as jq 1.7.1 does. A directory in the middle of the list (#6646) and a missing file last already did.
