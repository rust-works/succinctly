- **jq: `--stream` builds the events it keeps from the document's index instead of from a converted value** (#5618).
  When the program reads the events with `inputs`, `-n` or `--slurp`, each input document was converted to a value and then taken apart into its `[path, leaf]` events; the events are now walked from the document's index, so only the leaves are converted and the document is never built or dropped.
  The events and their order are unchanged, and a document with a repeated key (compared after decoding) still goes through the converted value, which keeps the key's first position and last value as before.
  On a 7950X, `--stream -n '[inputs] | length'` over 0.7 / 7 / 74 MB of records went from 29.7 / 355.6 / 2822 ms to 26.1 / 278.1 / 2494 ms, the `reduce (inputs | select(length == 2)) as $e (0; . + 1)` form by 8% / 16% / 10% and `--stream -s 'length'` by 6% to 10%; retired instructions over 7 MB fell 17.6% (3.30G to 2.72G).
  Release builds, interleaved, min of 11, output identical on every configuration, against a control run within 1.5%. A plain `--stream .`, which walks each converted document one event at a time, is not changed (its instructions are equal to within 0.001%; its wall-clock read up to 2.5% slower, which is code placement), and neither are queries without `--stream`.
