- **jq: input files are one byte stream, so a value can span two files** (#4305). `succinctly jq -c . a.json b.json` with `a.json` = `1` and `b.json` = `2\n` printed `1` and `2` where jq 1.7.1 prints the one number `12`, and `{"a":` then `1}\n` was two `Invalid JSON text` errors where jq reads `{"a":1}`; the same held for a split string, `true`, `-5` and `1.5`, through `-s`, `input`/`inputs` and `input_filename` (the later file, where jq completes the value). A token still open where a file ends is now moved onto the front of the next file before anything parses, through an empty file between them. A file that ends on a whole value, or in whitespace, is untouched, and the last file keeps whatever it ends with. Recorded residual: `input_line_number` for a value with a newline inside the part that moved counts it in the later file (`{"a":\n` then `1}\n` is line 2, jq's is 1).
