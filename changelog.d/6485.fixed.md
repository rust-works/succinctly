- **jq: under `-s`, a file that does not open after a fault in the text is not reported, and the run exits 5** (#6485). `jq -c -s . bad.json missing` with `bad.json` holding `[1,}` printed `jq: error: Could not open file missing: ...` before the parse error and exited 2; jq 1.7.1 prints the parse error alone and exits 5, because its parser stops the main loop at the fault before its reader opens the next file. The same holds for `-s --stream`. jq reports a file when its reader reaches it, so a failure before the file the fault is in is still reported first, and so is one after a fault at the end of the text (#6476). The `--stream` routes that read a file a chunk at a time (without `-s`) still report every failure up front. Pinned over 22 rows against jq 1.7.1 in `tests/jq_cli/i6485.rs`.
