- **jq: an input read whole that there is no room for is jq's `cannot allocate memory`, not an empty input** (#7576). Under a `ulimit -v` smaller than the file, `-s`, `-R -s`, `--slurpfile`, `--rawfile`, `-f` and standard input read whole reported the failed allocation as a file that would not open (`jq: error: Could not open file f: out of memory`, exit 2) and ran on without it, so `-s length` printed `0` and `-c -s .` printed `[]`; on standard input the read stopped where the room ran out (`-R -s length` printed the length it got) or a later copy aborted with `memory allocation of ... failed`. Each now prints `jq: error: cannot allocate memory` and aborts (exit 134), as jq 1.7.1 does on every one of those routes (x86_64 Linux, 300 MiB NDJSON under `ulimit -v 400000`). `--seq` over a stream with no RS, which jq streams, gets the same answer and is recorded in the limitations page.
