- **jq: a number with bytes glued on is refused wherever it is read** (#5654). `[0x1,2]`, `[12x3,2]`, `[0.0x1]` and `{"a":0x1}` read as `0`, `12` and `0.0` because the three JSON number scanners stopped at the first byte outside `[0-9.eE+-]` and dropped the rest. jq 1.7.1 reads the whole run up to the next token boundary as one token and refuses it (`Invalid numeric literal`); `succinctly jq` does now on every route that reads the element (`.`, `.[0]`, `.a`, `first(.[])`, `map(.)`, `add`, `tostring`), with jq's message and column. The check lives in the scanners, not on the comma gap, so routes that never read a number (`length` over a number array) pay nothing; such a route still answers for a digit-ending glued token that is not the last element (`[0x1,2] | length`), as `[1.5.5,2] | length` does. `succinctly yq` is unchanged.
