- **yq: the update-or-create idiom `(.a // (.a = 0)) += 1` writes as yq does** (#7068).
  On a document with no `a` it now creates `a: 1`, where the document was left unchanged: yq evaluates the target in the document the update writes to, so the write in the last operand of the `//` changes the left operand, which `//` then tests again, and the update goes to it if it is truthy now and to the document otherwise (`(.a // (.c.d = 0)) += 1` is yq's `!!int () cannot be added to a !!map ()`).
  It holds for `=`, `|=` and every `op=`, for chains (`.a // .z // (.a = 1)`), inside `with` and `|=` bodies, and keeps comments, anchors and flow style.
  `with(PATH; SRC as $v | WRITES)` now keeps the writes of every value the source yields, as yq does (the last value's write wins and `+=` accumulates: `with(.k; .x[] as $v | .y += $v)` over `x: [1, 2]` is `y: 3`, where it was `y: 1`), and `with(PATH; (SRC as $v | WRITE) | WRITE)` applies the writes behind the binding, which were discarded; over 864 `with`-and-binding rows 164 now match yq, and the 3 that stopped matching bind several absent keys.
  Over 700 random `//`-target updates (yq, `main`, this change) 304 outputs now match yq and none that matched stopped matching.
  A chain that ends in anything but a write still does not create its left operands (yq's `(.a // .z) += 1` leaves `a: null`), and the idiom in value position (`.a // (.a = 5)`, which yq answers `5`) is unchanged.
