- **yq: an update of a `//` target creates the left side and applies a write on the right, yq's update-or-create idiom** (#7068).
  `(.a // (.a = 0)) += 1` on a document with no `a` now writes `a: 1`, as yq does, where the document was left unchanged; `(.a // .z) += 1` leaves `a: null` beside `z: 1`, as reading `.a` creates it in yq; a chain creates each left side it reaches (`(.a // .z // .y) = 1`); and a write that leaves the left side falsy targets the document (`(.a // (.c.d = 0)) += 1` is yq's `!!int () cannot be added to a !!map ()`).
  It holds for `=`, `|=` and every `op=`, inside `with` and `|=` bodies, and keeps comments, anchors and flow style; 47 of 50 captured rows now agree with yq, where 16 did, and over 700 random `//`-target updates (yq, `main`, this change) 482 outputs now match yq and none that matched stopped matching.
  In value position (`.a // (.a = 5)`, which yq answers `5`) the write is still not seen by the left side.
