- **yq: the JSON rendering of a mapping no longer lists the keys of a `<<` source written in place** (#4987). `item: {<<: {q: 1}, k: 0}` printed `{"q":1,"k":0}` for `.item` and `.` where yq prints `{"k":0}`; the same held for an anchored inline source (`<<: &m {q: 1}`), an inline source beside an alias in a sequence (`<<: [*a, {q: 1}]` printed the inline `q` too) and a mapping with an own key written before the merge. yq expands only an alias source when it renders; `.item.q`, `.[]` and `keys` still see the inline keys, and an alias source still renders, all as before. Nine merge shapes over four filters, captured from yq v4.53.3, now match on the document-node route (`.`, `.item`); a value built first (`[.item]`, `tojson`, a write) still lists the inline keys, since a write expands the merge and must not drop them; the yq runner sets the rule on every index it builds, and `succinctly jq` over YAML keeps listing the inline keys, as there is no reference that drops them.
