- **yq: a standalone comment line of a CRLF file is followed by a blank line, as in yq** (#5053). go-yaml reads the `\r\n` that ends such a comment as two breaks, so `printf 'a: 1\r\n# c1\r\n# c2\r\nb: 2\r\n' | yq .` is `a: 1\n# c1\n\n# c2\nb: 2\n` (a blank line between the comments) and a lone comment between two siblings is followed by one (`a: 1\n# mid\n\nb: 2\n`, where `# mid` is `a`'s foot, not `b`'s head); succinctly printed the comments with no blank line and attached `# mid` to `b`. Windows-authored GitHub Actions and CircleCI files hit it on every comment block, on `.`, `-P` and a write. yq on a CRLF document equals yq on the LF document with one blank line added after each standalone comment line (196 documents over seven shapes, one to three comments, every blank-line gap: 0 differ, from 119; the same 196 as LF documents, 0 differ, from 8), so the rule is one predicate (`crlf_comment_blank_between`) that the placement code asks wherever it asks for a blank line. A comment after a node, a `#` line inside a block scalar, a lone `\r` and the first document's header (#5053, item 3) are unchanged. It also fixes the LF placement the extra blank line reaches: a comment block at column 0 after nested content that a blank line splits from the next block (`x:\n  k: 1\n# c1\n\n# c2\ny: 2\n`) is the foot of `x`, as yq prints it at column 0, not of `k` at column 2. Against yq v4.53.3 on random documents (nested mappings and sequences, block scalars, flow collections, trailing and standalone comments, blank lines; 900 per line-break form): CRLF 546 differing documents fell to 228 (3 that matched before now differ, all in the unfixed shapes below), LF 115 fell to 78, and no LF document that matched before differs. Not fixed, in `docs/compliance/yq/limitations.md`: comments at differing columns at the end of a document, a comment block after a sequence item that holds a block scalar, and a blank line below a block of comments on `-P` and writes.
