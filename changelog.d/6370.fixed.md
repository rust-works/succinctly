- **yaml: a block sequence at a bare `?`'s own column is the explicit key, as yq reads it** (#6370). `?` / `- a` / `: v` was `{"":["a","v"]}` (the sequence taken as the value of an empty key, the `v` joining it), `?` / `- a` / `k: w` as `{"":["a"],"k":"w"}` and `?` / `- a` as `{"":["a"]}`, where yq reads the sequence as a complex key and answers `{"":"v"}`, `{"":null,"k":"w"}` and `{"":null}`; the YAML Test Suite case 6PBE (`?` / `- a` / `- b` / `:` / `- c` / `- d`) now answers `{"":["c","d"]}` as yq does, where both sequences were merged into the value. A non-empty key still refuses a same-column sequence (`? k` / `- a`, #1104), and a sequence one column in (`?` / ` - a`) is unchanged. Checked against 11,718 YAML files on disk (none changed) and 12,000 randomized dash/key/`?` documents against yq v4.53.3: about 430 more documents match yq, and two that matched stopped matching, both an exotic nested explicit key inside the key sequence that already read wrongly with the dash on the `?` line (`? - ? a` / `   x` / `   x` is accepted where yq refuses it).
