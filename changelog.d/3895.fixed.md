- **jq: a `reduce`/`foreach` source reads `null` on every INIT fork after the first, as jq 1.7.1 does** (#3895, closing #2163).
  `[reduce (.) as $x ((.,.); $x)]` on `{"a":1}` is `[{"a":1},null]` in jq and was `[{"a":1},{"a":1}]` here, `[reduce (.a, .a) as $x ((0,0); . + $x)]` is `[2,0]`
  (was `[2,2]`), `reduce (.[]) as $x ((1,2); . + $x)` raises `Cannot iterate over null` on the second fork (it answered `3` and `4`), and
  `reduce ((.[]|stderr)?) as $x ((0,1); .)` writes its warning once (it wrote it twice). jq duplicates the fold's input with `DUPN`, which leaves `null` in the slot
  every later INIT output resumes from. The shared fork cores now tell the source drive which input a fork reads, and a later fork drives `null | SOURCE`,
  built on the first such fork only so a single-INIT fold never clones its source. A source that does not read `.` (`range(3)`, a literal) is unchanged, and
  `path()`/assignment position already agreed (#2388). Retires the open policy entry in `docs/compliance/jq/limitations.md` ("INIT-fork re-entry").
