- **jq: `--seq` over a stream that faults in the middle, with a directory given last, takes the fault's exit status and reports the other open failures where jq does** (#6610). `jq --seq -n '[inputs]' f.seq dir`, with a record cut short in `f.seq`, exited 2 where jq exits 5, and `jq --seq -n input f.seq dir` exited 2 where jq exits 0 (a program that stops after its first value never reads the directory). A directory last is read only by a read past the last file, so it is now left to the reads, as a missing last file is, and a missing file before it is reported where jq's reader reaches it (`--seq . f.seq gone dir` prints the warning first). A fault at the end of the text is raised by that same read and still fails the run, so a stream holding one keeps the old route. Over 1,120 runs (`--seq` x 7 programs x with and without `-n` x 8 streams x lists ending in a directory, with and without a missing file before it) 267 differed from jq 1.7.1 on `main` and 170 do now, none of the 97 fixed rows regressing; the rest are streams that fault twice, a last value that ends without a newline, and the extra `Is a directory` a `try input catch .` read prints (#6624, #6625).
