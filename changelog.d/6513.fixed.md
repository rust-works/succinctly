- **jq: `--seq` words the warning for a bare `n` after a string with a two-byte escape as jq does** (#6513). `printf '\x1e"\u00e9"\n\x1en\n' | jq --seq -c .` says `Invalid numeric literal` in jq 1.7.1 and `Invalid literal` here. jq decodes a string's escapes in place over its token buffer, so what its parser reads at index 1 when it classifies the next bare `n` is the second byte of the decoded text: a `u` (the escape for `A`) takes the keyword path (`Invalid literal`), and anything else the number path (`Invalid numeric literal`). The reader kept the raw bytes of the string, which agrees with jq only when the string has no escape or the escape decodes to one byte, so a string holding an escape for `U+00E9`, a lone surrogate, a surrogate pair or `A` followed by another character gave the wrong wording. It now decodes in place as jq does, including the part decoded before an invalid escape. Only the wording of a warning differed; stdout and the exit status were the same. A 13,000-case differential of random strings against `/usr/bin/jq` had 36 differences per 3,000 cases before and none after.
