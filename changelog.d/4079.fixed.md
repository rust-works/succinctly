- **yq: a numeric, boolean or `null` index on a mapping finds the member by its key text, for reads and writes** (#4079). yq's `matchKey` compares texts, so on `abc: 1 / 1: y / true: t / null: n / 1.5: w` `.[1]` is `"y"`, `.[true]` is `"t"`, `.[null]` is `"n"` and `.[1.5]` is `"w"` (all were `null`, or `Cannot index object with boolean/null`), `.[1] | key` is `1`, `.[1] | path` is `[1]`, and `.[1] = "z"`, `.[1] |= . + "!"`, `.[true] = "z"` and a computed `1 as $k | .[$k] = "z"` update the member, while `.[2] = "z"` creates the key `2` and `.a[0][].b = 9` on `a: {}` is `{"a":{"0":[]}}` (they raised `Cannot index object with number`). A miss is still `null` (#2459) and an array keeps its positions; `del(.[null])` and friends on a mapping are now yq's no-op instead of an error. The routes it covers: the cursor evaluator (`Expr::Index`, `index_one_generic`, the path-context step), the eager evaluator (`index_one`, `index_array_by_position`, `index_one_owned`, the owned `Expr::Index` arm) and the write walkers (`set_path`, `update_path`, `key_to_path_component`).  49 rows captured from yq v4.53.3 and a unit test of the eager route pin it. Not changed: a literal's own spelling (`.[1.0]` and `.[01]` find the `1:` member where yq, which compares the spelling, answers `null`) and names with other punctuation (`.a+1`).
