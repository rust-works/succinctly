- **yq: a numeric, boolean or `null` index on a mapping finds the member by its key text, for reads and writes** (#4079). yq's `matchKey` compares texts, so on `abc: 1 / 1: y / true: t / null: n / 1.5: w` `.[1]` is `"y"`, `.[true]` is `"t"`, `.[null]` is `"n"` and `.[1.5]` is `"w"` (all were `null`, or `Cannot index object with boolean/null`), `.[1] | key` is `1`, `.[1] | path` is `[1]`, and `.[1] = "z"`, `.[1] |= . + "!"`, `.[true] = "z"` and a computed `1 as $k | .[$k] = "z"` update the member, while `.[2] = "z"` creates the key `2` and `.a[0][].b = 9` on `a: {}` is `{"a":{"0":[]}}` (they raised `Cannot index object with number`). A miss is still `null` (#2459) and an array keeps its positions; `del(.[null])` and friends on a mapping are now yq's no-op instead of an error. Reads work on the cursor and eager evaluators; single-target writes (`=`, `|=`, `+=`, `style=`/`anchor=`/`line_comment=`, a computed key) work on both. 53 rows captured from yq v4.53.3 and a unit test of the eager route pin it. Grouped and multi-target writes follow in #4085. Not changed: `.[01]` is read as the integer `1` where yq finds the `01:` key, and names with other punctuation (`.a+1`).
