- **yq: `--properties-separator`, `--properties-array-brackets` and `--csv-separator` for `-o=props` and `-o=csv`** (#6922).
  `-o=props` writes `key<sep>value` with the separator given (an empty one keeps ` = `) and `a[0]` for an array element below the root with `--properties-array-brackets`; `-o=csv` separates fields with the byte given, refusing a longer one as yq does (`invalid argument "ab" for "--csv-separator" flag`) and the delimiters Go's CSV writer refuses (`"`, a line break).
  Checked against yq v4.53.3 over 1,152 flag, document and filter combinations.
  The `@props` / `to_props` and `@csv` / `to_csv` operators read the same flags, as yq's do (`--csv-separator=';'` makes `[1, "a;b"] | @csv` print `1;"a;b"`); `@tsv` keeps its tab, as in yq.
  A `props` comment is still not written, and the text an `eval` reads keeps the default separators; both stay in #6922.
