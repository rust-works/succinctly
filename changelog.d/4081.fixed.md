- **yaml: a node tag in front of a flow collection inside a flow sequence now parses** (#4081). `a: [!Foo {a: 1}]`, `[x, !Foo {a: 1}]`, `[!!str null, !Foo {a: 1}]` and `a: !!seq [!!str null, !Foo {a: !x.y 1, c: 2.5}]` were rejected (`Error: YAML parse error: unexpected character ']' at offset 15: expected ':' in implicit flow mapping entry`, exit 1, no output) where yq accepts them. The lookahead that decides whether a flow-sequence entry is an implicit single-pair mapping (`[k: v]`) skipped a leading anchor or alias but not a tag, so it scanned `!Foo {a` up to the `: ` inside the braces and took the tagged mapping for a pair whose key is `!Foo {a`. It now skips node properties (an anchor, an alias, a tag, in either order, a verbatim `!<tag:x,y>` included) and decides on what follows, as the real parse does. The same lookahead required the `:` after a flow-collection key to touch the closing bracket, so `[!Foo {a: 1} : v]` only parsed by accident (through the `: ` inside the braces) and the fix above would have rejected it; spaces and tabs before the `:` are now allowed after a flow collection as they already were after a quoted key, which also makes `[{a: 1} : v]` and `[[1] : v]` parse as yq reads them. `[!Foo k: v]`, `[!Foo "k": v]`, `[&x !Foo {a: 1}, *x]`, `[!Foo {a: 1}: v]` and `[!Foo [1], 2]` match yq. In a one-off sweep (not a committed test), output was identical to yq's across 2,400 tag/anchor/collection/context combinations on the default, JSON, `.a` and `-P`/write routes except two tag-rendering gaps that parsed before this change (a tag on an empty flow collection or on an implicit-pair key is dropped on YAML output, #4088).
