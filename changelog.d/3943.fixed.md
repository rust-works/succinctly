- **jq: `.[[$a]]` finds a NaN-bearing container that is the same handle** (#3943).
  `jq -nc '[nan] as $a | [$a] | .[[$a]]'` is `[0]` in jq and was `[]` here, as was `[nan] as $a | [[$a],[$a]] | .[[[$a]]]` (jq `[0,1]`).
  An array key on an array is jq's subarray search, which compares each element with `jv_equal`'s identity shortcut first, so a key built from the
  very handle the target holds is found even when it contains a NaN. A computed key was re-spliced into the AST as literals before the index ran, which gave
  every container and every parsed NaN in it a fresh identity; `indices([$a])`, `index` and `getpath` kept the key's storage and already answered `[0]`.
  An array key is now spliced as its own storage. A *different* handle (`[nan] as $a | [[nan]] | .[[$a]]`, `.[[[nan]]]`) still answers `[]`, as jq does. jq mode only; yq has no subarray search.
