- **jq: `-n` with `input`/`first(inputs)` over several files scans every file a chunk at a time** (#6455).
  #6450 did this for the last file; every file before it was still split, re-parsed with `serde_json` and
  checked for a token left open at its end before the first value. Now only the first file's first
  chunk is scanned before the program starts, and each later file when the program reaches it. A fault
  in a file, or a number or literal ending one before the last, hands the rest of the stream to the
  eager reader, so a stream that is not clean reads as before. On an Apple M5,
  `-n 'first(inputs)|.id' big.ndjson one-line.json` went from 279 to 13.8 ms at 95 MB and from 29.7 to
  3.7 ms at 9.3 MB, and two 95 MB files from 291 to 24 ms (jq 1.7.1: 2.2-2.4 ms). What is left is each
  file's whole read and UTF-8 check. A program that reads every input is unchanged.
