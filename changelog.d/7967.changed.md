- **jq: after the first fault of a stream, `succinctly jq` places a later fault where it is in the text** (#7967). This implements ADR-0018's #7963 amendment E1: everything through the first fault is still jq's (the values before it and their positions, the fault's message, line and column, and the exit status), and after it the reader stays above the floor, resuming where jq's next read starts so that it reads every value jq reads, in jq's order. What it no longer models is where jq's parser stands once a fault has made it drop the rest of a read, which jq never counts (#5923) and which only ever moved the line and column of a later fault: `}`, a newline, `}` and a newline now give the second fault at line 2, column 1, where jq 1.7.1 and 1.8.2 say line 1, column 2. The `--seq` hand-on no longer seeds the RS it was handed on at as a fault (#7260, #7404), which since #7718 moved nothing but positions. 107 lines of the reader go (161 deleted, 54 added). Over 12,000 generated fault-bearing cases (one to three files or standard input, long lines, NULs, invalid UTF-8, byte-order marks, `--seq`, `-n`, `-s`, `--stream`, `-R`, `-e`, `try input`, `input_line_number`, `input_filename`), the output through the first fault and the exit status are identical to a build of `main` (`bafff755a`) in every case, 1,605 differ only in a later fault's line and column, and every value printed on the 5,056 value-only rows is one jq 1.7.1 or 1.8.2 prints.
