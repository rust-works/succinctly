- **yq: a hexadecimal integer literal in the filter is read as yq reads it** (#7615). `0x10` (or `0X10`) was refused with `unexpected character 'x'` wherever it appeared, as a value, in an array or object, as an index or slice bound and on the right of an assignment. It is now the integer a document's `0x10` is: the value 16 for arithmetic, with its spelling kept, so `0x10 | tostring` is `"0x10"`, `.a = 0x10` writes `a: 0x10`, `.a == 0x10` is `false` on `a: 16`, `[0x1f, 31] | unique` keeps both, and `0x7fffffffffffffff + 1` wraps, as in yq v4.53.3. A literal past `i64` (`0xFFFFFFFFFFFFFFFF`) is refused with yq's `strconv.ParseInt: parsing "FFFFFFFFFFFFFFFF": value out of range`, and `succinctly jq` still rejects the literal, as jq does.
