- **`succinctly jq --stream` and `--stream-errors` are linear in a document's depth, as jq is** (#7567). Each event carried a copy of the path as it stood, so the closing events of a document nested `n` deep cost `O(n^2)` (`[`*10000 + `]`*10000, 20 KB, `-n --stream '[inputs] | length'`, took 205.6 ms on an Apple M4 Pro and 921.0 ms on an AMD Ryzen 9 7950X where jq 1.7.1 takes 16.8 ms and 4.6 ms); from 64 levels deep an event now takes a window on a path the parser keeps for its events, as jq's do, so the cost is linear in the depth; a shallower path is copied per event as before, so ordinary record streams run the instructions they did (within 0.2% on x86_64). A `--stream-errors` event, and the array `-s` slurps them into, is also read where it is now, as a `--stream` event is, instead of being written out as JSON and indexed again, which cost each event its path's length too. On an Apple M4 Pro the user CPU of every such route grew with exponent 2 in the depth (2,500 to 20,000 levels) and now grows with exponent 1, as jq's does (100,000 to 800,000 levels).
