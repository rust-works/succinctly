- **`succinctly jq` reports option errors in argv order, as jq does** (#7712). jq stops at the first word of its command line it refuses, so a bad `--argjson` text, an unreadable `--slurpfile`/`--rawfile` file or a `--jsonargs` word that is not JSON before `-h`, `-V` or `--build-configuration` is an error (exit 2) where `succinctly jq` printed the help or version with exit 0, and an unknown option, a missing value or a refused `--indent` later in argv no longer pre-empts an earlier error. A missing value is now reported in jq's words (`jq: --arg takes two parameters (e.g. --arg varname value)`). Over a generated matrix of 6,845 orderings of option pairs and triples, 1,702 differed from jq 1.7.1 in the error reported or the exit status (700 of them exiting 0), and none do now; jq 1.8.2 agrees with jq 1.7.1 on all of them.
