- **yq: a line below an own-line block scalar under `? - &x` is refused when it falls between the dash and the content, as yq refuses it** (#6570). `? - &x` / `   |` / `     t` / `` / `   u` is `did not find expected '-' indicator` in yq v4.53.3; here the document was accepted as `{"":null}` and the line `u` dropped without an error (the same for `? - !!str`, with a comment, and behind a `- `). The first item of an explicit key's sequence was parsed by a function that read the properties' own line end as a plain scalar over the lines that followed, so the header and its content were text of the item; it now treats properties alone after the dash, with a value on a line below, as every other item does: the item stays open, a comment after the properties goes with the value (`? - &x # c` / `    x` keeps `# c` where yq puts it), and the main loop reads the value from the line below, with the checks it makes of a line below a block scalar; with nothing below (`? - &x` / `: v`) the item is null and takes the path it did. A differential of 4,080 documents (an explicit key's `:` or `?` before a dash, a chain, a tag or a bare dash, under a mapping and a sequence; `|` and `>-` headers at columns 0 to 7; a line below at columns 0 to 7) against yq v4.53.3 found 196 differences before and none after; the old and new binaries compared over 780 more documents (twelve key-sequence heads with thirteen bodies and five followers) changed on 30 as JSON and 93 as YAML, 113 of the 123 now matching yq and the other 10 the double anchor `? - &x &y` that yq refuses and both builds accept; none the other way.
