- **jq: a deferred `as` bind decodes a node it reads whole at most once** (#4036). #3856's lazy bind (`. as $x | body` leaves the node undecoded until `$x` is read) kept the eager decode for a body that read the whole node under an iteration (`. as $x | .users[] | {r: $x}`, `select($x == .)`, `$x | tojson`), because the eager bind's embed-table entry shared one decoded copy across every read and a deferred read had no entry to hit, so it decoded the node per element (0.18 s against 6.7 s on a 1.4 MB document); a body naming the node bare `k` times decoded it up to `k` times (`. as $x | $x == .` +78%, `. as $x | {r: $x}` +17%). A deferred bind now registers a *lazily filled* entry for its node: the first materialization builds the value as before and fills the entry, and every later one is handed the same `Rc`. Those bodies defer, the one decode moves to the first read (and is not paid when no element reaches it), and the entry is invisible to the resolver that certifies identity for `path()`, so what `path()` accepts is unchanged. A member chain something consumes under an iteration (`$x.users | length`, `$x.users[0]`) keeps the eager bind (#4035). Without `std` there is no table to hold the entry, so a repeated whole-node read stays eager there. Apple M5 Max, release build, instructions retired and peak RSS against the commit before (`users` documents of 0.06 / 0.7 / 4.9 MB; baseline noise +-1%, measured with an unchanged second copy of the baseline): `. as $x | $x == .` -23% / -44% / -48% (101 -> 58 MB RSS at 4.9 MB); `. as $x | .users[] | select(.id < 0) | {r: $x} | .r.users[0].id` (no element reaches the read) -24% / -53% / -59% (59 -> 16 MB); `. as $x | .users[] | $x | length` -25% / -52% / -59%. Rows that still read the node once or on every element decode it once either way and are within the noise: `. as $x | {r: $x} | .r.users | length` +0.2%, `. as $x | .users[] | select(.id < 300) | {r: $x} | .r.users[0].id` +0.5%. Scalar binds, `. as $x | 1`, `. as $r | .users[] | .name` and `reduce` are within +-1%. Output identical on every row. Not measured on x86_64. Pinned by the lazy entry's own tests (`lazy_entry_fills_once_and_shares_the_copy_4036`, mutation-checked by disabling the fill and the pop), the differential sweeps against the decoding bind, and `test_deferred_bind_whole_node_reads_match_jq_4036` against `/usr/bin/jq` 1.7.1.
