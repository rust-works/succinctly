- **jq: a slice assigned onto `null`, a `del` that names nothing and `.[5] |= empty` build a new array** (#5761).
  `[nan] as $a | null | .[1:] = $a | . == $a`, `$a | del(.[5]) == $a` (also `.[-5]`, `.[-0.5]`, `.[5]?`, a computed index, `del(.[0][5])`) and `$a | (.[5] |= empty) == $a` handed back the array they were given, so `==` (which short-circuits on `jv_identical` in jq, while `[nan] == [nan]` is `false`) answered `true` where jq 1.7.1 answers `false`.
  The array is now split from any other handle that holds it, which costs a copy only when the array is shared; a path that runs through something absent (`del(.[5].x)`) keeps its identity, as in jq.
  A fold step that stores its loop variable through either no longer keeps the literal operand, so the fold shares the element there too. `succinctly yq` is unchanged.
