- **`succinctly jq -n` reaches an input file that would not open after a text's parse error, as
  jq does** (#6656). A `-n` program that catches a parse error (`try input catch .`) and reads on
  never reached a file after the fault, so `jq -n '(try input catch .), (try input catch .), (try
  input catch .)' lines.json missing.json` printed the errors and exited 0 where jq prints `Could
  not open file` and exits 2. The failures after the fault now go to the reads that follow it,
  and each of a text's parse errors says whether it is at the end of the text, so the read of an
  EOF fault reaches a file after it. A program that stops at the fault (no `try`) still never
  does. A text that starts with a clean value and faults later (`one.json lines.json`) and a
  main loop over several faults are #6663.
