- **jq: a directory given as an input file is a read error, as in jq, not an open error** (#6472). `jq . adir nums.json` printed `jq: error: Could not open file adir: Is a directory` and jq 1.7.1 prints `jq: error: Is a directory`; `jq -n input adir` named `<stdin>` in `jq: error (at <stdin>:0): break` where jq names `adir`; `jq -s . adir` printed the open error beside `[]` where jq prints no message. `fopen` succeeds on a directory and the first read fails, so the directory is a source with no bytes, and jq's reader says so when it moves on to the next file: once for each directory that a file follows, before that file, and not at all for the last. The exit status is 2 either way. A directory is an input file that opened, so `input_filename` names it and the run stops after the next value, as it does after a file that would not open. The `-R`, `--stream`, `-s` and chunked routes agree on 17 rows captured from jq 1.7.1; the rows where the program stops reading before it reaches the file (`jq -n 'input' nums.json adir`) still report it early, as a missing file does.
