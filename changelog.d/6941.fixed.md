- **yq: a flow mapping's key with no value ends before a blank line and a comment** (#6941). `{k` / `` / `}` read the key as `"k\n"`, and `{k # c` / `}` was a parse error (a `#` after a line break was key text), where yq reads the key `k` with a null. The key scanner trimmed spaces and tabs only, so the line break the scan had walked past stayed in the key; the value scanner had trimmed it since #6855. The key scanner, the explicit-key scanner and the value scanner now share one trim (`trim_flow_plain_end`), and a comment ends a key in both key scanners. A key that reaches a `:` on a later line, and a comment that swallows the closing brace, are still refused, as in yq. Flow-style YAML output does not print the comment back (the open "comment after an empty value" row of #6334); block style with `-P` does. Found by a mutation fuzz of the yaml-test-suite inputs against yq v4.53.3.
