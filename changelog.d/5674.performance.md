- **jq: `--seq` input is read as a plain JSON stream when it is clean** (#5674).
  A stream with one source, valid UTF-8, no byte-order mark, no diagnostic from jq's reader and nothing but
  whitespace and RS between its values is read the way NDJSON is, instead of indexing and converting every
  record on its own; any other stream takes the route it always did, with the same warnings. The reader's
  walk over the stream also takes a run of ordinary string bytes at once. On an Apple M5 Max,
  `--seq -r .name` takes 109 ms instead of 268 ms on a 10 MB stream and 1.02 s instead of 2.65 s on 100 MB
  (jq 1.7.1: 116 ms and 1.10 s), `--seq -s -c 'map(.score)|add'` 114 ms instead of 251 ms and 1.08 s
  instead of 2.42 s (jq: 133 ms and 1.26 s), and `--seq .` 167 ms instead of 256 ms and 1.56 s instead of
  2.52 s. Peak memory for `--seq -r .name` on 100 MB falls from 1.05 GB to 156 MB (jq: 2.5 MB).
