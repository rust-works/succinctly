- **yq: a write through an `as`-bound variable changes the bound copy, as in yq** (#2643). yq's `X as $y` binds a copy of the node, so `.a as $y | $y.b = 5` leaves the document as it was and `.a as $y | $y.b = 5 | $y` is `{"b":5}`; the same for `|=`, `+=` and the other `op=` forms, `//=`, `$y = 5` and `del($y.b)`, with the right side of `=` read against the stage's input as yq does. `succinctly yq` refused these with `Invalid path expression` (exit 1), and `. as $y | $y.a.b = 5` and `. as $y | del($y.a)` wrote the document where yq leaves it alone. The rows that write through `$y` as a stage of the `as` body (also inside a nested pipe, a comma path or a nested `as`) agree with yq v4.53.3 now; a bare `del($y)`, a variable-rooted path inside a write's left side and a write inside a construction (`[$y.b = 5]`) are still different (limitations). `succinctly jq` is unchanged.
