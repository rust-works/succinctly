- **jq: `now` is a whole number of microseconds on every platform, as jq's is** (#7484). jq reads `gettimeofday` (`tv_sec + tv_usec / 1000000.0`, the same in jq 1.7.1 and 1.8.2), so every reading of `[range(200)|now*1e6|.-round|fabs<0.001]|all` is true; `succinctly jq` converted the clock with `as_secs_f64`, which keeps the nanoseconds a Linux clock has, so about one reading in four was whole and the rest printed a seventh decimal (`1795225997.4185658` against jq's `1795225997.418565`). macOS clocks have microseconds, so the difference was Linux only. The nanosecond reading is cut to microseconds before it becomes a number. `succinctly yq` keeps its nanosecond timestamp text. Pinned by a unit test of the conversion and by `tests/jq_cli/i7484.rs`, which checks 300 readings.
