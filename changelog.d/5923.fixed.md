- **jq: the second of two parse errors `input` raises is placed where jq places it** (#5923).
  After a fault, jq drops the rest of the read it was in and never counts the dropped bytes, so its
  parser's line and column carry on from where the first fault stopped it, and from one file to the next:
  for the input `}\n}\n[4]\n`, `[limit(3; repeat(try input catch .))]` reports `Unmatched '}' at line 1,
  column 1` and then `... at line 1, column 2`, where `succinctly jq` said `line 2, column 1`. A run of
  faults on adjacent lines (`]\n}\n]`), a fault after blank lines or after a document, and a fault in a
  second file now report jq's positions; the text and the first fault's position were already right.
