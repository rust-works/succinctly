- **jq: an array of values computed per element of a document array holds a third to a half less memory** (#7267).
  `[.xs[] | f]` kept every element's result as an 80-byte evaluator result until the end of the walk, beside a
  second vector of the values that it grew by doubling, so it held 112-144 bytes per element where jq holds 16.
  Consecutive computed values now go straight into one vector sized for the elements left. At 100 MB,
  `[.numbers[]|floor]|add` peaks at 547 MiB instead of 1,081 MiB on an Apple M4 Pro and at 549 MiB instead of
  869 MiB on an AMD Ryzen 9 7950X, now below jq 1.7.1 on both, and runs 4% faster on the M4 Pro and 21% faster
  on the 7950X; `[.strings[]|length]|add` peaks at 158 MiB instead of 215 MiB (M4 Pro) and 160 MiB instead of
  195 MiB (7950X), and `[.users[] | {name, s: (.score + 1)}]` at 349 MiB instead of 402 MiB (M4 Pro) and 404 MiB
  instead of 436 MiB (7950X). The output is unchanged.
