- **jq: reads past invalid UTF-8 on a long line are counted in the bytes jq read** (#7934, #7931). jq reads its input 4,095 bytes at a time and counts those reads in the bytes it read; `succinctly jq` counted them over the text after each invalid byte had become a three-byte U+FFFD, so a read boundary after such a byte fell two bytes early per byte replaced. Behind a byte-order mark, a fault inside `inputs` then resumed inside a number and read part of it as a value jq never reads, which printed `[]` and exited 0 where jq exits 5 (#7934); a fault in the read holding the line break was named `(at f:0)`, and a fault jq drops with its read was raised again at top level (#7931). The same count put a value just past such a boundary one line short in `(at f:N)` and `input_line_number` (on the document loop, the lazy `input`/`inputs` route and the reader after a fault), ended reads of bytes moved across a file seam early, and counted a file that starts inside a replacement from the replacement's end. The windowed route also looked for a number's NUL tail after substituting a window, which ended a run of a file of 4 MiB or more at `Invalid JSON text` where both jq releases read the number. The windowed document loop's `(at f:N)` line is still counted over the window's text (#7938).
