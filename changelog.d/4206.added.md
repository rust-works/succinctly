- **yq: `to_number`, `from_json`, `from_yaml` and `with(path; update)`** (#4206). All four exist in yq v4.53.3 and were `X/0 is not defined` here. `to_number` is `tonumber` (yq words its error differently). `from_json` and `from_yaml` both decode YAML, JSON being a subset, and answer the string's first document (`"abc" | from_json` is `"abc"`, `"a: 1"` is `{"a":1}`); a non-string passes through, and an empty string is yq's `EOF` error. `with(path; update)` runs `update` for the assignments in it and discards the value of anything else, so `with(.a; .c = 2, .d = 3)` applies both, `[1,2] | with(.[]; select(.a == 2) | .b = 9)` writes only where the select passes, `[{"a":1},{"a":2}] | with(.[]; select(.a == 2) | .b = 9)` writes only where the select passes, `[1,2] | with(.[]; . + 1)` is `[1,2]`, and a missing path is created as `|=` does; a comma in the path is yq's `with must be given a block (;)` error. They are yq names only: jq mode may define its own `with`. `to_json` and `to_yaml` stay open on #4206.
