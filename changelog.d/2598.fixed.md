- **yq: a mapping key's `&anchor` survives a write** (#2598). `&k key: 1` / `b: 2` with `.b = 5`
  printed `key: 1`; it now prints `&k key: 1`, as yq does, for `=`, `|=`, `del()`, `-P` and
  `--arg`, and in flow mappings and nested keys. A value alias that targets a key's anchor
  (`b: *k`) used to be expanded to `b: key` on every such write, because the anchor-soundness
  gate never saw a declaration; it now stays `b: *k` while the key is still emitted before it
  (deleting or sorting the key below its alias still expands the alias, a documented divergence
  from yq, which prints an unresolvable `*k`).
