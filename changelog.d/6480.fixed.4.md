- **jq: a fault at the end of the text that `input` raises is raised at a last file that did not open** (#6480). `jq -n '[inputs]|length' t1.json missing` with `t1.json` holding `[1,` said `jq: error (at t1.json:0): Unfinished JSON term at EOF at line 1, column 3`; jq 1.7.1 says `(at missing:0)`, because its parser asks the reader past the last file before it gives up. When the text's first fault is at its end, the queue now raises it at the missing file, line 0, on the eager and lazy routes (a file scanned a chunk at a time, and one deeper than the lazy route reads, included), under `-n`, `-n -s`, and for an `input` the program reads without `-n` (`jq -c '[., input]' b.json missing`). The message keeps its own line and column. A fault earlier in the text, or a missing file before the last that opened, keeps the fault's file. Pinned over 24 rows against jq 1.7.1 in `tests/jq_cli/i6480_eof_fault.rs`, and `tests/jq_cli/i6480.rs` no longer masks the marker.
