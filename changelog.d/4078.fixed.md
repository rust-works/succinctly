- **yq: a write keeps the document's explicit tags** (#4078). Any DOM write (`=`, `|=`, `del()`, `-P`,
  `-i`, `--arg`) re-emitted the document without them, so `yq -i '.Resources.B.Properties.Other = 1'`
  turned `Name: !Ref Param` into `Name: Param`, `!GetAtt [Q, Arn]` into `[Q, Arn]` and an application
  tag on a mapping into a plain one: a CloudFormation template was silently a different document after
  any edit. Tags on scalars, mappings and sequences are now kept (`!Foo` on a block mapping goes on
  its header line, behind any anchor; before a flow or empty collection), along with `!!str 1`,
  `!!float 1` and `!!int "2"`. A written node keeps a custom tag and loses a core tag its new value no
  longer has, `-P` drops the core tags that only restate a type, as yq does. Checked against yq v4.53.3
  on about 1,900 random tagged documents. A node a write copies from elsewhere (`.b = .a`) still loses
  its tag.
