- **`succinctly jq` reads its input files with one free file descriptor, as jq does** (#7477). Under `ulimit -n 4` (descriptors 0, 1 and 2 open) every input file failed with `Could not open file a.json: Too many open files` and exit 2, where jq 1.7.1 and 1.8.2 print every file and exit 0. The cause was #7214's standard output, a duplicate of descriptor 1 that took the one free descriptor before the first input was opened. It now writes to descriptor 1 itself through a handle that never closes it, which still reports a descriptor that cannot be written (`jq . 1<file`, #7214). Over 15 programs (`-c .`, `-s`, `-R`, `--stream`, `--seq`, `-n '[inputs]'`, `--slurpfile`, `--rawfile`, `-f`, a missing file between two good ones) at `ulimit -n` 4, 5 and 6, stdout, stderr and exit status match jq 1.7.1 on every one of the 13 programs that failed at `ulimit -n 4` before. Pinned in `tests/jq_cli/i7477.rs`.
