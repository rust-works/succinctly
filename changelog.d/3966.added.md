- **yq: `any_c(f)` and `all_c(f)`, real yq's predicate spelling of `any`/`all`** (#3966, after #2005).
  `echo '[1,5]' | yq 'any_c(. > 3)'` is `true` in yq v4.53.3 and was `any_c/1 is not defined` here, so once #2005 gated the jq spelling `any(f)` behind `--jq-extensions`
  there was no unflagged way to write a predicate `any`/`all` in yq mode. They are native (no flag) and yq mode only: the input must be an array (a mapping or a scalar is
  the bare form's `any only supports arrays, was !!map`), `f` runs to completion for an element and only its first output decides it (so `any_c(true, error("x"))` still raises) while an element whose `f` yields nothing is skipped, `f` is read-only
  so an absent key is skipped where an explicit `null` is falsy (`[{"b":1}] | all_c(.a)` is `true`, `[{"a":null}] | all_c(.a)` is `false`), the walk stops at the first deciding
  element, and arguments after the first are never evaluated. Checked against yq on 1,125 filter/input rows and a 208-row null-versus-absent matrix, on the cursor and the DOM route.
  Pinned by `test_yq_any_c_all_c_3966` and its two siblings.
