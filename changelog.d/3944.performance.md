- **jq: a `reduce` assignment whose right side computes from the loop variable no longer copies its accumulator every step** (#3944). `.[$r.name] += ($r.score | floor)`, `.[$r.name] = ($r.score // 0)`, `.[$r.name] = $r.a + $r.b`, `.[$r.name] = ($r.score > 50)` and `(.[$r.name] = $r.score) // 0` (which is what `.[$r.name] = $r.score // 0` parses as) left `owned_assign_step`'s closed grammar, so each step re-copied the whole object and the fold was quadratic (15,000 records: 11-32 s). A comparison, `and`/`or`, arithmetic, `//` and the argument-free builtins `floor`, `ceil`, `round`, `sqrt`, `fabs`, `length`, `ascii_downcase` and `ascii_upcase` now count as closed in jq mode, and an outer `//` after a write is answered in place. Measured on an Apple M5 Max (release, interleaved A/B, min of 3, 5,000 / 15,000 records): `+= ($r.score | floor)` 1.27 s / 11.15 s → 0.03 s / 0.08 s, `= ($r.score // 0)` 1.76 s / 16.04 s → 0.04 s / 0.10 s, `= $r.score + 1` 3.40 s / 31.87 s → 0.04 s / 0.10 s, `(… = $r.score) // 0` 1.72 s / 13.31 s → 0.03 s / 0.07 s, with the control `= $r.score` unchanged at 0.03 s / 0.08 s. Output is identical to jq 1.7.1 on every row; an operand that raises still goes to the evaluator's route and text. An explicit `==`/`!=` on a container loop variable keeps its identity marker (#3896) and is unchanged.
