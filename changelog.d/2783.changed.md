- **yq: `{...}` object construction follows yq's grammar, so bare identifier keys and the `{x}` shorthand now need `--jq-extensions`** (#2783). Real yq parses `{ expr : expr , ... }` — both sides of a pair are expressions and a lone identifier is a lexer error (`yq '{b: 2}'` and `yq '{x}'` both fail with `invalid input text`) — while `succinctly yq` accepted jq's sugar and rejected every key that was not an identifier or a string. It now accepts `{.a: 5}`, `{1: 2}`, `{"a" | "b": 1}` and `"k" as $a | {$a: 3}` as yq does, and rejects `{b: 2}` and `{x}` unless `--jq-extensions` is passed (quote the key: `{"b": 2}`). An entry with no `:` is yq's bare `COLLECT_OBJECT` entry, reproduced bug-for-bug: `1 as $a | {$a}` prints nothing and exits 0 (it was a parse error), `{"a": 1, "b"}` fails with `CollectObject: mismatching node sizes`, and `[[{"k":1}]] as $a | {$a}` is `k: 1`. jq mode is unchanged.
