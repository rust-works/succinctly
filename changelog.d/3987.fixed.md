- **jq: `$x` after a `catch` handler that navigates under `//` no longer refuses when the `try` body raises a scalar literal** (#3987, a #3965 residual). `path(. as $x | try error("x") catch (.a)? // 5 | $x)` raised `Invalid path expression` where jq answers `[]`. On a string, number or boolean payload `.a` raises, the parenthesised `(.a)?` (or `try .a`) catches that, and `// 5` takes `5`, so the register is where the `try` entered it. A payload the program does not name (`error` raises its own input), a bare postfix `.a?`, and a body that emitted before it raised are still refused, as in jq.
