- **yq: `--front-matter` splits an input as yq does, and reads what yq reads** (#6910). yq's front matter is the text up to the first line that starts with `---` at column 0, after the input's own leading `---` line (blanks around it allowed); that line starts the body, which `process` writes back as it was. An input with no front matter (`a: 1`, `# c` / `---` / `a: 1` / `---` / `body`, a blank first line), an unterminated one (`---` / `a: 1`), an indented opening line, and a `...` (which closes nothing) were refused with `no front matter found` or `unterminated front matter`; they are read now, and a text that is not one YAML document is the YAML error yq raises. The opening `---` is the front matter's own line and goes through the stream like any header, so it is written back as the input had it, CRLF included (`---\r\n` stays), when the result is the front matter document; a closing line is written as it was (`---  `, `--- # c`, `----`); the last file's body keeps a missing final line break, as yq's does. Checked against yq v4.53.3 on 288 rows (32 inputs x `.a`, `.`, `.a = "N"`, `.b = 2`, `del(.a)` and `keys`, in `process` and `extract` where the filter reads): the old build agreed on 178, this one agrees on 273, and the 175 stdout rows and 50 `-i` file rows that agree are pinned in `tests/yq_cli/i6910.rs`. The four shapes that still differ (a scalar read of a front matter with an opening `---`, which prints one `---` more; a failing filter, after which the body is still written; a write over an empty input, which gains a blank line; a front matter that is not one YAML document, which fails before printing its first) are in `docs/compliance/yq/limitations.md`.
