- **yq: `-r` / `--unwrapScalar` take an optional boolean (`-r=false`, `--unwrapScalar=true`), and `-o=shell`, `-o=kyaml` and `-o=yaml`/`-o=props` honour it** (#7093). yq's flag is a boolean like any other of its: `-r=false` and `--unwrapScalar=true` were refused (`unexpected value 'false'`, `unexpected argument '-='`). With it true, `-o=shell -r` now leaves strings unquoted (`name=Mike Wazowski`) and `-o=kyaml -r` prints a string result as its own text, as `-o=json -r` did; with `=false`, `-o=yaml` prints a scalar result as the node it is (`"a b" # c`, a `|` block, `&x plain`) and `-o=props` Go-quotes a value that holds a space (`name = "Mike Wazowski"`), for `@props` too. The flag's default depends on the format (true for yaml and props, false for the rest), as in yq. A value that is not a Go boolean is refused in yq's words with exit status 1. 1,840 rows from yq v4.53.3 are pinned in `tests/yq_cli/i7093.rs`; an alias result (`*x`), a value reached through `to_entries` and `-P` quoting under `=false` still differ.
