- **jq: an `--argjson` value and a `--jsonargs` word of plain JSON are read in one pass** (#7881). Such a text now goes first to the one-pass reader a `--slurpfile` file is read by (#6110), which builds the same value, number spellings included (`1.000`, `1e1000`, `100000000000000000000`). Text that reader declines (a leniency such as a leading zero, a repeated key, a lone surrogate escape, `nan`, nesting past 128 levels, or text that is not JSON) takes the route every text took before: the validator, the index and the walk over it, which still decides every refusal. Cachegrind instruction counts on an AMD Ryzen 9 7950X box (Linux, valgrind 3.18.1, `--cache-sim=no`, stripped release builds with `--features cli`) for `-n --argjson v VALUE 1`, on top of the single parse above, with jq 1.7.1 on the same box in brackets: a 100 KB array of small objects 39.65M to 9.87M (31.97M), a 100 KB array of numbers 36.17M to 12.15M (33.36M), one 100 KB string 6.44M to 3.48M (17.97M); at 1 KB 1.54M to 1.22M, 1.50M to 1.24M and 1.18M to 1.14M. The same bytes through `--slurpfile` cost 8.69M, 11.09M and 2.28M.
