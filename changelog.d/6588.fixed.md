- **jq: `--seq` no longer drops a record before a file that did not open** (#6588). The reader's silent end of the stream (#2998), which drops a record in a final buffer that starts on a record separator, was applied to the last file that opened even when a missing file followed it. jq's reader asks the missing file for more first, so the final buffer is the empty one there. `jq --seq -c -n '[inputs]' last.json missing` with `last.json` holding `\x1e1\n\x1e[2]` printed `[1]` where jq prints `[1,[2]]`, and a file ending on a bare `\x1e` placed the `break` it raises at that file instead of the missing one (`at missing:0`). The `--stream` and `--stream-errors` readers have their own end and are unchanged (#6591). Swept against jq 1.7.1 over 18 programs and 300 file lists of clean, faulty, empty and missing files, 5400 runs per mode: `--seq` 348 runs differ where 893 did, and none the other way; `--stream`, `--stream-errors` and `-R` are identical to before.
