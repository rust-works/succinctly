- **jq: a standard input that cannot be read is an empty one that ends the run with exit 2, as in jq** (#7126). `jq . 0>>file` (a descriptor not opened for reading), the write end of a pipe and a directory (`jq . < /`) read as empty and exited 0 (a directory also printed `Failed to read from stdin` and exited 1); jq 1.7.1 reads each as empty, says nothing on a plain read, and exits 2 whatever the program left (`-e`'s 4, `-n input`'s 5), on the plain filter, `-R`, `-s`, `--seq` and the `input`/`inputs` routes, and a standard input the program never reads (`-n 1`, `halt_error`) is unaffected. A closed descriptor 0 (`0<&-`) still exits 0, because Rust reopens it on `/dev/null` before `main` and a few combinations (a `-` followed by another source, `--seq -s`) differ in stderr or in a `-` the program never reaches; all are recorded in the limitations page. Pinned by 16 programs captured from jq 1.7.1 under four redirections (`tests/jq_cli/i7126.rs`).
