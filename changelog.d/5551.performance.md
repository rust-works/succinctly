- **cli: the default build starts about 22% faster on macOS** (#5551). `ctrlc` was a dependency of the `cli` feature, but only the benchmark runners use it (to write partial results on Ctrl+C), and on Apple targets it links `libobjc`, `Foundation` and `CoreFoundation`, which dyld loads on every start. The suites now install a plain `SIGINT` handler through the `libc` the CLI already uses, and `ctrlc` is a `bench-runner` dependency: the shipped binary links `libSystem` and `libiconv` only, and `succinctly jq -n 1` starts in 2.86 ms instead of 3.68 ms (median of 300 interleaved spawns, Apple M5 Max; `--version` 2.82 ms instead of 3.67 ms). Ctrl+C during `dev bench`, `utf8 bench` and the like still writes the results gathered so far on Unix; a Windows build without `bench-runner` has no handler, and Ctrl+C ends the run as usual.
