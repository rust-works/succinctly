- **jq: `--seq -s --stream` and `--seq -s --stream-errors` run the main loop once past a failed file** (#6796). A program that reads one `input` (`input`, `[., input]`, `first(inputs)`) over a file that did not open, or a directory, in the middle of the list ran the loop a second time: jq's slurp read every file in its first call and counted the failure there, so its loop ended after that call, but succinctly popped what the stream still held and said the fault at the end of the text (`Unfinished JSON term at EOF` under `--stream`, an uncaught `break` under `--stream-errors`). A slurp's loop now ends after its first call once a failure has been counted, for every slurp; the sweeps of `-s`, `-s --stream`, `-s --stream-errors` and `--seq -s` found no other row that differed before or after (`jq -c --seq -s --stream input trunc gone obj` says only `Could not open file gone`, as jq 1.7.1 does).
