- **`succinctly jq`'s `input` resumes after a caught parse error, as jq's does** (#4311). jq discards the rest of the read the fault is in (a line, or 4095 bytes of a longer one) and keeps reading at the next, into later files too. So `[limit(4; repeat(try input catch "E"))]` over `1 } 2\n3\n` is `[1,"E",3,"E"]`; succinctly stopped at the first parse error (`[1,"E","E","E"]`). Plain processing still stops at the first parse error, as jq's main loop does. On every route, a number or literal that the faulty byte itself completes is now lost to the error as in jq: `jq -c .` over `1\n2]` prints only `1`, where succinctly printed `1` and `2`.
