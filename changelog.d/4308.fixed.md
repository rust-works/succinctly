- **`succinctly jq` reports jq's line for a value that shares its line, and for a parse error** (#4308). jq's `(at <file>:<line>)` line is the number of newlines its reads have consumed once the value is complete. It reads through a newline (or 4095 bytes) at a time, so a value that completes mid-line takes that line's newline: `jq -c error` over `1 2\n3\n` reports lines 1, 1, 2, where succinctly said 0, 1, 2. A parse error's line likewise comes from where jq detects it: at the fault inside a malformed container (`0\n[1,\n2,\n}\n` is line 4, not 2) and at the closing quote of a string holding a raw control character. Both the default document loop and the `input`/`inputs` route now match. Resuming after a caught parse error is #4311.
