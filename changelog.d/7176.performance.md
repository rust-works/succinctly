- **jq: a program that reads `input`/`inputs` over several files no longer walks every file for a fault when none failed to open** (#7176). `read_inputs` ran jq's parser model over every byte of every named file twice before the program started (`json_text_faults` in the `ends_cleanly` test and `first_stream_fault` for the deferral), only to place a file that did not open; with no such file both answers go nowhere. They, and the `-n -s` walk for the first fault of the slurped text, are now asked only when a failure exists (`all` over no failure is true, so `ends_cleanly` is unchanged); `tests/jq_cli/i7176.rs` pins what a fault in the text does with no failed file against jq 1.7.1's answers. Interleaved against the commit before it, with an A/A control within 1.3% and outputs identical, on terminus (Ryzen 9 7950X) and johns-mac-mini (M4 Pro) over 4 and 33 files of 100 MiB of NDJSON: `-n 'first(inputs) | .id'` reads 762 ms to 52 ms and 860 ms to 15 ms (-93% and -98%), `-n 'reduce inputs as $x (0; . + 1)'` -47% and -53%, `-c '[., input] | length'` -27% and -35%, and at 10 MiB `first(inputs)` 78 ms to 6.4 and 92 ms to 4.6. Peak memory is unchanged (the files are still read whole).
