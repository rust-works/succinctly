- **jq: `@urid` follows jq 1.8.2 for a non-string, bytes that are not valid UTF-8 and its error text** (#6726).
  `succinctly jq` decoded valid input as jq 1.8.2 does and differed on the rest: a non-string raised `expected string, got number` where jq stringifies it first (`1 | @urid` is `"1"`, `["%41"] | @urid` is `"[\"A\"]"`), escapes that decode to bytes that are not valid UTF-8 (`%E4`, `%FF%FE`, `a%E4b`, an overlong form, a surrogate) printed U+FFFD where jq raises, and a malformed escape reported `invalid URL escape "%"` (yq's wording) where jq names the whole input, `string ("%") is not a valid uri encoding`, truncating a dump over 29 bytes to its first 25, `...` and the closing quote. All three now match a jq 1.8.2 binary on 172 rows (4 programs over 43 inputs) and a 1,500-input sweep that weights the inputs towards bad bytes. `succinctly yq` is unchanged (`url.QueryUnescape`: it stringifies a scalar, reads `+` as a space, raises its own `invalid URL escape`, substitutes U+FFFD), and `format("urid")` keeps jq 1.7.1's `urid is not a valid format`, the pin; the split is recorded in `docs/compliance/jq/limitations.md`.
