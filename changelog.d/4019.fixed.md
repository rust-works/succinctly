- **jq: a `catch` handler that navigates the node its `try` body raised is a path for scalar registers and for more body shapes** (#4019). `path(.d | .[] | try (if . == 3 then error(.) else . end) catch .)` and `path(.s | try error catch .)` refused with `Invalid path expression with result 3` where jq 1.7.1 answers `["d",0]`, `["d",1]` and `["s"]`, and `path(try (error(.)|error("x")) catch ((.a)? // 5))` on `{"a":{"b":1}}` refused where jq answers `["a"]`. A `try` entered on a path-tracked value whose body raises only its own input (`error`, `error(.)`, `error | error`, `error(.) | error("x")`, `select(c) | error`, an `if` over a total condition, a comma) now hands the handler the register's node, a number or string register included (it has no storage to compare), so `.`, `.a`, `.[0]`, `.[1:]` and `(.a)? // 5` reach it, through `path`, `del`, `=` and `|=`; the stage after such a `try` reads each handler output's own register, so `path(. as $x | try (error(.)|error("x")) catch ((.a)? // 5) | $x)` is `[]` on `{"d":[3,4]}` and still a path error on `{"a":{"b":1}}`, as in jq. A body that navigates first (`.[0] | error`), builds the payload by value (`error([.][0])`) or whose condition can raise still refuses, as in jq. Inside a `reduce`/`foreach` UPDATE or EXTRACT the handler is seeded as before, since a fold's source may have moved jq's register off the accumulator. Refuse-only before.
