- **jq: `input_line_number` past invalid UTF-8 after a fault counts jq's reads in the bytes jq read on the lazy-prefix route too** (#7948, second shape). When a fault falls past a quarter of a file, the documents before it are handed to the program lazily; that hand-off did not count their lines in the bytes jq read, as #7934 made the other hand-offs do, so on a line longer than jq's 4,095-byte read that holds invalid UTF-8 the reads were counted over the text with U+FFFD in it, three bytes for each byte replaced. Over a 4,090-byte line holding three strings with invalid bytes, a `1`, a bare `0xC3` at byte 4,086 and a newline, `select(type == "number") | input_line_number` printed `0` where jq 1.7.1 and 1.8.2 print `1`; it now prints `1`. A value before the fault took the same hand-off (#7980): over a quote, 4,090 `a`s, a quote, the byte `0xFF` and a newline, `input_line_number` printed `0` where both releases print `1`, and now prints `1`. The issue's first shape, after a NUL-ended number, is not changed.
