- **`succinctly jq` reads the edges of its input through the model of jq 1.7.1's reader on the default route too, and hands back to the semi-index at the next sync point** (#7987). A program that reads no `input` (`.`, `-c .`, `.field`) over JSON read whole (a lone file under 1 MiB, several under 1 MiB in all, or a pipe that ends within 512 KiB) still splits its input with the semi-index, and enters the model (ADR-0033, step 6) only on a trigger: a byte-order mark that is not whole, a fault, or invalid UTF-8 the route substituted, where the model reads from the last sync point before the substituted byte to the first sync point after it, validating what it reads, and carries the reader's state there to the next one. A fault ends the run, as in jq, and is read from the stream's start, so it is jq's first fault. On this route a mark that breaks off (`printf '\xef\xbf\xbd1' | jq .`) is now `Malformed BOM`, as jq 1.7.1 and 1.8.2 word it, where it used to say `Invalid numeric literal` (#5804; `--slurp`, a list with a file that did not open and the routes that read a window at a time keep the old wording until their own steps), and a malformed value in the file a fault is in is jq's fault rather than printed. Over two 2,000-case differentials of edge inputs and 22 programs, the 5,172 answers that changed moved to what both releases print (5,145, 5,034 of them the mark's wording), differ from both only at a NUL (26, ADR-0018's E2), or, once, print one value fewer of those an earlier file's lazy read let through (#3035), with jq's fault; none moved away from both, and the materializing route, `--slurp`, `--seq`, `--stream` and `-R` changed on none. `SUCCINCTLY_READER_MODEL=0` selects the old reader.
