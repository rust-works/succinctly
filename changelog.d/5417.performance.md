- **jq / yq: a parenthesized pipe driven one output at a time is linear in its stage count, not quadratic** (#5417).
  #5404 made the pipe an array constructor collects keep the owned copy of each tail it hands on; a pipe driven
  through the streaming drivers (`select`, `limit`, `first`, `last`, `nth`, `any`, `all`, `isempty`, a streamed
  result) built a fresh copy of its rest for every value of its first stage, at every stage, and a pipe with an
  effect before its last stage (`input_line_number`, `input`, ...) did the same through `eval_pipe`. Those drivers
  now ask the pipe that owns the rest, so the copies are the ones it already keeps (and they no longer walk the
  rest for path context at each stage). 20,000 values through a 40-stage pipe, interleaved min of 3 CPU
  seconds, output identical: `range(0;20000) | (T) | select(. == -1)` 1.96 s -> 0.35 s on an AMD Ryzen 9 7950X
  (n=20 0.57 -> 0.16 s, n=80 7.36 -> 0.74 s), 1.26 s -> 0.27 s on an Apple M5 Max (n=80 4.56 -> 0.54 s);
  `last` and `[limit(...)]` match it; an effect before the last stage 2.08 s -> 0.36 s (7950X). The array
  constructor row #5404 fixed is unchanged (+2% on the 7950X, within noise on the M5 Max), and the native-stack
  recursion limit of `def f: if . >= N then . else (. + 1 | f) end; 0 | f` moves from 7144 to 7138 levels
  (-0.08%). A tail holding a `def`, and a body rebuilt for each value (`. as $x | ...`, the body of a
  `reduce`/`foreach`), still copy per value.
