- **yq: an alias used as a mapping key stays an alias** (#5469). `printf 'b: &a xy\ne: {k: *a, *a : 1}\n' | succinctly yq .` printed `e: {k: *a, xy: 1}` where yq prints `e: {k: *a, *a: 1}`: the key was written as its anchor's text on every route. It is now `*a`, with yq's space before a block mapping's `:` (`*a : 2`) and none in a flow mapping, on the streaming route, after a write (`.zz = 1`, `sort_keys`, `with_entries`) and under `-P`; a target past 128 bytes stays `*a` rather than becoming a `? ` explicit key. On a write the alias is held to the anchor-soundness rules a value alias is, so one whose anchor is deleted (`del(.b)`) or rewritten (`.b = "q"`) prints the key's text, where yq keeps a `*a` that names no anchor or reads back as another key (recorded in `docs/compliance/yq/limitations.md`). Still different: `keys` and `.c |= to_entries` print an alias key as its text (as they already print an anchored key bare), `sort_keys` orders an alias key by its text where yq orders it by the anchor's name, and a lookup by the key's text (`.e.xy`) finds it here where yq does not.
