- **jq: `/dev/stdin` named as an input file leaves a redirected stdin where jq does, and `--stream` reads it** (#7568). On macOS, where `/dev/stdin` and `/dev/fd/0` open as descriptor 0 itself, `{ jq -n input /dev/stdin; head; } < f` and `jq halt /dev/stdin` left the file at its end, where jq 1.7.1 and 1.8.2 leave it at the end of the line that completed the last value; it is now put back as a `-` is. `jq --stream . /dev/stdin < f` (and `/dev/fd/7 7<f`) failed with `Invalid numeric literal at line 1, column 2`, because the probe of the file's first bytes moved the shared offset; it is moved back, and the stream reads as jq reads it. On Linux, where the path opens the file again from its start, a `-` after it (`jq -n input /dev/stdin - < f`) left the file at its end, where jq's reader never reaches the `-` and leaves it untouched; the path is now read again by its name to count what jq read of it, as a named file is.
