- **yq: `--on-error=continue|stop`, the flag `succinctly jq` has had since #5471** (#5507). Without it nothing changes: `succinctly yq` stops at the first error the program raises and exits 1, as yq does (#2810). `--on-error=continue` evaluates every document and file instead, reports every error and exits 1 if any failed, on the streamed, evaluated, `--sort-keys` and `--split-exp` routes alike. `--on-error=stop` spells the default out, and under `--inplace` it also edits no file after the first one that failed (the default carries on and leaves a failed file untouched). yq has no such flag, so both are succinctly extensions (ADR-0018 rule 5); the exit code stays 1 in every mode. See `docs/guides/cli.md` and `docs/compliance/yq/limitations.md`.
