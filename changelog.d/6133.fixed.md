- **jq: a regex option run that repeats `-` or ends on one is read as in jq** (#6133). `"a" | test("(?-)a")`, `test("(?--i)a")`, `test("(?i-m-s)a")` and `test("(?i-:a)")` failed with the `regex` crate's parse error, where Oniguruma turns options off from the first `-` and takes a later `-` as a no-op (so `(?i-m-s)` is `i` on, `m` and `s` off). The run is rewritten to its single-`-` equivalent before the crate sees it, and the extended-mode tracking follows the rewritten run. Checked against jq 1.7.1 over every option run of up to four of `i`, `m`, `s`, `x`, `-` in four pattern shapes on five inputs (15,620 runs, 2,560 of them differing before). A blank inside a character class under the extended mode (`(?x:[a b])+`, `(?x)[a b]+`, `(?x-:[a b])+`) is now kept literal as in Oniguruma, where the `regex` crate dropped it, and a letter repeated in a rewritten run is applied once, in order.
