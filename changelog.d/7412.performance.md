- **jq: `[.[] | f]` over a document's array no longer holds every element's cursor beside every value** (#7412).
  Once a long run of elements has each yielded one computed value, the fold now writes those values over the
  32-byte cursors it has already read, in the cursors' own buffer, instead of into a second vector of the
  same size. Peak RSS at 100 MB, on an AMD Ryzen 9 7950X and an Apple M4 Pro: `[.numbers[] | floor] | add`
  545 -> 332 MB on both, `[.strings[] | length] | add` 156 -> 133 MB, `[.strings[] | ascii_upcase] | length`
  247 -> 225 MB, and `[.users[] | .name | ascii_downcase] | length` 153 -> 132 MB and 143 -> 122 MB. At 10 MB
  the `strings_*` rows drop 2.0-2.3 MB, which puts their private memory below jq 1.7.1's (13.9 against
  15.8 MB on the 7950X). `[.numbers[] | floor] | add` is also 8% faster on the 7950X.
