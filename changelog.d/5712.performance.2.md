- **jq: a stage that reads only a bound computed string or array is answered once per round, not through the reindex bridge each round** (#5712).
  `. as $t | [range(25) | ($t | length)]` after a computed stage (`.s | ascii_downcase | . as $t | ...`) wrote `$t` out as JSON text and indexed it again for every round, because the eager owned route had no answer for an expression that never reads `.` (its lazy twin did). It now takes the same closed-expression route, and a closed pipe answers a comparison, boolean or `try` over a string's length (`$t | length > 3`) and its prefix tests from the string.
  A closed pipe also reads a marker head in place instead of cloning it; a string marker's clone is a copy of the whole string, which a declined stage paid for nothing.
  On an AMD Ryzen 9 7950X (terminus, jq mode, min of 11 interleaved runs, output identical on all 18 configurations), over a computed string of 1 / 8 / 32 MB of text: `[range(25) | ($t | length)] | add` 281 / 2047 / 9484 ms to 40 / 308 / 1473 ms; `[range(25) | ($t | length > 3)] | length` 281 / 2006 / 9416 ms to 40 / 304 / 1472 ms; the same over a computed array 167 / 1298 / 5522 ms to 33 / 245 / 967 ms; `reduce range(25) as $i (0; . + ($t | length))` 41 / 308 / 1470 ms to 40 / 294 / 1165 ms. A shape the route does not answer (`$t | length + 1`) is unchanged within noise (-0.1% / -1.4% / -1.0%), and so is a lone `length` (+0.3% / -0.6% / -0.3%). yq mode is unchanged.
  Measured on x86_64 only; ARM64 was not.
