- **A malformed JSON document left with containers open at end of input no longer panics** (#7482). `{"a":` and 44 `[` closed by one `}` panicked `succinctly jq .` with an index out of bounds in `BalancedParens::is_open` (exit 101) on the file and pipe routes, `-s`, `-n input`/`inputs` and `--slurpfile`; it now prints jq's `parse error: ':' not as part of an object at line 1, column 55` (exit 5), as a shallower document already did. The standard JSON index takes its parenthesis length as two bits per open and the closes such a document lacks as the zero bits after the last one written; once they crossed a word boundary the length ran past the stored words, so the index now stores them. `succinctly jq-locate` on such a document now names a path, as it already did when the missing closes fit in the index's last word, where it answered `Could not locate position`.
