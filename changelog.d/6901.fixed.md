- **yq: `to_yaml`, `@yaml` and `tostring` of a document node keep how it was written** (#6901). yq encodes a node with its own presentation, and these printed the canonical block text of its value instead: `.o | to_yaml` over `o: {p: 1, q: {r: 2}}` is `{p: 1, q: {r: 2}}` in yq and was `p: 1` / `q:` / `  r: 2`. A container that is a document node (a navigated one, or one bound by `as $x`) is now encoded by the writer the CLI prints that node with: a flow collection stays flow, a flow collection nested in a block one too, a trailing comment (`[a, b] # c`) stays, a sequence item keeps its own head and foot comment lines, and an alias node is the reference `*x` (a scalar alias too). `to_yaml(N)` keeps the indent rule. Checked against yq v4.53.3 on 800 queries (`.. | select(kind == "map" or kind == "seq") | to_yaml` and `| tostring` over 400 YAML files in the repository): the old build agreed on 341, this one on 748, with no query that agreed before differing now; 37 rows are pinned in `tests/yq_cli/i6901.rs`. A value the filter builds (`[.a] | to_yaml`, `{"k": .a} | .k | to_yaml`, a node behind a write or `with_entries`) has no node to read, and still prints block; it is recorded in `docs/compliance/yq/limitations.md`.
