- **yq: a comment block between a bare `-` and its value, followed by a blank line, is the value's foot comment** (#7044).
  `- 1` / `-` / `  # c` / blank / `  n1: 1` prints `- n1: 1` / `  # c`, as yq does, where it printed `- # c` / `  n1: 1`, and `.[1].n1 | key | foot_comment` is `c` (it was the key's `head_comment`); a block after the blank line is still the head, and so is the whole run when nothing came before the item, a blank line sits above the block, or the dash line has a comment of its own.
  The same holds for a scalar, a nested sequence's first key, a later document, and CRLF text: against yq v4.53.3, 51 of 54 rows over 27 shapes now agree, where 7 did.
  Lines below the dash are now told from those above it by position, so a block above the dash that a blank line settles no longer pulls the first line below it onto the item (`- 1` / `# e9` / blank / `-` / `  # d` / `  k0: 1` puts `d` on `k0`, as yq does).
  Over 800 random comment-heavy sequences (yq, `main`, this change) 222 outputs now match yq, none that matched stopped matching, and none of the rest moved further from it.
  A flow collection value (before which yq drops the block) and a dash line carrying the value's tag or anchor still differ.
