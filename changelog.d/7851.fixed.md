- **jq: a byte-order mark that breaks off stops the read in the file it breaks off in, as in jq** (#7851). jq's parser faults with `Malformed BOM` on the first byte that departs from a mark at the front of the stream (`EF` in one file and `EF` in the next, or `EF BF BD` in one) and its main loop stops, so the files after that one are never opened. `succinctly jq` read on past it: `jq . ef.json ef.json missing.json` also printed `Could not open file missing.json` and exited 2 where jq exits 5, a directory there made the run exit 2, and `jq -n '[inputs]'` named the last file in `(at ...)` instead of the one the mark broke off in. Fixed for the plain routes, `-s`, `-n` with `input`/`inputs` and `--stream -s`, with the mark broken off across files or inside the first one; `--seq` and `-R`, which jq reads on past it, are unchanged. The fault keeps its numeric-literal wording outside `--stream`, as documented.
