- **`succinctly jq -n -s --seq --stream` reports a last file that does not open, and `-s --seq --stream` reads a program's `input` after the whole slurp** (#6676). `jq -c -n -s --seq --stream input two.seq missing.json` printed the array and exited 0 with nothing said (a regression of #6694); it now says `Could not open file` and exits 2, as jq does. A last file that does not open is now a source of the stream reader's slurp, so a closing event held back at the end of the file before it goes in the array (`jq -c -s --seq --stream . arr.seq missing.json`, `arr.seq` = `\x1e[1]`, prints `\x1e[[[0],1],[[0]]]`, not two values) and `input_filename` names the failed file. Without `-n`, a program that reads `input` no longer gets the stream's faults as inputs: jq's main loop reads the slurp first, so the warnings and failures print in the reader's order before the program runs, a warning met after a failure stops the run before the program starts (`jq -c -s --seq --stream input empty.seq dir`), and its `input` reads only what follows the array.
