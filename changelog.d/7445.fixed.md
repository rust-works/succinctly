- **jq: a bad escape in a program string literal is jq's JSON decoder message** (#7445). `jq -n '"ab\q"'` printed succinctly's own `invalid escape sequence '\q'`, and `"\u12"` and `"\ud800"` `invalid unicode escape` and `invalid surrogate pair escape`; `succinctly jq` now prints what jq 1.7.1 and 1.8.2 print, the decoder's message for the run of escapes the fault sits in: `Invalid escape at line 1, column 4 (while parsing '"\q"')`, `Invalid \uXXXX escape at line 1, column 6 (while parsing '"\u12"')` and `Invalid \uXXXX\uXXXX surrogate pair escape at line 1, column 8 (while parsing '"\ud800"')`. Every bad run is an error of its own and is counted (`"\q\(1)\q"` is `2 compile errors`), and the parse goes on after it, so a syntax error later in the program is reported too. The same for a format string, an object key, a field access and the path of an `include`. `succinctly yq` is unchanged.
