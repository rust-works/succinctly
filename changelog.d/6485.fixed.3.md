- **jq: `--stream` reports a file that does not open when its reader reaches it, not when the run starts** (#6485). `jq -c --stream . bad.json missing` with `bad.json` holding `[1,}` printed the open error first and exited 2; jq 1.7.1 prints the first event and the parse error and exits 5, because its reader stops at the fault and never opens the file after it. A second missing file after the value that follows the first failure (`nums.json missing mid.json missing`) is no longer reported either, as in jq, whose main loop reads no further once a file has failed. The same holds under `-n --stream` with `input`/`inputs`. A last file that did not open is a source of its own, so a number at the end of the file before it waits for the read that opens it (`-n --stream input a1 gone`), and a directory last fails the run when the reader reaches it. Pinned over 30 rows against jq 1.7.1 in `tests/jq_cli/i6485_chunked_stream.rs`. `--stream-errors` without `-n`, `-R`, `--seq` and DSV, which read every file first, still report every failure up front.
