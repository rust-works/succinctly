- **jq: a `--rawfile` or large `--arg` value is no longer read for `__jq` on every run** (#7880). Since #7719 the walk that decides which evaluator runs a program looked for `__jq`, the key of jq's label value, in every string of the program, and a named argument's value is substituted into the program as one, so `-n --rawfile s FILE '$s|length'` paid two passes over the file. Whether the run spells `__jq` is now decided from the program as written, before the arguments are substituted, and an argument's value is read for it only by a program that holds an `error`, the one way to raise a value that is not a string; the refusal check and the route decision also share one walk instead of two. Cachegrind instruction counts on an AMD Ryzen 9 7950X box (valgrind 3.18.1, `--cache-sim=no`): `-n --rawfile s users-10mb.json '$s|length'` 91.41M to 8.85M (8.84M before #7719) and 9.92M to 1.92M over the 1 MB file (1.90M before); `--arg` with a 120 KB value 4.25M to 2.81M; `-n 1` 1,135,403 to 1,133,237. A program that does raise (`try error($s|length) catch .` over the 10 MB file) reads the value once: 91.42M to 13.06M.
