- **jq: an `--argjson` text and a `--jsonargs` word are parsed once, not twice** (#7881). Since #7743 (option errors in argv order, #7712) the walk over argv parsed each `--argjson` text and each `--jsonargs` word to check it where jq's option loop checks it, dropped the value, and the run parsed the same text again to bind it. The walk now keeps the value it built, under the word's place in argv, and the run binds that value when the text it is asked for is that word's; a name an earlier flag bound is still skipped unread, and every option error is reported where it was. Cachegrind instruction counts on an AMD Ryzen 9 7950X box (Linux, valgrind 3.18.1, `--cache-sim=no`, stripped release builds with `--features cli`) for `-n --argjson v VALUE 1`, the commit before #7743 in brackets: a 100 KB array of small objects 81.17M to 39.65M (39.62M), a 100 KB array of numbers 73.58M to 36.17M (36.18M), one 100 KB string 10.59M to 6.44M (6.36M); at 10 KB 9.35M to 5.07M (5.06M), 8.62M to 4.78M (4.77M) and 2.10M to 1.68M (1.65M). The same 100 KB values as a `--jsonargs` word: 80.75M to 39.23M, 73.18M to 35.61M and 10.16M to 6.02M. `-n 1` is 1,102,295 before and 1,101,749 after (1,077,583 at the commit before #7743, so about 24,000 of each bracketed difference is start-up cost that other changes added since). The CI perf guard gains a row for an `--argjson` value (`argjson_objects`), which no row covered.
