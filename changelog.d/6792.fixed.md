- **yq: a `(PATH | key)` target inside a union is no longer dropped, and several key-node targets are written** (#6792). `((.a | key), .b) head_comment = "x"` wrote only `.b`'s text and printed the document with exit 0, because a union of targets was not read as holding a key target: the key's text was lost without a word, as were `line_comment` and `style`. Each branch of a union is now resolved on its own. A key node among value targets is refused (the head of a value is the next key's, which interact in an order yq's emitter decides and that is not modelled), and `(.[] | key) head_comment = "x"`, `((.a | key), (.c | key)) comments = "x"` and the `|=` forms, several key nodes and nothing else, are written, as yq writes them. Measured against yq v4.53.3 over a 224-row matrix of key targets (4 setters x 2 texts x `=`/`|=` x 14 target shapes): 116 rows match yq, the rest are refused, none exits 0 with a different result (before: 120 did, and 12 matched by accident because the key was dropped); 9 goldens pin it.
