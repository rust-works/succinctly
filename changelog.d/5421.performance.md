- **jq: a parenthesized pipe holding a `def` call is linear in its stage count, not quadratic** (#5421).
  #5404 and #5417 keep the owned copy of each tail a pipe hands on, but refused a tail holding a `def` call (a node
  remembers what evaluation did to it, so a copy shared across values would carry that across them), so one call
  anywhere in a tail made every tail containing it copy its rest per value at every stage. A tail of at least 8
  stages holding a call is now handed on in pieces: each run of plain arithmetic, comparison or literal stages
  between its other stages is a copy the pipe keeps like any other tail, and every other stage (the call, a
  `select`, a fan-out, a navigation, a `?//` bind) is cloned afresh for the call, so the evaluator reads a pipe of
  the same stages and every route behaves as before. `succinctly yq` is unchanged and hands the tail on whole.
  20,000 values, interleaved min of 5 CPU seconds, output identical, `[range(0;20000) | (. + 1 | ... | f)]` with
  a call at the end: n=8 0.125 s -> 0.065 s, n=14 0.375 s -> 0.117 s, n=20 0.658 s -> 0.171 s, n=40 (5,000
  values) 0.551 s -> 0.090 s on an AMD Ryzen 9 7950X; n=8 0.095 s -> 0.045 s, n=14 0.221 s -> 0.080 s, n=20 0.400 s
  -> 0.114 s, n=40 0.340 s -> 0.060 s on an Apple M4 Pro. Shorter tails and the same pipe without parentheses
  are unchanged (n=6 and the flat spelling within 4%). The kept runs are held for the life of the program, up to
  1,024 nodes each in pipes of up to 128 stages, which a pipe with a call did not hold before; a pipe with more
  than one call every few stages gains little, and a body rebuilt for each value that reads its variable (`. as $x | (...)`, the
  body of a `reduce`/`foreach`) still copies its rest per value (#5424 links the bodies that do not).
