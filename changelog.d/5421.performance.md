- **jq / yq: a parenthesized pipe holding a `def` call is linear in its stage count, not quadratic** (#5421).
  #5404 and #5417 keep the owned copy of each tail a pipe hands on, but refused a tail holding a `def` call (a node
  remembers what evaluation did to it, so a copy shared across values would carry that across them), so one call
  anywhere in a tail made every tail containing it copy its rest per value at every stage. A tail of at least 8
  stages holding a call is now handed on as the runs of stateless stages between its stateful stages, each a copy the
  pipe keeps like any other tail, and a fresh copy of each stateful stage; the evaluator sees a pipe of the same
  stages, so every route and both modes are unchanged. 20,000 values, interleaved min of 5 CPU seconds, output
  identical, `[range(0;20000) | (. + 1 | ... | f)]` with a call at the end: n=8 0.126 s -> 0.066 s, n=14 0.362 s
  -> 0.113 s, n=20 0.671 s -> 0.164 s, n=40 (5,000 values) 0.543 s -> 0.085 s on an AMD Ryzen 9 7950X; n=8
  0.094 s -> 0.047 s, n=14 0.228 s -> 0.083 s, n=20 0.418 s -> 0.115 s, n=40 0.351 s -> 0.062 s on an Apple M4 Pro.
  Shorter tails, and the same pipe written without parentheses, are unchanged (n=6 and the flat spelling within
  +3%). A body rebuilt for each value (`. as $x | (...)`, the body of a `reduce`/`foreach`) still copies its rest
  per value (#5424).
