- **jq: the fault after a number or literal directly before a final unterminated string is named `<unknown>`** (#7810). When the input ended in a number or `true`/`false`/`null` directly followed by an unterminated string (`printf '2"' | jq -nc '[inputs]'`), the error `input` raised named `(at <stdin>:0)` (or the file), which is jq 1.8.2's answer; jq 1.7.1, whose positions `succinctly jq` keeps after the last input (#7607), names `(at <unknown>)`, as it already did for a final `[` or `{` (#6004). Both shapes now also follow jq's 4095-byte reads: when the last line fills its reads exactly, the value was completed before the read that reached the end, and the fault keeps the file's name (4,093 spaces then `2[` named `<unknown>` before). The reader `--seq --stream` reads with (and `--stream -s`, since #7807) named `<unknown>` for a fault at the end of the text when an empty file or an empty read came after the last bytes, where both jq releases name that file (`(at e.json:0)`).
