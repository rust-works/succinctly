- **jq: a `catch` handler that is a compound of `select` stages keeps the path register, as in jq** (#4151). `succinctly jq 'path(. as $x | try (select(.), error("e")) catch (select(.), 7) | $x)'` raised `Invalid path expression with result {...}` where jq 1.7.1 prints `[]` three times, and the same held for `catch (numbers // 7)`, `catch (if . then select(.) else 7 end)` and `catch (select(.) | 7)`, through `del`, `=` and `|=`. The handler runs on the error's payload, a value with no position, so it is read branch by branch (`,` `//` `if`, a pipe) and each branch only has to navigate nothing, a `select` or type filter counting as one. A handler that navigates (`catch (select(.), .a)`) is refused as before. Checked with `scripts/jq-path-register-sweep.py` over 16,131 rows of 19 new handler operands (0 regressions, 0 `ACCEPT_WRONG`, 491 rows moved to jq's answer) and a seeded 40,000-row sample of the whole grid (`--sample 40000 --seed 7`).
