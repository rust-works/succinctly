- **yq: `fromjson` skips up to two leading byte-order marks** (#5325). `"<BOM>[1]" | fromjson` raised `Invalid numeric literal`; yq answers `[1]`, and `"<BOM><BOM>[1]"` too (its reader drops one mark and go-yaml another, so a third is part of the text). Captured against yq v4.53.3 for an object, a number, a string, `null`, `true`, and a value led by spaces or a newline. A mark with no JSON after it stays an error in both. Jq mode is unchanged (it skips one, #5312). Trailing content, text that is not JSON and whitespace alone are still decoded differently from yq's YAML decoder; `docs/compliance/yq/limitations.md` lists them.
