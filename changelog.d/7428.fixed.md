- **jq: `-L` replaces the module search list, and its `~/` and `$ORIGIN/` entries are expanded** (#7428, #7430). With any `-L`, `import`, `include`, a data import and `modulemeta` still searched a `~/.jq` directory after the `-L` directories, so a module that exists only in `~/.jq` was found where jq 1.7.1 and 1.8.2 answer `module not found` (`get_search_list` already reported the `-L` list alone). The default list (`~/.jq`, `$ORIGIN/../lib/jq`, `$ORIGIN/../lib`) is now searched only when no `-L` is given. `-L '~/dir'` and `-L '$ORIGIN/dir'` are expanded to `$HOME` and to the directory the binary was run from, as jq does (`~` and `$ORIGIN` with no slash stay literal), so the default `$ORIGIN/../lib/jq` and `$ORIGIN/../lib` are found too, and `-L ""` no longer stands for the working directory in `modulemeta`'s search. Pinned against a 513-row directory-tree matrix on jq 1.7.1, jq 1.8.2 and `succinctly jq`, where the two jq versions agree on every row.
