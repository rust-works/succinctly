- **jq: a non-ASCII letter in a name is a compile error, as in jq** (#7433). `.é`, `.中`, `{é:1}`, `def é: 1; é`, `. as $é | $é`, a label, an import alias and the like were accepted, where jq 1.7.1 and 1.8.2 refuse each as `INVALID_CHARACTER` (exit 3): a jq identifier is `[a-zA-Z_][a-zA-Z_0-9]*`. Every name scan now reads one ASCII predicate. A quoted name (`."é"`, `{"é":1}`) and a string still take any text. `succinctly yq` follows yq: the unquoted path element after a `.` still takes any character (`.é`, `.中`), and every other spelling of a non-ASCII name is refused, as yq's lexer does. `succinctly jq-locate` now writes a key with a non-ASCII letter as `["é"]` rather than the `.é` jq cannot read back.
