- **jq: streaming input reads 256 KiB windows instead of 1 MiB, so a stream holds about 1-2 MiB less** (#7412).
  The plain, `--seq`, `-R` and `inputs` routes read their source a window at a time, and the window was most of
  the private memory a streaming run held: `-r .name` over a 100 MB NDJSON file held 2.0 MiB of anonymous memory
  on an AMD Ryzen 9 7950X where jq 1.7.1 holds 0.8, the same over a pipe 3.2 (two windows in flight with the
  thread that certifies them), and `reduce inputs` 2.7. The window is now 256 KiB, a file is read in windows from
  1 MiB (4 MiB before) and a pipe from 512 KiB, and a file under 4 MiB that is one long document is read on to
  its end at once, as it was read whole before. Peak RSS at 100 MB: `-r .name` 6.5 to 5.6 MiB on the 7950X and
  4.8 to 3.8 MiB on an Apple M4 Pro (jq 1.7.1: 3.4 and 2.8), over a pipe 7.8 to 5.8 and 6.1 to 4.3, `reduce inputs`
  7.3 to 6.1 and 5.9 to 4.5; three 1 MB files 7.8 to 5.7 and 6.4 to 3.7. Times are unchanged within an A/A
  control on both machines from 1 MB to 1 GB, and the 1 MB rows are 2-11% faster on the 7950X.
