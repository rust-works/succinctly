- **jq: a parenthesized pipe over computed values is linear in its stage count, not quadratic** (#5404).
  A pipe of `n` stages that runs over values the program computed (`[range(0;20000) | (. + 1 | . + 1 | ...)]`)
  rebuilt an owned `Expr::Pipe` of the rest of the pipe for every value at every stage, and each copy re-ran the
  analyses a pipe asks of itself. The pipe now keeps the copy of each tail it hands on (pipes of up to 128 stages;
  a tail holding a `def` is still copied per call), and remembers the three syntactic facts the owned re-entry
  walked the whole rest for. 20,000 values on an Apple M5 Max, interleaved min of 3 CPU seconds, output identical:
  n=20 0.436 s -> 0.120 s, n=40 1.508 s -> 0.233 s, n=80 5.444 s -> 0.451 s, flat spelling unchanged
  (0.150 s -> 0.152 s at n=20); 200,000 values through a 10-stage pipe 1.150 s -> 0.408 s (-64.5%) and through a
  3-stage pipe -20.9%. Document-sourced pipes, which were already linear, are within noise.
