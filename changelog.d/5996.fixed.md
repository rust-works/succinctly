- **jq: `strptime`'s `%s` skips leading zeros before it counts digits** (#5996). `%s` read at most 19 characters, so `"00000000000000000001"` left a `1` behind and was no match, where jq's libc reads the whole run with `strtol`: it is `[1970,0,1,0,0,1,...]`, as are `"0000000000000000000000000042"` (42 seconds), `"-000000000000000000001"` (the second before the epoch) and a signed run (`"+0000000000000000000001"`). The 19-digit limit is now on the significant digits, so `"99999999999999999999"` and `"9223372036854775808"` stay no match, as in jq. Checked against jq 1.7.1 on macOS over 2,808 rows (three signs, 0 to 25 leading zeros, twelve values, three formats): 346 differed before and 52 now, all one value, `67768036191676799`, where jq's `tm_year` wraps to `-2147481748` and this answers no match as before.
