- **jq: a run at the user's process or thread limit answers instead of failing to start** (#7733). Under `ulimit -u`, `prlimit --nproc` or a container's pids limit, `main` could not create the evaluation thread it runs on at any stack size (`EAGAIN`), and every run, even `jq -n 1`, ended with `failed to spawn the evaluation thread ... (os error 11)`, exit 1, where jq 1.7.1, which is single-threaded, runs. The run now goes on the main thread, with ADR-0025's native-stack floor registered at that thread's real stack (on Linux the soft `RLIMIT_STACK` is first raised to 64 MiB when it is lower and the hard limit allows), so deep recursion is still refused with jq's depth error instead of overflowing, at a shallower depth than on the evaluation thread. `succinctly yq` and the other subcommands take the same route.
