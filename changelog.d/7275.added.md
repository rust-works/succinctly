- **`json generate -p users-seq` writes the `users` document as one RFC 7464 record** (#7275).
  It is an RS byte, the document and a line feed, the input `jq --seq` reads one large record from; `--verify` checks
  the frame. The plain `users` document holds no RS byte, so `--seq` over it reads no record in either tool, and the jq
  comparison's `users_seq_output` row, named for `--seq` output, timed discarding that stream. The row keeps its id and
  its input, because the committed reports quote it, and is now described as what it measures; a new row,
  `users_seq_records`, runs the same program over pinned `users-seq` inputs and writes one record per user. No
  committed report holds the new row until its platform is run again.
