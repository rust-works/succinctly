- **jq: a standard output that cannot be written is reported, as jq does** (#7214).
  `succinctly jq . 1<file` (a descriptor opened read-only) printed nothing and exited 0, because Rust's
  `std::io::Stdout` reads `EBADF` as success; it now prints `jq: error: writing output failed: Bad file descriptor`
  and exits 2, as jq 1.7.1 does. A closed descriptor 1 (`>&-`) is still written to `/dev/null`, which Rust's runtime
  reopens it as before `main`; the divergence is recorded in the limitations page.
