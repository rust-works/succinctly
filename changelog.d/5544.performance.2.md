- **jq: a `reduce`/`foreach` loop variable read through a parenthesis (`($u).score`, `(($u)).score`, `($u)["score"]`) converts only the members it reads** (#5544, item 1B). The test for "reads `$u` only as the head of a field chain" looked for a bare `$u` followed by `.k`, so a parenthesis around the variable counted as a read of the whole element and each element was converted whole. A parenthesis only groups, so it is now seen through there; one around the field stage (`$u | (.b)`) projects the same way (#5957). `reduce .users[] as $u (0; .+($u).score)` over a 35 MB document takes 344 ms instead of 442 ms on an Apple M5 Max (interleaved min of 7, output identical; `$u.score`, which already projected, is 256 ms either way, so the parenthesised spelling still pays for what it does to the arithmetic around it), and on a document with a member that does not decode and that nothing reads (`[{"a":"\ud800","b":5}]`) it answers `5` as `$u.b` does, where it raised. A bare `$u`, `[$u]`, `($u | length)` and a read of the member itself still decode. x86_64 and ARM64 chips other than the M5 Max were not measured.
