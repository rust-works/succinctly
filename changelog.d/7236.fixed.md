- **`succinctly yq` drops the old comments when `.[]` replaces each node it reaches with a literal sequence or mapping** (#7236). `x:` / `- 4 # c616` / `- 7 # c2` written `.[] |= [1, 2]` is `x:` / `- 1` / `- 2` as in yq v4.53.3, where it kept `# c616` and `# c2` on the new items (the same for `.[] = [1, 2]`, `.a[] |= [3]` and `.[] |= ([1] | .)`); it paired the old sequence's items with the new one's by position, because `.[]` named no path to write a literal at. A write through a named path (`.x |= [1, 2]`) was already right, and the two now agree. A scalar written through `.[]` keeps its own comment, as before, and so does a body that reads the node (`.[] |= . + [1]`). A random fuzz of 3,700 documents and writes against yq fixed 51 cases and changed none that already matched. A held comment beside an empty `[]` / `{}` or `null` result and a `select` inside the path are not part of this fix.
