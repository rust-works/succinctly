- **jq: under `-n --seq`, `input`/`inputs` raise the stream reader's parse errors** (#5640). A record cut off at EOF (`\x1e[1,`), an unfinished string, a number at EOF without its RS, a stream that starts with a malformed BOM or a stray `}` between records were read as no input and exited 0, where jq raises each (`Unfinished JSON term at EOF at line 2, column 0`, `Invalid numeric literal ... (need RS to resync)`, exit 5, named `(at <stdin>:N)`, or `<unknown>` for the EOF report jq defers past the last value). Each error comes behind the values read before it and the reads after it resume, so `try input catch .` sees it; under `-s` every one is raised before the slurped array. A plain run still only warns `jq: ignoring parse error`. The stream with no RS byte at all (`1 2`) also raises `Unfinished abandoned text at EOF`.
