- **yq: `eval(expr)` evaluates a stored or computed expression against the current node** (#6081). `printf 'path: .a.b\na: {b: 7}\n' | succinctly yq 'eval(.path)'` is `7`, as in yq v4.53.3, where it was `eval/1 is not defined`. Each string `expr` yields is parsed as a yq expression; a node that is not a scalar is the empty expression, which is the node itself, and a write through `eval` lands (`eval(".a") = 5`). 45 rows captured from yq are pinned; a node reached through `eval` prints in the style of a built value, nothing follows its position out (`eval(".a") | key`), and a stored expression that evaluates itself stops at 32 levels instead of overflowing the stack (`docs/compliance/yq/limitations.md`). `is_key`, the other half of #6081, is still not defined.
