- **`succinctly yq` writes a top-level string as its own text from `to_yaml` and `@yaml`** (#5836). yq's encoder unwraps a scalar root while `--unwrapScalar` holds, the default, so `"<<" | @yaml` is `<<`, `"1"` is `1`, `"- x"` is `- x` and `"x\ny"` is two lines, where go-yaml would quote each of them and they printed quoted here. A string inside a collection (`["<<"] | @yaml`) is quoted as before, and so is every string under `--unwrapScalar=false` and `-o=json`. A probe of 1,820 rows against yq v4.53.3 (27 strings, 14 filters, 5 flag sets) fixed 786 and changed none that already matched; a multi-line string inside a collection (yq writes a literal block) and a string encoded twice under `--unwrapScalar=false` are not part of this fix.
