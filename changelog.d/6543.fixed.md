- **yq: a block scalar header to the left of a chain of dashes or of an explicit key's value is refused, as yq refuses it** (#6543). `- -` / `|` / `  t` (the header at column 0, left of the second dash at column 2) is `did not find expected '-' indicator` in yq v4.53.3 and was read here as `[[null],"t\n"]`; the same held for `- - -`, a dash with only properties (`- - &x`), a bare `?`, and a key or dash after an explicit key (`? x` / `: - k:`, `- ? k:` / `  |`, `a:` / `  ? k:` / `  |`), which read as an empty value or as an item. #6540 refused the header left of a colon-ended key behind dashes; the same rule now covers the last marker of a line that ends in one and the `?` and `:` markers of an explicit key: a header on a line of its own is a value slot only at the owner's column or to its right (`- -` / `  |` is still the second dash's value), and is judged ahead of the arms that take an own-line header, which the chain and the bare `?` never reached. The wording of the refusal can differ from yq's for an explicit key (yq words it by the container it stops in), the exit status and the empty output do not. A differential of 2,556 documents against yq v4.53.3 found 87 accept-versus-refuse differences on the second grid before the change and 32 after, none of them in a header's column (they are a block scalar's content lines more indented than a later one, `- &x` / `  |` / `    t` / `` / `  u`), and no document yq reads is refused (#6550).
