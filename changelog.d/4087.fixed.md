- **yq: a boolean or `null` index into an absent container reads as `null` and a write builds a mapping keyed by its text** (#4087). On a document with no `a`, `.a[true]`, `.a[null]`, `.a[true].b` and `[.a[true]]` are `null` and `.a[true] = 1`, `.a[null] |= 5`, `.a[true][0] = 1`, `(.a[true], .x) = 1` and a computed `true as $k | .a[$k] = 1` build `a: {true: 1}`, `a: {null: 5}`, `a: {true: [1]}` (they raised `Cannot index null with boolean`/`null`); `del(.a[true])` and `del(.a[true], .x)` are no-ops. jq mode still raises. A boolean or `null` key on a scalar target is yq's no-op, as a numeric key is. Pinned by 32 rows captured from yq v4.53.3 and an eager-route unit test; a 5,376-row differential of reads, `?`, `=`, `|=`, `+=`, `del`, chained and grouped shapes over six documents against yq changed 1,427 rows to yq's answer and none away from it. Not changed: a `del()` through such a key on an explicit `null` (`d: ~`) stays `null` where yq vivifies `{}`, and a computed key that is `null` only because its source field is absent (`.a[.b]`) is not told apart from a literal one (yq: `a: []`).
