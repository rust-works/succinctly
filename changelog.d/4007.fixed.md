- **jq: a `foreach` source that destructures a computed `null` no longer lets `del`/`=`/`|=` write where jq refuses** (#4007, a #3940 residual). `del(null | foreach ((.|.) | foreach . as {a:$a} (0;.;.)) as $x (.;.;.))` on `{"a":null,"b":2}` is jq's error (exit 5, `Invalid path expression near attempt to access element "a" of null`); the walk seeded the ambient `null` of an untracked stage as the register and stepped through it, so `a` was deleted at exit 0. The same held for `null as $n | $n |`, a fold's `null` accumulator, `=` and `|=`. An untracked stage's placeholder value is now unknown to the walk, as `resolve_as_pattern` already treated it, so the first step refuses. On a `null` document the register really is `null` and the walk still answers (`["a"]`). The same placeholder after a fold UPDATE that leaves the register unknown (`foreach (1) as $y (.; (def f: null; f | f); foreach (null) as {a:$x} (.; .; $x))`) deleted `a` from `{"a":1,"b":2}` where jq refuses; it now refuses too, and on a `null` document the answer jq gives there (`["a"]`) is refused instead (the placeholder cannot be told from the document).
