- **jq: `transpose` follows jq's definition by value** (#3950). `[[1,2],[3]] | transpose` answered `[[1,3],[2]]` where jq 1.7.1 answers `[[1,3],[2,null]]`: short rows were not padded with `null`. A non-array row (`[1,"a"]`, `[true]`) was wrapped as a one-element row where jq raises `Cannot index number with number` / `boolean (true) has no length`, a `null` row (`[null]`) answered `[[null]]` where jq answers `[]`, and an object input (`{"a":[1,2],"b":[3]}`, `{}`) or a scalar raised `transpose requires array` where jq iterates an object's values and raises `Cannot iterate over string ("a")` for a scalar. The result and every error now match jq's `[range(0; map(length) | max) as $i | [.[] | .[$i]]]`; the same applies in yq mode (`transpose` is not gated behind `--jq-extensions` there yet, #3954). A ragged input whose output would be over a million cells and more than 16x the cells it holds (`[[0, ... 100k cells], [], [], ... 100k empty rows]`, ~10^10 cells, which exhausts jq itself) now raises `transpose: maximum output size exceeded` instead of taking the process down.
