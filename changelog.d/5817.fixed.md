- **jq: `Cannot index <type> with string` leaves the key out when it is 30 bytes or longer, as jq does** (#5817). `[1] | try .["kkkkkkkkkkkkkkkkkkkkkkkkkkkkkk"] catch .` (30 bytes) is `"Cannot index array with string"` in jq 1.7.1, which quotes the key only up to 29 bytes (and counts bytes, so 15 two-byte characters drop it); `succinctly jq` quoted it whole. It showed up when the key was a document's own text (`.[(. | tojson)]`). The message is the only difference: both fail the same way. `succinctly yq` shares the message and drops a long key's text too, but real yq's wording is different and neither matched it before (`docs/compliance/yq/limitations.md`).
