- **yq: an indented `---` in the head of a stream is a document marker** (#6859). yq's header slurp trims the lines of the head before go-yaml reads them, so a `---` with spaces or a tab before it, before any content, is its marker as the one at column 0 is: `  ---` / `a: 1` is `{"a":1}`. It was a plain scalar here: that stream was refused, `  ---` / `- x` was the string `"--- - x"`, and a lone `  ---` was `"---"` where yq reads a null document. The parser now reads the `---` of such a line as the marker when only yq's header lines (blank lines, comments, `%YAML`, other markers) come before it, with the same head as the indented `%YAML` of #6408; a `---` after content, inside a block, or indented behind `a: 1` stays content (`a: 1` / `  ---` / `b: 2` is `{"a":"1 ---","b":2}` in both). The marker is written back flush left (`  ---` prints `---`, as in yq), on the streaming and the write routes, and lines count from the first content line after it, as after a marker at column 0. A marker with only blanks after it no longer ends the header early, so `---  ` / `---` / `a: 1` keeps both markers as yq does (it printed one). Checked against yq v4.53.3 on 159 pinned rows (JSON, YAML, a write and `line`, over 40 head shapes) and on 4,500 random heads per output mode (fifteen head lines in runs of up to four, 23 bodies): over 2,000 newly agree in each of JSON and YAML, and none that agreed before differs; an indented marker behaves as the same marker at column 0 in all of 11,000 more document and filter pairs where yq reads them alike. Still different, as for a marker at column 0: a `%YAML` line before the marker on a write (`%YAML 1.2` / `---` / `a: 1` loses its marker), and the `---` yq prints between documents of a `.`-less query.
