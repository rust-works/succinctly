- **jq: `--stream`, `--stream-errors` and `--seq --stream` read the extra empty read jq makes of a file whose last read fills its 4,095-byte buffer** (#6760). jq reads a file a line at a time into 4,096 bytes; when the last read of a file fills the buffer with no newline, EOF has not been seen and jq reads that file once more, getting nothing, and a closing event the file held back comes out of that read, in that file. succinctly made no such read, so the event came out of the next file's read instead. `--seq --stream . full.seq arr` printed `arr`'s events where jq stops, `--seq --stream '[., input_filename]' full.seq arr` named `arr` for `full.seq`'s closing event, `--seq --stream '[., input]' full.seq arr` exited 5 where jq exits 0, and `--seq --stream . full.seq dir arr` lost `jq: error: Is a directory`. A closing event held back at a file whose last read filled the buffer is also no longer put at the next failed file's read, so `--stream-errors . full.json gone gone2` says both failures. Rows around the boundary (4,094, 4,096 and 8,190 bytes, a last line of 4,095 bytes after an earlier newline) were already right and still are; 125 of 3,408 rows of a sweep over those shapes moved to jq's answer and none moved away.
