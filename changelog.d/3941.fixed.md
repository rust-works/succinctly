- **jq: a `foreach` UPDATE comma that mixes a navigating pipe with a literal no longer skips the write under a `try` EXTRACT** (#3941).
  `jq 'del(foreach .a as $v (.; (($v | .b?), 1); try ($v | .b?)))'` on `{"a":{"b":1}}` is `{"a":{}}` in jq; this was `{"a":{"b":1}}` at exit 0, and the same shape under
  `=` and `|=` wrote nothing (jq `{"a":{"b":9}}` and `{"a":{"b":7}}`), and `path(...)` printed nothing where jq answers `["a","b"]`.
  jq forks the comma: the pipe sibling moves the register to `a.b` (its EXTRACT refuses) while the literal runs from `.a`, so its EXTRACT answers.
  Each sibling already stated the register on its own (#3862), but the fold read that statement only when *every* sibling left the register alone, so the literal's EXTRACT ran
  register-less and the `try` swallowed the refusal. A comma now counts as a producer of that statement when any sibling leaves the register alone, as a `//` alternate has since #3906.
  The same read answers a comma after a destructuring bind outside a fold: `path(. as {a:$q} | $q[0], $q)` is `["a",0]`, `["a"]` as in jq (it refused), and `del` and `=` through it match.
  A plain bind's `$y[0], $y` and an `if` around it keep refusing, as in jq. jq mode only. `scripts/jq-bind-origin-oracle-sweep.sh` exits 0 again.
  The same read answers an EXTRACT after a comma UPDATE ending in a literal (#3933): `path(foreach .a as {c:$v0} (0; (($v0 | .b?), 1); $v0))` is `["a","c"]` as in jq (it refused).
  Not covered: a sibling that is a pipe of non-navigating stages (`(.|length)`, `(2|.+1)`) still skips the write (#3959), and `now`/`input_line_number` still refuse (#3960).
