- **jq: `map(body)` of an array a stage computed out of numbers no longer takes the reindex bridge** (#6539). `[range(n) | . * 1.5] | map(. + 1) | map(. + 1) | add` wrote each `map`'s whole input array out as JSON text, indexed it and parsed it back; an array whose elements are all plain finite numbers (an `Int` or a finite `Float`) is now mapped number by number when each element's answer is one plain value (`. + c`, `. * c`, a comparison, `floor`, `sqrt`, `tostring`, `[.]`, `{a: .}`, `. as $x | ...`). A body that raises, fans out or answers a NaN, an infinity or a literal still takes the bridge, so jq's messages and its reading of an overflow are kept. The same program, interleaved against jq 1.7.1 on a Ryzen 9 7950X at 3,000,000 elements: 2208 to 729 ms (jq 1913 ms, so 0.87x became 2.6x); `map(. * 2) | map(. - 3) | length` 2149 to 658 ms (jq 1527 ms); `[range(n)] | map(. * 2) | add` 787 to 297 ms (jq 1202 ms). A `map` over a number array read from the document (`.numbers | map(. + 1) | map(. + 1)`) is a lazy sequence that never took the bridge and is unchanged.
