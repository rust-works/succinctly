- **A number that ends one file is not joined to a NUL at the front of the next once a fault has dropped it** (#7897). jq drops the rest of the read a fault is met in, so after `l 12` in one file its parser no longer holds the `12` when it reaches the next file, and a NUL and a newline there are a second fault (`Invalid numeric literal at line 2, column 0`), in jq 1.7.1 and 1.8.2. `succinctly jq` rewrote the digits and the NUL as one number across the two files (#7437, #7749), which moved the number's last digit into the second file: every reader that goes on past a fault then gave out `2` where jq has the fault, and `12` for `l 1` followed by a file of `2`, a NUL and `x`, where jq has `2`. That was `--stream-errors -s`, `--stream -s -n`, and the documents `input`/`inputs` read past a caught error (`jq -n 'try input catch ., input'`), over two or more files; `--stream-errors` and `--stream -n` without `-s` read the files a chunk at a time and were right. The digits are now handed on to the next file only when jq's parser still holds them, as the stitch of the files decides it, and the bytes jq's streaming parser reads are no longer rewritten at all: it ends a number at a NUL itself. Without a fault the two files are still the one number.
