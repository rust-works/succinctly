- **jq: a fold step that reads its state through a computed key or a `//` default no longer re-indexes the state every step** (#6567). `reduce .[] as $x ({}; .[$k] = (.[$k] // 0) + 1)`, the counting idiom, and `.b = (.a // 0) + 1` went to the evaluator for the whole assignment, which wrote the state out as JSON text and indexed it again at every step, so the cost per step grew with the state (0.20x of jq 1.7.1 at a hundred keys, minutes at ten thousand). The pure operand grammar now reads `.[K]` for a string or integer key (a key that reads nothing of the state, such as `($i % 100 | tostring)`, is computed once) and `a // b` of pure operands, as operands only, and a read that raises still takes the evaluator's route so jq's messages are kept. Against jq 1.7.1, interleaved, on a Ryzen 9 7950X: 400,000 steps over 100 keys 4827 to 391 ms (jq 873 ms, so 0.18x became 2.2x), over 1,000 keys 37,582 to 390 ms (jq 3146 ms), and 40,000 steps over 10,000 keys 32,473 to 42 ms (jq 2779 ms). On an Apple M4 Pro the same three rows are 3587 to 276 ms (jq 713 ms), 29,074 to 286 ms (jq 2695 ms) and 25,076 to 33 ms (jq 2795 ms). The `|=` and `+=` spellings of the same fold were already fast and are unchanged.
