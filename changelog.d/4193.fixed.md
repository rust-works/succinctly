- **yq: an entry of `{...}` that yields nothing is skipped, not the whole object** (#4193). `{"a": (1|select(false)), "b": 2, "c": 3}` is `{"b": 2, "c": 3}` in yq, and so is `{"a": .m.id, "b": .n}` when `.m` is a string (yq yields nothing, not `null`, for a key applied to a scalar); `succinctly yq` built the cross product of the entries, so one empty key or value printed nothing at all. When that cross product comes out empty it is now rebuilt as yq's `COLLECT_OBJECT` (the route a bare entry already took), which also reproduces its neighbour-dropping quirks (`{"a": 1, "b": (1|select(false)), "c": (3,4)}` is `{"c": 3}` and `{"c": 4}`). jq is unchanged, a construction that cannot be empty is untouched, and the usual shapes read -1% to +2% against the old binary on a 7-14 MB `users` document (M4 Pro, interleaved, control range -2% to +2%). Cost: a construction that is empty for every record is built twice (+69% on that query shape).
