- **yq: a `{...}` pair with an empty key or value is dropped from the fold, as yq does** (#4193).
  yq folds the entries of an object construction and skips a pair that has no maps, so `{"a": empty, "b": 2}` is `b: 2`
  and `{"a": 1, "b": empty, "c": 3}` is `c: 3` (an empty pair empties everything folded before it, so a trailing one
  empties the lot), where `succinctly yq` ended the whole construction at the first empty entry and printed nothing.
  yq also evaluates every entry first, so `{"a": empty, "b": error("boom")}` now raises `boom` too. A construction takes
  this route only when an operand is not provably non-empty, so `{name: .name, n: (.xs | length)}` keeps its fan-out
  (-0.7% median over four such constructions on a 7 MB document, M5 Max, interleaved A/B, inside noise); one with a
  `select` or a `.[]` in a pair pays for the fold, +9% (two entries) to +16% (five) on the same document. jq is unchanged.
