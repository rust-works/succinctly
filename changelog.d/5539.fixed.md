- **jq: a name bound by `as` destructuring keeps the storage of the node it binds** (#5539). `[[nan]] as $a | $a as [$x] | $x == $a[0]` was `false` where jq 1.7.1 says `true`, as were the object, nested and `?//` spellings: a destructured container was spliced into the body as a rebuilt literal, a new container that jq's `jv_identical` short-circuit does not match. A container the pattern binds is now spliced as the shared storage when the body compares it or hands it on, as `as $x` already did. A body that only reads the name by value keeps the literal, so the in-place assignment and arithmetic steps stay in place, and a fresh container that merely looks equal (`$a as [$x] | $x == [nan]`) is still `false`. `succinctly yq` is unchanged. Measured on an Apple M4 Pro (interleaved A/B, release, 200,000-element arrays of 10 and 16 MB, outputs identical): a body that reads a destructured container is 15% to 28% faster, since a shared marker replaces a literal rebuilt per binding; destructuring scalars is within ±1%, and the one shape that declines the marker (an assignment's right-hand side, `reduce .[] as $r ({}; $r as {tags:$t} | .x = $t)`) pays the gate's walk of the body, +2.2%.
