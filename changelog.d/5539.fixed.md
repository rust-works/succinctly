- **jq: a name bound by `as` destructuring keeps the storage of the node it binds** (#5539). `[[nan]] as $a | $a as [$x] | $x == $a[0]` was `false` where jq 1.7.1 says `true`, as were the object, nested and `?//` spellings: a destructured container was spliced into the body as a rebuilt literal, a new container that jq's `jv_identical` short-circuit does not match. A container the pattern binds is now spliced as the shared storage wherever the body reads the name other than in an assignment's or arithmetic's operands, as `as $x` already did. A name stored or added in place (`.a = $x`, `. + $x`) keeps the literal, so those in-place steps stay in place, and a fresh container that merely looks equal (`$a as [$x] | $x == [nan]`) is still `false`. `succinctly yq` is unchanged. Measured on an Apple M4 Pro (interleaved A/B, release, 200,000-element arrays of 10 and 16 MB, outputs identical): a body that reads a destructured container is 17% to 29% faster, since a shared marker replaces a literal rebuilt per binding; destructuring scalars and a container stored by assignment are within ±1%.
