- **jq: every `input` after a malformed byte-order mark repeats the fault, as in jq** (#7863). jq's parser stays in the fault when the stream opens with part of the mark (`EF`, or `EF BB`) and departs from it, so each later read says `Malformed BOM` again at the same `(at FILE:LINE)` and the text after the mark is never read: `printf '\xef1\n' | jq -c -n '(try input catch .), (try input catch .)'` prints `"Malformed BOM"` twice, and `jq -c -n '[inputs]?, input'` ends with `jq: error (at efbad.json:0): Malformed BOM`. `succinctly jq` raised the fault once and then found the stream at its end, so the second read said `break` (and `(at <unknown>)`), a second `first(inputs)` printed nothing, and a stream with text after the mark, one pipe past its first read included, handed that text out as documents. Every read after the first now repeats it, on the plain routes; the first read keeps the numeric-literal wording recorded for #5804, and `--stream`, which repeated it already (#7603), and `--seq` are unchanged.
