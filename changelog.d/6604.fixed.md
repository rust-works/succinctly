- **jq: `-s` with a program that reads `input` reports a directory that is the last input file** (#6604). `jq -c -s input one.json dir` printed only the `break` the extra read raises; jq 1.7.1 first prints `jq: error: Is a directory`, because a slurp asks for one more input after the array and its reader reads the directory then. The same holds for `inputs`, `first(inputs)`, `[limit(1; inputs)]`, `-n [inputs]`, `-e`, `--seq -s`, and a directory that is the only input. A program that never makes that read (`.`, `input_filename`, `input_line_number`, `-n input`, which gets the array itself) and a run without `-s` (#6472) print nothing, as before, and the run exits 2 in every case. The directory is now held for the input queue's read hook and said by the program's own read that finds the stream at its end, not by the main loop's. Swept against jq 1.7.1 over 11 programs, 6 flag sets and the file lists that end in a directory or hold one among files, `gone`, empty and truncated inputs, 5280 runs: 8 differ where 1390 did, and none the other way; the 8 are `-s --stream` with a directory that is not last (#6591).
