- **yq: a multi-index `del()` follows yq's path order, negative indices and repeats** (#4749). `[10,20,30] | del(.[5], .[0])` is `[20,30,null,null]` in yq, and `succinctly yq` answered `[20,30]`: a single past-the-end index already padded (#2305) but a batch of two or more did not. yq evaluates the paths left to right into nodes (an index past the end grows the array, a negative one counts from the length at that moment) and deletes them from the back, each by its key then, so `del(.[-1], .[5])` is `[10,20,null,null]`, `del(.[5], .[-1])` is `[10,20,30,null,null]` and `del(.[0], .[0])` is `[30]`; a batch of plain indices, negative ones, repeats, `.["5"]` spellings and a `null` target (`null | del(.[2], .[3])` is `[null,null]`) now gives the same answers (about 2,500 random batches checked against yq v4.53.3, no difference). A batch with a slice, and a negative index that is valid only once an earlier past-the-end index has grown the array, still differ (recorded in `limitations.md`). The issue's mapping row needs a key-spelling bit and stays open.
