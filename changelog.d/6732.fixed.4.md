- **`succinctly jq --stream-errors` counts every file that did not open when a token left open across files ends in a fault** (#6732). A bare number completes only when jq's reader asks for more, so after `[` and a missing file, the `2` of `1 2` is read together with the end of the text: jq opens, and reports, every file that did not open before it raises `Expected separator between values at EOF`. `jq -c --stream-errors . open.json gone r2.json gone` (`open.json` = `[`, `r2.json` = `1 2`) reported `gone` once where jq reports it twice, and so did `halt_error` and a program that reads `input` (the same for a directory: `open.json dir r2.json gone`). The same holds when the fault is raised in a file after the second failure (`open.json gone r2.json gone open.json`, `Expected separator between values at line 1, column 5`), and a fault met mid-text in the file before the failures (`[1,2` then `{"a":1}`) is no longer taken for a closing event held back for the failure's read (`open3.json obj.json gone gone` stopped after the first). Differential grids against jq 1.7.1 (`-c --stream-errors`, up to six programs, lists of 3-5 files with a directory and missing files, 9-11 fixtures, `-n`, `-e`, `-s`, `--seq` alongside) cover about 120,000 rows (they overlap): 150 rows were apart, and after the change none is, with no row changed for the worse.
