- **jq: a string interpolation of plain navigation no longer raises over a malformed sibling its slots do not read** (#5305). `echo '{"name":"a","bad":tru}' | sjq '"\(.name)"'` is `"a"`, as `.name` and `[.name]` already were; it used to raise `invalid boolean` because the evaluator decoded the whole object before reading `.name`. A slot that reads the malformed token still raises (`"\(.bad)"`), and an interpolation with any other kind of slot (a call such as `.name | ascii_upcase`, `..`, a position read) keeps the earlier behaviour. jq 1.7.1 rejects the document either way; `--validate` and `succinctly json validate` do too. See `docs/compliance/jq/limitations.md`.
