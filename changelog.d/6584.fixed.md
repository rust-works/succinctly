- **jq: `--seq` reports a file that did not open when a read reaches it, for any stream, and keeps what jq's reader reads past a missing last file** (#6584, #6588). #6555 handed the failures to the input queue's reads only for a `--seq` stream that reads without a fault; one with a fault, or whose last value completes only at the end of a file, still reported every file up front. With `a` holding `\x1e1\n\x1e2\n` and `c` holding `\x1e4`, `jq --seq -c -n input a c gone gone2` printed `1` and exited 0 in jq 1.7.1, and `succinctly jq` reported both files and exited 2; `--seq -c input c gone b gone2` reported `gone2` as well as `gone`. The `--seq` readers now place each read where jq's reader stands when it completes it, a fault included, and a last file that did not open is one more (empty) source to them, as it is to jq's: `--seq -n '[inputs]' q gone2` (`q` holding `\x1e1\n\x1e[2]`) no longer drops `[2]` to the #2998 end-of-stream drop, and `--seq -c input b d gone` raises `Unfinished JSON term at EOF` at `gone`, line 0, where it raised `break` at `d`. A differential sweep over `--seq`, `--seq --stream` and `--seq --stream-errors` (10,368 runs: 288 file lists of up to four entries over 8 programs, and 4 more under `-n`) moved 4,384 runs to match jq 1.7.1 and changed none that already matched. The `--seq --stream` and `--stream-errors` readers with several missing files at the end, `--seq -s` and `--input-dsv` keep their old order (#6589, #6591, #6585).
