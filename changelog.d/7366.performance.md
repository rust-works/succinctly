- **jq: a document holding one object that repeats a key is printed from its text around that object** (#7366). The canonical scan stopped at such an object unless it was the whole value, so `{"data": <1 M keys, the second repeating the first>}` (17.9 MB) and an array of 400,000 records one of which repeats a key walked and re-rendered every member. The scan now records the first such object below the value and goes on past it, and the printer writes the text before it, the object by its keys, and the text after it. On a 7950X, `-c .` over the 17.9 MB object takes 141.7 ms against 165.4 ms (0.86x; with the repeat at the last key 0.79x), and over the records 61.4 ms against 253.0 ms (0.24x); `.` reads 0.86x, 0.79x and 0.40x. Output and peak memory are unchanged and documents without a nested repeat are within noise; a document with two such objects still walks, and one whose nested repeat is followed by a byte jq would respell now scans to that byte before walking (+9% on 400,000 records).
