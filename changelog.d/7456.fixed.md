- **jq: a format-prefixed string is a field step after `.`, an object-pattern key and an `import`/`include` path** (#7456). `.@base64 "x"`, `. @json "k"`, `.a.@text "b".c`, `. as {@base64 "c": $c}` and `import @text "m" as m;` were compile errors (`expected identifier, found '@'`); they now parse as jq 1.7.1 and 1.8.2 do, as the step, key or path of the string with only its interpolations formatted, so `.@base64 "x"` is `.x` and `.@base64 "\(1)"` is `.["MQ=="]`. This holds after any term, with `?`, and in path expressions (`path`, `paths`, `=`, `|=`, `del`). `succinctly yq` still refuses a format followed by a string, as yq does.
