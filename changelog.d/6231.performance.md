- **jq: a slice of a large array, `.users | .[:10]`, reads the slice's elements by index instead of the whole array** (#6231). A literal-bound slice other than the full range was answered by materializing the array and indexing it again, so keeping ten elements cost what reading all of them cost; it is read as `E[S:T]` has been since #4287. On a 74 MB `users` document it falls from 595 ms to 108 ms (-82%) on an Apple M4 Pro and from 1,331 ms to 161 ms (-88%) on an AMD Ryzen 9 7950X; at 7 MB it is -79% and -87%, and at 0.7 MB -58% and -78% (interleaved, min of 11, output identical on all 21 configurations on both). `.[5:]`, which keeps almost everything, gains 12-15% from 7 MB. `.users | length` is unchanged. A slice now decodes only the elements it keeps, so a fault inside a dropped element's text (`["a","bad\x",3]` with `.[:1]`) is no longer diagnosed, as for `E[S:T]`; jq rejects such a document.
