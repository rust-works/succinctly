- **jq: `indices`, `index` and `rindex` on `null` or an object look the key up instead of answering `null`** (#3890, after #3347, #3453).
  jq defines `indices($i)` as `.[$i]` for every input but an array and a string, and `index`/`rindex` as that followed by `.[0]` / `.[-1:][0]`; succinctly answered
  `null` for any key on `null` or an object. `null | indices(true)` is `Cannot index null with boolean` in jq (likewise `false` and `null`, and through `index`/`rindex`),
  and `{"a":1} | indices("a")` is `1`, `{"a":[5,6]} | rindex("a")` is `6`, `{"a":1} | index("a")` is `Cannot index number with number` -- all `null` here. In `path()`
  the wrong `null` was the root's own, so `[path(indices(true))]` on `null` answered `[[]]` where jq raises, and `del(indices(true))` and `(indices(true)) = 1` ran
  through it; all raise now. A tracked array input (`path(.a | indices(1))` is `["a",[1]]` in jq) and a string `index`/`rindex` on a tracked value still refuse, in the safe direction.
