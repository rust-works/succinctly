- **jq: a wide object that repeats a key is printed from its text** (#7346).
  An object whose only fault is a repeated key has every member already in jq's spelling, so under `.`,
  `-c .`, `--indent n` and `--tab` the runs of members jq's duplicate-key rule leaves alone are now copied
  (`-c`) or re-indented from the text, and each repeated key is written in its first place with its last
  value. It used to be walked and re-rendered member by member. That holds for the object printed whole,
  for one inside the printed value (#7366) and for one that repeats an early key (#7355). On a 100 MB
  object of 7.1 M keys with one repeated key, `.` takes 0.64 s instead of 0.96 s and `-c .` 0.54 s
  instead of 0.94 s on an AMD Ryzen 9 7950X (0.48 s instead of 0.76 s, and 0.40 s instead of 0.75 s, on
  an Apple M4 Pro), and the same object one level in reads the same. Each now peaks where the same object
  without the repeat does, 196 MB on the 7950X and 192 MB on the M4 Pro, instead of 244-287 MB and
  297-340 MB. The saving grows with the object: `-c .` is 37%, 41% and 43% faster at 1, 10 and 100 MB on
  the 7950X. An object whose fields are mostly occurrences of repeated keys keeps the walk, which is the
  faster route for it, at 4-5% more time than before for recording spans it then gives up.
