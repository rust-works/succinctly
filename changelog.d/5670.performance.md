- **jq: `del` of several static paths is answered on the value instead of writing it out and indexing it again** (#5670, #5549 follow-up). `del(.a)` and `del(.a) | del(.b)` were deleted from the value itself since #5549; `del(.a, .b)`, `del((.a, .b), .c)` and `del(.[0], .[1])` still wrote each value out as JSON, indexed it and deleted from that. A comma of field names and literal indices now takes the same route (the builtin's own body, which collects every path before it deletes any, so the order written does not matter); a computed key, an iteration, a condition, a `?` and yq mode keep the bridge. `delpaths` of an array literal is not covered. A comma of distinct plain field names (`del(.a, .b, .c)`) deletes independent keys, so it is applied name by name, each the cheap single-path delete rather than a path set merged into a trie. Over a generated `users` document (Apple M5 Max, interleaved min of 7, 10 MB, jq 1.7.1): `.users|map(del(.email,.score))|length` 0.66x -> 1.54x of jq (instructions retired 4.90 G -> 1.90 G), `del(.email,.score,.age)` 0.67x -> 1.76x, `del(.email,.score)|tojson` 0.78x -> 1.74x, `del(.email,.score)|keys` 0.66x -> 1.48x and `[.id,.name,.age]|del(.[0],.[2])` 1.02x -> 1.24x; `del(.email)` is unchanged at 1.36x.
