- **jq: `del` of several static paths is answered on the value instead of writing it out and indexing it again** (#5670, #5549 follow-up). `del(.a)` and `del(.a) | del(.b)` were deleted from the value itself since #5549; `del(.a, .b)`, `del((.a, .b), .c)` and `del(.[0], .[1])` still wrote each value out as JSON, indexed it and deleted from that. A comma of field names and literal indices now takes the same route (the builtin's own body, which collects every path before it deletes any, so the order written does not matter); a computed key, an iteration, a condition, a `?` and yq mode keep the bridge. `delpaths` of an array literal is not covered. Over a generated `users` document (Apple M5 Max, interleaved min, 10 MB, jq 1.7.1, a loaded box): `.users|map(del(.email,.score))|length` 0.64x of jq before; see the pull request for the after.
