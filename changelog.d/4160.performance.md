- **jq: a run over a large document no longer counts newlines for a location nothing reads** (#4160). The default document loop resolved every value's `(at <file>:<line>)` line before evaluating, a scalar pass over the whole input, though only a diagnostic reads it and the M2 fast path never does; it is now resolved where first read, and counted in 64-byte chunks that vectorize. Interleaved A/B, 15 reps, output identical on every row, 2-10 MB inputs: `-c .` median of medians -3.1% on a Ryzen 9 7950X (-4.5% to -2.0% per row) and -2.6% on an M4 Pro (-3.9% to -1.7%); `length` and `[.[]?] | length` -3.9% and -3.4% (every one of 12 rows faster on both). The control (a copy of the base binary) reads +0.2% / -1.2%. `find_matching_close`, the other term the issue names, is unchanged.
