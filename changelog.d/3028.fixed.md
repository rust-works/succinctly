- **yq: a write keeps the way an untouched scalar was spelled** (#3028). Any DOM write (`=`, `|=`,
  `del()`, `-P`, `-i`) re-printed every null, bool and number in canonical form, so editing one line of
  a GitHub Actions workflow turned `on:` / `  push:` into `push: null` (about 490 of 2,178 real YAML
  files on a developer machine differed from yq on this alone) and `~`, `Null`, `True`, `0x1F`, `017`,
  `+1`, `.5`, `2.` became `null`, `true`, `31`, `17`, `1`, `0.5`, `2.0`. They are printed back as
  written, the empty value as nothing after the colon, while the spelling still names the node's
  value; a node a write replaces takes the new value's text. Checked against yq v4.53.3 on about 3,000
  random documents. Reads (`tostring`, `==`) still see the resolved value (#2802), and arithmetic on a
  hex or octal integer does not keep its base (#3027).
