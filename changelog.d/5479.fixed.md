- **yq: a write whose path selects nodes by their style, anchor, comment, line or alias-ness no longer silently does nothing** (#5479). `(.. | select(style == "double")) style = "single"`, `(.. | select(anchor != "")) anchor = ""`, `(.[] | select(line_comment == "TODO")) = "done"`, `(.[] | select(kind == "alias")) = 5` and `del(.[] | select(style == "double"))` matched no node and exited 0 with the document unchanged, because a write resolved its path against the owned document, which holds values and no presentation; the same predicate on a read always worked. The path is now resolved on the document's cursor first (`style`, `anchor`, `kind`, `line`, `column`, `line_comment`, `head_comment`, `foot_comment`, `document_index`, `file_index`, `filename`), for `=`, `|=`, the compound assignments, `//=`, a metadata write and `del()`, when the write is the whole filter or the first stage of a pipe; 21 rows captured from yq v4.53.3 now match. A later pipe stage that selects by metadata still selects nothing (recorded in `docs/compliance/yq/limitations.md`).
