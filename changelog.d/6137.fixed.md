- **jq: `--seq` without `-n` lets `input`/`inputs` raise a malformed record's error, as jq does** (#6137). A program that read `input` printed every `jq: ignoring parse error: ...` before it ran, so the records after a fault paired differently with the main loop: `[., input]` over `1`, `[1,]`, `2`, `3` printed `[1,2]` and a `break` error where jq prints `[2,3]` after `jq: error (at <stdin>:2): Expected another array element ...`. The fault is now the error the next `input` raises; one the program does not read is printed as ignored when the main loop reaches it, after the values before it, and the reader's message-less return ends the main loop there, as in jq. `-s` and programs that never read `input` are unchanged.
