- **yq: a TOML file written back as TOML keeps its comments** (#7170, #7160 follow-up). `yq -p toml -o toml` and `yq -i` on a `*.toml` file wrote no comment at all, so `yq -i '.package.version = "1.2.3"' Cargo.toml` stripped every one; yq's TOML decoder gives each comment to a value node and its encoder writes them. The read now writes a run that writes TOML as YAML text with each head comment above the key it belongs to, an array's line comment after its key and the root mapping's head comment ahead of an explicit `---`, and the encoder reads them back as the value nodes' own. Pinned against 4,600 random documents over six filters (identity, `.zz = "n"`, `del(.a)`, `sort_keys(.)`, `.. style=""`, `.a = "v"`) with no difference, and 2,005 of 2,026 real `*.toml` files under the identity filter (the other 21 hold inline tables, which are still written as tables). A copied node does not take its head comment with it (`.c = .a`) and a node that changes kind loses its line comment (`.a = [1]`), where yq keeps both (limitations.md).
