## Predicate vs structure

Block-sequence children split into *wrappers* (structured content beneath a
`-`) and *wrapperless scalars* (`- foo`, where the parser makes the scalar a
direct child whose text starts past the `- `). So `children > S` is expected
and correct, and no per-sequence caching of wrapper-ness is sound.

The two numbers that must be zero: a false positive would unwrap a non-item,
and an undetected wrapper would leak a wrapper node to a caller.

## Position storage: Compact vs Dense

Option 2 can only tag a high bit where a position is physically stored as a
`u32`, i.e. `OpenPositions::Dense`. `Compact` holds positions as interest bits
keyed by text offset (shared between duplicate opens) plus a per-open advance
bitmap, so there is no per-open word to tag.

| file                           | representation | heap bytes | dense equiv (4N) | compression |
| ------------------------------ | -------------- | ---------- | ---------------- | ----------- |

| actions/prometheus-ci.yml      | Compact        | 3752       | 3660             | 0.98x       |
| actions/stale.yml              | Compact        | 276        | 216              | 0.78x       |
| compose/nginx-flask-mysql.yaml | Compact        | 276        | 448              | 1.62x       |

- **Compact: 6 file(s); Dense: 0 file(s)** — Option 2 reaches only the Dense share.

## Option 3 sizing (sparse `Vec<u32>`)

Break-even: **3.12%** against a 1-bit-per-node bitvector, **6.25%** against the
2-bits-per-BP-position form O4 removed. The issue states 12.5%, which drops
the bits-to-bytes conversion (`4S = N/8` gives 1/32, not 1/8).

The baseline today is **0 bytes** — O4 deleted the structure — so this is a
pure retained-memory addition, not a cheaper encoding.

## Verdict

- Option 2 (high-bit tag): reaches 0 of 6 file(s) (the Dense share). **Infeasible** — no file stores a taggable per-open `u32`.
- Option 3 (sparse index): aggregate 8.87% vs 3.12% break-even, max 21.43% vs 6.25%. **Fails** the density gate.
