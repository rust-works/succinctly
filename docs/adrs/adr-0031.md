# ADR-0031: jq-Mode Regex Runs on Oniguruma at jq 1.7.1's Pin (#7965)

## Status

✅ Accepted (2026-11-27). Supersedes [ADR-0019](adr-0019.md) and its #5502 and #5530 amendments.
Applies [ADR-0018](adr-0018.md) rule 4(d) to new evidence: a dependency that closes the gap now exists at a cost the owner accepts.
Nothing changes behaviour until step 4 of the [migration plan](#migration-plan); the plan is tracked in #7965.

## Context

`succinctly jq` promises jq's answers, refusals, error text and error order for regular expressions (ADR-0018).
jq's engine is Oniguruma.
`f_match` (`src/builtin.c` of jq 1.7.1) calls `onig_new` with `ONIG_SYNTAX_PERL_NG`, `ONIG_OPTION_CAPTURE_GROUP` plus the flag letters and UTF-8, then `onig_search` in a loop.
ADR-0019 rejected binding Oniguruma for two flag gaps (`l`, `n`), on the portability bar: a pure `cargo build`, no C toolchain.
Since then the jq-mode regex path has translated each pattern for the `regex` crate, or for `fancy-regex` where that crate refuses it, and imitated the rest.

The imitation has grown to the size of the thing it imitates.
The jq-mode regex code in `src/jq/eval.rs` (from `has_anchor_only_group` to `scan_fancy_pattern`) is about 9,800 lines.
The modules `onig_loop`, `onig_look_behind`, `onig_quantifier`, `onig_fold`, `onig_capture_loop`, `onig_end_search`, `onig_fold_data` and `regex_blocks` add 8,885 more.
About 150 functions read pattern text, each with a scanner of its own.
They decide the same syntactic facts in different ways: where a class ends (at least 15 readers, three rules), the length of an escape (at least 20), what is an interval (9), and the extended mode's blanks (8).
Error order is not derived at all; it is recovered by compiling rewritten copies of the pattern.
In one day three rounds of fixes each broke something another pass relied on (#7865 then #7887; #7852 and #7858 then #7888).
The lessons log names the mechanism: duplicated predicates diverge silently.

### The corpus

A differential corpus was built for this decision.
It has 330,133 generated patterns in 459,678 rows; a row is one regex builtin on one pattern and flags string, run on three subjects.
The generators cover look-behind bodies, references and calls, malformed pieces, classes, intervals, escapes, option runs, comments and blanks, ordinary patterns, and 133 probes taken from the code reading.
Each binary answers in batches under `try`/`catch`.
A control runs every fortieth row as its own process, with no `try`; on 11,492 rows it equals the batched answer for both jq builds and for each candidate.
Rows that differ from jq 1.7.1, and from jq 1.8.2 where succinctly follows it (macOS arm64, release `--features cli`):

| Build | Rows differing |
|---|---|
| main at `cd718f9a6` | 49,641 (10.8%) |
| C Oniguruma 6.9.8 through the `onig` crate | 30,963 |
| C Oniguruma 6.9.10 | 113 |
| C Oniguruma 6.9.9 | **111** |
| ferroni 2.9.0, pure-Rust port, two post-pin syntax flags cleared | 6,835 |

The 6.9.9 build resolves 49,530 of main's rows and changes none that agreed.
Its 111 are the adapter's, not the engine's: after an empty match jq resumes one *byte* later and reports spans cut inside a multibyte character, and the prototype moved those spans onto character boundaries.

jq 1.7.1 and 1.8.2 differ from each other on 7,361 rows.
About 4,800 are the engine: Oniguruma 6.9.10 added `ONIG_SYN_ALLOW_CHAR_TYPE_FOLLOWED_BY_MINUS_IN_CC` to Perl_NG (upstream #298), so `[\d-a]` is accepted.
The rest are jq's own code: groups that took no part in an empty match (jqlang/jq#3238, about 1,420, adopted as #7520), and the letter order of `split`'s modifier error (about 1,100, kept at 1.7.1 as #7560).

### Which Oniguruma

jq 1.7.1's `modules/oniguruma` pins kkos/oniguruma commit `d2f1a14ced` (2023-07-11), 18 commits before 6.9.9.
Those 18 commits are the Unicode 15.0 to 15.1 tables, warning fixes and the version bump.
The pin still reports itself as 6.9.8 through `onig_version`.
The pinned `/usr/bin/jq` 1.7.1 treats U+2FFC and U+31EF as unassigned, which fits the pin's 15.0 tables.
jq 1.8.0 to 1.8.2 vendor the v6.9.10 tag.
Upstream ended on 2025-04-24: the repository is archived, and later fixes were never released.

### Alternatives considered

| Option | Rows it can resolve | Cost |
|---|---|---|

One Oniguruma-syntax parser in Rust; errors, look-behind rules and the translation derived from its tree | about 40,000 (a ceiling from the family table, not measured); none of the engine-level families (calls, constructs the engines cannot run, the backtracking budget, `l`/`n`) | 5,000-7,000 lines of a second Oniguruma parser, still fuzzed against Oniguruma |
| B. Bind the real Oniguruma for jq mode | all but the adapter's 111 (measured) | C compiled by `cc`, a vendored copy to keep, Oniguruma's matching cost |
| C. Keep the passes; put one shared tokenizer under them | at most the token-boundary families (R5, D2: about 4,000), not measured | the architecture that produced #7887 and #7888 stays |
| D2. B, with a substring search for literal patterns | as B | one predicate, added only if timing asks for it |
| E. A full port of Oniguruma to Rust | as B, once faithful | about 24,700 lines of C plus the Unicode tables |
| ferroni (an existing port, E done by someone else) | 6,835 left (measured) | a pinned fork that reverts upstream `3f966829ee` (strict UTF-8 bytes) and #343 (bare `\x`), fixes three port bugs (`\o{8}`, `\f` under `x`, a `\g` recursion check), and moves the MSRV to 1.94 |
| WebAssembly build of the pin under `wasmi` | as B | a committed binary module; speed and size not measured |

## Decision

We will compile and match jq-mode regular expressions with Oniguruma at commit `d2f1a14ced`, the commit jq 1.7.1 bundles.
Its C sources will be vendored in this repository and built with `cc`.
The text passes that imitate Oniguruma will then be deleted, with `fancy-regex`.

- **Adapter.** jq's `f_match` is ported as one unit: the flag check, `onig_new`, the error text (`Regex failure: ` plus `onig_error_code_to_str`), the search loop with jq's one-byte step after an empty match, and match and capture objects built from raw byte spans.
  The adoptions above the engine stay where they are (#7520 follows 1.8.2, #7560 keeps 1.7.1).
- **Own FFI, not the `onig` crate.** The crate serialises every compile behind a process-wide mutex and rewrites an error text cut inside a character.
  `onig_initialize` is called once under a `Once`; after that, compile and search write no global state.
- **Build.** UTF-8 sources only, `-std=gnu17` on non-MSVC targets (the pin does not compile under GCC 15's default C23), and no `bindgen`.
- **Limits.** The parse depth is 1024, as jq 1.8.1 sets it (GHSA-f946-j5j2-4w5m, #7528); the default is 4096.
  The match-stack and retry limits are set per search through `OnigMatchParam`.
  A finite match-stack limit is a divergence recorded under ADR-0018 rule 4(c), since jq leaves it unbounded.
  The guard against jq's endless global search on `(?<=a\Kb)` (#6169) stays.
- **Features.** `regex` keeps meaning "the regex builtins exist" and implies the engine.
  The imitation is not kept as a fallback beyond the release that switches.
- **yq mode is unchanged.** Its dialect is Go's (`go_regex::translate`), on the `regex` crate.

Not 6.9.10: its `[\d-a]` behaviour is listed upstream as a new behaviour (#298), not a fix, so jq 1.7.1's answer stands.
Not ferroni today: it ports upstream's final commit, not jq's, and needs a fork to reach the pin.
It exposes the same C-style API, so it can replace the C library later if a pinned fork reaches the C library's count on the corpus.

## Consequences

Positive:

- Answers, refusals, error text and error order are Oniguruma's own, for every pattern, not for the shapes fuzzed so far.
- The pattern is read once, by `onig_new`. The ~150 readers and the recompiles for error order go.
- ADR-0019's two permanent gaps (`l`, `n`) close, and so do #7864, #7877, #7878, #7887, #7926, #7929 and #7930.
- About 18,700 lines and `fancy-regex` leave the crate.
  The regex sections of `docs/compliance/jq/limitations.md` shrink to the adoptions above the engine, the process-safety limits and the version note.
- The corpus stays as the gate for any later change to the engine or the adapter.

Negative:

- The first C code compiled into a shipped build.
  Every platform that builds from source needs a C compiler; native Linux, macOS and Windows hosts already need one to link.
  Pull-request CI gains a Windows leg.
- The vendored copy is ours. Upstream has ended and Oniguruma has had no CVE since 2019, so no advisory feed will report a fix; the release checklist has to.
- Memory safety on this path is no longer the compiler's promise.
- Matching cost becomes Oniguruma's, a backtracking matcher where the `regex` crate runs an automaton.
  Old published logs put it 5-15x behind the `regex` crate on ordinary searches; not measured here.
  Compile cost falls: one `onig_new` per pattern behind the existing cache, where jq compiles on every call.
- Binary size: about +3.0% stripped (macOS arm64) before the imitation is deleted, against a 5% budget already at about 4% (#7959).
- 33 existing tests pin recorded divergences or engine choices and are re-pinned to jq's answers.

## Migration plan

Each step is one pull request, mergeable on its own; none changes behaviour by default until step 4.
The corpus gate: the rows equal to jq 1.7.1 do not fall, every changed row is listed by family in the PR, and no new family appears.

1. The corpus generator, batched driver and analysis go into `scripts/`, and they regenerate the corpus and both pinned jq builds' answers.
2. The vendored pin is built behind a feature, off by default, with the FFI declarations, a unit test that compiles and searches one pattern, and a Windows CI leg.
3. The adapter ports `f_match`. Gate: no differing rows outside the recorded adoptions.
4. The engine is linked in every build and chosen at run time (#7961). The tests are re-pinned and `limitations.md` is rewritten.
   The timing gate covers `dev compare jq`'s regex rows plus non-literal patterns (alternation, class, anchored, capture-heavy, `i`, many-match `gsub`, many short strings) at 1, 10 and 100 MB.
   It runs interleaved over seeded layouts (#7960) on both architectures. Then the default flips.
5. A literal fast path, only if step 4's table asks for it: no metacharacter, no flag but `g`, non-empty.
   `$` cannot join it (Perl_NG's `ONIG_OPTION_SINGLELINE` makes it match before a final newline), nor `i` (Oniguruma's multi-character folds).
6. The imitation, the `onig_*` modules and `fancy-regex` are deleted, and the binary size is recorded.
