# ADR-0025: Guard Recursion by the Native Stack It Spends, Not by Counted Frames (#3262)

## Status

✅ Accepted (2026-09-26). Amends [ADR-0020](adr-0020.md)'s recursion guard; its runtime
`def` calls, `Expr::DefCall` and `Expr::Shared` are unchanged. Amended (2026-10-28, #5379): a
zero-argument tail call loops in place instead of nesting, see the amendment below.

## Context

ADR-0020 bounds recursion with `MAX_EVAL_FRAMES` (40,000). `install_def_calls` charges one
frame per structural level of a body, and each call carries its parent's total forward.
That is a *prediction* of native stack from the shape of the program, calibrated once,
against the shapes measured then (a thin body and one wrapped in 40 array constructors), to
hold 4x or better on the CLI's 256 MB (release) / 2 GB (debug) evaluation stack.

#3262 found shapes the prediction cannot see. A bare `def` parameter binds by name, so each
level's argument wraps the previous level's (`Shared(prev) - 1`). Reading it evaluates the
whole chain natively, on top of the live levels. Measured on `main` (release, 256 MB, crash
floor bisected with the guard disabled, Apple M4 Pro):

| shape | native stack | guard admits | outcome on `main` |
|---|---|---|---|
| `def f(n): … f(n - 1)` | ~13 KB/level | 20,000 levels | refused 3% short of a crash at 20,530 |
| `f(((n - 1) + 0) * 1)` | ~21 KB/level | 20,000 | **aborts** at ~12,800 |
| `f(n - 1 \| .)`: a link through the lazy evaluator | quadratic, ~1 MB/level at the crash | 20,000 | **aborts** at ~243 |
| `def h: n - 1; … f(h)`: a nested def closing over `n` | as above | 20,000 | **aborts** at ~316 |
| `def g(x): x - 1; … f(g(n))`: a helper def | as above | 20,000 | **aborts** at ~289 |
| `def rep(f; n): … (f \| rep(f; n - 1))`: a closure passed through | — | — | **aborts** at ~673 |
| `f($n - 1 \| .)`, `f($acc + [$n]; …)`, `def f(g): g \| …` | — | 9,967–13,326 | refused 1.09–1.65x short (#3294) |

jq 1.7.1 answers all of them. Its call stack is heap-allocated (see ADR-0020), and it runs
the pipe-link shape to 100,000 levels in 22 MB.

PR #3280 tried three successive ways to extend the prediction. Each passed its own
calibration and failed the next review:

1. **A per-level charge at bind time**, sized from the argument's syntactic nesting down to
   its `Shared`. It can't see a link's real cost: the lazy evaluator's frames, a helper
   def's body, or a nested def's frozen body. The last three shapes above still aborted.
2. **Measuring the chain where it is read**, as a stack distance from the outermost live
   `Shared` evaluation, converted to frames. Holding that measurement across the
   evaluation's sink charged whatever the sink ran, usually the rest of the recursion, by
   the byte: `def f($n)` fell from 13,297 levels to 6,441.
3. **Holding it only for eager links, or only for lazy links that reach another `Shared`**,
   at two calibrated byte rates. Each rule fixed the last counterexample and admitted a new
   one. A single shallow `y | .` read left an origin that cut an unrelated later recursion
   from 9,998 levels to 3,604. `def f(k; $n): … f(0; k | $n - 1)` answered on `main` and
   was refused. A passed-through closure (`rep` above) still aborted.

The per-level cost measured across these shapes ranges from ~1.4 KB to ~1 MB, and for the
lazy shapes it grows with depth. A structural count can't be calibrated against a quantity
that varies by three orders of magnitude and changes complexity class.

The guard's unit is wrong. What overflows is bytes of native stack, and the evaluator can
read how many it has spent: `stack_address()` already backs #2918's native `recurse`
budget.

## Decision

### 1. A native-stack floor per evaluation thread

We will give a thread that evaluates jq a **floor**: the lowest stack address evaluation may
reach. It is registered with the number of bytes of stack *available below the registering
call*, and set half of that below the call's own stack address. The stack grows downward on
every target this crate builds for; the floor assumes it. The floor lives in a thread-local
(`native_stack` in `src/jq/eval.rs`; `0` means unregistered), is entered through a guard,
and is restored on drop. The CLI registers `EVAL_STACK_SIZE` first thing on the evaluation
thread `main` spawns, where the available stack and the thread's size agree to within a few
KB. A library caller registers what it knows is available, through a public entry point that
wraps a closure. A thread that registers nothing keeps exactly today's behaviour.

### 2. Checked where recursion can grow

We will check the floor, with one thread-local read and a comparison against the current
stack address, at every `Expr::DefCall` evaluation and every `Expr::Shared` evaluation in
every evaluator that has those arms: `eval_single`, `eval_each` and `resolve_node_sink` in
`src/jq/eval.rs`, and `eval_each_generic`, `path_context_step_generic` and
`eval_owned_identity_stages` in `src/jq/eval_generic.rs`. A new arm that evaluates either
node takes the check too.

Every native recursion in the evaluator that can grow without bound passes through one of
the two once per level: a `def` call, or a parameter read, which is how a chain of any shape
(arithmetic, lazy, through a helper or a nested def) is walked. Between two checks the stack
grows by at most:

- one level of structure, which the program's own text bounds;
- the sink ascent of one lazy chain;
- a walk over a value the program built, which `MAX_VALUE_TREE_DEPTH` (384)
  bounds (a builtin walking a deeply nested *input* document never passes a
  checked node, and this ADR does not cover it);
- a native `recurse` descent, which #2918's own 512 KiB budget bounds; or
- a static walk (`needs_path_context`, `any_subexpr` and their kin) that
  recurses through an argument chain. A chain's length is capped by the depth
  the floor has already allowed, and those walkers' frames are a small fraction
  of an evaluator level's: roughly 20 MB at the deepest chain the floor admits,
  against the 128 MB left. A walk that binds a `def` body to look inside it
  passes `bind_def_call`, which checks the floor too.

The other half of the stack covers all of these. Crossing the floor raises the same
uncatchable resource limit as `MAX_EVAL_FRAMES` (#2132): `f/1 exceeded maximum recursion
depth` at a `DefCall`, where the definition is in hand, and `exceeded maximum recursion
depth` at a `Shared`.

### 3. `MAX_EVAL_FRAMES` stays, as the structural backstop

We will keep the frame count. It still bounds a runaway `def` cheaply on any thread,
registered or not, and is the only guard on an unregistered thread. On a registered thread
whichever limit is reached first refuses. The #3262 measurement machinery from #3280
(`enter_shared_arg`, its two byte rates, and the hold rules) is not adopted.

### 4. A passed-through argument is shared, not re-wrapped

We will share a passed-through argument rather than re-wrap it. When a call's argument is
already an `Expr::Shared(rc)` (a parameter threaded unchanged, `rep(f; n - 1)`),
`bind_def_call` binds the parameter to `rc` itself instead of a new `Shared` around it. The
two are indistinguishable to evaluation, which is transparent through `Shared`, and to
substitution, which stops at it either way. The threaded closure then reads in `O(1)`
instead of walking `d` pass-through links, and builds no chain for the guard to catch.

### Measured result (2026-09-26, PR #3280)

Release, 256 MB stack. The crash floor is bisected on a build with
`MAX_EVAL_FRAMES` raised out of the way and nothing registered; "refuses" is the
deepest level that still answers.

| shape | Apple M4 Pro crash / refuses | AMD 7950X crash / refuses | `main` |
|---|---|---|---|
| thin `f(n - 1)`, also `[f(N)]`, comma chain, 8 params | 19,619 / 10,007 | 21,102 / 10,787 | refused at 20,000 (3% short) |
| pass-through `f(n - 1; g)` | 20,010 / 10,007 | — / 10,787 | refused at 20,000 |
| bare `sum_to` | 18,213 / 9,186 | 19,541 / 10,007 | 13,297 |
| `f(((n - 1) + 0) * 1)` | 12,591 / 6,296 | 13,449 / 6,862 | **aborted** at ~12,800 |
| `[path(f(N))]`, `f(N) \|= 1` | 22,664 / 11,607 | 24,772 / 12,623 | 20,000 |
| lazy link `f(n - 1 \| .)` | 243 / 172 | 252 / 179 | **aborted** |
| nested `def h: n - 1` | 321 / 223 | 330 / 236 | **aborted** |
| helper `f(g(n))` | 316 / 223 | 334 / 236 | **aborted** |
| `0 \| rep(. + 1; N)` | 12,825 / 6,413 | — / 7,038 | **aborted** at ~673 |
| #3294: `f($acc + [$n]; …)` / `f($n - 1 \| .)` / `def f(g): g \| …` | 16,104 / 8,053; 14,504 / 7,252; 16,182 / 8,210 | 11,264 / 8,678; 15,285 / 7,780; 16,417 / 8,991 | 9,967 / 13,326 / 9,967, 1.09–1.65x short |
| `def f($n)`, `$n` `sum_to`, 3×`$`, no parameter | frame count binds: 13,326 / 9,967 / 7,975 / 7,975 | same | same |

Every shape refuses before the stack runs out, on both machines.

- **Linear shapes** refuse at 1.92–2.00× of their crash depth. The floor is half the
  *registered* stack, measured from a point a few KB into the thread, and the crash
  comes a little before the stack's last byte.
- **The three lazy-link shapes are quadratic in stack**, so half the bytes is
  √2 ≈ 1.41× in depth: 4× the stack measured 2.00–2.09× the crash depth.
- **The pass-through collapse (§4)** turned `rep` from an abort at 673 levels into a
  linear recursion that crashes at 12,825 without the guard and refuses at 6,413
  with it.
- **Two x86 rows read lower in depth**: the accumulator at 1.30× and the combinator at
  1.83×. Their stack per level isn't constant, and their x86 crash floors come from
  the pre-collapse build. Both refuse with `exceeded maximum recursion depth` at
  every depth above the one shown, never with a crash.

**A tree recursion's stack follows its call count, not its depth.** `fib(n - 1) +
fib(n - 2)` runs each right-hand call inside its left sibling's output sink, so
`fib(20)` holds more than half the stack at depth 20: it answered on `main`, which
aborted from `fib(21)`, and now refuses. `[fib(n - 1), fib(n - 2)] | add` runs
`fib(24)` either way. This is #3296.

*Amended by #3296:* when both operands of an operator, or the source of an `as`, are
single-valued, effect-free and call a `def`, each is evaluated to completion before its
consumer runs (`settles_before_consumer` in `src/jq/eval.rs`, used by both evaluators'
operator and argument fan-outs). Each call returns before its sibling starts, so `fib`'s
stack follows its depth and all three spellings answer `fib(24)`. An operator with one
def-calling operand (`n + sum_to(n - 1)`) is left alone: its recursion runs inside that
operand either way, and the settling frame would cost every level stack. The floor
itself is unchanged.

**Refusing what `main` answered is a divergence ADR-0018 permits.** Every shape
this guard now refuses and `main` answered ran within 2x of a crash on `main`:
`fib(20)` against an abort at `fib(21)`, #3294's shapes at 1.09–1.65x.
"Matching would take the process down" can only be enforced with a margin: the
exact depth varies with a frame size, a toolchain or a build profile. ADR-0020's
own ceiling already refused shapes 4x short of their crash for the same reason.
#3262 asked for a 2x margin, and this ADR sets it in bytes.

## Alternatives rejected

- **Extending the frame charge** (#3280 approaches 1–3 above). Rejected on the evidence in
  Context: each rule is a prediction, and a shape it didn't model broke it.
- **Lowering `MAX_EVAL_FRAMES`.** A lower constant can't cover a per-level cost that grows
  with depth (the lazy shapes are quadratic), and it would cut every shape the constant
  already over-protects.
- **Querying the OS for the thread's stack bounds** (`pthread_getattr_np`,
  `pthread_get_stackaddr_np`, `GetCurrentThreadStackLimits`, or the `stacker` crate that
  wraps them). This would cover library callers who don't register, but it needs FFI or a
  new dependency with platform-specific code. Registration covers the CLI, which is where
  #3262's aborts were found. It can be revisited for library callers without changing the
  check.
- **A bounded-stack evaluator** (a trampolined `eval_each`, #3287). This is the fix that
  would *lift* the ceilings rather than make them safe, and the only one that would let the
  lazy-link shapes run as deep as jq's. It is out of scope, and the guard here stays correct
  once it lands. *Amended by #3287:* the three lazy-link shapes named below no longer
  need it -- a pure, finite argument is now read eagerly (`is_eager_arg`, remembered on
  the argument's `SharedArg`) and they reach ~8,500-9,600 levels. Only a link that calls
  a builtin, or reads an effectful or generating argument, still takes the lazy path.
  *Amended again by #5379:* a call jq itself jumps from no longer nests at all (see
  "Amendment: zero-argument tail calls loop in place" below), which is the part of this
  alternative a tail-recursive `def` needs. A recursion that is not a tail call still
  nests, and this ADR's guard still bounds it.

## Consequences

**Every shape gets at least the same margin, by construction.** The floor is half the
registered stack whatever the shape, architecture or build profile, so the debug build
(2 GB) and the release build (256 MB) are both safe without per-profile calibration, and a
new body shape needs no measurement to be safe. A shape's depth is the smaller of the two
limits. Where the frame count is already the tighter one, nothing moves: `def f($n)` stays
at 13,326 levels and ADR-0020's 40-array-constructor body at ~900. Where the frame count
over-admits, the floor now binds. Estimated from the crash floors above (M4 Pro, release):
thin bare recursion ~9,800 levels (`main` admits 20,000 unsafely; #3280 reached ~8,100),
bare `sum_to` ~9,100, the lazy-link shapes ~170. The implementation must bisect these
rather than trust the estimates.

**The frame count is now conservative on registered threads, and could be relaxed.** With
the floor guarding the real stack, `MAX_EVAL_FRAMES` only makes shapes like the
40-array body refuse sooner than their stack requires. Raising it on registered threads
would recover that headroom, but it widens what the evaluator runs and is left to a
follow-up with its own measurements.

**Some shapes `main` admits now refuse earlier.** The #3294 shapes run within 1.09–1.65x of a
crash on `main`, so a 2x margin must cut them: `f($acc + [$n]; …)` to roughly 5,600–8,000
levels. `MAX_EVAL_FRAMES`' own no-parameter shape (1.92x on the M4 Pro) moves slightly the
same way. These are divergences from jq in the direction ADR-0018 permits, recorded in
`docs/compliance/jq/limitations.md`.

**Library callers are unchanged unless they register.** Unregistered evaluation keeps
`MAX_EVAL_FRAMES` alone and keeps ADR-0020's caveat that it guarantees nothing on an
ordinary thread. Registering is how a library caller gets the CLI's guarantee. `no_std` has
no thread-locals and is always unregistered.

**Cheaper than the frame charge it sits beside.** One thread-local read and a compare per
`DefCall` and per `Shared` evaluation. Nothing is walked, cloned or recorded per level.

**The refusal depends on the stack the thread was given.** The same filter refuses at a
different depth under a different `EVAL_STACK_SIZE`, and at a different depth in debug and
release. That is the point, but golden tests must not pin a refusal *depth*, only that a
deep enough input refuses and a shallow one answers.

## Amendment: zero-argument tail calls loop in place (#5379)

jq compiles a call with no arguments that is followed by nothing to a jump
(`TAIL_CALL_JQ`), so `def f: if . < 300000 then . + 1 | f else . end; 0 | f` runs in
constant space (2.5 MB at 3,000,000 levels, jq 1.7.1 on macOS). The evaluators nested the
native frames of the body per call, and this ADR's guard refused it: `MAX_EVAL_FRAMES`
counts structural levels, about 5.3 of them per call for that program, so it stopped at
7,569 calls. No counter or stack size reaches jq's depth (3,000,000 levels at the ~19 KB a
level measures is tens of GB of stack, and the floor is half the registered size), so the
call must not nest.

### Rules

1. **A call jq jumps from, to a def that can bring the loop round, loops in place.** The
   call has no arguments, is to a def with no parameters, and is last in its body: the
   last stage of a pipe, an `if`/`elif`/`else` branch, the last branch of a comma, the body
   of an `as` binding (jq mode), or the `then` of a `def` declared in the body. The callee
   is the def itself or one declared in its body (a wrapper, an outer def called from a
   nested one): `tail_reachable` asks the raw body, once per definition, whether its spine
   ends in a call by name to one of those. A call to an *earlier* def is a helper, already
   resolved in the raw body, which runs its own loop if it has one and cannot come back, so a
   def that ends in one keeps the nested path and its pipes the fused evaluation they had.
   `each_def_tail_loop` (plain evaluator), `each_def_tail_loop_generic` (document evaluator
   and `succinctly yq`) and `Interp::call_def_loop` (path-mode interpreter) enter the callee
   as an `Expr::DefCall` arm does (`enter_def_call`: the floor, the ambient frame depth, the
   #3148 retention scope; the interpreter's `enter_call`) and leave it before the next round,
   so none of the three grows with the number of rounds.
2. **`MAX_EVAL_FRAMES` and the floor bound only a call that is not a tail call.** The first
   hop binds the callee's body as the nested call would, through the call node's own cache
   and with the node's `frames` (`bind_next`), so the charge for the call's place is paid
   once and a call that repeats reuses its body. A hop back to the def a round runs, whose
   body holds nothing but its jumps (`body_is_reusable`), runs the same body again; every
   other later hop binds a new body with the `frames` of the one it leaves, which nothing
   caches. A body kept by the previous round's call node would chain every round's body to
   the one before it, and a body reused with calls of its own would make each of them hot
   (#3148) and keep their call trees, where the nested form freed them as they returned.
   The charge for calls that nest (`install_def_calls`, #2135) is unchanged, and so is every
   refusal of a call that does.
3. **A round budget bounds a loop that never ends.** `def f: f; f` spins in jq in 2 MB until
   it is killed. A tail loop is the same kind of loop as `until` and `while`, so it charges
   the same `MAX_LOOP_ROUNDS` (2^24), counted from the start of each loop, and ends with
   the refusal the nested form raised: `f/0 exceeded maximum recursion depth`, uncatchable
   (#2132). It cannot tell a loop that ends from one that does not, so a finite loop of more
   than 2^24 rounds is refused too, as it is for `until`, and an accidental infinite
   recursion takes seconds to be refused (2^24 rounds at the cost of one round) where the
   nested form was refused in milliseconds. The outputs a loop emits ahead of its calls (the
   front branches of a comma) are bounded apart from its rounds, at 2^20
   (`MAX_LOOP_OUTPUTS`), once it has run 64 rounds: a generator that tail-calls itself holds
   one per round under a consumer that collects. Counted in outputs, not bytes. A round
   that binds a body of its own (every hop after the first that does not reuse one) is
   charged 16 rounds, so the time to refuse a loop that never ends grows less with the
   size of its body.

### What the walk passes through

The walk of a round's body (`tail_step`, `tail_step_generic`) passes only through nodes
that have nothing left to run once the call at the end has: parentheses, a condition and the
stages in front of the call, the branches in front of the last in a comma, the source of an
`as`. A condition, a stage or a source is evaluated to its one value first, and only if
`stage_settles` knows it answers at most once. That is one compositional question:
operators, `if`, pipes and assignments settle when their parts do, a call to a def with no
parameters when the def's body does (remembered on the definition), and a leaf by the two
recognitions the shipped evaluators already had (`single_valued_pure`,
`yields_at_most_one_value`), widened by the few shapes a loop that keeps its state in the
value writes (an assignment or update, `[f]`, `map`). A stage may have an effect (`debug`,
`input`): it runs before its one output, which is where jq runs it, and no shape in the list
can emit a value and then raise. A stage that answers twice anyway is raised, not dropped. In yq
mode a computed index or slice bound does not settle (an index whose key yields nothing
answers every child there), and a pipe that reads node metadata is left to the evaluator
that carries the node (#4696). Anything else ends the walk at that node, which is evaluated
the nested way.

Not covered, and still nesting: a call with arguments (jq does not jump from one either); a
call under `try`, `?` or `label` (nor does jq); a call behind a generator condition or
stage, which jq runs on its heap stack where here the fork point lives in the native
frames; a call in a comma branch that is not the last, or in the right operand of `//` (jq
jumps from both, and keeps the branches still to run on its heap); yq's `as` and a
destructuring pattern; an `as` that binds a node of the document and names its variable in
the body, which the nested evaluator binds with the deferral of what the body never reads
(#3856); and a pipe that needs path context (`key`, `parent`). The evaluators that resolve
`path()` and assignment targets through `DefCall` (`resolve_node_sink`,
`path_context_step_generic`) keep the nested path. The path-mode interpreter, which runs a
program with a dynamic path target as a whole, loops, and asks the same `stage_settles`
question of the program as written, where a call to a def is a call by name that is not
followed, so a stage there that calls a def nests where on the other routes it settles when
the def's body does.

### Consequences

- The issue's program answers `300000` and `3000000` as jq does, and a tail loop holds no
  memory per round (`tests/jq_tail_call_alloc_5379.rs` pins the peak live heap flat across a
  20x depth, from a literal and from a node of the document, with an `as` and with a def
  declared under one, and fails when a round keeps a pointer).
- A def the walk cannot reach a call in takes the path it always did: the loop costs a
  recursion that is not a tail call one read of a cell per call (`tail_reachable`).
- A node of the document bound by an `as` in the plain evaluator's loop is bound as
  `each_as` binds it, with its origin and its embed-table entries, which the round holds in
  `EmbedGuards` and releases before the next. A built value has no node.
- **A `def` call arm that grows the evaluator's own frame moves the floor.** Every level
  of a recursive `def` pays for `eval_each_generic`'s frame, and a debug build's floor
  refused `def r($p1; $p2): ... r(12000; 7)` when the loop's call sat in the arm. Both
  evaluators' `DefCall` arms are out of line (`each_def_call`, `each_def_call_generic`), and
  so is the interpreter's loop (`call_def_loop`), for that reason.
- jq mode and yq mode share the loop. `def` is a succinctly extension in yq mode (yq's
  lexer rejects it), so the extension follows jq and there is no reference to check.
