# ADR-0030: Owned Values Carry a Handle to Their Source Node (#7243)

## Status

🟡 Proposed (2026-11-15). Answers Q1-Q5 of #7243. Builds on [ADR-0017](adr-0017.md)'s presentation
side-trees and sits beside [ADR-0028](adr-0028.md) (spelled scalars) and
[ADR-0029](adr-0029.md) (windows on shared storage). Nothing here binds until it is Accepted, and
the first PR changes no behaviour. The measurements it asks for are in
[What the prototype must show](#what-the-prototype-must-show); none was taken for this text, so
every size and cost below that is not already pinned in the tree is labelled a proposal.

## Context

In yq mode a node's presentation and origin depend on where it sits in its document, or on a live
cursor: its tag, its head, line and foot comments, its style and quoting, its anchor, a mapping
key's spelling, and its document and file index. [ADR-0017](adr-0017.md) keyed the side-trees
(`CommentTree`, `NodeMeta`) by position, which covers a value that stays where it was or is written
to a known path. Whatever rebuilds a value as an `OwnedValue` loses all of it: a collect, a
construction, a variable binding, `to_entries`, a slice, a merge, and the owned routes
(`--eval-all`, `--slurp`, `-P`, the reindex bridge). #7243 lists seventeen issues that stopped at
that point, each fixed one route at a time.

Three facts about the tree today shape the answer.

- **`NodeMeta` already holds everything the issue lists, except origin.** Comment, style, anchor,
  and, in the boxed `HeadFootComment`, head and foot lines, the explicit tag, the scalar's
  source spelling (#3028) and the preamble. `CommentTree::Object` carries a `KeyMap` for the
  key-scoped comment (#765). The data exists. What is missing is a way for a *built* value to name
  the node it came from.
- **Identity by storage address is an established pattern.** `embed_table` (#2889),
  `bridge_provenance` (#3069) and `dom_roots` (#3479) all map a container's storage address to
  where it came from, in a thread-local, and they are sound for the reason
  `bridge_provenance`'s doc comment gives: a registered table holds a strong reference, so a
  later write through either handle copies first.
- **Mutation of an owned array has one door.** [ADR-0029](adr-0029.md) made `ArrayOf`'s
  `DerefMut` and `make_vec()` the only ways to change an element or the length, and a shared
  handle copies first. Anything attached to the storage can be dropped there, once.

### Constraints that decide between carriers

`OwnedValue` is 32 bytes, pinned by `owned_value_is_32_bytes_because_its_containers_are_one_pointer_3000`
(`src/jq/value.rs`). Its widest arm, `NumberLiteral(NumberRepr, SharableLiteral)`, uses the null
niche of `SharableLiteral`'s thin pointer to fit, and `SharableLiteral`'s own comment records that
a fat pointer there makes the enum 40 bytes. An 8-byte handle added to every value would therefore
be a 25% growth of every array element, object entry and scalar in both evaluators, to serve a
feature jq mode never uses. A new variant that wraps another value is not free either: 968 sites
name `OwnedValue::Null` and 588 `OwnedValue::Bool` ([ADR-0028](adr-0028.md)'s count), and a wrapper
over *every* kind would put an unflagged `_` arm in front of every reader of every kind, which is
the risk ADR-0028 accepts for two kinds, multiplied.

## Decision

**A handle names a node in an immutable source tree, and lives beside the value, never in it.**
It does not subsume ADR-0028's spelled scalar (Q1), and it is consulted only where position keying
has nothing (Q4).

### The handle (Q2, Q3)

`SrcRef` is `{ doc: u32, node: u32 }`: a slot in a per-run table of source documents, and a node's
pre-order number in that document's `CommentTree`. Eight bytes, and `Option<SrcRef>` is eight too
with a `NonZeroU32` slot. The table's entry holds an `Rc` of the pristine tree and the document's
origin: its document index, its file index and its file name. A handle resolves, at emit time and
for the readers below, to:

| Resolves to | Per | Source |
|---|---|---|
| comment (line, head, foot), style and quoting, tag, anchor mark | node | `NodeMeta` |
| the node's own document index, file index, filename | document | the table entry |
| a mapping key's spelling, tag and anchor, the key-scoped comment, a collection key | **entry** | `KeyMap` beside `ChildMap` |
| a `<<` merge entry's key | entry | the same |

A key's spelling and comment belong to the mapping entry, not the value, so an object child's slot
is an `EntrySrc { key: Option<SrcRef>, value: Option<SrcRef> }`. A sequence item has only the
value half. Scalar spelling is deliberately absent from the table (Q1).

### Where it is stored

- **Children live in the container's shared storage.** An array's and an object map's allocation
  gains one `Option<Box<[EntrySrc]>>`-shaped slot (proposal: one pointer, `None` for every
  container built from a document that uses none of this and for every jq-mode container). It is
  indexed by *storage* position, so [ADR-0029](adr-0029.md)'s windows share it for free: a slice is
  a window on the same storage and sees the same elements' handles. `OwnedValue` stays 32 bytes.
- **A lone value's handle lives in the evaluator's carrier,** the place that holds one
  `OwnedValue` between stages and in a binding (`$x`, a stage's result, `GenericResult::One` and `Many`).
  That carrier becomes a pair `(OwnedValue, Option<SrcRef>)` where it is not one already; jq mode
  always carries `None`.
- **Rejected:** a wrapper variant `OwnedValue::Sourced(Rc<(OwnedValue, SrcRef)>)` (every reader of
  every kind meets a new arm the compiler does not flag), and an inline field (32 to 40 bytes).

### Q1. Does the handle carry a scalar's spelling? **No.**

ADR-0028 stays alternative A, and its P2 and P3 are unblocked by this answer.

1. **The readers have only a value.** `tostring`, `==`, `select(.)` and `unique` take
   `&OwnedValue`. A handle that lives beside the value is not in their hand, so reading the
   spelling through it means passing the carrier to all of them, including the seven truthiness
   definitions with their 84 call sites. The spelled variant is the one place a reader that has
   only the value can still see the text.
2. **The text is the value's identity, not its presentation.** ADR-0017's soundness rule keeps a
   mark only while the value equals what the mark describes. For presentation that is a side
   check; for `True == "True"` the text *is* the compared quantity, so a handle would be compared
   against the source text on every `==`. That is the spelled scalar, stored twice.
3. **Lifetime.** A handle needs its source tree alive and its document in the table. A spelled
   scalar is self-contained, so `from_entries`, a computed copy and the bridge keep it by
   construction.
4. **The hot path.** A handle check in `==` is a branch on every comparison of every value in yq
   mode; the spelled variant costs one arm that only a non-canonical scalar reaches.

What is shared is the invalidation rule (Q5) and the bridge token ([ADR-0028](adr-0028.md),
#5466), which carries both.

### Q4. Interaction with what exists

- **ADR-0017's side-trees.** The handle does not replace position keying. A write path keeps
  `reconcile_presentation` and its position-keyed pairing. The handle is consulted where that has
  nothing: a value built by a collect, a construction, `map`, a binding, a slice, a merge or an
  owned route, which is exactly the set #7243 lists. `NodeId` is the tree's pre-order number, so
  nothing in `CommentTree` changes; the pristine tree is shared behind an `Rc` instead of being
  rebuilt per call.
- **[ADR-0029](adr-0029.md).** A slice shares storage, so it shares its elements' handles
  (indexed by storage position, so `.[1:]` finds element 1 where the source had it).
  `shares_storage_with` and `jq_identical` ignore handles: two values with the same storage and
  window are one node whatever they came from, and two equal values with different handles are
  equal. A handle is presentation and origin, never identity.
- **`jq::alias_identity` (#1351).** Two handles with the same `(doc, node)` *are* the same source
  node, which is the identity the redirect reconstructs from paths. The first slices do not drive
  the redirect from handles: it keeps its copy model. Replacing it is the follow-up that serves
  #2501 and #4223's residual, and it should wait for the handle to exist.

### Q5. When a handle is dropped

A handle is valid while the value is equal to the node it names. It is checked without comparing a
document:

- **Container:** valid while the storage allocation it was attached to is unchanged. Every change
  goes through `DerefMut` or `make_vec()` ([ADR-0029](adr-0029.md)) or a copy, and each clears the
  slot (O(1), complete by construction). A shared handle copies first, and the copy starts
  without handles for the written part. The object map's mutators are the same choke point; the
  prototype lists them.
- **Scalar:** an operation that produces a new number or string produces a carrier with no
  handle: arithmetic, `tostring`, `ascii_downcase`, `+`, `length`. A scalar that passes through
  untouched (`.[0]`, `$x`, `select`, `first`) keeps it. Comparing a scalar to its source text
  would be O(its length), so it is done only where a value is *rewritten in place* (`.a |= f`
  keeps its position-keyed mark by the existing reconcile).
- **Kind change** (`.a | tostring` of a mapping) produces a new value and so no handle.
- **Origin is not presentation.** A node built by an operator has no document, so `di`, `fi` and
  the `---` rule read none for it ([#7180](https://github.com/rust-works/succinctly/issues/7180):
  `5 | fi`), and a node taken from a later document reads that document's index
  ([#2427](https://github.com/rust-works/succinctly/issues/2427), #3986). yq's rule is per
  operator, so each operator that returns an input node unchanged propagates the handle, and
  every other builds without one. That per-operator table is the work of the slices, and it is a
  fixed list, not a framework.

## Alternatives considered

**A. Inline field on every `OwnedValue`.** Rejected: 32 to 40 bytes for every value, in jq mode too.
ADR-0017's second reason against fields (the JSON-text round trip discarded them) still holds for
the reindex bridge, which serializes a value and re-indexes the text: whatever is carried inline
needs the bridge token anyway.

**B. A wrapper variant.** Rejected, above.

**C. Position keying only (today).** Cannot name a built value's source: #5431's "`RelTarget` has no
record of the written value" is the same sentence.

**D. A thread-local address table for every value (as `bridge_provenance`).** Fits containers, and
is the cheapest to build, but scalars have no address and strings share storage only after a bind
(#3191), so the cases #6101 and #5429 name (`.a as $x | [$x]` on a scalar) are the ones it cannot
serve. It is the right mechanism for the reindex bridge and stays one.

**E. Do nothing.** Seventeen issues keep their residual rows, and #2802's P2 and P3 have no answer.

## Proposed plan

Each step its own PR, with a differential row against yq v4.53.3 and an interleaved two-machine A/B.

1. **P0.** The measured prototype: width of every candidate, the cost of the storage slot on a
   corpus with no presentation marks, one dependent row through it (the issue asks for one or two).
2. **P1.** `SrcRef`, the source table, the storage slot with its clearing, the carrier pair. No
   producer and no behaviour change.
3. **P2.** The producer for a cursor conversion that today calls `to_owned_with_comments`, and the
   first reader: `.a as $x | [$x]` (#5429).
4. **P3.** Document and file origin, `fi`, `di`, `filename` and the `---` rule (#7154, #2427,
   #3986, #7180).
5. **P4.** The remaining readers, one issue each, and the optional alias-identity replacement.

## What the prototype must show

The constraints in #7243, restated as gates: the width of `OwnedValue` and `JqValue` unchanged
(both pins pass); jq mode and every document with no presentation mark build what they build today,
shown by an allocation count and an interleaved A/B on **terminus** (7950X) and the **M4 mac mini**,
control first, output identity gated, two input sizes at least, `comprehensive` and a no-marks
corpus ([docs/guides/benchmarking.md](../guides/benchmarking.md#ab-benchmarking-method)); and a
dependent row reproduced through the handle.

## Consequences

**Positive.** One mechanism for seventeen issues; no change to `OwnedValue`'s width; jq mode
unaffected by construction (no producer); ADR-0028 unblocked; the soundness rule is enforced at
the two doors ADR-0029 already made.

**Negative.** A carrier pair in the evaluator, which is plumbing in every stage that holds a lone
value; one more word in every container allocation unless the prototype shows it can sit in a
spare niche; two mechanisms for "what was this written as" (inline spelling for scalars, a handle
for the rest) with a documented boundary between them.

## Questions for the owner

1. **Beside, not in.** Accept the carrier pair and the storage slot over a wrapper variant.
2. **Q1.** Accept that the handle does not subsume ADR-0028, so P2 and P3 there proceed.
3. **Order.** Presentation first (P2), origin second (P3), or origin first, since `fi` and the
   `---` rule need no tree at all.
