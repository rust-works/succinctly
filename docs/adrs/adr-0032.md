# ADR-0032: A Call Machine for jq Programs with a Recursive `def` (#7977)

## Status

✅ Accepted (2026-11-27). Amends [ADR-0020](adr-0020.md) (runtime `def` calls by substitution) and
[ADR-0025](adr-0025.md) (the native-stack floor) for the programs it routes, and extends
[ADR-0026](adr-0026.md), whose path-mode route already owns the routing hook and the leaf evaluator.
[ADR-0018](adr-0018.md) still decides every behaviour. The machine has two refusals jq does not
give, the byte budget and the `MAX_LOOP_ROUNDS` loop cap, and both are rule 4(c) divergences. The
full design, each step's acceptance criteria and the risks are in #7977. The competing designs and
the spikes that chose between them are in #7957.

The machine lands behind a switch that defaults to off (step 1). The amendments it makes apply to
routed programs from step 6, which flips the default, and before that only to runs with
`SUCCINCTLY_CALL_MACHINE=1`. Nothing changes for any other run before step 6.

Amended (2026-11-27, #7977 step 2): the byte budget counts the control state alone, not what
`[...]` collects, and the loop cap and the prelude loops' caps follow the shipped evaluators' own
rules, see the amendment below.

Amended (2026-11-28, #7977 step 4): a zero-argument self tail call is a jump, a constant right
operand is read in place, and a finished `try` or label is a dead fork point, see the amendment
below.

Amended (2026-11-28, #7977 step 3): a leaf holds the `.[]` and `range` it collects and reads its
variables from the slots through a borrowed view, see the amendment below.

Amended (2026-11-28, #8064): a limit on the memory the process holds, sampled as the machine
runs, bounds a run, and with it the machine has no bound on a loop's outputs, see the amendment
below.

## Context

`succinctly jq` runs a `def` call in four places: `each_def_call` (`src/jq/eval.rs`),
`each_def_call_generic` (`src/jq/eval_generic.rs`), `owned_call::call` and `Interp::call_with`
(`src/jq/path_mode.rs`). The first three share two choices made in ADR-0020 and kept in ADR-0025:

1. **Binding is substitution.** `bind_def_call_body` copies the body for each call, through
   `substitute_params`, `install_def_calls` and an `as` per `$` parameter. That costs time per call
   in proportion to the body. On `main` at `0dac2e2d7`, #7699's `f($n-1) | f($n-1)` is linear in
   its calls and still takes 2.36x, 3.16x and 3.45x jq 1.7.1's time at N = 12, 14 and 16 on an
   Apple M4 Pro, and 2.60x, 3.54x and 4.02x on an AMD Ryzen 9 7950X (#7957's re-time).
2. **Control is a push sink on the native stack.** A producer hands each output to its consumer's
   `sink`, so the consumer runs inside the producer's frames. Every boundary between a producer and
   its consumer then has to choose:
   - **collect the producer first**, which loses laziness: #7870's `first(f(g + (1,3); n))` built
     the whole `2^n`-output chain before `first` could stop it. Since #7915 makes the chain eager,
     `main` answers n = 500 (1.41x and 3.11x jq's time), but it still refuses n = 20,000 and
     128,000, which jq answers;
   - **or stream it**, so the consumer nests on the producer's stack: #7787's tree recursion is
     refused at 2,048-8,192 leaves, and linear recursion near 10,000 levels.

Rules that approximate "collecting is unobservable here" grew to fill the gap. Each is written once
per route, and each closes one shape:

| Rule                | Where                                                   | Size              |
|---------------------|---------------------------------------------------------|-------------------|
| Settle rule         | `tail_call::call_answers_once`, `eval::operands_settle` | about 1,900 lines |
| Eager-argument rule | `is_eager_arg`                                          |                   |
| Output check        | `DefOutputWatch` (ADR-0025's #7856 amendment)           | about 175 lines   |
| Remembered answers  | `SharedArg`, `TailMemo`                                 | 15 cells          |

The rules interact:
- #7893 was quadratic because of #7856's output check. It was closed by a further rule: a call
  handed its own wrapper is not wrapped again.
- #7928 is a regression from the settle rule's #7828 widening. A `try` closure passed down a doubled
  recursion takes about 15 s at depth 4 on Apple silicon. jq, and the build before the widening,
  answer at once.

#7803's memoised Hofstadter Q copies its whole memo at every level. A value carried through `as`
bindings is still held when `setpath` writes it. jq has the same term, because it moves only fold
accumulators (`LOADVN`): from N = 400 to 3,200 its instructions grow 1.95x, 2.20x and 2.51x per
doubling of N (43.8M to 473.8M, cachegrind on the 7950X). #7803's "about linearly" for jq came from
a check at small N on a laptop.

jq avoids all of these problems except #7803's copies by design:
- its call stack is heap-allocated (`exec_stack.h`, see ADR-0020);
- a closure is code plus the environment it was written in;
- a generator suspended at a fork point costs one record on a contiguous stack, not a native frame.

gojq and jaq bind through environments too. #7957 compared three designs for a machine with those
properties. It built all three, plus a fourth variant, as spikes to one fairness contract, and
measured them on both chips.

## Decision

We will run a jq-mode program that holds a self-recursive `def` on a **call machine in jq's image**:
compiled instructions over contiguous data, frame, slot and fork stacks, protected by a watermark,
with values moved out at their last use.

The reference implementation is #7957's spike d2. It lives on the local, unpushed branch
`spike-7957-d2-stack-vm` at `3b26ab457`, in `src/jq/path_mode/vm.rs` and
`src/jq/path_mode/vm/compile.rs`. Step 1 ports it into the repository, with the spike's 109-program
corpus and its harness (`cases.py`, `check.py`, `ladders.py`) under `scripts/`, where readers will
find them.

### Routing

- **What counts as a recursive `def`** is `vm::self_recursive`'s syntactic test: a `def` whose body
  contains a call of its own name and arity. Nested `def`s and closure arguments count as part of
  the body. Mutual recursion in jq can only be written by nesting one `def` inside the other, so it
  counts. Recursion that happens only inside the prelude does not count, for example `-.`, which is
  desugared to a call of `_negate`.
- **Where the route is decided.** ADR-0026's `path_mode::route` (through its walk, `route_walked`)
  returns `Route::Interpreter` when `vm::decide(program)` answers compiled code.
  `run_program_seeing` then runs that code on `vm::run` instead of `Interp::eval`. The runner, label
  numbering, input preparation and output handling are ADR-0026's, shared.
- **`decide` runs once per run**, as the route is pinned: the rule is
  `self_recursive && compile(program).is_ok()`, and **the compiler is the decliner**, so there is
  one definition of what the machine runs (it declines the input builtins, with the other forms it
  does not run, through `declined_anywhere`). The pin tags the route `PIN_MACHINE` in
  `PINNED_ROUTE`, and `PINNED_MACHINE` keeps the compiled code for the run, so every document runs it
  (step 5). The code owns what it holds (a leaf keeps a copy of its subtree) and nothing in it
  changes as it runs; a document's state is the machine's, which starts afresh for each document.
  Only allocations carry over: a document's run leaves the data, frame, slot and fork-point stacks
  and the call scratch buffer (`Spare`) empty for the next, each cut back to 64 KiB (`KEEP_BYTES`),
  so a per-record run allocates them once. A caller that pins nothing decides per call.
- **A program is routed whole**, never split between evaluators. Until a step below extends the
  machine, these stay on today's evaluators unchanged:
  - yq mode;
  - a module call (`route` keeps one on the shipped route);
  - `?//`;
  - `input`, `inputs`, `input_line_number`;
  - the path forms: `path`, `paths`, `getpath`, `del`, `pick`, `tostream`, assignment and update;
  - `last`;
  - a call inside an object constructor, a string interpolation, an index or a C builtin's
    argument;
  - prelude bodies that hand a closure to a `_sp_hook_*` helper.
- **The switch.** `SUCCINCTLY_CALL_MACHINE=0|1` (#7961), read once per process, switches the route.
  It defaults to off until step 6.

### Compilation

`compile` makes one pass over the program and the prelude bodies it reaches. It follows jq's code
generators: `gen_reduce`, `gen_foreach`, `gen_collect`, `gen_definedor`, `gen_try` and `gen_label`.

- **Environments, not substitution.** Each `def`, closure argument and reached prelude body is a
  function. Variables, closure parameters and labels are slots addressed by `(level, index)` along
  static links, as jq's `frame_get_level` does. Names are resolved once, at compile time.
- **Parameters.** A `$` parameter whose bare name the body never calls is passed by value. That
  makes `r($p - 1; $q)` a tail call.
- **Forwarded closures.** A closure passed on unchanged is a copy of the caller's (jq's
  `CLOSURE_REF`), so `def f(g): ... f(g)` stays a tail call. jq does not do this (jqlang/jq#547):
  jq 1.7.1 runs `def f(g): if . < N then . + 1 | f(g) else . end; 0 | f(.)` in 13.4 MB at
  N = 10^5 and 80.3 MB at N = 10^6, against a flat 2.5 MB for the zero-argument form.
- **Tail calls.** A call followed by a return, with no lambda argument and no callee closing over the
  current frame, pops the caller's frame before pushing the callee's. A frame or slot region that a
  live fork point protects is not freed.
- **Leaves.** A maximal call-free subtree compiles to one leaf instruction. `Interp::eval` runs it
  over the leaf's free variables. A leaf is the only code that recurses natively. That recursion is
  bounded by the leaf's own text, and its walks over values (`..`, a deeply nested value) by
  ADR-0025 §2's value-depth guards.
- **Prelude loops.** `first`, `limit`, `until`, `while` and `repeat` are the prelude's jq definitions
  and are compiled like user code. `label` is syntax, compiled as jq's `gen_label`. Early stop is
  therefore a fork-stack unwind, and a producer that has been stopped runs no further.

### Machine state and the protection invariant

`Vm` holds a data stack, a frame stack, slots (a `Vec<Slot>`) and fork points. The data and frame
stacks are gojq's `stack.go`: blocks with an `index` and a `limit`. Saving a fork point raises
`limit`, and restoring it resets both.

**The protection invariant: a block a live fork point can reach is never overwritten, and its value
is never moved out.** Every other rule follows from it. It is enforced in safe indices: in
`Stack<T>` for the data and frame stacks, and for the slots by the slots-watermark check below.
There is no `unsafe` and no new crate.

Errors, `break`, `try` and labels are fork kinds. `try` follows jq's `TRY_END`: once a `try` body
has produced an output, the `try` does not catch an error its consumer raises. Asking for the next
output is a backtrack. The native stack is constant, because everything runs in one dispatch loop.

### Ownership: last-use moves

Values are immutable. An `OwnedValue` container is copied only when it is written while shared
(`Rc::make_mut`), so the machine's job is to keep a container uniquely held when it is written.

- **Loads.** `Load` clones (jq's `LOADV`). `LoadMove` moves a fold accumulator out (jq's `LOADVN`).
- **The static analysis.** A per-binding last-use analysis turns a read that nothing later in its
  scope reads into `LoadLast`. A binding's last reads can sit inside a node whose evaluation order
  the walk does not track: a call's arguments, a leaf or a fold. Then the analysis emits
  `Kill(slot)` after that node.
- **Exclusions.** Variables a nested `def` reads, and the pattern variables of `reduce` and
  `foreach`, are never moved: they always copy.
- **The runtime check.** `LoadLast` moves, and `Kill` drops, only when the slot is above the slots
  watermark, the slot height the top fork point saved. Otherwise `LoadLast` clones and `Kill` does
  nothing.
- **Why the moves are sound.** A fork point that could re-run the read is live while the read runs.
  It saved a slot height above the binding, so the move becomes a copy. The static walk only ever
  errs towards copying. Step 1 checks this argument with a property test and the spike's 24 hand
  cases.
- **`setpath/2`** is a native instruction that takes its input by value, so a uniquely held array
  is written in place.
- **Rule for future native builtins:** one that writes its input takes it by value, one that only
  reads takes a reference, and neither takes a closure.

This goes further than jq, which moves only fold accumulators. On #7803 the machine's instructions
grow 1.91x to 1.98x per doubling of N (26.3M to 194.8M from N = 400 to 3,200, cachegrind on the
7950X), which is linear. It forces one copy at every N, and at N = 3,200 it takes 0.48-0.56x jq's
time.

### Budget and refusals

**The byte budget.**
- **What it counts:** the control state, in bytes, at `size_of`: data blocks, frames, slots and
  fork points, by capacity, plus `[...]` accumulators and buffered leaf outputs.
- **It is not a memory bound.** The values the slots reference are not counted. (#8064's
  amendment adds a limit on the memory the process holds.)
- **When it is checked:** at every call and every fork push, against 1 GiB. The control stacks are
  allocated fallibly (`try_reserve`).
- **The refusal.** Past the budget, or when an allocation fails, the machine refuses with the
  shipped evaluators' refusal wording (ADR-0025 §2), naming the innermost definition:
  `f/1 exceeded maximum recursion depth`. Like the floor's refusal it cannot be caught by `try`
  (exit 5).
- **Why it is allowed:** jq has no bound and aborts on memory (`cannot allocate memory`, ADR-0020),
  so this refusal is an ADR-0018 rule 4(c) divergence: matching would take the host process down.
  Step 2 records it in `docs/compliance/jq/limitations.md`.

**The loop cap.** A loop that never deepens keeps the shipped evaluators' `MAX_LOOP_ROUNDS` (2^24)
refusal.
- **Why it is needed.** The machine makes more calls tail calls than `main` does: a `$` argument
  passed by value (`r($p - 1; $q)`) and a forwarded closure (`f(g)`) both qualify. A non-terminating
  loop through such a call therefore runs in constant space, and neither the byte budget nor a
  check that only recognises `def f: f; f` stops it. `main` refuses `def f($n): f($n); f(0)` in
  0.04 s. The spike counts no rounds, so it spins, which would be a regression.
- **What is counted.** Every tail call that reuses a frame, at any arity, charges one round, and so
  does every round of the prelude's `until`, `while` and `repeat`. They are counted as the shipped
  tail loop and `until`/`while` count them.
- **The wording.** Past the cap the machine refuses with the shipped wording: `f/1 exceeded maximum
  recursion depth` for a `def`, and `until: maximum iterations exceeded` (likewise `while:` and
  `repeat:`) where `main` gives that today.
- **The divergence.** jq spins on a loop that never ends (ADR-0025's #5379 amendment), and answers a
  finite loop that runs past the cap. Both stay refused, as `limitations.md` already records.
- **Where it lands.** Step 2 implements the cap.

### Decisions taken (#7977's "Decisions for the owner")

1. **End state (a).** The machine stays a route for programs with a recursive `def`, with the
   shipped evaluators for the rest, through step 11. Whether it then becomes the only jq-mode
   evaluator (b) is decided from measurements of its per-node cost on `def`-free document programs
   against `main`'s cursor evaluator. No spike has measured that.
2. **Budgets in bytes, with fallible allocation**, not frame counts (above).
3. **A loop that never deepens keeps the `MAX_LOOP_ROUNDS` refusal**, matching `main`. It is counted
   at every frame-reusing tail call and every prelude loop round (above).
4. **How the machine is made generic over the mode waits on #7384** (step 10): over `EvalSemantics`,
   or over the mode as a runtime value if #7384 makes it one.
5. **The machine follows the pin** (jq 1.7.1, ADR-0018 rule 1), with the shipped evaluators'
   recorded exceptions, which it inherits through its leaves. Examples are `@urid` (#6726) and
   `Array index too large` (#7536).

## Alternatives considered and rejected

**Fidelity did not separate the spikes.**
- All four answered the same 109 cases exactly as jq 1.7.1 (stdout, stderr, exit status).
- On the full `jq_cli_tests` suite, d1, d1v and d2 each had 9 failures and d3 had 8. Every failure
  pins a refusal that jq does not give, except `i7846`, which `main` fails in the same environment.
- Three tests were skipped for every spike, because they never terminate under a machine:
  `def f: f; f`, `def _negate: -.; 1 | -.` and `[def f: ., (. + 1 | f); 0 | f]`. Step 2 and
  decision 3 must make them terminate.

So the measurements decide. The first run's geomeans over jq 1.7.1, on the 46 cells all four
answer (below 1 is better than jq):

| Spike                               | Time, M4 Pro | Time, 7950X | Instructions, 7950X | Peak RSS, M4 Pro / 7950X |
|-------------------------------------|-------------:|------------:|--------------------:|-------------------------:|
| d1: persistent continuations        |        1.115 |       1.243 |               0.690 |              1.58 / 2.60 |
| d1v: d1 on `Vec` stacks             |        0.980 |       0.963 |               0.595 |              1.57 / 2.55 |
| d2: compiled stack machine (chosen) |        0.820 |       0.829 |               0.494 |              1.47 / 2.22 |
| d3: pull iterators                  |        0.919 |       1.004 |               0.552 |              1.66 / 2.67 |

d2 lost one shape in that run: #7803's memo, at 2.23x jq on the 7950X. The last-use moves fixed it.
A second run over 47 cells then re-timed d2 against d1v, so d1v has a geomean from each run:

| Second run, over jq 1.7.1       | M4 Pro        | 7950X         |
|---------------------------------|---------------|---------------|
| Time, d2 (d1v)                  | 0.794 (0.993) | 0.781 (0.970) |
| Instructions, d2 (d1v)          |               | 0.473 (0.600) |
| Cells where d2 beats d1v, of 47 | 44            | 40            |

- **d1, persistent continuations over the AST** (the first prototype). Rejected, because it is the
  slowest of the four.
  - Its `Rc` node per continuation frame alone costs 12% of time on the M4 Pro and 23% on the
    7950X. That is d1 against d1v, which changes nothing else.
  - Its environment chain grows on tail calls with `$` arguments: 2.4x jq's RSS, where d2 runs in
    constant space.
- **d1v, d1's model on gojq-style `Vec` stacks with a watermark.** Rejected as the base, and kept
  as the **fallback** if the compiler is ever judged too costly to carry. d2 is about 20% faster
  (d1v takes 1.24-1.25x d2's time on the second run), and d1v has no quadratic shape. What is left
  of the gap is per-node dispatch over the AST, `Interp`'s `Rc` frames and d1's environment growth
  on tail calls.
- **d3, pull iterators with environments and a trampoline** (jaq's model). Rejected on depth and on
  memory. Its depth is native, so it refuses linear recursion at about 310,000 levels. Its peak RSS
  is the highest of the four: 4.6-5.2x jq on #7787's tree.
- **Keep fixing the shipped evaluators shape by shape.** Rejected:
  - there are already four rules, each written once per route;
  - each fix has exposed the next shape;
  - #7893 and #7928 were caused by the rules themselves.
- **Make the machine the only jq-mode evaluator now.** Not rejected but deferred (decision 1): it
  needs a measurement no spike took.

## Consequences

**Positive**

- **The targeted issues are fixed by the model, not by a rule per shape.**
  - At step 6: #7699, #7787, #7870 and #7928, and #7803 for `-n` and owned inputs.
  - At step 9: #7803 for document inputs.
  - #7893 is closed already. Its family, a recursion's outputs climbing native frames, cannot arise
    on the machine.
- **Spike measurements**, against `main` and jq 1.7.1 (47 cells, 5 interleaved reps, A/A spread at
  most 0.4%):
  - 0.79x jq's time on the M4 Pro and 0.78x on the 7950X;
  - 0.21x and 0.14x `main`'s time on the 31 cells `main` answers;
  - 16 cells that `main` refuses or cannot finish are answered.
- **Depth.** Linear recursion runs to 1,000,000 levels and beyond in constant native stack.
- **Unrouted programs** run exactly as today, and startup is unchanged.
- **#7946.** Values that stay owned through the machine do not pass through #7946's re-index
  bridge, though a leaf still can.

**Negative**

- **Known slower shapes, each removed by a named step.** Both are still faster than jq (0.27-0.71x
  its time).
  - Array building such as `[range(1e6)]` inside a routed program takes 1.3-1.9x `main`'s time.
    Step 3 removes it (leaf granularity).
  - A zero-argument tail loop takes 1.03-1.35x `main`'s time. Step 4 removes it (the call compiles
    to a `Jump`).
- **A leaf's code is a copy of its subtree**, literal text included, so a 20 MB string literal in a
  leaf costs 20 MB more memory, once per run.
- **A caller that pins nothing compiles twice per call**: `route` decides and drops the code, and
  `run_program` decides again. The CLI pins every run; carrying the code from `route` to
  `run_program` would change every evaluator entry that asks for the route.
- **A third evaluator during the overlap.** `Interp` and the plain and generic evaluators keep their
  call paths for unrouted programs.
  - The switch, the corpus gate on both arms and whole-program routing contain the overlap.
  - At step 8 the path forms run through the machine, so routed programs no longer reach `Interp`'s
    call path or the resolver's `DefCall` arm.
  - Step 11 deletes the shipped call rules once every jq-mode program with a recursive `def` routes.
- **Binary growth.** The spike is about 2,100 lines, and steps 7-9 add more. Each PR is held to
  #7959's per-PR size gate. Step 11 deletes more than it keeps, and records the size.
- **A protection or last-use mistake gives a wrong answer, not a crash.** Step 1 adds a property
  test of the protection rule and the spike's 24 hand cases for `LoadLast`. Every step runs the
  corpus gate against captured jq 1.7.1 answers.
- **A routed program materializes its input** (`OwnedValue` only, as ADR-0026's route does) until
  step 9 makes the value slot generic over cursors.
- **Divergences.**
  - The byte-budget refusal is new, recorded at step 2.
  - The loop cap is the shipped evaluators' divergence, extended to more tail calls.
  - The divergences and pins the machine makes obsolete are deleted in the PR that flips the
    default (step 6) or at step 11.

## Migration plan

Each step is one PR that can merge alone, with the test that fails without it.

Each step runs the corpus gate:
- the spike's 109 programs and a generated call-heavy corpus are equal to captured jq 1.7.1 answers;
- `jq_cli_tests` is unchanged apart from listed refusal pins.

#7977 holds each step's acceptance criteria.

1. **The machine behind a switch.** Port the machine behind `SUCCINCTLY_CALL_MACHINE`, default off,
   with unit and property tests and the spike's corpus and harness in `scripts/`.
2. **The budget and the loop cap.** A complete byte budget with fallible allocation, and
   `MAX_LOOP_ROUNDS` at every frame-reusing tail call and prelude loop round. Record the
   divergence.
3. **Leaf granularity.** A call-free subtree whose consumer cannot stop early becomes one leaf, which
   reads slots through a borrowed view.
4. **The zero-argument tail loop.** A zero-argument self tail call compiles to a `Jump`.
5. **Compile once per run**, without `unsafe`.
6. **Flip the default** (#7961), A/B'd as one binary with the switch set in both arms. This closes
   #7699, #7787, #7870 and #7928, and #7803 for `-n` and owned inputs. It also deletes their
   recorded divergences and pins.
7. **The declined forms**, one PR each:
   - `?//`;
   - `last(f)`;
   - calls inside constructors, interpolations, indexes and C builtin arguments;
   - `input`, `inputs` and `input_line_number`.
8. **The path register** in every fork point, taking ADR-0026's path forms through calls.
9. **Cursor values** instead of a materialized document.
10. **yq mode**, after #7384.
11. **Retire the rules** the machine made unreachable, then re-measure ADR-0025's depth table and
    decide the end state:
    - `is_eager_arg`'s comma clause;
    - the settle rule;
    - `DefOutputWatch`;
    - `BoundBody` for recursion;
    - the tail loop's reachability analysis;
    - the `limitations.md` paragraphs for #7460-#7856.

## Amendment (#7977, adopted 2026-11-27): what step 2's bounds count

Step 2 found that the budget as decided above refused programs `main` and jq answer, and that the
loop cap needed the shipped evaluators' own rules to refuse what they refuse and nothing more.
ADR-0018's order decides each point: a refusal is allowed only where matching jq would take the
host process down or never end, and otherwise the machine answers as jq does.

**The byte budget counts the control state alone.**
- **What it counts:** the data, frame, slot and fork stacks, by the capacity the run has grown them
  to. A stack kept from an earlier document (step 5) is charged as a fresh one would be, as the run
  grows into it, so each document has the whole budget and refuses where a fresh machine does.
  What a kept vector holds beyond its charge, up to 64 KiB each, is outside the budget: with the
  call scratch buffer, which the budget never counts, that is five vectors, about 320 KiB in all.
  `[...]` accumulators and a leaf's buffered outputs are not counted: counting them refused
  `def f: f; [range(1e7), range(1e7)] | length`, which `main` and jq answer, and nothing lets the
  machine refuse that. They are values the program builds, as on the shipped routes. (#8064's
  amendment bounds them by the memory the process holds, a limit that program fits in.)
- **When it is checked:** whenever one of the four stacks grows (a call, a fork point, a data push
  or a slot past the capacity), counting the old block and the new one as if it were copied. When
  the growth fits in a kept vector's capacity nothing is copied, so against the memory really held
  the check errs towards refusing early, by the old block at most; it refuses where a fresh machine
  does. Every
  growth is fallible (`try_reserve`), an accumulator's and a leaf buffer's included, so a failed
  allocation is a refusal, not an abort.

**No bound on closure composition.** A chain that composes a closure at every level
(`def f(g): g | f(g + 1); 0 | f(.)`) is quadratic to read, and `main` refuses such chains at its
native-stack floor. A bound in the machine refused #7870's `first(f(g + (1,3); n))` at
n = 20,000, which jq answers in milliseconds, and #7870 is one of the issues this design exists to
fix. The byte budget already bounds memory, so the machine follows jq: a finite chain answers, and
an endless one runs until the budget refuses it, as long as jq runs.

**The loop cap follows the shipped tail loop.**
- **A round** is a tail call to the caller's own definition, to one it is nested in, or to one
  declared in it, at any arity. A round into a definition that declares definitions of its own
  costs `BOUND_ROUND_WEIGHT` rounds, as the shipped loop charges a round that binds a body. A
  tail call to any other definition (a helper), with closure arguments or without, starts a count
  of its own, and its outputs are charged to the caller's loop.
- **The output bound** (`MAX_LOOP_OUTPUTS`, for a zero-argument `def`) started after
  `OUTPUT_BUDGET_AFTER_ROUNDS` tail rounds counted one each, however much each cost against the
  round cap, as the shipped loop counts them. #8064's amendment keeps it only where no memory
  probe is installed.
- **The refusal is named for the definition the loop started at**, as the shipped loop names it,
  and a refusal names the innermost user definition, past the prelude's frames.
- **The prelude loops keep the shipped caps exactly**, counting the round that starts the loop:
  `until` and `while` refuse at `MAX_LOOP_ROUNDS` evaluations of their condition, `range/3` past
  `MAX_RANGE_TOTAL` numbers (with `range:` wording, as does the machine's own `range/2`), and an
  eager `repeat` (one whose nearest consumer is a `[...]` or a `reduce`, rather than a prelude
  label it runs inside) after `MAX_REPEAT_ROUNDS` rounds or `REPEAT_WIDTH_BUDGET` outputs. A
  `repeat` a consumer can stop is unbounded and ends after `MAX_EMPTY_REPEAT_ROUNDS` empty rounds.

**A loop through a nested `def` returns in constant work.** A call in tail position to a callee
that closes over the caller's frame keeps that frame and returns past it (`Tail::Keep`), so an
output of `def f: def g: ., (. + 1 | f); g` returns at once, not through every frame the loop has
kept, which made it quadratic.

**A dead fork point does not hold a frame per round.** At a tail call whose caller a fork point
protects, the fork points at the top that can only answer nothing are dropped and the watermarks
lowered to what they saved: one resuming at a `BACKTRACK` (`. + 1, empty`), or at `//`'s check of
a `found` slot that is set. So a `while` or `until` whose update is `(. + 1) // 0` runs in constant
control state, as the shipped evaluators and jq run it, where it met the byte budget at about 2-3
million rounds.

## Amendment (#7977 step 4, adopted 2026-11-28): the tail jump and the fork points a round leaves

**A zero-argument self tail call is a jump.** A self tail call of a zero-argument `def` compiles to
`TailJump`, back to the function's entry in the frame it runs in (gojq's `opjump` case of
`optimizeTailRec`), when the function makes no closure over its frame: it passes no closure
argument and declares no `def`. That is decided in the compiler, conservatively: a closure
argument the body passes (`first(.)`), a `def` it declares, and a call that is not in tail
position (under `try` or `label`, or an operand) keep the ordinary call. `$__loc__` is a constant,
and a `reduce` or `foreach` that has finished leaves nothing over the frame, so those jump. The
prelude's `until` and `while` loop through such a `def` and jump too.
- **What it keeps.** At run time the jump is the `Tail::Pop` call in every respect: it checks the
  room for a frame as the call does, so the byte budget refuses where it did; it charges a round,
  and a round past `MAX_LOOP_ROUNDS`, or an uncounted `repeat`'s, is the call's, which refuses
  with the same wording at the same count; it drops the dead fork points as the call drops them.
- **When it reuses the frame.** Only when, after that drop, no fork point protects the frame and
  the frame sits where the call would push its successor. The state is then the one the call
  reaches by popping the frame and pushing its successor: the same function, static link, return
  address and `exit`, the slot base, fresh slots, and the input on top. A frame a fork point
  protects is kept, by the ordinary call, so `Stack<T>`'s watermark and the protection invariant
  are untouched.
- **Constant operands.** A binary operator whose right operand is a constant reads it where the
  code keeps it (`BinK`, `CmpK`), instead of `DUP`, `LOADK`, `SWAP` around the operator: a
  constant has no effect, no error and one output, so not running it first changes nothing. With
  the jump this halves the instructions of a zero-argument tail loop
  (`def f: if . < N then . + 1 | f else . end; 0 | f`): 1,422M at N = 10^6 against 2,875M on the
  shipped route and 3,155M before (instructions retired, Apple M5 Max). The jump alone took 6% of
  the machine's instructions; the constant operands took most of the rest.

**A finished `try` or label is a dead fork point.** Step 2's drop at a tail call took only a
`FORK` that resumes at a `BACKTRACK` or at `//`'s set `found` check, so a `while` or `until` whose
update left a finished `try` or label (`try (. + 1) catch 0`, `label $x | . + 1`,
`first(. + 1, 0)`) kept one fork point per round and met the byte budget at 1-2 million rounds,
where the shipped routes run in constant memory. The drop now reads the fork points at the top as
`backtrack` would run them, twice:
- with no error, as when a later output is asked for, where a `FORK` resuming at a `break` raises
  it through the fork points below;
- with an error the code above raises later.

A run of fork points is dead when both readings come out of it as they went in, with no code
resumed. A `try` an error reaches unwrapped would catch it, swallow it or stop it, so a `try` is
passed only with its `TRY_END` above it in the run: a body that has finished, whose `TRY_END`
wraps any later error and whose `try` unwraps it again. So a `try` or label whose body can still
output, whose `catch` can still fire, or whose label a pending `break` can still reach, is kept.
Each of the three updates now runs four million rounds in constant memory, as the shipped routes
do; jq answers them in memory that grows with the rounds.

## Amendment (#7977 step 3, adopted 2026-11-28): leaves that collect, read through a borrowed view

**A leaf holds the generators it collects.** Step 1's leaves held no `.[]` and no `range`, so a
call-free `[range(1e6)]` in a routed program was built by the machine's own code, a fork point and
a backtrack per element. A call-free subtree may now hold `.[]` and `range(n)` where it takes all
their outputs itself, so no consumer outside it can stop them early:
- under a `[...]` inside the leaf, or in a `reduce`'s source or update (a `reduce` takes every
  output of each, keeping the update's last); a `reduce`'s init is not collected by it, since each
  of its outputs starts a fold that is one of the `reduce`'s outputs;
- so a call-free `[...]` or `reduce` compiles to one leaf, and so does a call-free node that holds
  such generators only under one, an object constructor or a string interpolation, which the
  machine declined before.

The leaf then runs to its end on `Interp::eval` doing the work jq does, where buffering the outputs
of `first(range(1e9))` would not. These stay the machine's:
- a generator a consumer can stop: under `first`, `limit` or a label (blocked in a leaf
  outright), or with no collector around it, so `first(.[])` still stops after one element;
- a generator that runs a call (the prelude's `select` included) or an effect, under the step-1
  effect rule: a leaf holds `debug`, `stderr` or `halt_error` only as that builtin alone;
- `range/2` and `range/3`: `Interp::eval` starts `range/2` at its first bound as written, so
  `[range(0; 2) | -.]` would answer `[0,-1]` where jq and the machine answer `[-0,-1]`, and
  `range/3` is a prelude call. `range(n)` starts at the spelling-less `0` both use;
- a destructuring pattern `Interp::eval` binds otherwise than jq: one that binds a name twice (jq
  keeps the first store that runs, `Interp` the last) or computes a key (`Interp` evaluates the
  key with the pattern's own variables in scope). A leaf holding one would answer as `Interp`
  does, so a node that would be a leaf only by holding one is compiled by the machine, or, where
  the machine has no code for it (an object constructor), declined.

The byte budget and the loop cap are unchanged: what a leaf collects is a value the program
builds, which the budget never counted, and a leaf holds no call, so no round. `Interp::eval`'s
`range` keeps the shipped `MAX_RANGE_TOTAL` cap with the same wording.

**A leaf reads its variables through a borrowed view.** A leaf's free variables were bound into
an `Env` frame each, one allocation per variable per evaluation. `Env` now carries, below its
frames, an optional view of the machine's slots (`vm::LeafView`), which every frame pushed on it
inherits: a variable the leaf does not bind itself is read from its slot, found by the
`(level, index)` the compiler resolved, when the leaf reads it. No frame is built, and nothing is
copied for a variable the leaf does not read. The view borrows the slots for the leaf's run only,
which holds no call, so nothing writes them meanwhile. `Env` grows by one word on every route of
the path-mode interpreter.

**The bounds are step 2's.** This step changes neither the byte budget nor the loop cap nor the
output bound: a leaf holds no call, so no round, and what it collects is a value the program
builds, as an accumulator's values are. Reviews of this step tried to move the output bound
(checking it where the shipped loop checks it, on the spines the shipped loop walks) and to
replace it with a byte budget that charges what the machine collects; both lost the bound for
shapes the shipped route and step 2's machine refuse in bounded memory, so both are left to a
follow-up issue, ahead of step 6. #8064 bounds memory instead, below.

**Measured** in instructions retired (`/usr/bin/time -l`, the least of three runs, Apple M5 Max),
on every ladder cell of `scripts/call_machine/ladders.py`, against the machine before this step
and the shipped route (`=0`) of the same build:

| Cell                                             | Before | Shipped route |  Now |
|--------------------------------------------------|-------:|--------------:|-----:|
| L13 `[range(1e6)] \| w(1)`, `first(.[])`         |   503M |          217M | 179M |
| L13c, the same with `.[0]`                       |   503M |          217M | 179M |
| `def f($n): ...; [range(1e6)] \| f(1)`, `length` |   505M |          219M | 181M |
| L05, #7803's memo at N = 3,200                   |   199M |       20,185M | 172M |

L13's gap was this cost: `[range(N)]` built a fork point and a backtrack per element; its own
`first(.[])` was never slow. Every other routed cell is within 0.4% of before. On the shipped
path-mode route `Env`'s second word moved its rows by -0.1% to +0.45%, about the spread of three
runs.

## Amendment (#8064, adopted 2026-11-28): a memory limit instead of the output bound

Step 2 kept the shipped tail loop's output bound (`MAX_LOOP_OUTPUTS` outputs of a zero-argument
`def`'s loop once it has run `OUTPUT_BUDGET_AFTER_ROUNDS` rounds) to keep a collector from
exhausting memory. The machine runs a different control model from the shipped tail loop, so it
cannot say exactly where that loop's spine ends: it refused programs the shipped route and jq
answer, and missed collectors the shipped route bounds, so that a loop through a local `def` grew
past 2.6 GB. A budget that charged each collected value 32 bytes missed what the value holds
(`{a: .}`, strings, `[.,.,.,.]` past 3 GB), and a `reduce`'s state. #8064 records the findings.

**The machine is bounded by the memory the process holds.**
- **What is read.** The library reads no figure of the process: a caller installs a probe and a
  limit (`path_mode::set_call_machine_memory`). `succinctly jq` reads the resident set from
  `/proc/self/statm` on Linux, with `pread` on a descriptor opened once, and the physical
  footprint (`proc_pid_rusage`) on macOS, which keeps the pages the system has compressed, so a
  run is not read as shrinking when its memory is compressed. Elsewhere it installs none.
- **The limit**, computed once per process: the least of half the physical memory, half the
  cgroup's `memory.max` (v1's `memory.limit_in_bytes`), a quarter of the address space a
  `ulimit -v` cap leaves when the process starts, and 1.5 GiB. Half, because the limit is
  sampled and a leaf can grow inside one evaluation, which no check point sees; a quarter under
  an address-space cap, which counts reserved address space the resident set does not. The
  ceiling answers `[range(1e7)]` four times over (jq 1.7.1 answers it in 1.84 GB) and refuses a
  runaway collector at a size on a large machine instead of after half of it.
- **When it is read.** At the machine's check points (every call, append and store, after every
  leaf, after an operator or `setpath` that builds a container or a string), one in an interval
  of them: 16 at first, 65,536 while the reading stands still, and otherwise the check points
  that, at the growth per check point since the last sample, spend half the room left. A check
  point is a decrement and a branch. The interval is kept across the documents of a run, and a
  nested run reads the same process against the same limit. Every growth of a stack or an
  accumulator is read too, and refused when the old block and the process's memory together
  pass the limit. On macOS it moves the elements into the new block instead of calling
  `realloc`, whose lazily remapped pages the footprint did not count until the refusal's
  unwinding read them, a fifth past the limit; Linux's `realloc` moves the pages and the resident
  set counts them.
- **Why not count allocations.** The first form of this amendment counted every allocation in a
  metered global allocator. It charged every command of the binary, the machine off by default
  included: the x86_64 perf guard read +2.5% on `nd_id` and up to +2.7% on yq rows. Sizing values
  by a walk is quadratic wherever a collected value is collected again; a size kept on the value
  would have to be kept through every write of the shared container types, on every route.
- **The refusal** has its own wording, `f/0: memory limit exceeded` (or `memory limit exceeded`
  when no user definition is on the call chain), uncatchable, exit 5. An ADR-0018 rule 4(c)
  divergence: jq grows until its allocation fails.
- **What it does not cover.** The input document counts toward the limit, as everything the
  process holds does. What one leaf builds within one evaluation is seen only when it ends
  (`[range(1e7) | range(1e7)]` grows past 3 GB on every route and in jq). The control-state budget
  above is unchanged.

**The output bound goes where a probe is installed.** With one no loop is refused for its outputs,
as jq refuses none: a loop past 2^20 outputs answers as jq does, where the shipped route still
refuses it, and one that never ends meets the memory limit or `MAX_LOOP_ROUNDS`, which is
unchanged. Without one (a library caller that installs no probe, or a platform the CLI cannot read)
the output bound stays, so no run is unbounded. A program the machine declines (`unique`,
`last(...)`) keeps the shipped route's bound.

**Measured** on an Apple M5 Max, where the limit is the 1.5 GiB ceiling: #8064's ten memory repros
are refused at a peak RSS of 1,028 to 1,544 MiB (main refused them at its output bound in 38 to
360 MB), and at limits of 256 MiB and 1 GiB the fastest-growing collectors pass the limit by at
most 13 MiB. Instruction counts are in the description of the PR that closed #8064.
