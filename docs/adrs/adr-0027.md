# ADR-0027: Keep a Repeated Key's Earlier Entries Beside the Map (#1344)

## Status

🟡 Proposed (2026-10-28). Amends [ADR-0017](adr-0017.md)'s out-of-scope bullet on
`OwnedValue::Object`'s duplicate-key collapse (#796). [ADR-0018](adr-0018.md)'s fidelity rule is the
reason for the work: `succinctly yq` follows yq, and yq keeps a repeated key.

## Context

yq holds a mapping as an ordered list of entries, so `a: 1 / a: 2 / b: 3` is three entries. An
`OwnedValue::Object` is an `IndexMap<String, OwnedValue>`: one value per key, so the first `a` is
gone before any builtin sees the tree. Every route that materializes a document (the
`--slurp`/`--eval-all`/`--inplace` input bridge, `[...]`, a `$var` binding, `to_entries`, `walk`, a
write through a path) loses it, where yq prints, counts, lists and rewrites both.

Captured against yq v4.53.3 with `a: 1 / a: 2 / b: 3`, yq's behaviour is one rule with three
exceptions:

- Navigation (`.a`, `.[]`), every write through a path and `map_values` act on the **last** entry of
  a key, at the **first** entry's position: `.a = 5` is `{"a":1,"a":5,"b":3}`, `.[] |= . + 10` is
  `{"a":1,"a":12,"b":13}`, `[.[]]` on `b: 1 / a: 2 / b: 3` is `[3, 2]`. That is the `IndexMap` you
  get by inserting the entries in order.
- `del` removes **every** entry of the key (`del(.a)` is `{"b":3}`).
- Only output and the listing builtins (`keys`, `length`, `to_entries`, `with_entries`,
  `from_entries`, `contains`, `tojson`, `@yaml`) see every entry.
- Exceptions: `+` overwrites the **first** entry (`. + {"a": 9}` is `{"a":9,"a":2,"b":3}`), `pick`
  reads the first entry, and `sort_keys` copies the last value over the earlier ones.

#1344 (`tostream`, `walk`, `recurse`), #1343 (`-s` and `--eval-all` bypass the fix `paths` got),
#2063 (`[.[0]]`), #4095 and the #1687 residuals are all this one missing representation. Three
issues each fixed one builtin with a cursor-native arm, and #1344's first decision (a) did the same
for `..` and `recurse`; what is left is every route that holds an owned value.

## Decision

**`OwnedValue::Object`'s handle keeps the `IndexMap` as the collapsed view every reader already sees,
and carries the earlier entries of repeated keys ("shadows") in a second pointer beside it.**

```rust
// src/jq/value/object_map.rs -- the map's heap block is still just the IndexMap.
struct ObjectMapOf<V> {
    map: Rc<IndexMap<String, V>>,        // Box<..> under unshared-containers: the collapsed view
    shadows: Option<Rc<Shadows<V>>>,     // None unless some key repeats
}
struct Shadows<V> {
    order: Vec<Occurrence<V>>,           // every entry, in document order
    live_pos: Vec<usize>,                // map slot -> position of its Live entry in `order`
}
enum Occurrence<V> {
    Live(usize),                         // a key's last entry: a map slot
    Shadow(String, V),                   // an earlier entry of a key whose later entry is live
}
```

The design comment on #1344 put the side list inside the map's heap block (`Rc<ObjectStore>`). This
ADR puts it in the handle instead, for the reason the measurements below give: a field in the block
steps the allocator one bin on glibc for every object.

**Invariants**

- **I1.** `map` is the collapsed view: each key once, at its first entry's position, holding its
  last entry's value. Every existing reader, through `Deref`, sees exactly what it saw when the
  target was a bare `IndexMap`.
- **I2.** `shadows.is_none()` exactly when no key repeats.
- **I3.** A shadow is created (`push_occurrence`), removed along with its key, or dropped wholesale
  (`collapse`). Nothing writes to one, with the single exception of `first_occurrence_mut`, which
  exists for yq's `+`.
- **I4.** `jq` mode never creates a shadow. Only producers gated on `!S::COLLAPSE_DUPLICATE_KEYS`,
  plus yq-only builtins, create one. The mode decides once, at creation, and a consumer needs no
  mode check: on a map without shadows the full view *is* the collapsed view.

**API.** An inherent method on `ObjectMapOf` is chosen before the `IndexMap` method of the same name
it would auto-dereference to, so the existing call sites pick up the new behaviour unedited.

| Method                                                                            | With shadows                                             |
|-----------------------------------------------------------------------------------|----------------------------------------------------------|
| `Deref` to `&IndexMap`                                                            | the collapsed view (unchanged for every existing reader) |
| `get_mut`, `get_index_mut`, `iter_mut`, `values_mut`, `insert` on an existing key | the live (last) entry only                               |
| `insert`/`entry` on a vacant key                                                  | appends                                                  |
| `entry`                                                                           | a restricted entry type with no removal                  |
| `shift_remove`, `swap_remove`, `retain`, `clear`                                  | remove **every** entry for the key                       |
| `DerefMut` (a raw `&mut IndexMap`)                                                | **collapses first**, then hands out the map              |
| by-value `IntoIterator`, `into_index_map`, `FromIterator`, `Extend`               | collapsed                                                |
| `occurrences`, `occurrence_len`, `has_shadows`, `into_occurrences`                | the full view                                            |
| `push_occurrence`                                                                 | appends; an existing live entry becomes a shadow         |
| `first_occurrence`, `first_occurrence_mut`                                        | the earliest entry for a key                             |
| `collapse`, `eq_occurrences`                                                      | drop shadows; equality over every entry                  |

`DerefMut` already marks where copy-on-write happens (#2999). It now also collapses, so a raw
`&mut IndexMap` caller can only ever produce today's answer, never a mix of today's answer and
yq's. `OwnedValue::as_object_mut` returns `&mut ObjectMap` instead of `&mut IndexMap` (a public
signature change), so its callers reach these methods; `ObjectMap` dereferences to the map, so
every call that compiled against the old type still compiles.

**Rules the later phases must keep**

- **Equality.** jq-value equality (`==`, `sort`, `unique`, `group_by`, `PartialEq`) stays on the
  collapsed view. Anything asking "would these print the same", such as `enforce_anchor_soundness`'s
  "holds an equal value" test, `reconcile_presentation` and #3615's provenance check, has to use
  `eq_occurrences`, or a `*alias` could be written for a node whose shadows differ from its
  anchor's, and reading the output back would silently give the anchor's entries.
- **`CommentTree`.** `CommentTree::Object`'s per-field subtree map becomes an `ObjectMapOf` filled
  by the same `push_occurrence` calls as the value, so both trees share one occurrence structure by
  construction. Reconciliation pairs shadows by occurrence index, which I3 makes sound. This changes
  that variant's width, so the deep-recursion and stack-budget tests of
  [ADR-0025](adr-0025.md) rerun.
- **Producers.** One helper, `push_field::<S>(&mut map, key, value)`, does `insert` when
  `S::COLLAPSE_DUPLICATE_KEYS` and `push_occurrence` otherwise. Every materializer uses it, not six
  copies.
- **Writers.** Every `OwnedValue` writer (`to_json`, `stream_owned_value_*`, `emit_yaml_value`,
  `output.rs`) iterates `occurrences()`. A map without shadows prints byte for byte as before.
- **Raw-map sites.** `DerefMut` compiles for every `IndexMap` mutator the wrapper does not override
  (`sort_keys`, `sort_by`, `drain`, `pop`, `truncate`, `reverse`, `insert_full`, `shift_insert`,
  `swap_indices`), and each collapses the shadows silently. Before P3 can produce one, every such
  site is audited: removing `DerefMut` from `ObjectMapOf` in a scratch build lists them at compile
  time (29 in the library when the design was written, among them `owned_slot_mut`,
  `merge_object_fields`, `set_field`, `set_path_steps`, `update_path_with_deletes`,
  `delete_paths_under`, `delete_at_path` and `path_mode.rs`'s `promote_built`; `yq_runner.rs` has its
  own 86 `OwnedValue::Object` sites). A site either moves to an inherent method or is recorded as
  collapsing on purpose.
- **Consumers land before producers.** Once shadows exist, a builtin still on the collapsed view
  would disagree with the output on the same route (`--eval-all '.'` would print three entries while
  `--eval-all 'keys'` answered `["a","b"]`).

**Phases** (one PR each; every intermediate `main` gives either today's answer or yq's)

| Phase | Content                                                                                                                                                     | Behaviour change |
|-------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------|
| P1    | This ADR, the side list in `ObjectMapOf` and the API above, the `as_object_mut` signature, the model-based test, the cost measurements                      | none             |
| P2    | Full-view consumers in both evaluators (`length`, `keys`, `to_entries`, `with_entries`, `contains`, `paths`, `tostream`, `tojson`, `@yaml`) and the writers | none             |
| P3    | Producers (`push_field`, yq-mode `from_entries`) and `CommentTree`; closes #1343 and #1344                                                                  | yes              |
| P4    | The exceptions (`+`, `pick`, `sort_keys`); the duplicate-key section of `docs/compliance/yq/limitations.md`                                                 | yes              |

Proposed for P4: `sort_keys` stable-sorts the entries (`a:1, a:2, b:3`) instead of copying yq's
`{"a":2,"a":2,"b":3}`. Matching yq would destroy a document value, which ADR-0018 allows us to
refuse; the limitations page records it.

## Consequences

**Positive**

- The representation is in place before any producer uses it, with a model-based test (random
  sequences of every mutator against a reference multimap, checked after every step) and mutation
  checks that each fail at least one test. A bug in the store cannot reach output until P3.
- jq mode and every existing reader are unchanged by construction (I1, I4).
- `OwnedValue` stays 32 bytes
  (`owned_value_is_32_bytes_because_its_containers_are_one_pointer_3000`): the handle is two pointers,
  still under `NumberLiteral`'s 32, and `JqValue` stays 40. The map's heap block is exactly the
  `IndexMap` it was, so #3000's recycling argument (the `OwnedValue` and `JqValue` object blocks stay
  the same chunk size) is untouched.

**Negative**

- The handle grows from 8 to 16 bytes inline. It lives in an `OwnedValue` or `JqValue` whose width
  does not change, so no value grows; the extra word is paid only where an `ObjectMapOf` is held on
  its own (a field, a local).
- Cloning an object bumps two refcounts (the second a `None` test for an object with no repeated
  key), where it bumped one.
- `DerefMut` gains one `is_some` test on a path the copy-on-write check already guards.
- A removal on an object that has shadows is O(entries), because the side list is re-indexed: that
  includes `swap_remove`, O(1) on a plain `IndexMap`, so a loop of k removals from an n-entry object
  that repeats a key is O(k * n). A duplicate-free object takes the `IndexMap` path and pays
  nothing. `first_occurrence` is likewise a scan of the side list; P4 measures before adding an
  index.
- `swap_remove` on an object that still repeats a key keeps document order for the full view, while
  the collapsed view is permuted as `IndexMap::swap_remove` permutes it; once no shadow is left the
  full view is the collapsed view, in that permuted order.
- `as_object_mut`'s return type changed: a public API change (a `changed` entry in the changelog).

## Alternatives Considered

- **Replace `IndexMap` with a multimap** (`Vec<(String, V)>` plus an index). Every reader's `Deref`
  target changes, so all ~600 sites need a collapsed-or-full decision in one PR, and jq mode pays
  for a second structure on every object. The side list is this same design with the collapsed view
  as the default and the full view opt-in.
- **A hidden ordinal in the key.** It breaks `Borrow<str>` lookup, because `get("a")` would have to
  find the latest ordinal, and changes `len` and iteration for every reader, which silently
  un-collapses `.[]`.
- **A cursor-carrying yq DOM value.** It covers reads only. Writes are the reason for this work:
  they drop `a: 1`, which ADR-0018 4(b) forbids (a discarded write).
- **Route `-s` input as `YamlIndex`'s virtual root cursor (for #1343).** That handles single-file
  reads only; multi-file `-s` and every write would still collapse. The representation covers `-s`
  and `--eval-all` anyway.
- **Put the side list inside the map's heap block** (`Rc<ObjectStore { map, shadows }>`, the form on
  #1344). Built and measured first: wall clock on the M4 Pro and in the 7950X's `users` and
  `yusers` rows was within noise, but peak RSS rose 0.9% to 3.3% on glibc for object-heavy inputs
  (the block steps from a 96-byte to a 112-byte malloc chunk, and a `to_entries` on a wide object
  allocates one per entry) and 1.5% to 1.9% on macOS for a yq write, and the 7950X's wide-object rows
  read 1.7% slower with identical instruction and cache-simulator counts. The side list in the
  handle removes the cost from the heap entirely.
- **Keep the shadows' pointer in a tag bit of the `Rc`, or a lazily attached side table.** Rejected
  for the same reason as the above plus the lifetime bookkeeping a table needs (the handle's `Drop`
  would have to unregister it).
