# ADR-0024: Structural Sharing in `OwnedValue` (#2999)

## Status

🟡 Proposed (2026-09-16) — decided by the measurements in [Decision](#decision), not by
argument. The Options table is filled in as #3000 (Experiment B) and Experiment C report.

## Context

Every jq write route that must keep an *unmutated* document alongside a *written* one pays a
whole-tree copy of `OwnedValue` (`src/jq/value.rs`):

- `eval_assign_streaming` (`src/jq/eval.rs`) clones the pristine document before applying
  each write as its path resolves. The separation is jq's own and is observable
  (`.[(.a,.a)] = 5` on `{"a":"b","b":1}` must resolve the second `.a` against the unwritten
  document), so it cannot be dropped. #2976 measured it at **+18% peak RSS** on a 1.5 MB /
  200,000-element array (`.[(0,1)] = 0`: 74.8 MB → 88.5 MB). #2990 narrowed the set of
  shapes that pay it to genuinely multi-path ones; the residual is this ADR's subject.
- `fork_rhs_over_paths` clones the document once per right-hand-side output.
- `set_path`'s `Iterate` arm clones the new value once per slot, and the streaming write
  clones it once per path.
- `eval_update` would inherit the same cost if #2974 moves `|=` to a streaming write.

jq pays nothing for any of these because `jv` is refcounted and `jv_setpath` copies on
write. succinctly's `OwnedValue` owns its containers inline, so a "copy" is a deep copy.

Facts measured against the tree at `223360178` (2026-09-16), which every option below is
priced against:

| fact | value |
|---|---|
| `size_of::<OwnedValue>()` | **72** — `Object(IndexMap<String, Self>)` is the widest arm (`IndexMap` = 72; `Vec`/`String` = 24; `NumberRepr` = 16; `Box<str>` = 16) |
| same, with the object map boxed (`Object(Box<IndexMap<..>>)`) | **32** |
| same, with `Rc<Vec<Self>>` + `Rc<IndexMap<..>>` | **32** |
| same, with `Rc<str>` + `Rc<[Self]>` + `Rc<IndexMap<..>>` | **32** |
| construction sites | 875 `OwnedValue::Array(` + 543 `OwnedValue::Object(` across 11 files (`eval.rs` 928, `eval_generic.rs` 221, `yq_runner.rs` 85, `lazy.rs` 40, `value.rs` 31, `stream.rs` 28, five files ≤ 10) |
| by-value `mut` destructures of a container | 13 |
| `&mut` entry points | `as_array_mut`, `as_object_mut`; walkers `set_path`/`set_path_steps`, `update_path`/`update_path_steps`, `delete_at_path`/`delete_at_path_through_absent`, `autovivify_object`/`autovivify_array` |
| exact size pins that a 32-byte value trips | `eval_error_size_is_pinned_for_the_1021_stack_overflow_fix` (96), `eval_error_payload_is_no_larger_than_the_option_it_replaces` (`src/jq/error.rs`); `test_generic_result_size_stays_bounded_789` (120), `test_generic_item_size_stays_bounded_789` (80) (`src/jq/eval_generic.rs`) |
| thread boundary | `main` runs `run_main` on one big-stack thread; only `anyhow::Result<()>` crosses the join. No `Send`/`Sync` bound anywhere in `src/jq`; `jq_runner` never wraps an `EvalError` (which carries an `OwnedValue`) in `anyhow::Error` |
| existing precedent | `Expr::Shared(Rc<Self>)`, `Expr::TrackedVar(Rc<Tracked>)`; `PathNode::Owned(Rc<OwnedValue>)` and `WalkNode::Made(Rc<OwnedValue>)` already share a *whole* owned value by refcount — the containers inside it are what this ADR would share |
| serde | no impl on `OwnedValue`; the `serde` feature covers the bit structures |
| public API | `succinctly::jq::OwnedValue` is `pub` on crate 0.8.0; a payload change breaks downstream `Array(v)`/`Object(m)` patterns |

Two of those facts reshape the question the issue asked. All three boxed layouts measure
**32**, not the ~40 #2976 estimated: `NumberLiteral(NumberRepr, Box<str>)` becomes the
widest arm at exactly 32 and the discriminant packs into `NumberRepr`'s niche. That is
−55% per array element on *every* route, eager ones included — for the #2976 repro a
single copy drops from 14.4 MB to 6.4 MB before any sharing exists. And the size effect is
available *without* sharing (boxing the map alone), which means the two mechanisms can be
measured separately. They must be: an A/B of the `Rc` layout against the status quo would
attribute the size win to sharing.

## Decision

**The decision is made by measurement against four criteria, in the order below, and this
section is completed — not rewritten — when the numbers exist.** Until then the status quo
stands.

Options priced:

| | layout | size | sharing | cost | status |
|---|---|---|---|---|---|
| A | status quo | 72 | none | — | baseline |
| B | `Object(Box<IndexMap<..>>)` only | 32 | none | +1 allocation per object; +1 pointer chase per object access; per object 32 inline + 72 heap instead of 72 inline | #3000, measuring |
| C | `Array(Rc<Vec<Self>>)` + `Object(Rc<IndexMap<..>>)` | 32 | containers | as B for both container kinds, +16 B refcount header, a refcount check on every `Rc::make_mut` | after B |
| D | C + `String(Rc<str>)` / `Array(Rc<[Self]>)` | 32 | everything | as C; every string mutation (`+=`, `ltrimstr`, `ascii_downcase`, …) clones first; keys stay `String` regardless | deferred |
| E | `Arc` variants of C | 32 | containers | atomic refcounts for a thread boundary that does not exist | rejected |

Procedure:

1. **B first, as the mechanism holdout (#3000).** It realises 100% of the size drop and 0%
   of the sharing, so its result is C's floor: both carry the same pointer chase. If B loses
   on time where the change is charged to every input — arrays of many small objects, where
   allocation count rises — C starts from that loss and must buy it back with the copies it
   removes.
2. **C, built on B.** `Rc::make_mut` at the `&mut` entry points listed above; the
   whole-document clones in `eval_assign_streaming` and `fork_rhs_over_paths` become a
   refcount bump per shared subtree. The risk class #2976 named — a by-value destructure
   that silently lands in the clone arm — is instrumented directly rather than left to an
   A/B: a test-only counter on every `Rc::try_unwrap`-fell-into-clone and
   `make_mut`-had-to-clone site, run over the test suite and the bench queries, listing
   every site that cloned where a unique refcount was expected.
3. **Accept C only if all four hold**, measured on an Apple M4 Pro and an AMD Ryzen 9 7950X
   with the interleaved method in `docs/guides/benchmarking.md` (both binaries alternate
   within each repetition; a never-triggering holdout build measures the layout bias and is
   subtracted; inputs ≥ 1 MB at two sizes; the machine verified idle):
   - **Output identity** on every A/B input in both modes, before any number is read.
   - **Peak RSS and wall time** across `jq_bench`, `yq_bench`, the perf-guard matrix, the
     #2976 shapes (`.[(0,1)] = 0`, `.[$k] = 0`, `.[0] = 0`, `del(.[(0,1)])`,
     `.[(0,1)] |= 0`) and a small-objects array shape (the allocation-count worst case):
     no shape regresses beyond the holdout's own band, and the multi-path shapes lose their
     second copy.
   - **perf-guard green on both CI architectures** with no per-query threshold override.
     The rows that reach `OwnedValue` today are `users_assign_scores`, `users_del_select`,
     `users_del_bound_select`, `users_path_walk`, `users_yq_del_select`; the identity rows
     move ±5% from code layout alone and are read against the holdout.
   - **The clone list from step 2 is empty**, or every entry is explained on the PR.
4. **Size pins are re-derived, never bumped.** Each pin's comment states what it guards
   (#1021's controlled panic before a stack overflow; #789's per-push cost). The new number
   carries the same justification, and `into_owned_panics_past_nesting_depth_limit_1021`
   must still pass.
5. **The public-API break is recorded**, as a breaking CHANGELOG entry for the next 0.x
   minor, with construction and access still possible through constructors and accessors.

## Alternatives rejected

- **Dry-run every write against the pristine document and apply them all at the end.**
  Unsound: write N's validity depends on writes 1..N−1. `null | .[("a",0)] = 1` vivifies an
  object at `.["a"]` and then fails at `.[0]`; against pristine `null`, `.[0]` would vivify
  an array and succeed. Same class as #2608's verify-then-echo.
- **Resolve the path generator against the semi-index cursor instead of a copy.** Closed by
  the resolver's signature: `resolve_node_sink` takes `&OwnedValue` and every `PathBranch`
  borrows it, so both documents must be owned trees for the whole loop.
- **Copy only the write's spine, without sharing.** The 200,000-element `Vec` *is* the
  spine; without element sharing its clone is the whole cost.
- **`Arc` (option E).** Nothing crosses a thread. Rejected on the facts above, not on
  taste; revisit only if a thread boundary appears.
- **Sharing strings and slices too (option D).** Deferred, not rejected: strings are
  mutated in place by several builtins, keys are `String` either way, and D adds nothing to
  the copies this ADR exists to remove. It can be a later amendment with its own numbers.

## Consequences

Expected, to be confirmed or corrected by the measurements:

- `.[(0,1)] = 0` on the #2976 repro: 88.5 MB → ≈ 57 MB, matching `.[$k] = 0`; every
  eager-route row shrinks by the per-element factor whether or not C lands.
- Arrays of many small objects gain one allocation per object under B and one per
  container under C; this is the row most likely to refuse the change.
- `identical` (#1360) can gain an `Rc::ptr_eq` fast path for *reads* under C. It is not
  sound across a mutating walk — the streaming write is one — and is a separate change.
- `EvalError` shrinks with `OwnedValue` (its payload rides `Option<OwnedValue>`), which is
  the safe direction for #1021 but still moves an exact pin.
- Downstream users of `succinctly::jq::OwnedValue` who match on `Array(v)`/`Object(m)`
  must change with the next 0.x minor.
- The `docs/compliance/jq/limitations.md` residual paragraph for `.[(0,1)] = 0` points at
  #2999 until C lands or this ADR is marked Rejected with the numbers that rejected it.
