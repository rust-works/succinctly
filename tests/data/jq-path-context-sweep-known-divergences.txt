# Known divergences of succinctly from the pinned oracles for the path-context
# sweep (scripts/jq-path-context-oracle-sweep.sh, #2416 phase 0).
#
# One line per divergent *class*, whitespace-separated:
#
#   <mode>/<class glob>    <category>    <reason — #issue>
#
# The glob is matched against `<mode>/<class>` with shell pattern matching, so
# `*` spans `/`. `#` lines and blank lines are ignored. First match wins, so
# order is significant: put the construct-specific patterns above the
# position-specific ones.
#
# The check is two-sided, like tests/data/jq-golden-known-failures.txt: a
# divergence with no line here fails the sweep, and a line here that never
# matched a divergence fails it too — so a fix is forced to shrink this file
# and no gap can hide behind a stale entry.
#
# Every line is an oracle capture, never a memory claim: each was recorded by
# this sweep against /usr/bin/jq 1.7.1 and Homebrew yq v4.53.3 on 2026-09-05.
# The representative shapes are pinned as golden cases under
# tests/data/{jq,yq}-golden/cases/path_ctx_* so CI enforces them on every leg;
# this file is what keeps the *sweep* a pass/fail signal rather than a list a
# reader has to re-triage by hand.

# --- yq mode ----------------------------------------------------------------

# Real yq's `first(f)` is not jq's. `.a | first(key)` answers `1` (the first
# child's *value*), `.a[] | first(key)` answers nothing at all, and the
# argument is never evaluated as a filter. succinctly implements jq's
# `first(f)`. Not a path-context gap — the leaf under it is incidental.
yq/*/first/*/*        yq_first        real yq's first(f) ignores its argument and yields the first child — #2377

# `{"k": key}`/`{"k": path}`/`{"k": parent}` answer null/[]/{} at every
# position: the deleted eager path-context evaluator has no `Expr::Object` arm,
# so the whole object construction falls to the context-dropping fallback.

# `file_index` itself agrees everywhere since #2427: the ordinary multi-file
# path installs a per-file scope (`jq::enter_file_index_scope`) around each
# file's evaluation, the way real yq stamps `fileIndex` on every node as it
# decodes the file (`pkg/yqlib/utils.go:60-89`), and `--eval-all` carries the
# same origin per document. The `.. | ((file_index), 1)` row that used to
# stand here went with spine 2416's walk residue, which made `..` carry path
# context (#2428): with `..` walked as positions, the union's outputs come
# out in the order real yq prints them.

# `parent`/`key` at the document root: real yq emits nothing (exit 0),
# succinctly prints `{}` and `null`. These are the positions the #2061 walk
# refuses as Unsupported today; phase 2 flips them.

# Recursive descent carries path context since spine 2416's walk residue
# (#2428): `..` is a navigational step of the walk (`path_context_step_recurse`,
# every node at its own position in document order) and a cursor-threading
# arm of the generic evaluator (`each_recurse_cursor_generic`), so the three
# `descend_path` rows that stood here (`key`/`parent`/`path` under `..`) went
# with it.

# #2072: a leaf read through an `as`-bound variable (`.a as $x | $x | key`,
# the `bind_*` prefix family added 2026-09-08) sees no node identity at all —
# `substitute_bound_var` re-materialises `$x` as a value, not the node it was
# bound from. `bind_root` (`. as $x | $x`) is exempt: the bound value there
# equals the ambient input exactly, so the existing value-equality
# passthrough (`OwnedIdentityRule::Bound`) happens to agree with real
# identity by coincidence. `select`'s own `path`-leaf combination is exempt
# too: `select((path) != null)` only asks whether the produced path is
# non-null, which is true either way, so nothing observes the wrong path
# value there. Every other `key`/`parent`/`path` row under a `bind_*` prefix
# does diverge, `file_index` does not (it is exactly the value-equality
# passthrough case `test_bound_variable_eval_all_rows_2072` documents as
# already passing).
yq/key/*/plain/bind_*      bind_identity   a bound variable ($x) carries no node identity — key answers wrong or nothing — #2072
yq/parent/*/plain/bind_*   bind_identity   a bound variable ($x) carries no node identity — parent answers wrong or nothing — #2072
yq/path/*/plain/bind_*     bind_identity   a bound variable ($x) carries no node identity — path answers `[]` instead of the real path — #2072

# --- jq mode ----------------------------------------------------------------

# `path(foreach (getpath(...)) as $x (null; $x))` raises "Invalid path
# expression with result ..." where jq 1.7.1 resolves it to the path. Same
# family as #2388's `foreach` INIT-fork disagreement, and the shape the
# promoted scratch sweep was originally written to hunt.
jq/getpath/foreach/path/*   foreach_path   path(foreach getpath(..) as $x ...) raises where jq resolves the path — #2388

# `.. | (getpath([<path producer>]))?` drops the `[]` output jq produces for
# the root position; the `?` swallows it instead of letting it through.
jq/*/getpath/opt/descend    optional_root  `?` over getpath at the root drops jq's own `[]` output — #2416 phase 0
