# Known divergences of `succinctly jq` from the pinned-jq golden fixtures.
#
# Consumed by tests/jq_golden_tests.rs. One line per failing case:
#
#   <case>            <category>        <reason — #issue>
#
# <case> is a directory name under tests/data/jq-golden/cases/. Columns are
# whitespace-separated; `#` lines and blank lines are ignored.
#
# The check is two-sided: a case failing without a line here fails the build,
# and a line here for a case that now passes also fails the build — so every
# fix is forced to shrink this file, and no divergence can hide. The goldens
# themselves always hold the correct (pinned jq) output; only this manifest
# records where succinctly currently disagrees. See
# tests/data/yq-golden-known-failures.txt for the sibling manifest.
#

# (#307), format_csv (#306), int_float_eq (#156), try_catch_error (#158),
# alt_multi_output (#160), comma_in_index (#155, via #360) and assign_rhs_root
# (#159) have since been fixed and dropped, leaving 0.

# as a scoreboard instead of reading as a false clean bill of health.

# and dropped, leaving 9; label_break_after_comma (#400) plus the

# filed issues, bringing it to 12, and assign_autovivify_nested (#486) has
# since been fixed and dropped, leaving 11 — each drop/add the scoreboard

# 15 entries. They are the first entries whose golden carries a non-empty
# expected.out **and** a non-zero expected.status: jq streams some outputs
# and then fails. Exit code and stderr already match, so each fails on

# would fail on status instead, which is the pairing #400/#494 need pinned.
#
# #400/#494 fixed: `QueryResult`/`GenericResult` gained a `Partial(prefix,
# control)` terminal that lets a stream carry outputs *and then* an error or

#
# #572 added four more cases from #534's own body: reduce_update_zero_output,
# foreach_extract_fanout, while_backtrack and until_backtrack. Unlike the
# already-pinned INIT-forking pair above (silent wrong answers), the interim
# parse_pipe_no_comma() restriction #534 describes rejects all four outright
# — jq succeeds with real output, succinctly exits 1 on a compile error, so
# no expected.status/expected.err is needed (those encode jq's own failure,
# and jq doesn't fail here); the mismatch is the bare exit-code branch in
# tests/jq_golden_tests.rs, taking the file to 14.
#
# comma_literal_before_document (#353) has since been fixed and dropped,
# leaving 13.
#
# if_multi_output_condition (#378) has since been fixed and dropped, leaving
# 12: `if`/`select` now fan out over every output of the condition instead of
# consulting only the first one, in both evaluators.
#
# nan_type (#472), slice_computed_bounds (#499), recurse_null_child (#490) and
# path_recursive_descent (#483) have since been fixed and dropped, leaving 8:
# `builtin_recurse_f`/`builtin_recurse_cond` now resolve `f` through
# `eval_owned_multi` instead of `eval_owned_expr`, so a null child is queued
# like any other value instead of being filtered out, and a single
# array-valued child is visited as one node instead of being spliced into its
# elements (#570). Separately, `resolve_node`'s `..`/`recurse`/`select`/
# typeof-filter arms already existed but were never reached, because
# `needs_path_prepass` — the gate deciding whether the pre-pass runs at all —
# only fired for a computed-key `IndexExpr` or a `Comma`. Rewritten as an
# exclusion check (anything other than the bare
# `Identity`/`Field`/`Index`/`Slice`/`Iterate` primitives the walker already
# handles natively needs the pre-pass) so a resolver arm existing without the
# gate routing to it can't recur the same way for the next combinator (#483).
#
# #354 fixed object construction's cartesian product (`eval_object_construction`
# now emits one object per key/value combination instead of taking each
# generator's first output). object_construct_cartesian — seeded far earlier by
# #513 and predating the fix's own five new golden cases — passes too, dropping
# the file to 7.
#
# assign_multi_output_rhs (#392) has since been fixed and dropped, leaving 6:
# `eval_assign` now forks once per RHS output instead of collapsing to the
# first, matching jq's own `value as $value | reduce path(paths) as $p
# (...)` desugaring. `update_path`'s `Expr::Identity` arm was fixed the same
# way for `|=`/`+=`/`-=`/`*=`/`/=`/`%=`/`//=`: it now takes the update
# filter's first output via `eval_owned_multi` instead of collapsing every
# output into an `OwnedValue::Array` via `eval_owned_expr`.
#
# recurse_f_dfs_sibling_order — seeded by #676 ahead of #635, pinning
# `resolve_recurse`/`builtin_recurse_f`/`builtin_recurse_cond`'s
# breadth-first FIFO queue (`queue.remove(0)`), which visited a branching
# node's children level-by-level instead of jq's depth-first `def r: .,
# (f | r); r;` definition — has since been fixed and dropped: all three
# now drive recursion with an explicit LIFO stack instead, collecting each
# node's next-to-visit entries and pushing them reversed so the
# first-encountered entry's whole subtree completes before the next
# sibling is touched, matching jq exactly. Leaving 6.

# #534 fixed: `reduce`/`foreach`/`while`/`until` now implement jq's real
# per-output fanout/fold for INIT/UPDATE/COND/EXTRACT instead of assuming a
# single output (#681 traced it to two shared choke points,
# `eval_owned_expr_ctrl` and `result_to_owned`, replaced here by
# `eval_owned_expr_fork`/`finish_fork`). `reduce_multi_output_init`,
# `foreach_multi_output_init`, `reduce_update_zero_output`,
# `foreach_extract_fanout`, `while_backtrack` and `until_backtrack` all now
# match jq, and the `parser.rs` restriction to `parse_pipe_no_comma()` for
# these four constructs' INIT/UPDATE/COND/EXTRACT slots is lifted back to
# `parse_expr()`, dropping the file to 0.

# Seeded by #716's date/time oracle-coverage sweep: the builtins had unit
# tests checking self-consistency but zero cross-checks against real jq.
# Writing golden cases for gmtime/mktime/strftime/strptime/todate/fromdate —
# including a direct port of jq's own leap-year/weekday round-trip torture
# test from tests/optional.test — surfaced three distinct bugs, each filed
# with its own verified repro. `localtime` is deliberately absent from the
# corpus: succinctly's implementation is a best-effort TZ-environment stub
# (see estimate_local_offset in src/jq/eval.rs) and real jq's localtime output
# depends on the capturing host's timezone, so a golden captured on one
# machine would spuriously fail the jq-drift CI check on another.
#
# strftime_unsupported_specifiers originally also covered `%s`, but real jq's
# `%s` round-trips through libc mktime() on the (UTC-valued) broken-down time,
# which mktime treats as *local* time — so its output shifts by the capturing
# host's UTC offset, the exact `localtime` problem above in a second builtin.
# Caught when this golden, captured under AEST (UTC+10), failed the jq-drift
# check on a UTC CI runner. Dropped `%s` from the filter; %U/%V/%W/%G/%g are
# ordinary calendar week/year specifiers with no TZ dependency and still pin
# succinctly's non-implementation of all six.
#
# strftime_raw_number_input and date_roundtrip_leap_year_torture (#759) have
# since been fixed and dropped, leaving 1: strftime(fmt) now auto-converts a
# raw Unix timestamp number the same way gmtime does, matching real jq.
#
# strftime_unsupported_specifiers (#760) has since been fixed and dropped,
# leaving 0: format_strftime now implements %U/%V/%W/%G/%g (portable
# calendar-week arithmetic) and %s (recomputed from the broken-down fields
# via the same math mktime uses, not libc's TZ-dependent reinterpretation —
# see the comment above about why that's the correct portable choice).

# Reseeded by #1279/#1277 with 48 cases pinning generator-argument fan-out:
# real jq desugars `f(x)` as `x as $b | body`, so it emits one result per
# output of `x`, while succinctly resolves the argument to its first output
# and discards the rest — along with any trailing break/error/halt (#1277).
# Captured before the fix, so this block is the scoreboard for it: each stage
# of the fix deletes its own rows, and the two-sided check means a row left
# behind fails the build just as loudly as a missing one.
#
# Four kinds, in order below:
#
#   fan-out        one result per argument output (the #1279 repro shape)
#   fanout-order   *which* order, for a builtin with two generator arguments.
#                  jq has four different mechanisms here and they disagree:
#                  a C builtin nests rightmost-outermost (setpath, test/match/
#                  capture), a jq-level `def f($a; $b)` nests leftmost-outermost
#                  (range, scan), a plain non-`$` filter parameter is COLLECTED
#                  rather than fanned out (split/splits' flags — 2 outputs where
#                  the naive nesting gives 4), and a replacement evaluated per
#                  match transposes (sub/gsub). Getting these wrong yields the
#                  right count in the wrong order, which nothing else catches.
#   trailing-escape  the argument's own break/error/halt, fired after the whole
#                  prefix — except where the builtin's own error is reached
#                  first, which for setpath/delpaths outranks even a halt.
#   zero-output    #1045's "zero outputs means zero results" contract, extended
#                  to the ~16 builtins that still report a bare "no value".

#

# = 9` wrote `9` to a document jq leaves untouched — at the cost of the three
