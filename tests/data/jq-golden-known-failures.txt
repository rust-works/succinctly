# Known divergences of `succinctly jq` from the pinned-jq golden fixtures.
#
# Consumed by tests/jq_golden_tests.rs. One line per failing case:
#
#   <case>            <category>        <reason — #issue>
#
# <case> is a directory name under tests/data/jq-golden/cases/. Columns are
# whitespace-separated; `#` lines and blank lines are ignored.
#
# The check is two-sided: a case failing without a line here fails the build,
# and a line here for a case that now passes also fails the build — so every
# fix is forced to shrink this file, and no divergence can hide. The goldens
# themselves always hold the correct (pinned jq) output; only this manifest
# records where succinctly currently disagrees. See
# tests/data/yq-golden-known-failures.txt for the sibling manifest.
#
# Seeded from the #300 initial capture: 8 of 41 cases diverged from jq-1.7.1.
# Six mapped to enumerated jq issues; two were surfaced by this capture itself
# and filed fresh — format_csv (#306) and index_oob_null (#307) — exactly the
# systematic bug-surfacing #300 anticipated. collect_map_pipe, index_oob_null
# (#307), format_csv (#306), int_float_eq (#156), try_catch_error (#158),
# alt_multi_output (#160), comma_in_index (#155, via #360) and assign_rhs_root
# (#159) have since been fixed and dropped, leaving 0.
#
# Reseeded by #513 from the open bug corpus: 11 cases pinning bugs filed
# *before* a fix existed, rather than alongside one, so the manifest can act
# as a scoreboard instead of reading as a false clean bill of health.
# path_empty (#489) and comma_pipe_precedence (#462) have since been fixed
# and dropped, leaving 9; label_break_after_comma (#400) plus the
# reduce/foreach_multi_output_init pair (#534) were then seeded from newly
# filed issues, bringing it to 12, and assign_autovivify_nested (#486) has
# since been fixed and dropped, leaving 11 — each drop/add the scoreboard
# working as intended.
#
# Extended by #514 with four *_error_after_output cases, taking the file to
# 15 entries. They are the first entries whose golden carries a non-empty
# expected.out **and** a non-zero expected.status: jq streams some outputs
# and then fails. Exit code and stderr already match, so each fails on
# stdout alone — and a fix that emits the prefix while losing the failure
# would fail on status instead, which is the pairing #400/#494 need pinned.
#
# #400/#494 fixed: `QueryResult`/`GenericResult` gained a `Partial(prefix,
# control)` terminal that lets a stream carry outputs *and then* an error or
# break, instead of collapsing the whole stream to a bare `Error`/`Break`.
# alt_error_after_output, label_break_after_comma, limit_error_after_output,
# while_error_after_output and foreach_error_after_output all now match jq,
# dropping the file to 10. Verifying that fix against the pinned oracle
# surfaced a distinct, pre-existing gap — try/catch not catching break — but
# #562 fixed that separately (and landed first), and the #400/#494 branch
# extended the same fix to a Partial-prefixed break, so the count stays 10.
#
# #572 added four more cases from #534's own body: reduce_update_zero_output,
# foreach_extract_fanout, while_backtrack and until_backtrack. Unlike the
# already-pinned INIT-forking pair above (silent wrong answers), the interim
# parse_pipe_no_comma() restriction #534 describes rejects all four outright
# — jq succeeds with real output, succinctly exits 1 on a compile error, so
# no expected.status/expected.err is needed (those encode jq's own failure,
# and jq doesn't fail here); the mismatch is the bare exit-code branch in
# tests/jq_golden_tests.rs, taking the file to 14.
#
# comma_literal_before_document (#353) has since been fixed and dropped,
# leaving 13.
#
# if_multi_output_condition (#378) has since been fixed and dropped, leaving
# 12: `if`/`select` now fan out over every output of the condition instead of
# consulting only the first one, in both evaluators.
#
# nan_type (#472), slice_computed_bounds (#499), recurse_null_child (#490) and
# path_recursive_descent (#483) have since been fixed and dropped, leaving 8:
# `builtin_recurse_f`/`builtin_recurse_cond` now resolve `f` through
# `eval_owned_multi` instead of `eval_owned_expr`, so a null child is queued
# like any other value instead of being filtered out, and a single
# array-valued child is visited as one node instead of being spliced into its
# elements (#570). Separately, `resolve_node`'s `..`/`recurse`/`select`/
# typeof-filter arms already existed but were never reached, because
# `needs_path_prepass` — the gate deciding whether the pre-pass runs at all —
# only fired for a computed-key `IndexExpr` or a `Comma`. Rewritten as an
# exclusion check (anything other than the bare
# `Identity`/`Field`/`Index`/`Slice`/`Iterate` primitives the walker already
# handles natively needs the pre-pass) so a resolver arm existing without the
# gate routing to it can't recur the same way for the next combinator (#483).
#
# #354 fixed object construction's cartesian product (`eval_object_construction`
# now emits one object per key/value combination instead of taking each
# generator's first output). object_construct_cartesian — seeded far earlier by
# #513 and predating the fix's own five new golden cases — passes too, dropping
# the file to 7.
#
# assign_multi_output_rhs (#392) has since been fixed and dropped, leaving 6:
# `eval_assign` now forks once per RHS output instead of collapsing to the
# first, matching jq's own `value as $value | reduce path(paths) as $p
# (...)` desugaring. `update_path`'s `Expr::Identity` arm was fixed the same
# way for `|=`/`+=`/`-=`/`*=`/`/=`/`%=`/`//=`: it now takes the update
# filter's first output via `eval_owned_multi` instead of collapsing every
# output into an `OwnedValue::Array` via `eval_owned_expr`.

reduce_multi_output_init       reduce             a multi-output reduce INIT forks in jq; only the first init output is used — #534
foreach_multi_output_init      foreach            a multi-output foreach INIT forks in jq; only the first init output is used — #534
reduce_update_zero_output      reduce             a comma in reduce's UPDATE clause is a compile error; jq keeps only UPDATE's last output as the new state, discarding earlier ones — #534
foreach_extract_fanout         foreach            a comma in foreach's EXTRACT clause is a compile error; jq emits once per EXTRACT output instead of collapsing to one — #534
